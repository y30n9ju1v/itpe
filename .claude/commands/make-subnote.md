# 단권화 서브노트 생성

`content/docs/notes/`의 원자 노트(및 필요 시 `content/docs/problems/`의 기출문제)를 하나의 주제로 통합하여, 1교시형 단권화 서브노트를 `content/docs/subnotes/`에 생성합니다.

## 사용법

```
/make-subnote $ARGUMENTS
```

`$ARGUMENTS`에 다음 중 하나를 입력하세요.
- 주제명 또는 통합할 노트 경로 (예: `mmu-virtual-memory`, `content/docs/notes/04_ComputerSystems/05_Algorithms/paging.md content/docs/notes/04_ComputerSystems/05_Algorithms/segmentation.md`)
- 카테고리 번호/이름만 입력 (예: `06_InfoSecurity`) — 해당 카테고리에서 노트는 있는데 서브노트가 없는 주제들을 찾아 **커버리지 공백 목록을 제시**하고, 사용자 확인 후 순차 생성
- 생략 시 → 전체 카테고리를 훑어 커버리지 공백이 가장 큰 카테고리부터 후보를 제안

---

## 핵심 원칙

- 서브노트는 **1개 노트 = 1개 서브노트**가 아니라, **1개 시험 답안 주제 = 1개 서브노트**입니다. 서로 밀접히 연관된 여러 원자 노트(예: paging.md + segmentation.md + tlb.md)를 하나의 서브노트로 묶는 것이 정상입니다.
- 이미 다른 서브노트가 다루는 내용과 겹치면 새로 만들지 말고, 기존 서브노트에 통합할지 사용자에게 먼저 물어보세요 (중복 생성 방지).
- 사실 관계는 반드시 원본 노트/기출문제 내용에 근거하세요. 노트에 없는 내용을 추측으로 채우지 마세요.

## 0단계: 현재 시각 확인

```bash
date +"%Y-%m-%dT%H:%M:%S+09:00"
```

이 값을 `date` 필드에 그대로 사용하세요.

## 1단계: 대상 카테고리 및 소스 파악

- `content/docs/notes/{카테고리}/` 하위 폴더 구조를 `/make-note`의 매핑표 기준으로 확인하고, 대상 주제가 속한 카테고리를 정합니다.
- 커버리지 공백 모드일 경우: 해당 카테고리의 `notes/` 전체 파일 목록과 `subnotes/{같은카테고리}/` 파일 목록을 비교해, 아직 서브노트가 없는 노트(또는 노트 클러스터)를 나열합니다. 관련 노트끼리는 미리 묶어서 후보 주제 단위로 제시하세요.
- 대상 노트 파일과, 필요시 관련 `content/docs/problems/` 기출문제를 읽어 핵심 내용을 파악합니다.

## 2단계: 파일 배치

- 저장 경로: `content/docs/subnotes/{notes/와 동일한 1레벨 카테고리 폴더}/{주제명-영문-하이픈}.md`
- **서브노트 카테고리는 반드시 소스 노트가 속한 카테고리와 동일해야 합니다.** (예: `notes/04_ComputerSystems/...`의 노트를 통합하면 `subnotes/04_ComputerSystems/`에 저장)
- 파일명: 영어 소문자 + 하이픈. 예) `mmu-virtual-memory.md`

## 3단계: 서브노트 작성 형식

기존 서브노트(`content/docs/subnotes/06_InfoSecurity/zero-trust-architecture.md` 등)와 동일한 포맷을 정확히 따르세요.

```markdown
---
title: "{주제명 (한글)}"
date: {현재시각 RFC3339}
tags: ["{대분류}", "키워드1", "키워드2", ..., "서브노트"]
draft: false
---

# {주제명 (한글)} 서브노트

> **두음 머리에 박기 🧠**
> - **{두음}** ({무엇의 두음인지}: {풀이1}, {풀이2}, ...)
> - (필요한 만큼 반복, 보통 2~4개)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **{정식 명칭, 영문 병기}** |
| **정의** | {한 문단 정의} |
| **키워드** | {쉼표로 구분된 핵심 키워드 5개 내외} |
| **개념도** | {ASCII/화살표 다이어그램. `<br>`와 `&nbsp;`로 줄바꿈/들여쓰기 표현} |
| **구성요소** | {번호 매긴 핵심 구성요소, `<br>`로 구분} |
| **비교** | {대비되는 두 개념을 나란히, `<br><br>`로 구분} |
| **차별화** | {실무 로드맵/설계 전략 등 답안 심화용 내용, 번호 매김} |
```

**두음(니모닉) 작성 규칙 — 반드시 지킬 것:**
- 두음은 나열하는 각 용어의 **실제 앞글자(이니셜)**여야 합니다. 앞글자가 아닌 설명어를 이니셜인 것처럼 표기하지 마세요.
- 영문 약어(PE/PA/PEP, R/W/N 등)는 한글로 억지로 음역하지 말고 로마자 그대로 표기하세요 (예: `피·이·에이·피` ❌ → `PE·PA·PEP` ✅).
- 숫자나 뻔한 단어를 그대로 나열한 것(예: 그냥 "영·일·오·육")은 두음으로서 기억 효과가 없으므로 지양하고, 실제 암기 포인트가 있는 조합만 두음으로 만드세요.
- 작성 후 스스로 각 음절이 어떤 단어의 몇 번째 글자를 딴 것인지 다시 확인하세요.

## 4단계: `_index.md` 갱신

각 카테고리 `_index.md`는 frontmatter 아래에 그 카테고리의 전체 서브노트를 "토픽명 | 정의" 2열 표로 요약합니다 (파일명 가나다/알파벳 순 정렬).

```markdown
---
bookCollapseSection: true
title: "{한글 카테고리명}"
---

| 토픽명 | 정의 |
| :--- | :--- |
| [{제목}]({{< relref "/docs/subnotes/{카테고리}/{파일명}" >}}) | {정의 행 내용 그대로} |
```

- 대상 카테고리 폴더에 `_index.md`가 없으면 위 형식으로 새로 생성하세요.
- 이미 있으면 **frontmatter는 그대로 두고**, 표에 새로 만든 서브노트 행만 추가하세요 (전체 재생성 금지 — 기존 행을 실수로 훼손하지 않도록).
- 토픽명 링크는 `relref`로 절대경로(`/docs/subnotes/...`)를 사용하세요. 상대경로나 파일명만 쓰는 방식은 쓰지 마세요.
- 정의 칸은 본문 표의 **정의** 행 내용을 그대로 복사하세요 (재작성/요약하지 말 것).

## 5단계: 결과 보고

생성/수정한 서브노트 목록, 통합에 사용한 원본 노트 경로, 그리고 해당 카테고리의 남은 커버리지 공백(있다면)을 요약해서 보고하세요.
