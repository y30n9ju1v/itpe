## 문제

정보시스템감리 과업이행여부 점검 시 표본조사가 원칙이나 현실적으로는 발주기관에서 전수조사를 원칙으로 요구하는 사례가 많은 실정이다. 다음에 대하여 설명하시오.

- 1) 과업이행여부 전수점검에 대한 현실적 한계성과 감리에 미치는 문제점
- 2) 과업이행여부 전수점검에 대한 개선방안인 문서검토확인과 제3자 검증 방법

## 해설

### 출제 배경 및 의도

"RFP에 적힌 요구사항 300개를 감리원 2명이 3일 안에 전부 검증하라"는 요구가 실제 감리 현장에서 반복된다. 감리 방법론(정보시스템 감리기준)은 원래 위험기반 표본조사를 원칙으로 하지만, 발주기관은 예산 집행 책임을 감리에 전가하려는 심리로 전수조사를 요구하는 경우가 많다.

이 문제는 감리의 본질(제한된 시간·인력으로 시스템 품질을 "검증"하는 것이지 "보증"하는 것이 아님)과 현실 간의 괴리를 다룬다. 채점관은 응시자가 전수조사의 비현실성을 구조적으로 설명하고, 이를 대체할 수 있는 실효적 개선방안(문서검토확인, 제3자 검증)을 감리 방법론 관점에서 제시할 수 있는지를 평가한다. 이는 최근 감리 품질 저하 논란, 감리원 처우 문제와도 연결되는 SW생태계의 구조적 이슈이다.

### 1. 정보시스템 감리와 표본조사 원칙

정 의  • 정보시스템 감리는 감리기준(행정안전부 고시)에 따라 사업 전체 요구사항 중 위험도가 높은 항목을 표본 추출하여 점검하는 것을 원칙으로 한다.
       - 전수조사는 물리적으로 감리 기간(통상 3~10일) 내 수행이 불가능한 경우가 대부분이다.

```
[표본조사 원칙 vs 전수조사 요구]
정상 원칙: 요구사항 모집단(N) → 위험도 기반 표본 추출(n) → 심층 점검
현실 요구: 요구사항 모집단(N) → "전부 확인해달라" → 형식적 점검으로 변질
```

### 2. 1) 전수점검의 현실적 한계성과 감리에 미치는 문제점

| 구분 | 한계/문제점 | 세부 내용 |
|------|-----------|---------|
| 시간적 한계 | 감리기간 대비 검증 물량 과다 | 요구사항 수백 건을 수일 내 검증 불가 |
| 인력 한계 | 감리원 1인당 검증 가능 항목 제한 | 소수 감리원으로 전체 커버 불가능 |
| 품질 저하 | 형식적 확인으로 전락 | 화면 캡처·클릭 테스트 수준의 표피적 점검 |
| 책임 전가 | 발주기관 관리책임을 감리에 전가 | "감리 통과=완벽 보증"이라는 오인 확산 |
| 감리 신뢰도 훼손 | 부실 감리 논란, 사고 발생 시 감리 책임 공방 | 감리의 본질(위험기반 검증)이 왜곡 |

```
[악순환 구조]
발주기관 "전수조사 요구" → 감리기간/인력 불변 → 개별 항목당 점검시간 급감
   → 형식적 확인(스크린샷 확인 수준) → 실제 결함 미발견 → 사고 발생 시
   → "감리가 놓쳤다" 책임론 → 감리 신뢰도 하락 (반복)
```

### 3. 2) 개선방안: 문서검토확인과 제3자 검증

| 개선방안 | 방법 | 효과 |
|---------|------|------|
| 문서검토확인 | 수행사가 자체 이행결과를 문서(체크리스트, 테스트 결과서, 산출물 매핑표)로 사전 정리·제출, 감리는 문서 정합성과 표본 재검증에 집중 | 검증 대상을 좁혀 감리 효율 확보 |
| 제3자 검증 | 발주기관·수행사와 무관한 독립 검증 조직(별도 QA팀, 전문기관)이 사전 검증 수행, 감리는 검증 결과 신뢰성 재확인 | 이해관계 배제된 객관적 검증 이원화 |
| 위험기반 표본 확대 | 요구사항 중요도·복잡도·변경이력을 기준으로 표본 크기를 동적으로 조정 | 고위험 영역에 감리 자원 집중 |
| 상시 형상관리 연계 | 이행결과를 형상관리시스템(CI/CD)과 연동하여 실시간 추적 | 감리 시점 이전에 이행 여부 상시 확인 |

```
[개선 프로세스]
수행사: 이행결과 문서화(체크리스트+산출물 매핑) + 자체 테스트 결과 제출
        │
        ▼
제3자 검증기관: 독립적 샘플 재검증(수행사와 이해관계 없음)
        │
        ▼
감리인: 문서 정합성 검토 + 위험기반 표본 재검증(전수 아님)
        │
        ▼
감리보고서: "이행 확인" + "잔여 위험" 명시 (완벽 보증 아님을 명확화)
```

- 핵심은 "감리가 모든 것을 확인해줄 것"이라는 발주기관의 기대를 "수행사 자체 검증 + 제3자 검증 + 감리의 위험기반 표본 검증"이라는 3단계 책임 분담 구조로 전환하는 것이다.  "끝"

### 실무 제언

**발주기관의 감리에 대한 과도한 기대 관리**
- **챌린지**: 발주기관은 감리를 "품질보증(Warranty)"으로 오인하여 사고 발생 시 책임을 감리에 전가하려 한다.
- **제언**: 계약 단계에서부터 감리의 역할이 "위험기반 표본 검증"임을 명시하고, 전수조사 요구 시 추가 대가(감리기간·인력 증원)를 지급하도록 감리계약 특수조건에 반영해야 한다.

**문서검토확인의 실효성 확보**
- **챌린지**: 수행사가 제출하는 자체 점검 문서가 형식적이거나 실제와 괴리되면 문서검토확인 자체가 무의미해진다.
- **제언**: 문서 제출 시 산출물과의 추적성(RTM, 형상관리 이력)을 필수 첨부하도록 하고, 감리는 표본을 추출해 문서와 실제 시스템 간 교차검증(Cross-check)을 수행함으로써 신뢰성을 담보해야 한다.

**제3자 검증기관의 독립성 제도화**
- **챌린지**: 제3자 검증기관 선정 시 발주기관·수행사와의 인적·자본적 연관성이 있으면 검증 결과의 객관성이 훼손된다.
- **제언**: 제3자 검증기관 선정 기준에 이해상충 배제 조항을 명문화하고, 검증기관 스스로도 감리 대상에 준하는 독립성 점검을 받도록 제도화해야 한다.
