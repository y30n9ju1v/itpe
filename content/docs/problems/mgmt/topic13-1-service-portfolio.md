## 해설

### 출제 배경 및 의도

ITIL의 서비스 전략(Service Strategy) 단계에서 다루는 서비스 포트폴리오 관리는, 기업이 제공하는 모든 IT 서비스를 하나의 투자 포트폴리오처럼 관리하여 자원 배분의 우선순위를 결정하는 경영 활동이다. 기술사 시험에서 이 주제가 출제되는 이유는, IT 서비스를 단순 기술 제공이 아닌 "비즈니스 투자 대상"으로 바라보는 경영 마인드를 검증하기 위함이다.

서비스 포트폴리오, 카탈로그, 파이프라인은 자주 혼동되는 개념으로, 각각이 서비스 수명주기 상 어느 단계(기획중/운영중/폐기)에 해당하는지, 그리고 세 개념이 유기적으로 어떻게 연결되는지를 정확히 구분해서 설명하는 것이 핵심 채점 포인트다.

### 1. 서비스 포트폴리오(Service Portfolio) 개념

정 의 • 서비스 포트폴리오는 서비스 공급자가 관리하는 모든 서비스에 대한 전체 집합으로, 현재 계약중인 서비스, 개발중인 서비스, 폐기된 서비스를 모두 포함하는 상위 개념의 서비스 관리 저장소

```
[서비스 포트폴리오 = 파이프라인 + 카탈로그 + 폐기 서비스]

서비스 포트폴리오(Service Portfolio)
 ├─ 서비스 파이프라인(Pipeline) : 기획/개발 중 (아직 고객에게 제공 안 됨)
 ├─ 서비스 카탈로그(Catalogue) : 현재 운영중, 고객에게 제공중
 └─ 폐기된 서비스(Retired Services) : 단종/폐기됨
```

| 항목 | 내용 |
|------|------|
| 목적 | 전체 서비스 투자 포트폴리오의 가치·리스크·비용 관리 |
| 관리 주체 | 서비스 전략 담당(경영진/포트폴리오 관리자) |
| 의사결정 | 어떤 서비스에 투자·유지·폐기할지 결정하는 근거 |

### 2. 서비스 카탈로그와 서비스 파이프라인

1) 서비스 카탈로그(Service Catalogue)

| 구분 | 내용 |
|------|------|
| 정의 | 현재 운영 중이며 고객에게 실제 제공되는 서비스 목록(주문 가능한 서비스 메뉴) |
| 구성 | 비즈니스 서비스 카탈로그(고객 대상) + 기술 서비스 카탈로그(IT 내부 대상) |
| 활용 | 고객의 서비스 요청, SLA 협의, 가격 산정의 기준 |

2) 서비스 파이프라인(Service Pipeline)

| 구분 | 내용 |
|------|------|
| 정의 | 아직 고객에게 제공되지 않은, 기획·설계·개발 중인 서비스 목록 |
| 구성 | 아이디어 단계, 요구사항 정의 단계, 개발/테스트 단계의 서비스 |
| 활용 | 향후 서비스 로드맵, 신규 투자 우선순위 결정 |

```
[서비스 상태 전이도]
아이디어 → 요구사항정의 → 개발/테스트  ⟶  운영전환  ⟶  카탈로그 등재  ⟶  (수명 종료 시) 폐기
   └──────── 서비스 파이프라인 ────────┘        └── 서비스 카탈로그 ──┘   └ 폐기서비스 ┘
```

### 3. 세 개념의 상호 관계

```
[포트폴리오 관점의 흐름도]

           서비스 포트폴리오(Portfolio) — 전체를 관장
                    │
      ┌─────────────┼─────────────────┐
      ▼             ▼                 ▼
  파이프라인      카탈로그          폐기서비스
 (미래 서비스)   (현재 제공 서비스)  (단종 서비스)
      │             │                 │
      └── 서비스전환(개발완료) ────►    │
                    └── 서비스 수명 종료 ──►
```

| 관점 | 파이프라인 | 카탈로그 | 폐기서비스 |
|------|---------|---------|---------|
| 시점 | 미래(투자 검토중) | 현재(운영중) | 과거(단종) |
| 고객 노출 | 비노출(내부 검토) | 노출(주문 가능) | 비노출 |
| 관리 목적 | 투자 우선순위 결정 | SLA 이행/과금 기준 | 이력 관리, 대체서비스 검토 |
| 전이 조건 | 개발완료·서비스전환 승인 시 카탈로그로 이동 | 서비스 노후화/대체 시 폐기로 이동 | - |

- 세 요소는 서비스 포트폴리오라는 하나의 저장소 안에서 시간 축을 따라 이동하는 생애주기 관계를 가지며, 포트폴리오 관리자는 이 전체 흐름을 통해 투자 대비 가치(ROI)를 지속적으로 재평가한다.  "끝"

### 실무 제언

**카탈로그와 파이프라인의 단절**
- **챌린지**: 많은 조직이 카탈로그(현재 서비스) 관리에만 집중하고 파이프라인(미래 서비스 기획)을 체계적으로 관리하지 않아 신규 서비스 투자 결정이 즉흥적으로 이루어진다.
- **제언**: 분기별 포트폴리오 리뷰 회의를 통해 파이프라인 상의 서비스 후보를 비즈니스 가치·리스크 기준으로 정기 평가하고, 카탈로그 전환 여부를 공식 게이트(Stage-Gate)로 결정하는 프로세스를 운영해야 한다.

**폐기 서비스 관리의 소홀**
- **챌린지**: 사용률이 낮은 레거시 서비스가 폐기되지 않고 방치되어 유지보수 비용과 보안 리스크가 누적된다.
- **제언**: 서비스별 이용률·비용·리스크를 정기 측정하는 서비스 최적화(Service Optimization) 활동을 통해 저활용 서비스를 적극적으로 폐기 판정하고, 폐기서비스 이력을 관리해 유사 서비스 재기획 시 참고자료로 활용해야 한다.

**클라우드/SaaS 확산에 따른 포트폴리오 복잡도 증가**
- **챌린지**: 다양한 클라우드 서비스, SaaS 구독 서비스가 늘어나면서 서비스 포트폴리오 관리 범위가 기하급수적으로 확대되고 있다.
- **제언**: SaaS Management Platform(SMP) 등의 도구를 도입해 자동으로 조직 내 사용중인 클라우드/SaaS 서비스를 탐지·카탈로그화하고, 중복·미사용 서비스를 상시 모니터링하는 거버넌스 체계를 구축해야 한다.
