## 해설

### 출제 배경 및 의도

이 문제는 10-1, 10-2에서 다룬 BCP 절차와 BIA 세부지표(MBCO/MTPD)를 이미 알고 있다는 전제 하에, "BCP 수립 시 관리해야 할 지표 전체"와 "DRS를 실제로 구축할 때 고려해야 할 요소"라는 실무적 관점으로 초점을 좁힌 문제다. 즉, 이론적 절차보다 프로젝트 착수 시 실제로 챙겨야 할 체크리스트성 지식을 검증한다.

특히 DRS 구축은 데이터센터 이중화, 네트워크 이원화, 조직·인력 대응체계까지 포괄하는 복합적 엔지니어링 과제이므로, 단순 RTO/RPO 수치를 넘어 실제 구축 시 고려해야 할 기술적·관리적 요소를 폭넓게 설명하는 것이 채점 포인트다.

### 1. BCP 수립 시 주요 지표

정 의 • BCP 수립 시 주요 지표를 재해 발생 시 복구의 시간·데이터·자원·범위·서비스 수준 목표를 정량화하여, 복구 전략 수립과 DRS 구축의 기준이 되는 핵심 관리 지표라 한다.

| 지표 | 정의 | 산정 관점 |
|------|------|---------|
| RTO(목표복구시간) | 재해 후 서비스 복구까지 허용 시간 | 시스템/서비스 관점 |
| RPO(목표복구시점) | 허용 가능한 데이터 손실 시점 | 데이터 관점 |
| MTPD(최대허용중단기간) | 조직이 감내 가능한 최대 중단 기간 | 사업 존속 관점 |
| MBCO(최소사업연속성목표) | 재해 시 유지할 최소 서비스 수준 | 서비스 품질 관점 |
| RCO(Recovery Capacity Objective) | 재해 시 확보해야 할 최소 자원(인력/설비) 비율 | 자원 관점 |
| RSO(Recovery Scope Objective) | 복구 대상 업무/시스템의 범위 | 범위 관점 |

```
[지표 간 관계]
RSO(무엇을) → MTPD(언제까지) → RTO(목표시간) ≤ MTPD
                                RPO(데이터 손실 허용치)
                                MBCO(최소 서비스 수준) / RCO(최소 자원 확보율)
```

- 지표들은 독립적이지 않고 상호 제약 관계를 가지며, BIA를 통해 통합적으로 산정된다.

### 2. DRS(Disaster Recovery System) 구축 핵심 고려사항

```
[DRS 구축 고려 영역]
① 사이트 전략 : Mirror/Hot/Warm/Cold Site 선정
② 데이터 복제 방식 : 동기식 vs 비동기식 복제
③ 네트워크 이원화 : 이중 회선, DNS Failover
④ 전환 절차(Failover/Failback) : 자동/수동 전환 기준
⑤ 조직/인력 대응체계 : DR 조직도, 비상연락망
⑥ 정기 훈련 및 검증 : 모의훈련 주기, 결과 반영
```

| 고려사항 | 세부 내용 | 실패 시 리스크 |
|------|---------|---------|
| 데이터 복제 방식 | 동기식(무손실, 거리제약) vs 비동기식(지연 허용, 원거리 가능) | RPO 목표 미달성 |
| 지리적 이격거리 | 동일 재해권역 회피(최소 수십km 이상) | 동시 피해로 DR 무력화 |
| 네트워크 이중화 | ISP 이원화, BGP 라우팅, DNS TTL 최소화 | Failover 지연 |
| 전환 자동화 수준 | Automatic Failover vs Manual 전환 승인 | 전환 지연 또는 오탐 전환 |
| 데이터 정합성 검증 | 전환 후 데이터 무결성 체크섬 검증 | 데이터 오염 상태로 서비스 재개 |
| 인력/거버넌스 | DR 선언 권한자, 비상 대응 조직(CERT) 명확화 | 의사결결정 지연 |
| 비용 최적화 | 업무 등급별 차등 DR 투자(Tiering) | 과잉/과소 투자 |

### 3. 지표와 DRS 구축의 연계 관점

```
[지표 → DRS 설계 매핑]
RTO 짧음 ─────► Hot/Mirror Site + 자동 Failover 필요
RPO 짧음 ─────► 동기식 복제, 실시간 스토리지 미러링 필요
MBCO 높음 ─────► 다중화된 핵심 서비스 아키텍처(Active-Active) 필요
RCO/RSO 큼 ─────► 광범위한 백업 인프라·인력 확보 필요
```

- 지표가 엄격할수록 DRS 구축 비용이 기하급수적으로 증가하므로, BIA 결과에 따른 업무 등급화와 DRS 유형 매핑이 프로젝트 착수 전 필수적으로 선행되어야 한다.  "끝"

### 실무 제언

**동기식 복제의 물리적 한계**
- **챌린지**: RPO=0(무손실)을 목표로 동기식 복제를 요구하는 경우가 많으나, 물리적 거리 제약(통상 100km 이내)으로 광역 재해에 취약해진다.
- **제언**: 3-Site 구조(운영-근거리 동기식-원거리 비동기식)를 도입하여 무손실 복제와 광역재해 대응을 동시에 확보하는 하이브리드 전략을 채택해야 한다.

**Failover 자동화와 오탐 전환의 트레이드오프**
- **챌린지**: 자동 Failover는 신속하지만, 네트워크 일시 장애를 재해로 오판하여 불필요한 전환(False Positive)이 발생할 위험이 있다.
- **제언**: 복수 모니터링 지점의 합의(Quorum) 기반 장애 판정 로직을 도입하고, 중요 시스템은 자동 탐지 후 수동 최종 승인의 반자동 방식을 채택해 안정성을 확보해야 한다.

**DR 훈련의 형식적 운영**
- **챌린지**: DRS를 구축했으나 정기 훈련을 하지 않아 실제 재해 시 절차 오류, 데이터 불일치가 뒤늦게 발견되는 경우가 많다.
- **제언**: 연 2회 이상 실제 Failover 훈련(Live Failover Test)을 통해 RTO/RPO 목표 달성 여부를 정량 측정하고, 결과를 DR 계획서에 지속 반영하는 PDCA 체계를 운영해야 한다.
