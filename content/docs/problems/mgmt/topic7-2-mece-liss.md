## 문제

## 해설

### 출제 배경 및 의도

컨설팅 산업에서 문제를 구조적으로 분해하는 것은 해결책의 품질을 좌우하는 핵심 역량이다. MECE는 맥킨지 등 글로벌 컨설팅 펌에서 정립한 논리적 분류 원칙이며, LISS는 선형대수학의 개념을 차용하여 요인들이 서로 독립적이면서 전체 공간을 포괄하는지를 검증하는 원리이다.

이 문제는 IT 컨설팅 실무에서 문제를 어떻게 빠짐없이, 중복 없이 분해하는지에 대한 사고의 틀을 묻는다. 채점위원은 두 원리의 개념적 차이(집합론적 vs 벡터공간적 관점)를 이해하고, 이를 실제 IT 컨설팅 방법론(로직트리, 밸류체인 등)에 적용할 수 있는 실무 응용력을 평가한다.

### 1. MECE(Mutually Exclusive, Collectively Exhaustive)의 개념

정 의 • MECE란 문제나 항목을 상호 배타적(중복 없음)이면서 전체적으로 포괄적(누락 없음)이 되도록 분류하는 논리적 사고 원칙이다(McKinsey & Company).

```
[MECE 분류 예시 - 매출 하락 원인 분석]

매출 하락
  ├─ 판매량 감소 (Mutually Exclusive: 중복 없음)
  │    ├─ 신규고객 감소
  │    └─ 기존고객 이탈
  └─ 판매단가 하락 (Collectively Exhaustive: 두 항목이 매출하락 전체를 커버)
       ├─ 할인 정책 확대
       └─ 제품 믹스 변화
```

| 원칙 | 의미 |
|------|------|
| Mutually Exclusive | 각 분류 항목이 서로 겹치지 않음(중복 배제) |
| Collectively Exhaustive | 모든 분류 항목의 합이 전체를 빠짐없이 포괄 |

### 2. LISS(Linearly Independent Spanning Set)의 개념

정 의 • LISS란 선형대수학의 벡터공간 개념을 차용하여, 문제를 구성하는 요인들이 선형적으로 독립적(서로 다른 방향/차원)이면서 전체 해(Solution) 공간을 생성(Span)할 수 있어야 한다는 분석 원리이다.

```
[LISS 개념도 - 벡터 공간 유추]

  요인 A(독립축1) ─┐
  요인 B(독립축2) ─┼── 전체 문제공간(Span)을 생성
  요인 C(독립축3) ─┘

- 각 요인이 선형독립(Linearly Independent): 다른 요인으로 설명되지 않는 고유한 정보 제공
- 요인들의 조합(Span)이 전체 해 공간을 포괄
```

- MECE가 집합론적 관점(중복/누락 배제)이라면, LISS는 벡터공간적 관점(요인 간 독립성 + 전체 커버리지)으로 문제를 분해하는 원리이다.

### 3. MECE vs LISS 비교

| 구분 | MECE | LISS |
|------|------|------|
| 이론적 기반 | 집합론(Set Theory) | 선형대수학(Linear Algebra) |
| 핵심 조건 | 상호 배타성 + 전체 포괄성 | 선형 독립성 + 전체 공간 생성(Span) |
| 적용 초점 | 항목 분류의 명확성 | 요인 간 설명력의 중복 제거 |
| 정량화 가능성 | 정성적 분류 중심 | 정량적 요인 분석(회귀분석 등)에 적합 |
| 주 활용 | 이슈트리, 문제 구조화 | 다중 요인의 통계적 독립성 검증 |

### 4. MECE/LISS를 적용한 IT 컨설팅 방법론 3가지

| 방법론 | 적용 원리 | 설명 |
|--------|---------|------|
| ① 로직트리(Logic Tree) | MECE | 문제를 계층적으로 분해하되 각 가지가 중복 없이 전체를 포괄하도록 구성 |
| ② 밸류체인 분석(Value Chain) | MECE | 기업 활동을 본원적/지원적 활동으로 MECE하게 분류하여 개선 영역 식별 |
| ③ 이슈 트리 기반 가설 검증(Hypothesis Tree) | MECE + LISS | 가설을 MECE하게 분해하고, 각 가설 검증에 사용되는 데이터 요인이 서로 독립적(LISS)이도록 설계 |
| ④ 요인분석(Factor Analysis) | LISS | 다수의 IT 성과 지표에서 서로 독립적인 핵심 요인을 추출하여 중복 설명 배제 |

```
[IT 환경개선 컨설팅 적용 사례]
현황분석: 로직트리로 문제 영역 MECE 분해
   (인프라/애플리케이션/조직/프로세스)
        ↓
원인분석: 각 영역별 요인을 LISS 관점에서 독립성 검증
   (중복되는 원인 요인 통합)
        ↓
개선방안: 밸류체인 분석으로 우선순위 도출
```

- MECE와 LISS는 문제를 빠짐없이 겹치지 않게 분해하고 독립적 요인으로 검증하는 논리적 사고의 기본 원리로, IT 컨설팅 방법론 전반의 신뢰성을 뒷받침한다.  "끝"

### 실무 제언

**MECE의 형식적 적용에 따른 실효성 저하**
- **챌린지**: 컨설턴트가 MECE 형식만 갖추고 실제로는 항목 간 경계가 모호하거나 중요 원인이 누락되는 "MECE처럼 보이는" 분석을 하는 경우가 많다.
- **제언**: 분류 후 반드시 전체 데이터를 항목에 매핑해보는 검증(Exhaustiveness Check)을 수행하여 실제 누락·중복 여부를 확인해야 한다.

**LISS 개념의 정성적 오용**
- **챌린지**: 선형대수학적 개념인 LISS를 정성적 컨설팅 상황에 그대로 적용하려다 요인 간 실제 통계적 독립성을 검증하지 못하고 주관적으로 판단하는 경우가 있다.
- **제언**: 데이터 기반 컨설팅에서는 실제 요인분석(Factor Analysis), 다중공선성(VIF) 검증 등 통계 기법을 통해 LISS 원리를 정량적으로 확인해야 한다.

**AI 기반 데이터 분석과의 결합**
- **챌린지**: 대량의 IT 운영 데이터가 존재함에도 컨설턴트의 직관에만 의존해 MECE/LISS 분해를 수행하는 경우 편향이 발생할 수 있다.
- **제언**: AI 기반 클러스터링·주성분분석(PCA)을 활용해 데이터 기반으로 독립적 요인을 추출하고 이를 MECE 이슈트리와 결합하는 하이브리드 컨설팅 방법론을 도입해야 한다.
