## 해설

### 출제 배경 및 의도

정부는 「전자정부법」에 근거하여 2005년부터 범정부 EA를 구축하여 각 부처의 정보시스템 중복 투자를 방지하고 상호운용성을 확보해왔다. EA는 조직의 업무, 데이터, 애플리케이션, 기술 인프라를 하나의 청사진(Blueprint)으로 통합 관리하는 체계로, IT 거버넌스를 구체적으로 실행하는 핵심 수단이다.

이 문제는 EA 프레임워크의 구조적 이해(가)와 실제 활용 사례를 통한 실증적 이해(나)를 함께 요구한다. 채점위원은 EA를 단순한 "시스템 도면"이 아니라, 의사결정 지원·투자 효율화·상호운용성 확보를 위한 경영 도구로 설명할 수 있는지를 평가한다.

### 1. EA(Enterprise Architecture)의 정의와 필요성

정 의 • EA란 조직의 비즈니스 전략과 IT 자원을 정렬시키기 위해 업무, 데이터, 응용시스템, 기술 기반을 체계적으로 정의하고 관리하는 청사진 및 관리 체계이다(전자정부법 제2조).

| 구분 | 내용 |
|------|------|
| 목적 | 중복투자 방지, 상호운용성 확보, 정보화 투자 효율화 |
| 대상 | 업무(BA), 데이터(DA), 응용(AA), 기술(TA), 보안(SA) |
| 관점 | 현행 아키텍처(As-Is) → 목표 아키텍처(To-Be) → 이행계획(Transition Plan) |

### 2. 가. EA Framework 구조

```
[범정부 EA 참조모델 구조]

  성과참조모델(PRM) ── 정책 목표와 성과지표 연계
        │
  업무참조모델(BRM) ── 업무 기능 분류 체계
        │
  데이터참조모델(DRM) ── 공통 데이터 표준
        │
  서비스참조모델(SRM) ── 응용서비스 컴포넌트 분류
        │
  기술참조모델(TRM) ── 기술 표준, 아키텍처 원칙
        │
  보안참조모델(SRM-Security) ── 정보보호 요건
```

| 참조모델 | 영문 | 역할 |
|---------|------|------|
| 성과참조모델 | PRM(Performance) | 정책·성과 목표와 IT 투자 연계 |
| 업무참조모델 | BRM(Business) | 정부기능분류체계(BRM) 기반 업무 표준화 |
| 데이터참조모델 | DRM(Data) | 기관 간 데이터 공유·표준 코드 정의 |
| 서비스참조모델 | SRM(Service) | 응용 서비스 컴포넌트 재사용 체계 |
| 기술참조모델 | TRM(Technical) | 하드웨어·소프트웨어 표준 기술 스택 |

- Zachman Framework(6하원칙×6계층 매트릭스)나 TOGAF(ADM 방법론)와 달리, 범정부 EA는 5대 참조모델(PRM~TRM) 중심의 정부 특화 프레임워크로 설계되었다.

### 3. 나. EA 활용 사례

| 활용 영역 | 사례 |
|---------|------|
| 정보화사업 사전 협의 | 신규 정보화사업 추진 시 EA 정보시스템(EAP)에 등록·검토하여 중복 사업 여부 사전 확인 |
| 정보자원 현황관리 | 범정부 정보자원 현황(정보시스템, 서버, DB) 통합 관리로 클라우드 전환 대상 식별 |
| 상호운용성 확보 | 행정정보 공동이용망을 통한 기관 간 데이터 연계(주민등록 정보 등) |
| 정보화 투자심사 연계 | EA 참조모델 기반 사업 적정성 검토 결과를 정보화사업 예산 심사에 반영 |
| 클라우드 전환 로드맵 | 디지털플랫폼정부 추진 시 As-Is/To-Be EA 분석을 통한 우선순위 마이그레이션 대상 도출 |

```
[EA 활용 흐름]
사업계획 수립 → EA포털 등록 → 유사/중복 시스템 검토
   → 상호운용성 표준 적용 → 사업 심의/예산 반영 → 구축 → EA 현행화
```

- EA는 일회성 구축 산출물이 아니라 정보화사업 심의·투자평가·상호운용성 확보 전 과정에서 지속적으로 활용·갱신되는 살아있는 관리 체계여야 한다.  "끝"

### 실무 제언

**EA 현행화(Actualization) 부실 문제**
- **챌린지**: 다수 기관에서 EA를 구축 시점에만 작성하고 이후 시스템 변경 시 갱신하지 않아 As-Is 정보가 실제와 괴리되는 경우가 빈번하다.
- **제언**: 정보시스템 변경관리 프로세스에 EA 갱신을 필수 절차로 내재화하고, CMDB(Configuration Management DB)와 EA 저장소를 연계하여 자동 현행화 체계를 구축해야 한다.

**부처별 사일로(Silo)와 상호운용성 한계**
- **챌린지**: 범정부 EA가 있음에도 부처별 독자적 데이터 표준을 고수하여 실질적 데이터 연계가 어려운 경우가 많다.
- **제언**: 공공 데이터 표준화 협의체를 통해 DRM(데이터참조모델)의 강제성을 높이고, 마이데이터·행정정보 공동이용 확대와 연계하여 실효성을 강화해야 한다.

**디지털플랫폼정부와 EA의 재정의**
- **챌린지**: 클라우드 네이티브, API 기반 서비스 전환이 가속화되면서 전통적 EA의 문서 중심 접근이 실무 속도를 따라가지 못하고 있다.
- **제언**: EA를 정적 문서가 아닌 API 카탈로그·서비스 메시 형태의 동적·실행 가능한 아키텍처로 전환하여, 디지털플랫폼정부의 공공 마이데이터 API 생태계와 정합성을 확보해야 한다.
