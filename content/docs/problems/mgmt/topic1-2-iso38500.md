## 문제

최근 기업은 투명성과 경쟁력 확보를 위해 IT 거버넌스(Governance)를 기업의 핵심 영역으로 채택하고 있다. 이에 IT 거버넌스에 대해 설명하고, 국제표준인 ISO38500에 대해 설명하시오.

## 해설

### 출제 배경 및 의도

전 세계 이사회는 IT 투자 실패와 정보보안 사고에 대한 법적·재무적 책임을 직접 지는 시대에 접어들었다. 이에 따라 IT 거버넌스를 특정 프레임워크(COBIT 등) 없이도 이사회 수준에서 적용 가능한 국제표준으로 정립할 필요성이 대두되었고, 그 결과물이 ISO/IEC 38500(2008년 제정, 호주 AS8015 기반)이다.

이 문제는 IT 거버넌스의 개념을 조직 통제(Management)가 아닌 이사회의 감독 책임(Board-level Oversight) 관점에서 설명할 수 있는지를 묻는다. 채점위원은 COBIT처럼 상세한 프로세스 프레임워크와 ISO 38500처럼 원칙 중심(Principle-based) 표준의 차이를 이해하고 있는지를 중요하게 평가한다.

### 1. IT 거버넌스의 정의와 목적

정 의 • IT 거버넌스란 이사회 및 최고경영진이 IT의 현재와 미래 사용에 대한 효과적·효율적·수용 가능한 방식을 보장하기 위해 행사하는 통제와 프로세스 체계이다(ISO/IEC 38500).

| 구분 | 내용 |
|------|------|
| 목적 | 조직 목표 달성을 위한 IT 활용의 적정성 보장 |
| 주체 | 이사회, 최고경영진(Governing Body) |
| 대상 | IT 전략, 투자, 위험, 성과 전반 |
| 차별점 | IT Management(운영·실행)와 달리 방향 제시·감독 중심 |

### 2. ISO/IEC 38500의 구조: 3대 과업(Task)과 6대 원칙

```
[ISO/IEC 38500 거버넌스 모델]

  이사회(Governing Body)
        │
   ① 평가(Evaluate) ─── 현재/미래 IT 활용 상태 평가
        │
   ② 지시(Direct) ───── 정책과 계획 수립을 지시
        │
   ③ 모니터(Monitor) ── 정책 준수와 성과를 감시
        │
        └──── 피드백을 통해 다시 평가로 순환
```

| 과업 | 설명 |
|------|------|
| Evaluate(평가) | IT의 현재 사용 현황과 향후 사용 계획을 평가 |
| Direct(지시) | 목표 달성을 위한 정책, 계획을 준비·시행하도록 지시 |
| Monitor(모니터) | 정책 준수 여부와 계획 대비 성과를 모니터링 |

| 6대 원칙 | 내용 |
|---------|------|
| ① 책임(Responsibility) | 개인·그룹에게 IT 관련 명확한 책임 부여 |
| ② 전략(Strategy) | 조직의 현재/미래 역량을 고려해 IT 전략을 사업전략에 정렬 |
| ③ 획득(Acquisition) | 투명하고 적절한 절차로 IT 자원을 취득 |
| ④ 성과(Performance) | IT가 사업을 지원하도록 적정 서비스 수준 확보 |
| ⑤ 준거성(Conformance) | 관련 법률·규제·내부정책 준수 |
| ⑥ 인적 행동(Human Behavior) | 현재/미래 이해관계자의 요구를 존중하는 IT 정책 |

### 3. COBIT과 ISO/IEC 38500 비교

| 구분 | ISO/IEC 38500 | COBIT |
|------|--------------|-------|
| 성격 | 원칙 중심(Principle-based) 표준 | 프로세스 중심 상세 프레임워크 |
| 대상 | 이사회, 경영진 | IT부서, 감사인, 실무자 포함 |
| 상세도 | 6대 원칙 제시(How는 조직 자율) | 40개 프로세스, KPI 상세 제공 |
| 관계 | 상위 거버넌스 원칙 | 원칙을 실행하는 하위 실행 체계 |

- 두 표준은 대립적이지 않고 상호 보완적이다. ISO 38500이 "무엇을(What)" 방향을 제시한다면, COBIT은 "어떻게(How)" 실행할지를 구체화한다.  "끝"

### 실무 제언

**이사회의 IT 문해력(Literacy) 부족**
- **챌린지**: 다수의 이사회 구성원이 IT 전문성이 낮아 ISO 38500의 평가·지시·모니터 과업을 형식적으로만 수행하는 경우가 많다.
- **제언**: IT 거버넌스 위원회에 CIO/CTO를 상시 참여시키고, 이사회 보고 시 IT 리스크를 재무 지표로 환산한 대시보드를 제공하여 실질적 의사결정을 지원해야 한다.

**규제 준수(Conformance)와 혁신의 균형**
- **챌린지**: 개인정보보호법, 클라우드 보안인증(CSAP) 등 규제 준수 부담이 커지면서 신기술 도입 속도가 저하되는 경우가 있다.
- **제언**: 준거성 원칙을 만족하면서도 샌드박스·규제 유예 제도를 활용한 애자일 컴플라이언스 체계를 구축해 혁신과 준법의 균형을 확보해야 한다.

**글로벌 표준 정합성 확보**
- **챌린지**: 국내 기업이 해외 진출 시 ISO 38500 인증/준수 여부를 요구받는 사례가 증가하고 있다.
- **제언**: ISO 38500을 COBIT, ISO 27001, ITIL 등과 통합한 단일 IT 거버넌스 체계로 설계하여 글로벌 감사 대응력을 높여야 한다.
