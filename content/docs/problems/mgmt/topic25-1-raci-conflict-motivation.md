## 문제

성공적인 프로젝트 수행을 위해 프로젝트 관리자는 프로젝트 구성원에 대한 정확한 역할 할당 및 상호간의 갈등을 해결해야만 한다. 프로젝트 관리자의 팀 관리를 위한 기법에 대해 질문에 대해 답하시오.

- 가. RACI 차트
- 나. 갈등 해결 기법
- 다. 동기부여를 위한 이론 2가지 이상

## 해설

### 출제 배경 및 의도

IT 프로젝트는 결국 사람이 수행한다. 아무리 정교한 일정·비용 관리 체계를 갖춰도 역할이 불분명하고, 팀 내 갈등이 방치되고, 구성원의 동기가 저하되면 프로젝트는 실패한다. PMBOK의 자원관리(구 인력관리) 지식영역이 시험에 꾸준히 출제되는 이유다.

이 문제는 역할 명확화 도구(RACI, 가), 갈등이 발생했을 때의 대응 기법(나), 그리고 갈등의 근본 원인이 되기도 하는 동기부여 부족을 예방하는 이론(다)까지 세 층위를 종합적으로 묻는다. 채점위원은 RACI의 4개 역할 정의의 정확성, Thomas-Kilmann 갈등관리모델 5가지 유형의 상황별 적합성 판단, 그리고 동기부여 이론(매슬로우·허즈버그 등)을 프로젝트관리 맥락에 적용하여 서술하는 능력을 평가한다.

### 1. RACI 차트

정 의  • RACI 차트를 프로젝트의 각 활동/의사결정에 대해 구성원의 역할을 4가지 유형(Responsible, Accountable, Consulted, Informed)으로 명확히 구분하여 할당하는 책임 배정 매트릭스(RAM: Responsibility Assignment Matrix)로 정의한다.

| 역할 | 의미 | 설명 | 인원 수 제약 |
|------|------|------|------------|
| R (Responsible) | 실행 책임자 | 실제로 작업을 수행하는 담당자 | 1명 이상 가능 |
| A (Accountable) | 최종 승인 책임자 | 결과에 대한 최종 책임과 승인 권한 보유 | 반드시 1명(중복 시 책임 분산 문제 발생) |
| C (Consulted) | 자문 대상 | 의사결정 전 의견을 구해야 하는 전문가/이해관계자(양방향 소통) | 제한 없음 |
| I (Informed) | 통보 대상 | 결과를 사후 통보받는 대상(일방향 소통) | 제한 없음 |

```
[RACI 차트 예시 — SW개발 프로젝트]

활동             │ PM │ 아키텍트 │ 개발자 │ QA │ 스폰서
─────────────────┼────┼─────────┼───────┼────┼───────
요구사항 정의      │ A  │   C     │   I   │ C  │  I
아키텍처 설계      │ I  │   A/R   │   C   │ I  │  I
코드 구현         │ I  │   C     │  A/R  │ I  │  -
테스트 수행       │ I  │   I     │   C   │ A/R│  -
릴리즈 승인       │ C  │   C     │   I   │ C  │  A
```

- 핵심 원칙: 하나의 활동에 A는 반드시 1명이어야 한다. A가 중복되면 "누가 최종 책임지는가"가 불분명해져 책임 회피(Responsibility Diffusion) 현상이 발생한다.
- RACI 외에도 RASCI(+Support), RACI-VS(+Verify, Sign-off) 등 변형 모델이 대형 프로젝트에서 활용된다.

### 2. 갈등 해결 기법

정 의  • 프로젝트 팀 내 갈등을 자원 경쟁, 우선순위 이견, 의사소통 방식 차이 등에서 발생하는 자연스러운 현상으로 보고, 이를 건설적으로 해결하기 위한 PM의 개입 기법이다.

```
[Thomas-Kilmann 갈등관리 모델 — 협조성×주장성 2축]

주장성(Assertiveness)
  高 │  경쟁(Competing)      │  협력(Collaborating)  │
     │  강행(Forcing)        │  (Win-Win)            │
  中 │           타협(Compromising, Win-Lose 절충)     │
  低 │  회피(Avoiding)       │  수용(Accommodating)   │
     │  (Lose-Lose)          │  (양보, Lose-Win)      │
     └───────────────────────┴───────────────────────┘
        低                                  高
                  협조성(Cooperativeness)
```

| 기법 | 상황 적합성 | 장점 | 단점 |
|------|-----------|------|------|
| 협력(Collaborating) | 시간 여유 있고 양측 win-win 필요 | 최선의 해결책, 관계 유지 | 시간·노력 많이 소요 |
| 타협(Compromising) | 시간 제약 있고 양측 힘이 비슷 | 신속한 부분 합의 | 최적해 아닌 절충안일 뿐 |
| 강행/경쟁(Forcing) | 긴급 상황, PM의 결단 필요 | 신속한 결정 | 패배자 불만 누적, 관계 악화 |
| 수용(Accommodating) | 관계 유지가 이슈보다 중요 | 관계 보호 | 근본 문제 미해결 가능 |
| 회피(Avoiding) | 사소한 이슈, 감정 격화 시 냉각기 필요 | 즉각 충돌 방지 | 문제 방치 시 악화 위험 |

```
[갈등 해결 프로세스 절차]

① 갈등 인지(조기 감지) → ② 원인 분석(자원/일정/역할/성격 갈등 구분)
        │
        ▼
③ 적합한 기법 선택(위 5가지 중 상황별 선택)
        │
        ▼
④ 중재 실행(1:1 면담, 필요시 제3자 중재)
        │
        ▼
⑤ 재발 방지(RACI 재정의, 프로세스 개선)
```

- PMI 연구에 따르면 프로젝트 갈등의 주요 원인은 일정(우선순위) > 자원 배분 > 개인 간 의견 차이 순으로 나타나며, PM은 협력(Collaborating)을 기본 전략으로 하되 긴급 상황에서는 강행(Forcing)을 선택적으로 활용해야 한다.

### 3. 동기부여를 위한 이론

1) 매슬로우의 욕구 5단계 이론(Maslow's Hierarchy of Needs)

```
[매슬로우 욕구 피라미드 — 프로젝트 적용]

        ▲ 자아실현 욕구  ─ 도전적 과업 부여, 성장 기회 제공
       ╱ ╲
      ╱ 존경 욕구 ╲     ─ 성과 인정, 공개 표창, 승진 기회
     ╱─────────────╲
    ╱  소속 욕구      ╲  ─ 팀 빌딩, 심리적 안전감 조성
   ╱───────────────────╲
  ╱   안전 욕구           ╲ ─ 고용 안정, 명확한 역할(RACI)
 ╱─────────────────────────╲
╱     생리적 욕구             ╲ ─ 적정 근무시간, 급여
──────────────────────────────
```

- 하위 욕구가 충족되어야 상위 욕구로 동기부여가 이동한다는 전제로, PM은 팀원의 현재 욕구 단계를 파악하여 맞춤형 동기부여 전략을 적용해야 한다.

2) 허즈버그의 2요인 이론(Herzberg's Two-Factor Theory)

| 구분 | 위생요인(Hygiene Factors) | 동기요인(Motivator Factors) |
|------|--------------------------|------------------------------|
| 정의 | 불만족을 예방하나 만족을 증대시키지 않음 | 실제 만족과 동기부여를 유발 |
| 예시 | 급여, 근무환경, 회사 정책, 직무 안정성 | 성취감, 인정, 책임감 부여, 성장 기회 |
| 관리 시사점 | 부재 시 불만 발생 → 최소 수준 반드시 충족 | 충족 시에만 진정한 동기부여 발생 |

```
[프로젝트 적용 예시]

위생요인 관리: 초과근무 최소화, 명확한 RACI로 역할 갈등 예방
      │ (불만족 예방 단계)
      ▼
동기요인 강화: 도전적 기술과제 배정, 성과 발표 기회, 승진 경로 제시
      │ (적극적 동기부여 단계)
      ▼
결과: 위생요인만 충족하면 "불만 없음" 상태에 그치나,
      동기요인까지 충족해야 "적극적 몰입" 상태로 전환
```

3) 두 이론의 프로젝트관리 통합 활용

- RACI로 역할을 명확히 하는 것은 매슬로우의 안전 욕구, 허즈버그의 위생요인 충족에 해당한다.
- 갈등을 협력적으로 해결하고 팀워크를 강화하는 것은 매슬로우의 소속 욕구 충족에 기여한다.
- 도전적 과업과 인정을 제공하는 것은 매슬로우의 존경·자아실현 욕구, 허즈버그의 동기요인에 해당하며, PM은 이 두 이론을 결합해 팀 관리 전략을 계층적으로 설계해야 한다.  "끝"

### 실무 제언

**RACI 매트릭스의 형식적 작성과 실효성 부재**
- **챌린지**: RACI 차트를 프로젝트 착수 시점에 한 번 작성한 후 갱신하지 않아, 조직 변경·역할 재배치가 발생해도 실제 업무와 괴리된 문서로 방치되는 경우가 많다.
- **제언**: 스프린트/마일스톤 전환 시점마다 RACI를 재검토하는 체크포인트를 정례화하고, A(최종 승인) 역할의 중복 여부를 정기 감사하여 책임 공백을 사전에 제거한다.

**원격/하이브리드 근무 환경에서의 갈등 조기 감지 어려움**
- **챌린지**: 재택·하이브리드 근무가 보편화되면서 비대면 소통으로 인해 갈등의 초기 신호(어조 변화, 협업 저하)를 PM이 놓치기 쉽다.
- **제언**: 정기 1:1 면담과 팀 분위기 설문(Pulse Survey)을 병행하여 갈등을 조기에 감지하고, 화상회의에서도 의도적으로 발언 기회를 균등 배분하여 잠재적 갈등 요인을 사전에 완화한다.

**세대별·직군별 동기부여 요인의 차별화 필요성**
- **챌린지**: 매슬로우·허즈버그 이론을 획일적으로 적용하면 세대(MZ세대 vs 시니어)와 직군(개발자 vs 기획자)별로 실제 동기부여 요인이 다름을 간과하게 된다.
- **제언**: 정기적인 팀원 개별 면담을 통해 각자의 현재 욕구 단계와 중요시하는 동기요인(성장 기회, 워라밸, 금전적 보상 등)을 파악하고, 개인화된 동기부여 전략(과업 배정, 인정 방식)을 수립하여 팀 전체의 몰입도를 균형 있게 향상시킨다.
