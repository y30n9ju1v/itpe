## 해설

### 출제 배경 및 의도

PMBOK의 위험관리 지식영역은 계획-식별-분석(정성/정량)-대응계획-실행-감시의 6개 프로세스로 구성되며, 이 중 정성적 분석과 정량적 분석의 구분과 연계 방법이 시험에서 반복적으로 출제되는 핵심 포인트다. 많은 수험자가 두 분석 기법을 병렬적으로 나열하는 데 그치지만, 실제로는 정성적 분석이 정량적 분석의 선행 필터링 역할을 한다는 프로세스적 연계를 이해해야 한다.

이 문제는 전체 위험관리 프로세스의 흐름 속에서 정성적 분석(빠르고 저비용, 우선순위화)과 정량적 분석(정밀하고 고비용, 수치화)이 각각 언제, 왜 사용되는지 구분하여 서술하는 능력을 평가한다. 특히 EMV(기대금전가치), 몬테카를로 시뮬레이션 등 정량적 기법의 실제 계산 원리를 설명할 수 있는지가 변별 포인트다.

### 1. 위험관리 프로세스 전체 구조

정 의  • PMBOK 위험관리를 프로젝트에 영향을 미치는 불확실한 사건을 식별·분석하여 대응계획을 수립하고 지속적으로 감시하는 6단계 체계적 프로세스로 정의한다.

```
[PMBOK 위험관리 6대 프로세스]

① 위험관리 계획수립(Plan Risk Management)
   └─ 위험관리 방법론, 역할·책임, 예산, RBS(Risk Breakdown Structure) 정의
           │
           ▼
② 위험 식별(Identify Risks)
   └─ 브레인스토밍, 체크리스트, SWOT, 델파이 기법 → Risk Register 등재
           │
           ▼
③ 정성적 위험분석(Qualitative Risk Analysis)
   └─ 확률·영향 매트릭스로 신속한 우선순위화
           │
           ▼
④ 정량적 위험분석(Quantitative Risk Analysis)
   └─ EMV, 민감도 분석, 몬테카를로 시뮬레이션으로 수치화(선택적 수행)
           │
           ▼
⑤ 위험대응 계획수립(Plan Risk Responses)
   └─ 회피/전가/완화/수용(부정적), 활용/공유/증대/수용(긍정적)
           │
           ▼
⑥ 위험대응 실행 및 감시(Implement Risk Responses / Monitor Risks)
   └─ 트리거 모니터링, 잔존위험(Residual Risk) 재평가, 이슈 전환
```

- ③ 정성적 분석은 모든 프로젝트에서 필수로 수행하나, ④ 정량적 분석은 프로젝트 규모·복잡도·계약 유형(대형 공공사업 등)에 따라 선택적으로 수행하는 것이 일반적이다.

### 2. 정성적 위험분석 vs 정량적 위험분석

1) 정성적 위험분석(Qualitative Risk Analysis)

정 의  • 위험의 발생 확률과 영향을 상대적 등급(고/중/저)으로 평가하여 신속하게 우선순위를 매기는 기법

```
[확률-영향 매트릭스(P-I Matrix)]

영향(Impact)
  高 │  중  │  고  │ 최고 │
  중 │  저  │  중  │  고  │
  低 │  저  │  저  │  중  │
     └──────┴──────┴──────┘
       低      중      高    ← 확률(Probability)

  * 우측 상단(고확률×고영향)에 위치한 위험을 최우선 대응 대상으로 선정
```

| 기법 | 설명 |
|------|------|
| 확률·영향 평가 | 각 위험을 5점 척도 등으로 확률·영향 개별 평가 |
| 확률-영향 매트릭스 | 확률×영향을 매트릭스에 매핑해 고/중/저 등급 분류 |
| 위험 데이터 품질 평가 | 위험 정보의 정확성·신뢰성·데이터 소스 신뢰도 검증 |
| 위험 긴급성 평가 | 대응이 시급한 위험(트리거 임박)을 우선 식별 |
| RBS 기반 카테고리 분석 | 기술적/외부/조직적/프로젝트관리적 위험으로 분류하여 패턴 파악 |

2) 정량적 위험분석(Quantitative Risk Analysis)

정 의  • 식별된 주요 위험(정성적 분석에서 고위험군으로 선별된 항목)의 발생확률과 영향을 화폐가치·수치로 정밀하게 계량화하는 기법

```
[EMV(기대금전가치, Expected Monetary Value) 계산 예시]

위험 A: 발생확률 30% × 영향(손실) 1,000만원 = EMV -300만원 (위협)
위험 B: 발생확률 20% × 영향(이익)  500만원 = EMV +100만원 (기회)

프로젝트 전체 EMV = -300 + 100 = -200만원
→ 컨틴전시 예비(Contingency Reserve)를 200만원 이상 확보 필요
```

| 기법 | 설명 | 산출 결과 |
|------|------|----------|
| EMV 분석(의사결정나무 포함) | 확률×영향의 화폐가치 기대값 산출 | 컨틴전시 예비 산정 근거 |
| 민감도 분석(토네이도 다이어그램) | 개별 변수 변화가 결과에 미치는 영향력 순위화 | 관리 우선순위 변수 식별 |
| 몬테카를로 시뮬레이션 | 다수 변수의 확률분포를 수천 회 무작위 반복 계산 | 프로젝트 완료일·비용의 확률분포(S-Curve) |
| PERT 3점 추정 | 낙관치(O)·최빈치(M)·비관치(P)로 기대치·표준편차 산출 | 기대공수 = (O+4M+P)/6 |

```
[몬테카를로 시뮬레이션 결과 해석 예시]

프로젝트 완료일 확률분포:
  10% 확률로 완료 ≤ 8개월
  50% 확률로 완료 ≤ 9.5개월  ← 중앙값 목표일로 흔히 채택
  90% 확률로 완료 ≤ 11개월  ← 컨틴전시 반영 목표일
```

3) 정성 vs 정량 비교

| 구분 | 정성적 분석 | 정량적 분석 |
|------|------------|------------|
| 목적 | 신속한 우선순위화 | 정밀한 수치적 영향 산출 |
| 소요 시간/비용 | 낮음 | 높음(전문 도구·데이터 필요) |
| 수행 대상 | 식별된 전체 위험 | 정성 분석에서 선별된 고위험군 |
| 산출물 | 위험 등급(고/중/저), 우선순위 목록 | EMV, 확률분포, 컨틴전시 예비 금액 |
| 적용 규모 | 모든 프로젝트 필수 | 대형·고위험 프로젝트 선택적 수행 |

- 정성적 분석으로 전체 위험을 신속히 우선순위화한 뒤, 고위험군에 한해 정량적 분석을 선택적으로 수행하는 단계적 접근이 비용 효율적인 위험분석 전략이다.  "끝"

### 실무 제언

**정량적 분석 생략으로 인한 예비비 산정 부실**
- **챌린지**: 중소규모 IT 프로젝트는 시간·비용 제약으로 정량적 분석을 생략하고 정성적 등급만으로 예비비를 "관행적으로 총사업비의 10%"와 같이 어림잡아 산정하는 경우가 많다.
- **제언**: 고위험군으로 분류된 상위 3~5개 위험에 한해서라도 EMV를 계산하여 최소한의 정량적 근거를 확보하고, 이를 컨틴전시 예비 산정에 반영하여 예비비의 타당성을 높인다.

**정성적 분석의 주관성 편향 문제**
- **챌린지**: 확률·영향 등급 평가가 평가자의 주관(낙관 편향, 최근 경험 편향)에 좌우되어 실제 위험 우선순위와 괴리가 발생할 수 있다.
- **제언**: 다수 이해관계자가 참여하는 델파이 기법이나 위험 데이터 품질 평가를 병행하여 개인 편향을 완화하고, 과거 유사 프로젝트의 실제 발생 데이터를 기준선으로 활용해 평가 일관성을 확보한다.

**몬테카를로 시뮬레이션의 도구 접근성 한계**
- **챌린지**: 몬테카를로 시뮬레이션은 전용 도구(@Risk, Primavera Risk Analysis 등)와 통계 전문성이 필요해 중소 조직에서는 도입 장벽이 높다.
- **제언**: 초기에는 스프레드시트 기반 간이 몬테카를로(RAND 함수 활용) 또는 PERT 3점 추정만으로 근사적 정량 분석을 수행하고, 조직의 위험관리 성숙도가 높아짐에 따라 점진적으로 전문 도구를 도입하는 단계적 접근이 현실적이다.
