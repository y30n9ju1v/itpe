## 해설

### 출제 배경 및 의도

1990년대 마이클 해머(Michael Hammer)가 제창한 BPR은 "기존 프로세스를 근본적으로(Fundamental) 재고하고 급진적으로(Radical) 재설계"하는 혁신 개념으로 등장했다. 이후 실무에서는 BPR의 급진성이 조직 저항과 실패를 초래하는 사례가 빈번해지면서, IT 기반의 점진적·전사적 프로세스 혁신 개념인 PI(Process Innovation)가 널리 사용되기 시작했다.

이 문제는 두 개념이 유사해 보이지만 혁신의 범위·속도·IT 활용방식에서 어떻게 다른지를 비교하는 능력을 평가한다. 채점위원은 응시자가 단순 정의 나열이 아니라, 두 접근법의 실제 적용 맥락(전사적 vs 부문별, 급진적 vs 지속적)의 차이를 구조적으로 설명할 수 있는지를 중점적으로 확인한다.

### 1. BPR(Business Process Reengineering)의 개념

정 의 • BPR이란 비용, 품질, 서비스, 속도와 같은 핵심적 성과 측정치에서 극적인 개선을 이루기 위해 업무 프로세스를 근본적으로 재고하고 급진적으로 재설계하는 경영혁신 기법이다(Michael Hammer, 1990).

```
[BPR 추진 절차]

  ① 비전 및 목표 설정
        ↓
  ② 현행 프로세스 분석(As-Is)
        ↓
  ③ 프로세스 백지상태 재설계(Clean Sheet, To-Be)
        ↓
  ④ IT 기반 신프로세스 구현
        ↓
  ⑤ 조직/인력 재배치 및 정착
```

| 특징 | 내용 |
|------|------|
| 혁신 범위 | 전사적, 핵심 프로세스 전면 재설계 |
| 혁신 속도 | 급진적(Radical), 단기간 집중 |
| IT 역할 | 재설계의 촉매(Enabler), 필수 전제 |
| 위험 | 조직 저항, 실패율 높음(약 50~70% 실패 사례 보고) |

### 2. PI(Process Innovation)의 개념

정 의 • PI란 정보기술을 활용하여 기존 프로세스의 문제점을 지속적·전사적으로 개선함으로써 경영 성과를 향상시키는 프로세스 혁신 활동이다(Davenport, 1993).

```
[PI 추진 절차]

  ① 프로세스 비전 수립
        ↓
  ② 프로세스 식별 및 우선순위화
        ↓
  ③ 현행 프로세스 이해 및 측정
        ↓
  ④ IT 활용 신프로세스 설계(단계적/반복적)
        ↓
  ⑤ 프로토타입 구현 및 지속 개선
```

| 특징 | 내용 |
|------|------|
| 혁신 범위 | 부문별·점진적 확대 가능 |
| 혁신 속도 | 지속적(Continuous), 단계적 |
| IT 역할 | 프로세스 개선의 지원 도구 |
| 위험 | 상대적으로 낮음, 조직 수용성 높음 |

### 3. BPR vs PI 비교

| 구분 | BPR | PI |
|------|-----|-----|
| 개념 창시자 | Michael Hammer | Thomas Davenport |
| 혁신 강도 | 급진적, 전면 재설계(Zero-base) | 점진적·지속적 개선 |
| 접근 범위 | 전사 핵심 프로세스 | 개별/부문 프로세스에서 확대 |
| IT의 위치 | 재설계를 가능케 하는 전제조건 | 개선을 지원하는 도구 |
| 조직 변화 | 조직구조·인력 대규모 재편 수반 | 상대적으로 유연한 조직 적응 |
| 실패 위험 | 높음(변화관리 실패 시 큰 충격) | 낮음(단계적 검증 가능) |
| 적용 상황 | 근본적 위기, 경쟁력 상실 상황 | 지속적 경쟁우위 확보가 목표 |

```
[혁신 스펙트럼 상의 위치]
점진적 개선(Kaizen) ── PI(프로세스 혁신) ── BPR(전면 재설계) ── 신사업/사업모델 전환
      낮음 ◄────────────── 변화 강도 ──────────────► 높음
```

- BPR과 PI는 대립적 선택이 아니라 조직의 위기 수준과 전략적 목표에 따라 선택적으로 조합해야 하는 상호 보완적 혁신 접근법이다.  "끝"

### 실무 제언

**BPR 실패의 조직적 원인**
- **챌린지**: BPR은 개념적으로 매력적이나 실제로는 조직문화·인력 저항을 충분히 고려하지 않아 절반 이상이 실패로 귀결된 역사적 사례가 많다.
- **제언**: BPR 추진 시 반드시 변화관리(Change Management) 트랙을 병행하여 이해관계자 커뮤니케이션, 단계적 파일럿 적용, 인센티브 설계를 함께 수립해야 한다.

**디지털 전환 시대 PI의 재조명**
- **챌린지**: 클라우드·저코드(Low-Code) 플랫폼 확산으로 프로세스 개선의 기술적 장벽이 낮아졌으나, 여전히 많은 조직이 IT 프로젝트를 단순 시스템 교체로만 접근한다.
- **제언**: RPA·프로세스 마이닝(Process Mining) 기술을 활용해 실제 업무 흐름을 데이터 기반으로 분석하고, 이를 근거로 한 지속적 PI 사이클을 운영해야 한다.

**BPR과 PI의 하이브리드 전략**
- **챌린지**: 완전한 급진적 재설계(BPR)와 완전한 점진적 개선(PI) 중 하나만 선택하기 어려운 조직이 많다.
- **제언**: 핵심 경쟁 프로세스(고객 접점 등)는 BPR로 과감히 재설계하고, 비핵심 지원 프로세스는 PI 방식의 지속적 개선을 적용하는 이원화 전략(Dual-track) 을 구사하는 것이 실무적으로 효과적이다.
