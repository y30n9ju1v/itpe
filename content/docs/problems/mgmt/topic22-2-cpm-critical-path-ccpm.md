## 문제

다음은 어떤 프로젝트를 수행하기 위한 활동과 그 활동에 필요한 시간, 이를 수행하기 전에 해야 할 선행활동 및 가용 인원 수를 나타낸 것이다. (※ 원문에는 활동 "가"~"마" 등으로 구성된 선행활동/소요시간/가용인원을 나타낸 PDM 네트워크 활동표가 표 형태로 제시되어 있었으나, 자료 변환 과정에서 표 자체가 유실되었다. 이에 아래 해설은 표의 구체적 수치 대신, 문제가 요구하는 CPM/CCPM 계산 방법론과 풀이 절차를 중심으로 서술한다.) 각각의 물음에 답하시오.

- 가. 프로젝트 완료일은 언제인가?
- 나. 주공정(Critical Path)은 어떤 경로인가?
- 다. 활동 "라"를 2일 앞당긴다면 프로젝트 완료 일정은 어떻게 되는가?
- 라. "가"번의 경우, 가용인원을 4명/일로 제한한다면 프로젝트 완료 일정은 어떻게 되는가?
- 마. "라"번의 경우, 주공정연쇄법(Critical Chain Project Management)으로 관리한다면 어떤 버퍼를 어디에 설치해야 하는가?

## 해설

### 출제 배경 및 의도

CPM(Critical Path Method) 계산 문제는 정보처리기술사 시험에서 PM 역량을 정량적으로 검증하는 대표 유형이다. 단순 이론 서술이 아니라 실제 네트워크 다이어그램을 그리고, 전진 계산(Forward Pass)과 후진 계산(Backward Pass)을 통해 주공정과 여유시간(Float)을 산출하는 계산 능력을 요구한다.

이 문제는 여기서 한 걸음 더 나아가 (다) 특정 활동 단축 시 전체 일정 변화, (라) 자원 제약(가용인원 제한) 하의 자원 평준화(Resource Leveling), (마) CCPM의 버퍼 관리까지 묻는다. 이는 이상적인 CPM 이론과 실제 현장의 제약(인력 부족, 학생증후군, 파킨슨 법칙)을 통합적으로 이해하는지를 평가하는 고난도 문항이며, 특히 CCPM은 골드랫(Goldratt)의 제약이론(TOC)을 프로젝트관리에 적용한 것으로 최근 출제 빈도가 높다.

### 1. CPM(주공정법) 계산 절차

정 의  • CPM을 프로젝트를 구성하는 활동들의 선후행 관계를 네트워크로 표현하고, 전체 프로젝트 기간을 결정하는 가장 긴 경로(주공정)를 산출하는 일정관리 기법이라 한다.

```
[CPM 계산 표준 절차]

① AOA/AON 네트워크 다이어그램 작성
   └─ 활동(Activity), 선행관계(Predecessor), 소요기간(Duration) 반영
           │
           ▼
② 전진 계산(Forward Pass): ES, EF 산출
   └─ ES(Early Start) = 선행활동 중 최대 EF
   └─ EF(Early Finish) = ES + Duration
           │
           ▼
③ 후진 계산(Backward Pass): LS, LF 산출
   └─ LF(Late Finish) = 후행활동 중 최소 LS
   └─ LS(Late Start) = LF - Duration
           │
           ▼
④ 여유시간(Float) 계산
   └─ Total Float = LS - ES = LF - EF
   └─ Float = 0 인 활동들을 연결한 경로 = 주공정(Critical Path)
           │
           ▼
⑤ 프로젝트 완료일 = 주공정 경로 총 소요기간
```

- 예시 절차: 활동 "가"가 시작활동(선행 없음, ES=0)이고 소요기간 5일이면 EF=5, 이후 활동 "나"의 선행이 "가"이면 ES(나)=5가 된다. 이러한 방식으로 전체 네트워크를 순차 계산하여 마지막 활동의 EF가 프로젝트 완료일(가 항목의 답)이 된다.
- 여러 경로 중 Float=0인 경로(들)가 복수 존재할 수 있으며, 이 경우 병렬 주공정(Parallel Critical Path)으로 리스크가 배가된다.

### 2. 활동 단축(다) 및 자원 제약 하 일정(라) 분석

1) 다. 특정 활동("라") 2일 단축 시 영향 분석

| 판단 기준 | "라"가 주공정 위 활동인 경우 | "라"가 비주공정(Float 보유) 활동인 경우 |
|----------|---------------------------|----------------------------------|
| 프로젝트 완료일 | 2일 단축(단, 단축 후 타 경로가 새 주공정이 되는지 재확인 필요) | 변화 없음(Float 범위 내 흡수) |
| 후속 검토 | 단축 후 두 번째로 긴 경로와 재비교하여 새로운 주공정 여부 판단 | Float 소진 여부만 확인 |

- 원칙: 활동 단축의 효과는 반드시 "그 활동이 주공정 위에 있는가"를 먼저 확인해야 하며, 비주공정 활동을 아무리 단축해도 프로젝트 완료일은 변하지 않는다(자원 낭비).

2) 라. 가용인원 4명/일 제한 시 — 자원 평준화(Resource Leveling)

```
[자원 제약이 일정에 미치는 영향]

이상적 CPM(자원 무제한):  활동"가" 5일 완료 (예: 6명/일 필요 가정)
                              │
                              ▼ 가용인원 4명/일로 제한
자원 제약 CPM:            활동"가" 소요기간 증가
                          (필요 인원÷가용인원 비율만큼 순연되거나
                           작업을 분할하여 후속 기간에 걸쳐 수행)
                              │
                              ▼
                          → 프로젝트 완료일이 원래 CPM 대비 지연
                          → 이 지연이 새로운 주공정(자원 제약 주공정)을 형성
```

- 자원 평준화는 산출된 이상적 주공정에 자원가용성 제약을 반영해 재계산하는 과정이며, 결과적으로 프로젝트 완료일이 순연되는 것이 일반적이다. 이 순연분을 정량적으로 명시하고 그 근거(필요인력 대비 부족분)를 제시하는 것이 채점 포인트다.

### 3. CCPM(주공정연쇄법)의 버퍼 설치(마)

정 의  • CCPM을 골드랫의 제약이론(TOC)에 기반해 자원 제약까지 고려한 주공정(Critical Chain)을 도출하고, 개별 활동의 여유시간을 제거한 뒤 이를 모아 프로젝트 버퍼로 재배치하는 기법이라 한다.

```
[CCPM 버퍼 3종 설치 위치]

Critical Chain(주공정연쇄) ──[PB: Project Buffer]──▶ 프로젝트 완료
     ▲
     │
Feeding Chain(비주공정) ──[FB: Feeding Buffer]──▶ 합류점(주공정 연쇄 진입 직전)

자원 제약 지점(동일 자원이 순차 사용) ──[RB: Resource Buffer]──▶ 자원 재투입 시점 알림
```

| 버퍼 종류 | 설치 위치 | 목적 |
|----------|----------|------|
| 프로젝트 버퍼(PB) | 주공정연쇄 종료 지점(프로젝트 최종 완료일 직전) | 개별 활동 안전마진 제거분을 합산해 전체 일정 보호 |
| 피딩 버퍼(FB) | 비주공정(Feeding Chain)이 주공정연쇄에 합류하는 지점 | 비주공정 지연이 주공정연쇄를 침범하지 않도록 완충 |
| 자원 버퍼(RB) | 동일 핵심 자원이 순차로 여러 활동에 투입되는 시점 | 자원 가용성 확보를 위한 사전 알림(물리적 시간 지연 아님) |

- (라)에서 가용인원 4명/일 제약으로 재산출된 주공정연쇄(Critical Chain)를 기준으로, 각 활동의 개별 안전 여유(학생증후군·파킨슨 법칙으로 낭비되는 시간)를 제거하여 이를 모두 합산한 뒤 연쇄 말미에 프로젝트 버퍼(PB)로 설치하고, "가" 활동처럼 비주공정에서 주공정연쇄로 합류하는 지점에는 피딩 버퍼(FB)를, 자원이 순차 재사용되는 지점에는 자원 버퍼(RB)를 배치한다.  "끝"

### 실무 제언

**계산 문제에서 원문 표 누락 시 대응 원칙**
- **챌린지**: 실제 시험이나 학습 과정에서 활동표(선행관계·소요기간·가용인원)가 누락되면 계산 자체가 불가능하다.
- **제언**: 표가 없는 상황에서도 CPM 계산 절차(전진/후진 계산 공식)와 판단 기준(주공정 여부 우선 확인)을 명확히 기술하면 방법론 이해도를 입증할 수 있으며, 실전에서는 반드시 네트워크 다이어그램을 직접 그려 ES/EF/LS/LF를 표기하는 것이 고득점 전략이다.

**자원 제약을 무시한 이상적 CPM의 함정**
- **챌린지**: 이론적 CPM은 자원이 무한하다고 가정하지만, 실제 프로젝트는 인력·장비가 제한되어 이상적 주공정과 실제 완료일 사이에 괴리가 발생한다.
- **제언**: CPM 산출 후 반드시 자원 평준화(Resource Leveling)를 2차로 수행하고, 자원 제약으로 인한 순연 가능성을 사전에 이해관계자에게 커뮤니케이션하여 일정 리스크를 조기에 관리한다.

**CCPM 도입 시 조직 문화 저항 관리**
- **챌린지**: CCPM은 개별 활동의 안전 여유를 제거하므로, 개발자들이 "여유 없는 빡빡한 일정"으로 인식해 저항하는 경우가 많다.
- **제언**: 개별 버퍼를 없애는 대신 전체 프로젝트 버퍼로 통합 관리한다는 개념을 팀에 명확히 교육하고, 버퍼 소진율(Buffer Consumption Rate)을 시각화한 Fever Chart로 진행 상황을 투명하게 공유하여 신뢰를 확보한다.
