## 문제

스택(Stack)의 개념을 설명하고, 아래의 조건을 만족하는 스택의 작동 알고리즘을 작성하시오. (K: 스택의 크기, Top: 스택 포인터, S: 스택의 이름)

가. 스택(S)의 스택 포인터(Top)를 1 증가시킨다. 스택 포인터가 스택의 크기(K)보다 크면 Overflow 처리한다. 그렇지 않으면 Item이 가지고 있는 값을 스택의 Top 위치에 삽입한다.

나. 스택 포인터가 0이면 스택의 바닥이며 더 이상 삭제할 자료가 없으므로 Underflow 처리한다. 그렇지 않으면 Top 위치에 있는 값을 Item으로 옮기고 스택 포인터를 1 감소시킨다.

## 모범답안

1. 스택(Stack) 개념 및 Overflow/Underflow 정의

    정 의  • 삽입과 삭제가 한쪽 끝(Top)에서만 이루어지는 후입선출(LIFO) 구조의
             선형 자료구조
           - Top: 최근 삽입 원소 위치를 가리키는 포인터, K: 스택 최대 크기

    ```
          Top → [ C ]  ← 마지막 삽입(가장 먼저 삭제)
                 [ B ]
                 [ A ]  ← 최초 삽입
         Bottom → [   ]
    ```

    | 구분 | 조건 | 설명 |
    |------|------|------|
    | Overflow | Top > K | 삽입 공간이 없는 상태 |
    | Underflow | Top = 0 | 삭제할 원소가 없는 상태 |

2. "가" Push / "나" Pop 알고리즘

    1) Push(S,K,Top,Item) 알고리즘

    ```
    1. Top ← Top+1
    2. If Top > K then
    3.      Print "Overflow"; Top ← Top-1
    4. Else
    5.      S[Top] ← Item
    ```

    2) Pop(S,Top) 알고리즘

    ```
    1. If Top = 0 then
    2.      Print "Underflow"
    3. Else
    4.      Item ← S[Top]; Top ← Top-1
    5. Return Item
    ```

    - Push는 포인터 증가 후 검사, Pop은 검사 후 값 추출 순서를 반드시 지켜야 정합성 보장.

3. Push/Pop 알고리즘 검증(Trace, K=3)

    | 연산 | Top 변화 | 스택 상태 | 결과 |
    |------|----------|-----------|------|
    | 초기 | Top=0 | (empty) | - |
    | Push(10) | 0→1 | [10] | 정상 삽입 |
    | Push(20) | 1→2 | [10,20] | 정상 삽입 |
    | Push(30) | 2→3 | [10,20,30] | 정상 삽입 |
    | Push(40) | 3→4(4>K) | [10,20,30] | |Overflow|, Top 원복(3) |
    | Pop() | 3→2 | [10,20] | Item=|30| |
    | Pop() | 2→1 | [10] | Item=|20| |
    | Pop() | 1→0 | (empty) | Item=|10| |
    | Pop() | Top=0 | (empty) | |Underflow| |

    - K=3 스택에서 4번째 Push 시 Overflow, 4번째 Pop 시 Underflow가 정확히 재현됨을 확인.

4. 실무 적용 시 고려사항

    | 이슈 | 대응방안 |
    |------|----------|
    | 경계조건 검사 순서 오류(버퍼 오버런) | 삽입/삭제 앞단 경계조건 검사 선행 + 정적분석 CI 적용 |
    | 고정 크기 스택의 확장성 한계 | 동적 배열(ArrayList) 기반 자동 확장 스택 채택 |
    | 멀티스레드 환경 Top 포인터 경쟁 상태 | Lock 또는 CAS 기반 Lock-Free 스택 구현 |

    - 최근 방어적 프로그래밍 기반 경계조건 자동검증(정적분석) 적용 증대 예상.  "끝"
