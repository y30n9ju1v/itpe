## 모범답안

1. 머신 언러닝 필요성 및 개념 (가)

   정 의  • 이미 학습이 완료된 모델에서 특정 데이터(또는 그 영향)를
            효율적으로 제거하여, 해당 데이터를 처음부터 학습하지
            않은 것과 동등한 상태로 모델을 재구성하는 기술
          - 완전 재학습(Full Retraining) 대비 낮은 비용으로 삭제권 이행

```
[원본 데이터셋 D] → 학습 → [모델 M]
        │(삭제 요청 데이터 Df 발생)
        ▼
[D - Df]  ──언러닝──▶  [모델 M'] ≈ [D-Df로 처음부터 학습한 모델]
```

- GDPR 잊힐 권리·개인정보보호법 삭제권이 학습데이터에도 적용되나, 딥러닝은 데이터가 가중치 전반에 분산 저장되어 단순 원본 삭제만으론 정보가 사라지지 않는 것이 근본 문제.

| 필요성 | 설명 |
|--------|------|
| 법적 요구 | GDPR 잊힐 권리, 개인정보보호법 삭제권 이행 |
| 보안 요구 | 데이터 오염(Poisoning), 백도어 데이터 제거 |
| 저작권 요구 | 무단 수집 데이터·저작물 학습 영향 제거 |
| 비용 효율 | 특정 데이터마다 전체 재학습 시 막대한 컴퓨팅 비용 발생 |

- 완전 재학습(Full Retraining) 대비 낮은 비용으로 삭제권을 이행하는 것이 목적.

2. 머신 언러닝 주요 기법 (나)

| 구분 | 기법 | 설명 |
|------|------|------|
| 완전 재학습 | Exact Unlearning | 삭제 데이터 제외 후 처음부터 재학습, 가장 정확하지만 고비용 |
| 분할 학습 | SISA (Sharded, Isolated, Sliced, Aggregated) | 데이터를 샤드로 분할해 서브모델 학습, 삭제 시 해당 샤드만 재학습 |
| 근사적 삭제 | Gradient/Influence 기반 | 삭제 데이터의 그래디언트·영향함수(Influence Function)를 역산해 가중치 보정 |
| 근사적 삭제 | Fisher Information 기반 | 파라미터 중요도(Fisher 정보량)를 활용해 선택적 가중치 스크러빙(Scrubbing) |
| 지식 증류 | Teacher-Student Unlearning | 삭제 데이터를 제외한 지식만 학생 모델로 증류 |
| 검증 | Membership Inference 검증 | 언러닝 후 해당 데이터의 잔존 여부를 멤버십 추론 공격으로 검증 |

- 완전 재학습은 정확하나 비용이 크고, 근사적 기법은 효율적이나 완전성 검증이 어려운 트레이드오프 존재.

3. 머신 언러닝 발전 방안 (다)

| 구분 | 발전 방안 |
|------|----------|
| 기술 | 언러닝 효율성·정확성 검증을 위한 표준 벤치마크·평가지표 개발 |
| 아키텍처 | 초기 설계 단계부터 언러닝을 고려한 모듈형(SISA류) 모델 아키텍처 설계 |
| 검증체계 | 언러닝 완료 여부를 제3자가 검증할 수 있는 인증·감사 체계 구축 |
| 제도 | 삭제 요청 처리 기한·절차를 규정하는 법·가이드라인 정비 |
| 생태계 | 오픈소스 언러닝 툴킷·프레임워크 확산으로 중소 AI 기업 접근성 제고 |

- 근사적 기법의 완전성 입증을 위해 멤버십 추론 공격 등 사후 검증을 표준 프로세스화하고, 이행 로그를 감사 가능하도록 보관.

4. 실무 이슈 및 시사점

| 이슈 | 대응 방향 |
|------|----------|
| 모델 성능 저하(파국적 망각 유사) | SISA류 국소화 아키텍처 채택으로 전체 성능 영향 최소화 |
| LLM 확장 과제 | LoRA 등 경량 파인튜닝 + 프롬프트 레벨 필터링 결합 하이브리드 언러닝 |

- 최근 LLM 대상 선택적 지식 삭제 수요 증대로 경량 파인튜닝 기반 언러닝 기법 적용 확대 예상.  "끝"
