## 문제

알고리즘 기법에 대한 다음 질문에 대하여 설명하시오

가. BST(Binary Search Tree)와 AVL Tree 에 대한 설명
나. AVL Tree 를 유지하기 위한 Rotation 연산 설명
다. 아래 노드를 순서대로 삽입하면서 균형을 유지하는 AVL Tree 구성

## 모범답안

1. "가" BST와 AVL Tree 개념

    정 의  • 모든 노드의 균형인수(BF)가 -1~1로 유지되는 자기균형
             이진탐색트리(BST)
           - 삽입/삭제 시 회전(Rotation) 연산으로 항상 O(log n) 높이를
             보장하는 구조

    | 구분 | BST | AVL Tree |
    |------|-----|----------|
    | 균형 보장 | 없음(편향 가능) | 회전으로 항상 균형 유지 |
    | 최악 높이 | O(n) | O(log n) |
    | 탐색 성능 | 최선 O(log n), 최악 O(n) | 항상 O(log n) |
    | 부가 비용 | 없음 | 회전 연산 오버헤드 |

    - BF(Balance Factor) = height(좌)-height(우), AVL은 모든 노드에서 |BF|≤1 유지.

2. "나" Rotation 연산 4가지 유형

    | 유형 | 발생 조건 | 처리 방법 |
    |------|-----------|-----------|
    | LL | 왼쪽 자식의 왼쪽으로 삽입 | 단순 우회전(Right Rotation) 1회 |
    | RR | 오른쪽 자식의 오른쪽으로 삽입 | 단순 좌회전(Left Rotation) 1회 |
    | LR | 왼쪽 자식의 오른쪽으로 삽입 | 좌회전 후 우회전(2단계) |
    | RL | 오른쪽 자식의 왼쪽으로 삽입 | 우회전 후 좌회전(2단계) |

    - LR/RL은 "자식을 먼저 회전해 LL/RR 형태로 바꾼 뒤 다시 회전"하는 Double Rotation.

3. "다" 2,1,8,9,7,3,6,4,5 순차 삽입 AVL 트레이스

    | 삽입 | 불균형 검사 | 케이스 | 처리 결과 |
    |------|-------------|--------|-----------|
    | 2,1,8,9,7 | 각 단계 균형 | - | 2(L:1,R:8(L:7,R:9)) |
    | 3 | 노드2 BF=-2 | RL(8의 BF=+1) | |7이 새 루트|: 7(L:2(L:1,R:3),R:8(R:9)) |
    | 6 | 전 노드 균형 | - | 7(L:2(L:1,R:3(R:6)),R:8(R:9)) |
    | 4 | 노드2 BF=-2 | RR(3의 BF=-1) | |4가 노드2 자리 대체|: 7(L:4(L:2(L:1),R:3),R:8(R:9)) |
    | 5 | 전 노드 균형 | - | 회전 없이 완료 |

    - 3 삽입: 노드2 BF=0-2=-2, 자식8 BF=1-0=+1(RL) → 8 우회전 후 2 좌회전, 7이 새 루트로 승격.
    - 4 삽입: 노드2 BF=-2, 자식3 BF=-1(RR) → 노드2 기준 단순 좌회전, 4가 노드2 자리 대체.
    - 5 삽입: 노드6 BF=+1, 노드4 BF=0, 노드7 BF=+1로 모두 균형 유지, 추가 회전 없이 완료.

    **최종 완성된 AVL 트리:**
    ```
                  |7|
               /     \
              4         8
            /   \         \
           2     6           9
          / \   /
         1   3 5
    ```
    - 검증: 노드7 BF=1, 노드4 BF=0, 노드2 BF=0, 노드6 BF=1, 노드8 BF=-1, 전 노드 |BF|≤1 성립.

4. 실무 적용 시 고려사항

    | 이슈 | 대응방안 |
    |------|----------|
    | LR/RL을 LL/RR 단순 회전으로 오판 시 트리 붕괴 | 자식 BF까지 확인하는 4분기 판별 로직 단위테스트 검증 |
    | 삽입/삭제 빈번 워크로드의 회전 오버헤드 | 조회 위주는 AVL, 삽입/삭제 위주는 Red-Black Tree 채택 |
    | 디스크 인덱스에 AVL 적용 시 I/O 과다 | AVL은 In-Memory 전용, 디스크 인덱스는 B-Tree 계열 채택 |

    - 최근 메모리 상주 캐시·인메모리 DB에서 AVL 기반 균형 탐색 구조 적용 증대 예상.  "끝"
