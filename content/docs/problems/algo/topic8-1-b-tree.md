## 문제

B 트리(Balanced tree)와 관련하여 다음을 설명하시오.

가. B 트리 삽입 알고리즘
나. B 트리 삭제 알고리즘
다. 26, 57, 5, 33, 72, 45 를 순서대로 삽입하고, 72, 33, 45 를 순서대로 삭제하는 B 트리를 그리시오. (단, 차수는 3)

## 모범답안

1. B 트리 개요 (차수 m=3 기준)

    정 의  • 모든 리프 노드가 동일 깊이를 갖도록 자가 균형을 유지하는
             다진 탐색 트리
           - 삽입/삭제 시 분할·병합으로 균형과 정렬 순서를 동시 보장하는 구조

    ```
    [B 트리(m=3) 제약]
      - 노드당 키 개수: 1~2개(루트는 1개 이상)
      - 노드당 자식 개수: 0(리프) 또는 2~3개
      - 모든 리프는 동일 레벨(높이 균형 보장)
      - 최소 키 수=⌈m/2⌉-1=1, 최소 자식 수=⌈m/2⌉=2
    ```

    - RDBMS 인덱스(InnoDB B+Tree), 파일시스템 디렉터리 구조 등 저장 시스템의 근간.

2. "가" 삽입 알고리즘 / "나" 삭제 알고리즘

    1) 삽입 알고리즘

    ```
    1. 루트에서 키 값 비교로 삽입할 리프 노드 탐색
    2. 리프에 정렬 위치로 키 삽입
    3. 키 개수가 m-1(=2) 초과 시 오버플로우
    4. 분할: 중앙값(Median) 부모로 승격, 나머지 좌/우 분리
    5. 부모도 오버플로우 시 재귀 분할(루트 전파 시 높이+1)
    ```

    2) 삭제 알고리즘

    ```
    1. 리프 키는 바로 삭제, 내부노드 키는 선행자/후행자로 대체 후 리프에서 삭제
    2. 삭제 후 키 개수가 최소치(⌈m/2⌉-1=1) 미만(언더플로우)이면
       a. 형제 여유 有 → 회전(Rotation): 부모 키 하강 + 형제 키 승격
       b. 형제 여유 無 → 병합(Merge): 부모 분리키 하강 + 좌우 병합
    ```

3. "다" 26,57,5,33,72,45 삽입 및 72,33,45 삭제 트레이스

    1) 삽입 트레이스

    | 단계 | 삽입 키 | 처리 결과 |
    |------|---------|-----------|
    | 1~2 | 26,57 | [26,57] |
    | 3 | 5 | [5,26,57] 오버플로우 → 중앙값 26 승격, 분할 |
    | 4 | 33 | 우측 자식[57]에 삽입 → [33,57] |
    | 5 | 72 | [33,57,72] 오버플로우 → 중앙값 57 승격 |
    | 6 | 45 | 중앙 자식[33]에 삽입 → [33,45] |

    ```
    최종 삽입 결과:        |[26,57]|
                          /   |    \
                       [5] [33,45] [72]
    ```

    2) 삭제 트레이스

    | 삭제 키 | 처리 | 결과 |
    |---------|------|------|
    | 72 | 리프 언더플로우 → 좌형제[33,45] 회전(57 하강, 45 승격) | [26,45] / [5]\|[33]\|[57] |
    | 33 | 리프 언더플로우 → 형제 여유無 → [5]+26+빈노드 병합 | [45] / [5,26]\|[57] |
    | 45 | 내부노드 키 → 선행자 26 대체, 리프[5,26]에서 26 삭제 | |[26]| / [5]\|[57] |

    - 최종 삭제 결과: 루트|[26]|, 좌측 자식[5], 우측 자식[57].

4. 실무 적용 시 고려사항

    | 이슈 | 대응방안 |
    |------|----------|
    | 삭제 시 언더플로우 처리(회전/병합) 생략 시 인덱스 파편화 | 검증된 B+Tree 라이브러리/DBMS 구현 참고 |
    | 대량 배치 삭제 시 병합 연쇄로 디스크 I/O 집중 | 삭제 트랜잭션 분할 + 오프피크 재구축(Reindex) |
    | 차수(m)가 작으면 트리 높이 증가로 I/O 과다 | 디스크 페이지 크기(4KB 등)에 맞춰 차수 설계 |

    - 최근 대용량 인덱스 환경에서 B+Tree 차수 최적화 및 온라인 재구축 적용 증대 예상.  "끝"
