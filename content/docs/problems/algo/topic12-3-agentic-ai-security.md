## 모범답안

1. 에이전틱 AI 개념 및 주요 특징 (가)

   정 의  • 목표(Goal)가 주어지면 스스로 계획 수립, 도구 호출, 실행,
            평가를 반복하며 자율적으로 다단계 작업을 완수하는 AI 시스템
          - 단순 응답형 LLM과 달리 '자율성(Autonomy)'이 핵심 차별점

```
[목표 입력] → 계획(Plan) → 도구 호출(Tool/API) → 실행(Act)
                 ↑                                    │
                 └───── 평가·재계획(Reflect/Loop) ◀────┘
                              (Memory 저장)
```

- 국가정보원 등 보안 당국이 "AI 보안 가이드북"을 배포한 배경에는 공공부문 AI 도입 확산에 따른 정보유출·오남용 우려가 자리함.

2. 에이전틱 AI 주요 특징

| 특징 | 설명 |
|------|------|
| 자율성 | 인간 개입 최소화, 목표 기반 다단계 의사결정 |
| 도구 사용 | 외부 API·DB·파일시스템 등 실제 시스템과 상호작용(MCP, Function Calling) |
| 기억(Memory) | 단기/장기 메모리로 맥락 유지 및 학습 |
| 다중 에이전트 협업 | 여러 에이전트가 역할 분담하여 협업(Multi-Agent) |

- 챗봇형 생성 AI의 수동적 응답과 달리, 실행 권한을 갖고 다단계 작업을 자율 수행하는 것이 특징.

3. 에이전틱 AI 환경의 주요 보안 위협 (나) — 3축 분류

```
[축1: 입력/추론 조작]        [축2: 권한/실행 남용]        [축3: 데이터/신뢰 붕괴]
• 프롬프트 인젝션            • 과도한 권한 위임            • 메모리/맥락 유출
• 환각 기반 오작동           • 툴 체이닝 익스플로잇        • 다중 에이전트 오염
```

| 구분 | 위협 유형 | 설명 |
|------|----------|------|
| 입력 조작 | 프롬프트 인젝션 | 악성 지시를 입력·문서·웹페이지에 은닉해 에이전트 행동 조작 |
| 권한 남용 | 과도한 권한 위임 | 에이전트가 과도한 시스템 권한(파일 삭제, 결제 등)을 보유해 오남용 |
| 도구 체인 공격 | 툴 체이닝 익스플로잇 | 여러 도구 호출을 연쇄시켜 우회적으로 민감 작업 수행 |
| 데이터 유출 | 메모리/맥락 유출 | 장기 메모리에 저장된 민감정보가 이후 세션에서 유출 |
| 신뢰 경계 붕괴 | 다중 에이전트 오염 | 하나의 오염된 에이전트가 협업 체계 전체로 악성 지시 전파 |
| 환각 기반 오작동 | 잘못된 행동 실행 | 모델 환각으로 잘못된 API 호출·자원 삭제 등 실제 피해 발생 |

- 기존 LLM 보안 위협(프롬프트 인젝션 등)에 '실행 권한'이 더해지며 피해 파급력이 확대되는 것이 핵심 차이.

4. 안전한 에이전틱 AI 보안 대책 (다) — 관리적·기술적 2×2 결합

```
① 권한/승인 통제                    ② 입력/모니터링 통제
• PoLP 정책, RBAC 스코프 제어        • 프롬프트 인젝션 탐지, 행동 로깅
• Human-in-the-loop 승인 게이트      • 실행 이력 감사 체계

③ 격리 통제                          ④ 데이터 보호 통제
• 업무별 에이전트 분리, 샌드박스      • 메모리 보존기간·파기 정책
• 네트워크 세그멘테이션              • 메모리 암호화, PII 마스킹
```

| 구분 | 관리적 대책 | 기술적 대책 |
|------|------------|------------|
| 권한 통제 | 최소권한 원칙(PoLP) 정책 수립 | 도구별 세분화된 권한·스코프 제어(RBAC) |
| 입력 검증 | 프롬프트/도구 사용 가이드라인 제정 | 입력 필터링, 프롬프트 인젝션 탐지 모델 적용 |
| 모니터링 | 실행 이력 감사 체계 구축 | 행동 로깅, 이상행위 탐지(Anomaly Detection) |
| 승인 절차 | 고위험 작업 인간 승인(Human-in-the-loop) | 민감 작업(삭제·결제 등) 자동 승인 게이트 적용 |
| 격리 | 업무별 에이전트 분리 운영 정책 | 샌드박스 실행환경, 네트워크 세그멘테이션 |
| 데이터 보호 | 메모리 보존기간·파기 정책 | 메모리 암호화, PII 마스킹 |

- 업무 위험도에 따라 완전자동/반자동(승인)/수동 3단계로 자율성 등급을 구분하는 거버넌스와, MCP 서버·플러그인 화이트리스트·서명 검증 등 공급망 관리를 병행.
- 최근 공공부문은 저위험 업무부터 시범 적용 후 단계적으로 고위험 업무로 확대하는 관리적·기술적 심층방어(Defense in Depth) 적용 증대.  "끝"
