## 모범답안

1. 점근표기법 개요

    정 의  • 입력 크기 n이 무한히 커질 때 알고리즘의 수행시간(공간) 증가 추이를
             함수로 근사해 표현하는 수학적 표기법
           - 상수 계수/저차항을 무시하고 지배적인 증가율만 표현하는 구조

    ```
    [알고리즘 수행시간 T(n)]
            ↓ n→∞ 극한적 성장 추이만 추출
       [점근표기법: O, Ω, Θ, o, ω]
            ↓
      하드웨어/언어 독립적 성능 비교 가능
    ```

    - 클라우드 비용이 자원 사용량에 직결되는 환경에서 복잡도 분석 오류는 곧 비용/장애로 직결.

2. 점근표기법 5종 비교

    | 표기법 | 명칭 | 의미 | 실무 해석 |
    |--------|------|------|-----------|
    | O(f(n)) | Big-O | 상한(Upper Bound) | 최악의 경우(Worst Case) 성능 보장 |
    | Ω(f(n)) | Big-Omega | 하한(Lower Bound) | 최선의 경우(Best Case) 성능 |
    | Θ(f(n)) | Big-Theta | 상하한 동시 성립 | 평균/정확한 성장률 |
    | o(f(n)) | Little-o | 엄격한 상한 | f(n)보다 항상 느리게 증가 |
    | ω(f(n)) | Little-omega | 엄격한 하한 | f(n)보다 항상 빠르게 증가 |

    1) SLA 관점의 Big-O 우선 사용

    - 실무에서 O(빅오)가 가장 널리 쓰이는 이유는 "최악의 상황에서도 이 정도는 보장된다"는 SLA 안전마진 확보가 중요하기 때문.

3. 주요 복잡도 등급 및 계산 예시

    ```
    증가율(느림→빠름): O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

    예) T(n) = 3n² + 5n + 100
      - n→∞ 이면 3n²항이 지배적, 상수/저차항 무시
      - Big-O 표기 : |O(n²)|
    ```

    | 복잡도 | 대표 알고리즘 |
    |--------|----------------|
    | O(1) | 배열 인덱스 접근, 해시 조회 |
    | O(log n) | 이진 탐색 |
    | O(n log n) | 병합정렬, 퀵정렬(평균) |
    | O(n²) | 버블/삽입/선택 정렬 |
    | O(2ⁿ) | 완전탐색, 순수 재귀 피보나치 |

    - 최선/평균/최악을 구분하되 시스템 설계는 보통 Big-O(최악) 기준으로 용량계획 수립.

4. 실무 적용 시 고려사항

    | 이슈 | 대응방안 |
    |------|----------|
    | 평균 우수 알고리즘(퀵정렬)이 실무 패턴상 최악에 빠짐 | 최악 복잡도 확인 + 무작위 피벗 등 방어 기법 적용 |
    | 상수항 무시로 이론상 우수해도 실제로 느림 | 점근표기법은 1차 필터, 실제 데이터로 프로파일링 병행 |
    | 시간 복잡도 개선에 치중해 공간 복잡도(OOM) 간과 | 시간-공간 트레이드오프 사전 산정, 롤링 배열로 최적화 |

    - 최근 대규모 트래픽 환경에서 최악 시나리오 기반 복잡도 검증과 벤치마킹 병행 증대 예상.  "끝"
