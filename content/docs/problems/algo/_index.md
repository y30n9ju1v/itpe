## Part 1. 알고리즘 기초와 설계 기법

### 1-1. 점근표기법과 알고리즘 복잡도

#### "택배 상하차, 몇 명이 와도 똑같이 빠른 작업은?"

물류 창고에서 일한다고 상상해 봅니다. 택배 상자를 컨베이어 벨트에서 꺼내 트럭에 싣는 작업은, 상자가 100개든 10,000개든 한 사람이 상자 하나를 처리하는 시간은 항상 똑같습니다. 상자 개수(n)가 늘어나면 작업 시간도 정직하게 비례해서 늘어납니다. 이런 작업을 **O(n)** — "입력 크기에 정비례해서 시간이 걸리는 일"이라 부릅니다.

반면 전화번호부에서 이름을 찾는 상황은 다릅니다. 1,000명이 적힌 전화번호부든 100만 명이 적힌 전화번호부든, "가운데를 펼쳐서 찾는 이름이 앞쪽에 있는지 뒤쪽에 있는지 보고, 그 절반을 또 반으로 쪼개는" 방식(이진 탐색)을 쓰면 100만 명이라도 20번 이내에 찾아냅니다. 데이터가 아무리 늘어도 걸리는 시간은 거의 늘지 않는 이런 작업을 **O(log n)**이라 부릅니다.

가장 무서운 경우는 반 친구들 30명이 모두 서로 악수를 나누는 상황입니다. 사람이 1명 늘어날 때마다 악수해야 할 상대가 기하급수적으로 늘어나는 것처럼, 입력이 조금만 늘어나도 계산량이 폭발적으로 치솟는 것을 **O(2ⁿ)**(지수 시간)이라 부릅니다. 완전탐색으로 모든 부분집합을 다 뒤져보는 알고리즘이 여기에 해당합니다.

이렇게 "입력 크기 n이 무한히 커질 때 알고리즘의 수행 시간(또는 공간)이 어떤 추세로 늘어나는지"를 상수항이나 자잘한 저차항은 무시하고 가장 지배적인 항만 뽑아 함수로 표현하는 수학적 표기법이 **점근표기법(Asymptotic Notation)**입니다. 하드웨어 성능이나 프로그래밍 언어에 상관없이 "이 알고리즘의 본질적인 성장 속도"를 비교할 수 있게 해주는 공통 잣대인 셈입니다.

```
[알고리즘 수행시간 T(n)]
        ↓  n → ∞ 극한적 성장 추이만 추출
   [점근표기법: O, Ω, Θ, o, ω]
        ↓
  하드웨어/언어 독립적 성능 비교 가능
```

#### 상한, 하한, 그리고 정확한 값 — Big-O, Big-Ω, Big-Θ

똑같은 알고리즘이라도 "운이 좋을 때(최선)", "운이 나쁠 때(최악)", "평균적으로" 걸리는 시간이 다를 수 있습니다. 이를 구분해서 표현하는 세 가지 대표 표기법이 있습니다.

* **Big-O — 상한(Upper Bound), "아무리 늦어도 이 정도 안에는 끝난다"**
  최악의 경우(Worst Case)를 기준으로 성능을 보장하는 표기법입니다. 마치 택배 기사가 "아무리 길이 막혀도 오늘 안에는 반드시 배송을 마칩니다"라고 상한선을 약속하는 것과 같습니다. 실무에서 가장 널리 쓰이는 이유도 여기 있습니다. 서비스 SLA(서비스 수준 협약)를 정할 때는 "최선일 때 얼마나 빠른가"보다 "최악일 때도 이 정도는 보장된다"는 안전마진이 훨씬 중요하기 때문입니다.
* **Big-Ω(오메가) — 하한(Lower Bound), "아무리 빨라도 이 정도는 걸린다"**
  최선의 경우(Best Case)를 기준으로 한 하한선입니다. "아무리 도로가 뻥 뚫려도 최소 30분은 걸린다"는 이야기와 같습니다.
* **Big-Θ(세타) — 상한과 하한이 동시에 성립, "정확히 이 정도 속도"**
  상한과 하한이 사실상 같은 지점에서 만날 때 쓰는, 가장 정밀한 표기법입니다. 평균적인 성장률을 정확하게 나타냅니다.

> 💡 **little-o, little-ω도 있습니다**
> Big-O/Ω가 "같거나 낮은/높은" 느슨한 경계라면, little-o(오)와 little-ω(오메가)는 "반드시 더 낮은/더 높은" 엄격한 경계를 뜻합니다. 실무에서는 잘 쓰이지 않지만 이론적으로 성장률을 더 세밀하게 구분할 때 등장합니다.

| 표기법 | 명칭 | 의미 | 실무 해석 |
|--------|------|------|-----------|
| O(f(n)) | Big-O | 상한 | 최악의 경우에도 이 정도는 보장 |
| Ω(f(n)) | Big-Omega | 하한 | 최선의 경우 성능 |
| Θ(f(n)) | Big-Theta | 상하한 동시 성립 | 평균/정확한 성장률 |
| o(f(n)) | Little-o | 엄격한 상한 | f(n)보다 항상 느리게 증가 |
| ω(f(n)) | Little-omega | 엄격한 하한 | f(n)보다 항상 빠르게 증가 |

#### 대표적인 시간복잡도 등급 한눈에 보기

아래로 갈수록 데이터가 늘어날 때 시간이 훨씬 가파르게 증가합니다. 100개까지는 큰 차이가 없어 보이지만, 데이터가 100만 개, 1억 개로 늘어나면 O(n²)과 O(n log n)의 격차는 하늘과 땅 차이가 됩니다.

```
증가율(느림 → 빠름):
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

  느림 ▲
       │                                          O(n!), O(2ⁿ)  (완전탐색 지옥)
       │                                    ╱
       │                              ╱
       │                        ╱          O(n²)  (버블/삽입 정렬)
       │                  ╱
       │            ╱               O(n log n)  (병합/퀵정렬)
       │      ╱
       │╱───────────────────  O(n)  (순차 탐색)
       │─ ─ ─ ─ ─ ─ ─ ─ ─ ─  O(log n)  (이진 탐색)
       │───────────────────  O(1)  (배열 인덱스 접근)
  빠름 └───────────────────────────────────▶ 입력 크기 n
```

| 복잡도 | 이름 | 대표 알고리즘 | 체감 비유 |
|--------|------|----------------|-----------|
| O(1) | 상수 시간 | 배열 인덱스 접근, 해시 조회 | 몇 명이 오든 계산대 스캔 한 번 |
| O(log n) | 로그 시간 | 이진 탐색 | 전화번호부를 반씩 접어가며 찾기 |
| O(n) | 선형 시간 | 순차 탐색, 택배 상하차 | 상자 개수만큼 정직하게 일하기 |
| O(n log n) | 선형로그 시간 | 병합정렬, 퀵정렬(평균) | 반으로 쪼개며 정렬 후 합치기 |
| O(n²) | 이차 시간 | 버블/삽입/선택 정렬 | 모든 사람이 서로 한 번씩 비교 |
| O(2ⁿ) | 지수 시간 | 완전탐색, 순수 재귀 피보나치 | 부분집합을 모조리 나열 |

> ⚠️ **점근표기법을 계산하는 실전 요령**
> 예를 들어 `T(n) = 3n² + 5n + 100`이라는 수행시간 함수가 있다면, n이 무한히 커질수록 `3n²` 항이 나머지를 압도합니다. 상수 계수 `3`과 저차항 `5n + 100`은 무시하고 **O(n²)** 하나로 표기합니다. "가장 크게 자라는 항 하나만 남긴다"가 핵심 요령입니다.

#### 실무에서 점근표기법을 다룰 때 조심할 점

| 이슈 | 대응 방안 |
|------|-----------|
| 평균적으로 우수한 알고리즘(퀵정렬)이 특정 입력 패턴에서 최악 케이스에 빠짐 | 최악 복잡도를 함께 확인하고, 무작위 피벗 선택 등 방어 기법 적용 |
| 상수항을 무시하다 보니 이론상 우수해도 실제로는 느림 | 점근표기법은 1차 필터일 뿐, 실제 데이터로 프로파일링을 병행 |
| 시간 복잡도 개선에만 몰두해 공간 복잡도(메모리 부족)를 간과 | 시간-공간 트레이드오프를 사전에 따져보고 롤링 배열 등으로 최적화 |

### 1-2. 4대 알고리즘 설계 기법 (백트래킹 / 분할정복 / 탐욕법 / 동적계획법)

#### "큰 문제를 어떻게 쪼갤 것인가" — 네 가지 전략가의 성격

같은 미로를 탈출하는 문제라도 사람마다 접근 방식이 다릅니다. 어떤 사람은 길이 막히면 즉시 되돌아가고, 어떤 사람은 미로를 절반씩 나눠 분석하고, 어떤 사람은 눈앞에 보이는 가장 넓은 길만 골라 가고, 어떤 사람은 한 번 가본 갈림길을 기억해뒀다가 재사용합니다. 알고리즘 설계에서도 이렇게 문제를 쪼개고 해를 조합하는 네 가지 대표적인 성격의 전략이 있습니다.

```
[문제 해결 전략]
   │
   ├─ 분할정복(Divide & Conquer) : 부분 문제로 나눠 독립적으로 해결 후 병합
   ├─ 동적계획법(DP)             : 중복되는 부분 문제를 메모이제이션으로 재사용
   ├─ 탐욕법(Greedy)             : 매 단계 눈앞의 국소 최적만 선택, 전역 최적을 기대
   └─ 백트래킹(Backtracking)     : 해 공간을 탐색하다 조건 불만족 시 되돌아감(가지치기)
```

네 가지 모두 "큰 문제를 작은 단위로 나눈다"는 공통점을 갖지만, **부분 해를 다시 쓰는지(재사용 여부)**와 **탐색 방식**에서 성격이 크게 갈립니다.

#### 백트래킹(Backtracking) — "막다른 길이면 즉시 되돌아가는 미로 탐험가"

미로를 탈출할 때 무작정 모든 길을 다 걸어보는 것은 비효율적입니다. 대신 한 걸음 내디딜 때마다 "이 길이 막다른 골목인지" 미리 점검하고, 조건에 맞지 않으면 그 즉시 발길을 돌려(Backtrack) 다른 갈림길을 시도하는 방식이 **백트래킹**입니다.

예를 들어 체스판에 8개의 퀸을 서로 공격하지 못하게 배치하는 **N-Queen 문제**를 생각해 봅니다. 퀸을 한 줄씩 배치해 나가다가, 새로 놓은 퀸이 이미 놓인 퀸과 같은 대각선·같은 열에 걸리면 "이 배치는 틀렸다"고 즉시 판단하고 그 지점에서 가지를 잘라버립니다(가지치기, Pruning). 이렇게 하면 8×8 칸에 대해 모든 경우의 수를 다 헤아리지 않고도 훨씬 빠르게 답을 찾을 수 있습니다.

> 💡 **백트래킹 ≠ 무작정 완전탐색**
> 단순 완전탐색은 끝까지 가본 뒤에야 틀렸다는 걸 알지만, 백트래킹은 "가는 도중에" 틀렸음을 감지하고 조기에 포기합니다. 이 가지치기 덕분에 탐색 공간이 극적으로 줄어듭니다.

#### 분할정복(Divide and Conquer) — "부하 직원에게 절반씩 나눠 맡기는 팀장"

전체 문제를 서로 독립적인 작은 부분 문제로 쪼갠 뒤, 각 부분을 따로따로 해결하고 마지막에 결과를 합치는 전략입니다. 마치 팀장이 100장짜리 보고서 검토를 혼자 다 하지 않고 팀원 두 명에게 절반씩 나눠준 뒤, 각자 검토가 끝나면 취합하는 것과 같습니다.

대표적인 예가 **병합정렬(Merge Sort)**입니다.

```
[병합정렬의 분할정복 과정]

  [8, 3, 5, 1]
      │ 분할(Divide)
  ┌───┴───┐
[8, 3]   [5, 1]
  │ 분할    │ 분할
[8][3]   [5][1]
  │ 정복(Conquer, 이미 원소 1개)
[3, 8]   [1, 5]
  │ 결합(Combine, 병합)
  └───┬───┘
  [1, 3, 5, 8]
```

각 절반은 서로의 결과에 전혀 의존하지 않고 독립적으로 계산되므로, 부분 문제의 결과를 따로 저장해둘 필요가 없습니다. 이진 탐색이나 퀵정렬도 같은 계보의 기법입니다.

#### 탐욕법(Greedy) — "지금 당장 제일 좋아 보이는 선택만 하는 성격 급한 사람"

매 순간 눈앞에 보이는 가장 좋은 선택지를 고르고, 한 번 선택한 것은 절대 번복하지 않는 전략입니다. **거스름돈 문제**가 대표적인 비유입니다. 1,750원을 거슬러 줘야 할 때 가장 큰 화폐 단위(500원)부터 최대한 많이 집어 들고, 남는 만큼 그다음 큰 단위(100원)로, 이런 식으로 눈앞의 최선만 골라 나가는 방식입니다. 우리나라 화폐 체계에서는 이 방식이 실제로 최적의 답(동전 개수 최소화)을 만들어 냅니다.

하지만 탐욕법은 항상 최적해를 보장하지는 않습니다. 예컨대 500원, 400원, 100원짜리 동전만 있을 때 800원을 거슬러줘야 한다면, 탐욕법은 500원 + 100원 + 100원 + 100원(4개)을 고르지만, 실제 최적해는 400원 + 400원(2개)입니다. 탐욕법이 최적해를 보장하려면 다음 두 가지 성질이 성립해야 합니다.

```
1. 탐욕 선택 속성(Greedy Choice Property)
   : 각 단계에서의 국소 최적 선택이 전역 최적으로 이어져야 한다
2. 최적 부분 구조(Optimal Substructure)
   : 부분 문제의 최적해들이 모여 전체 문제의 최적해를 구성해야 한다
```

이 조건이 성립하는 대표 사례가 크루스칼/프림의 최소 신장 트리(MST), 다익스트라 최단 경로, 허프만 코딩입니다.

#### 동적계획법(DP) — "한 번 계산한 값은 노트에 적어두고 다시 꺼내 쓰는 똑똑한 학생"

피보나치 수열을 순수 재귀로 계산하면 `fib(5)`를 구하기 위해 `fib(3)`을 여러 번 반복해서 계산하는 낭비가 발생합니다. 마치 같은 수학 문제를 풀 때마다 처음부터 다시 푸는 것과 같습니다.

```
[순수 재귀의 중복 계산 - fib(5)]

              fib(5)
             /      \
        fib(4)      fib(3)
        /    \       /    \
   fib(3)  fib(2) fib(2) fib(1)
   /   \    ...    ...
fib(2) fib(1)
  ...          ← fib(3), fib(2)가 여러 번 반복 계산됨!
```

동적계획법(DP)은 "한 번 계산한 값은 표(메모)에 적어두고, 다음에 같은 계산이 필요하면 다시 풀지 않고 표에서 꺼내 쓴다"는 아이디어입니다. 이 덕분에 순수 재귀 피보나치가 O(2ⁿ)이던 것이, 메모이제이션을 적용하면 O(n)으로 극적으로 줄어듭니다.

DP를 구현하는 방식은 크게 두 가지로 나뉩니다.

| 구분 | 하향식 (Top-down, 메모이제이션) | 상향식 (Bottom-up, 테이블화) |
|------|--------------------------------|------------------------------|
| 접근 방향 | 큰 문제 → 재귀 호출로 작은 문제로 내려감 | 가장 작은 문제부터 → 차곡차곡 쌓아 올라감 |
| 구현 방식 | 재귀 함수 + 캐시(배열, 해시맵)에 결과 저장 | 반복문(for)으로 테이블을 채워나감 |
| 비유 | "얘야, fib(3) 먼저 구해서 알려줘" 하고 아래로 위임 | 기초 문제집 1번부터 차례로 풀어 답을 쌓아감 |
| 장점 | 실제로 필요한 부분 문제만 계산(불필요한 계산 생략) | 함수 호출 오버헤드가 없고 스택 오버플로 위험이 없음 |
| 단점 | 재귀 깊이가 깊으면 스택 오버플로 위험 | 필요 없는 부분 문제까지 전부 계산할 수 있음 |

```
[피보나치 - 하향식 vs 상향식]

하향식(Top-down):                     상향식(Bottom-up):
def fib(n, memo={}):                  def fib(n):
    if n in memo: return memo[n]          dp = [0, 1]
    if n <= 1: return n                   for i in range(2, n+1):
    memo[n] = fib(n-1,memo)+fib(n-2,memo)     dp.append(dp[i-1]+dp[i-2])
    return memo[n]                        return dp[n]
```

대표 사례로는 피보나치 수열, 0/1 배낭 문제, 최장 공통 부분 수열(LCS), 편집 거리 계산 등이 있습니다.

#### 4대 기법 종합 비교

| 비교 항목 | 분할정복 | 동적계획법 | 탐욕법 | 백트래킹 |
|-----------|----------|------------|--------|----------|
| 최적해 보장 | O (부분 문제가 독립일 때) | O (최적 부분 구조 성립 시) | X (조건부 O) | O (전체 탐색 시) |
| 부분 문제 중복 | 없음 | 있음 (핵심 조건) | 해당 없음 | 있을 수 있음 |
| 결정 번복 | 해당 없음 | 모든 경우 고려 후 최적 선택 | 불가 (한 번 선택하면 끝) | 가능 (되돌아가서 재시도) |
| 시간복잡도 경향 | O(n log n) 대 | O(n²) ~ O(n·W) | O(n log n) | 지수적 (가지치기로 완화) |
| 대표 문제 | 정렬, 탐색 | 배낭 문제, 편집 거리 | MST, 최단 경로 | 조합 탐색, 제약 만족 문제 |

> ⚠️ **네 기법은 서로 배타적이지 않습니다**
> DP 내부에서 분할정복적인 사고(부분 문제로 나누기)를 그대로 활용하듯, 실무에서는 네 기법을 문제 특성에 맞춰 혼합해서 사용하는 경우가 많습니다. "이 문제는 반드시 이 기법 하나로만 풀어야 한다"는 고정관념을 버리는 것이 중요합니다.

#### 설계 기법 선택 시 실무 체크포인트

| 이슈 | 대응 방안 |
|------|-----------|
| 탐욕 선택 속성이 성립하지 않는 문제에 탐욕법을 잘못 적용(근사해에 그침) | 속성 성립 여부를 사전에 증명하거나, DP/정수계획법 결과와 벤치마크 비교 |
| DP의 상태 공간이 다차원으로 확장되며 메모리 폭증 | 비트마스크 DP, 롤링 배열로 차원과 메모리 축소 |
| 백트래킹의 가지치기가 느슨해 탐색 시간이 폭발 | 제약 전파, 휴리스틱 순서 지정으로 조기 가지치기 강화 |

### 1-3. 유전자 알고리즘 (Genetic Algorithm)

#### "다윈의 자연선택을 컴퓨터 안에서 재현하면?"

찰스 다윈은 "환경에 잘 적응한 개체가 살아남아 자손을 남기고, 그 자손이 세대를 거듭하며 점점 더 환경에 최적화된다"는 자연선택 이론을 제시했습니다. **유전자 알고리즘(GA, Genetic Algorithm)**은 이 자연의 진화 원리를 그대로 컴퓨터 탐색 기법으로 옮겨온 것입니다.

정확한 최적해를 수학적으로 딱 떨어지게 계산하기 어려운 복잡한 문제(예: 외판원 문제, 물류 경로 최적화, AI 모델의 하이퍼파라미터 탐색)에서, "완벽하지는 않아도 충분히 좋은 답(근사 최적해)을 빠르게" 찾아내기 위해 널리 쓰입니다.

#### 진화의 6단계: 초기화 → 평가 → 선택 → 교배 → 돌연변이 → 세대교체

여러 마리의 동물이 사는 서식지를 떠올려 봅니다. 처음에는 다양한 개체가 무작위로 태어나고, 그중 환경에 잘 적응한 개체가 짝짓기 기회를 더 많이 얻으며, 자식에게는 부모의 유전자가 섞여서 전달되고, 가끔 돌연변이가 일어나 새로운 특성이 등장합니다. 이 과정을 세대를 거듭하며 반복하면 집단 전체가 점점 더 환경에 최적화됩니다.

```
[초기 개체군 생성]
       ↓
   [적합도 평가]
       ↓
   [선택]        → 적합도 높은 개체의 생존·번식 확률 ↑
       ↓
   [교배]        → 부모의 염색체(유전자)를 결합해 자식 생성
       ↓
   [돌연변이]     → 유전자 일부를 무작위로 변경(지역 최적해 탈출)
       ↓
   [세대교체/종료 검사]  → 종료 조건 미충족 시 다시 반복
```

| 단계 | 명칭 | 내용 | 자연계 비유 |
|------|------|------|-------------|
| 1 | 초기화 | 염색체(해 후보)를 무작위로 대량 생성 | 다양한 개체가 서식지에 태어남 |
| 2 | 적합도 평가 | 목적함수로 개체별 점수(적합도)를 산출 | 환경에 얼마나 잘 적응했는지 측정 |
| 3 | 선택 | 적합도 높은 개체가 부모로 뽑힐 확률 증대 | 강한 개체가 짝짓기 기회를 더 얻음 |
| 4 | 교배 | 부모 염색체의 유전자를 교환·결합해 자식 생성 | 부모의 형질이 자식에게 섞여 유전 |
| 5 | 돌연변이 | 낮은 확률로 유전자 일부를 변경, 다양성 확보 | 돌연변이로 새로운 형질 등장 |
| 6 | 세대교체 | 자식 세대로 개체군을 대체, 종료 조건 충족 시 종료 | 세대가 바뀌며 집단이 진화 |

> 💡 **선택과 교배는 서로 다른 질문에 답합니다**
> 선택(Selection)은 "누가 부모가 될 것인가"를 정하고, 교배(Crossover)는 "그 부모들의 유전자를 어떻게 섞을 것인가"를 정합니다. 둘은 서로 보완적인 연산입니다.

#### 선택기법 — "누구를 부모로 뽑을까"

* **룰렛휠 선택(Roulette Wheel):** 카지노의 룰렛판을 각 개체의 적합도 크기만큼 넓게 나눠 그린 뒤, 화살을 돌려 부모를 뽑는 방식입니다. 적합도가 높을수록 당첨 구간이 넓어 뽑힐 확률이 높지만, 특정 개체의 적합도가 지나치게 크면 다른 개체들이 뽑힐 기회를 거의 잃어 조기수렴(다양성 소실)의 위험이 있습니다.
* **토너먼트 선택(Tournament):** 개체군에서 무작위로 k마리를 뽑아 미니 경기를 붙이고, 그중 가장 우수한 개체를 부모로 선택하는 방식입니다. 구현이 간단하고 선택 압력을 k값으로 쉽게 조절할 수 있어 실무에서 가장 많이 사용됩니다.
* **엘리트주의(Elitism):** 매 세대마다 가장 우수한 개체 몇 마리는 교배나 돌연변이 없이 다음 세대로 무조건 그대로 보존하는 방식입니다. 최우수 해가 우연히 사라지는 것은 막아주지만, 지나치게 적용하면 집단의 다양성이 떨어질 수 있습니다.

#### 교배기법 — "유전자를 어떻게 섞을까"

```
[단일점 교차 vs 균등 교차]

부모1: [A B C D E F]        부모1: [A B C D E F]
부모2: [a b c d e f]        부모2: [a b c d e f]
          ↑ 교차점                  ↕ ↕ ↕ ↕ ↕ ↕ (자리마다 무작위 선택)
자식:  [A B C d e f]        자식:  [A b C d E f]
     (단일점 교차)                (균등 교차)
```

* **단일점 교차(Single-point Crossover):** 염색체의 한 지점을 잘라 앞부분은 부모1, 뒷부분은 부모2에서 가져오는 가장 단순한 방식입니다. 구현이 쉽지만 교차점 근처의 유용한 유전자 조합이 통째로 깨질 위험(연쇄 파괴)이 있습니다.
* **균등 교차(Uniform Crossover):** 각 유전자 자리마다 동전 던지듯 확률적으로 부모1 또는 부모2의 값을 선택합니다. 탐색 다양성이 가장 크다는 장점이 있습니다.
* **순서 교차(OCX, Order Crossover):** 외판원 문제(TSP)처럼 "방문 순서"가 중복 없이 유지되어야 하는 순열 문제에서, 부모의 상대적 순서 정보를 보존하며 교차하는 특수 기법입니다.

| 구분 | 기법 | 특징 |
|------|------|------|
| 선택 | 룰렛휠 | 적합도 비례 확률, 편차가 크면 조기수렴 위험 |
| 선택 | 토너먼트 | k개 중 최우수 선택, 실무 최다 사용 |
| 선택 | 엘리트주의 | 최우수 개체 무조건 보존, 다양성 저하 가능 |
| 교배 | 단일점 교차 | 한 지점 기준 유전자 교환, 연쇄 파괴 위험 |
| 교배 | 균등 교차 | 자리마다 확률적 선택, 탐색 다양성 최대 |
| 교배 | 순서 교차(OCX) | 순열(TSP) 문제에서 순서 보존 교차 |

#### 조기수렴이라는 함정

GA를 처음 돌려보면 초반에는 답이 빠르게 좋아지다가, 어느 순간부터 더 이상 개선되지 않고 정체되는 경우가 흔합니다. 이를 **조기수렴(Premature Convergence)**이라 부르는데, 우수한 개체 몇 마리가 집단을 지나치게 장악해 개체군의 다양성이 사라지고, 진짜 최적해가 아닌 지역 최적해에 갇혀버리는 현상입니다.

| 이슈 | 원인 | 영향 |
|------|------|------|
| 조기수렴 | 선택압 과다, 엘리트주의 과다 적용 | 개체군 다양성 소실, 지역 최적해 함몰 |
| 적합도 함수 설계 오류 | 제약조건 미반영 | 실현 불가능한 해로 수렴, 탐색 왜곡 |
| 계산 비용 누적 | 세대 수·개체군 크기 증가 | 실시간 서비스 적용에 부적합 |

> ⚠️ **조기수렴을 막는 실무 처방**
> 돌연변이 확률을 세대가 진행될수록 동적으로 조절하는 적응형 돌연변이(Adaptive Mutation)를 적용하거나, 다양성 지표를 모니터링하면서 필요하면 무작위 개체를 강제로 집단에 투입해 유전적 다양성을 되살리는 방법이 널리 쓰입니다.

최근에는 GA로 빠르게 초기해를 대량으로 탐색한 뒤, 그 결과를 2-opt 같은 경량 지역 탐색 기법으로 다듬는 하이브리드 전략이 AutoML·신경망 구조 탐색(NAS) 등 AI 자동화 도구에서 재조명받고 있습니다.

## Part 2. 그래프와 트리 알고리즘

### 2-1. 최단경로 알고리즘 (Dijkstra, Bellman-Ford, Floyd-Warshall, A*)

#### 내비게이션 앱은 어떻게 최단 경로를 계산할까?

우리가 매일 쓰는 내비게이션 앱을 켜면 몇 초 만에 "이 길이 가장 빠릅니다"라는 답이 튀어나옵니다. 그런데 지도 위에는 수만 개의 교차로(정점)와 도로(간선)가 거미줄처럼 얽혀 있습니다. 이 복잡한 미로 속에서 최단 경로를 찾아내는 것이 바로 **최단경로 알고리즘**의 역할입니다.

최단경로 문제는 상황에 따라 쓰는 도구가 다릅니다. "출발지 하나에서 모든 목적지까지"를 구할지, "모든 지점 쌍 사이의 거리"를 통째로 미리 구해둘지, 혹은 "출발지에서 특정 목적지까지만" 빠르게 구할지에 따라 최적의 알고리즘이 달라집니다.

```
[최단경로 문제]
   │
   ├─ 단일출발(Single-Source)
   │     ├─ Dijkstra    : 음수 가중치 불가, Greedy + 우선순위 큐
   │     └─ Bellman-Ford: 음수 가중치 가능, 음수 사이클 탐지, DP 기반
   │
   ├─ 전체쌍(All-Pairs)
   │     └─ Floyd-Warshall: 3중 반복 DP, 음수 가중치 가능(음수 사이클 無 전제)
   │
   └─ 휴리스틱 탐색
         └─ A* : f(n)=g(n)+h(n), 목적지가 정해진 탐색
```

#### 4대 알고리즘 한눈에 비교

| 구분 | 범위 | 음의 가중치 | 시간복잡도 | 대표 용도 |
|------|------|--------------|------------|-----------|
| Dijkstra | 단일출발 | 불가 | O((V+E)logV) | OSPF 라우팅 |
| Bellman-Ford | 단일출발 | 가능(사이클 탐지) | O(V·E) | RIP, 음수 사이클 탐지 |
| Floyd-Warshall | 전체쌍 | 가능(사이클 無 전제) | O(V³) | 전체쌍 사전계산 |
| A* | 단일출발-단일목적 | 불가(휴리스틱 전제) | 휴리스틱 의존 | 내비게이션·게임 |

> 💡 **왜 이렇게 4가지나 필요할까요?**
> 다익스트라는 "욕심쟁이(Greedy)" 전략으로 매번 가장 가까운 곳부터 확정해 나가는데, 만약 도로 중 하나가 "통행료를 오히려 돌려주는(음수 가중치)" 이상한 도로라면 그리디 전략이 틀린 답을 낼 수 있습니다. 이럴 때는 모든 도로를 여러 번 반복해서 다시 확인하는 벨만-포드가 필요합니다. 반대로 모든 지점 쌍의 거리를 미리 표로 뽑아두고 싶다면 플로이드-워셜을, 목적지가 뻔히 정해져 있어 엉뚱한 방향은 아예 탐색하고 싶지 않다면 A*를 씁니다.

#### Dijkstra 실제 계산 과정 (A → E 최단 경로 구하기)

다음과 같은 도로망이 있다고 합시다. A가 출발지, E가 목적지입니다.

```
그래프 간선: A-B=4, A-C=1, C-B=2, B-D=3, C-D=7, B-E=6, D-E=5
```

다익스트라는 "아직 확정 안 된 노드 중 가장 가까운 곳"을 매번 그리디하게 선택해서 확정해 나갑니다. 마치 여러 갈래 길 앞에서 지금까지 알려진 가장 싼 길부터 하나씩 도장을 찍어가는 것과 같습니다.

| 단계 | 처리 노드 | A | B | C | D | E |
|------|----------|---|---|---|---|---|
| 1 | 초기화 | 0 | ∞ | ∞ | ∞ | ∞ |
| 2 | A 방문 | 0 | 4 | 1 | ∞ | ∞ |
| 3 | C 방문(최소=1) | 0 | 3 | 1 | 8 | ∞ |
| 4 | B 방문(최소=3) | 0 | 3 | 1 | 6 | 9 |
| 5 | D 방문(최소=6) | 0 | 3 | 1 | 6 | 9 |
| 6 | E 방문(최소=9) | 0 | 3 | 1 | 6 | **9** |

C를 거쳐 B로 가면(1+2=3) A에서 바로 B로 가는 것(4)보다 더 싸다는 걸 3단계에서 발견해 B값을 4→3으로 갱신합니다. 이렇게 "더 싼 길을 발견하면 즉시 갱신"하는 과정을 반복한 끝에, **A→E 최단거리는 9, 경로는 A-C-B-E**로 확정됩니다.

같은 그래프를 벨만-포드, 플로이드-워셜, A*로 풀어도 결과는 동일합니다.

| 구분 | 계산 과정 | 결과 |
|------|-----------|------|
| Bellman-Ford | 전체 간선을 \|V\|-1(=4)회 반복 이완, A-C-B-E 경로를 순차적으로 발견 | dist[E]=9 (4회 내 수렴) |
| Floyd-Warshall | k=C 경유 D[A][B]=min(4, 1+2)=3, k=B 경유 D[A][E]=min(∞, 3+6)=9 | D[A][E]=9 |
| A* | f(n)=g(n)+h(n), h는 과소추정(Admissible) 가정, E와 먼 노드는 탐색 후순위로 밀림 | 경로 A-C-B-E, 비용 9 (탐색량 최소) |

> ⚠️ **음수 가중치를 다익스트라에 넣으면 안 되는 이유**
> 다익스트라는 "한 번 확정한 노드는 절대 값이 줄어들지 않는다"는 전제 위에서 동작합니다. 그런데 음수 간선이 있으면 이미 확정된 노드조차 나중에 더 싼 경로가 나타날 수 있어 이 전제가 깨집니다. 비용을 "이익(음수)"으로 모델링해야 하는 상황이라면 반드시 벨만-포드 계열을 채택하고, 음수 사이클 탐지 로직도 함께 배치해야 합니다.

### 2-2. 최소신장트리 (크루스칼, 프림)

#### "도시를 잇는 가장 싼 도로망 설계하기"

여러 도시를 도로로 연결해야 하는데, 예산은 한정되어 있다고 상상해봅시다. 모든 도시가 서로 (직접 또는 간접적으로) 연결되기만 하면 되고, 굳이 두 도시 사이에 여러 갈래 길을 놓을 필요는 없습니다(사이클은 예산 낭비입니다). 이렇게 **"모든 정점을 사이클 없이, 가장 싼 총 비용으로 연결하는 부분 그래프"**를 찾는 문제가 바로 **최소신장트리(MST, Minimum Spanning Tree)**입니다.

```
[가중치 그래프 G]
        ↓ MST 알고리즘 적용
[사이클 없는 N-1개 간선의 트리]
        ↓
   총 가중치 합 최소 보장
```

N개의 도시(정점)를 모두 연결하려면 딱 N-1개의 도로(간선)만 있으면 충분합니다. 하나라도 더 있으면 어딘가에 굳이 필요 없는 우회 도로(사이클)가 생긴다는 뜻입니다. 통신망 설계, 전력망 설계, 데이터 클러스터링 등에서 이 개념이 그대로 쓰입니다.

이 도로망을 설계하는 대표적인 두 가지 전략이 **크루스칼(Kruskal)**과 **프림(Prim)**입니다. 둘 다 "욕심쟁이(Greedy)" 방식이라는 점은 같지만, 접근하는 각도가 완전히 다릅니다.

* **크루스칼 — "전국의 도로 견적서를 다 모아 싼 것부터 산다"**
  나라 안의 모든 가능한 도로 견적서(간선)를 비용순으로 쭉 정렬해 놓고, 가장 싼 것부터 하나씩 채택합니다. 단, 이미 연결된 두 도시를 또 잇는 도로(사이클을 만드는 도로)는 건너뜁니다. 이 사이클 여부를 빠르게 판별하기 위해 **Union-Find(Disjoint Set)** 자료구조를 사용합니다.
* **프림 — "한 도시에서 시작해 계속 이웃 마을을 흡수해나간다"**
  시작 도시 하나를 정하고, 지금 연결된 마을 집합에서 "바깥으로 나가는 가장 싼 도로"를 매번 하나씩 골라 마을을 흡수해 나갑니다. 마치 눈덩이를 굴리듯 트리가 점점 커지는 방식입니다.

```
Kruskal: 간선 정렬 → 최소 간선부터 선택 → Union-Find 사이클 검사 → N-1개 채택 시 종료
Prim   : 시작 정점 → 인접 최소간선 탐색(우선순위 큐) → 트리 집합 확장 → 전 정점 포함 시 종료
```

#### 크루스칼 vs 프림 비교표

| 구분 | 크루스칼 | 프림 |
|------|----------|------|
| 접근 방식 | 간선(Edge) 중심 | 정점(Vertex) 중심 |
| 사이클 판별 | Union-Find(Disjoint Set) | 방문 집합으로 자연 배제 |
| 자료구조 | 간선 리스트 + Union-Find | 우선순위 큐 + 인접리스트 |
| 시간복잡도 | O(E logE) | O(E logV) |
| 적합 그래프 | 희소 그래프 (도로가 듬성듬성) | 밀집 그래프 (도로가 촘촘) |
| 트리 성장 방식 | 여러 개의 부분 트리(숲)가 서서히 병합 | 하나의 트리가 계속 몸집을 불림 |

> 💡 **언제 무엇을 써야 할까?**
> 도시(정점) 수에 비해 도로(간선) 후보가 적은 **희소 그래프**라면, 정렬 비용이 적고 Union-Find가 거의 상수 시간에 동작하는 **크루스칼**이 유리합니다. 반대로 도시 간 도로 후보가 매우 많은 **밀집 그래프**라면 인접행렬과 힙을 조합한 **프림**이 정점 단위 확장에 더 효율적입니다. 여러 서버가 나누어 계산하는 분산/병렬 환경에서는 간선을 독립적으로 정렬·병합할 수 있는 크루스칼이, 실시간으로 트리를 점진적으로 키워가야 하는 상황에서는 항상 하나의 연결된 트리를 유지하는 프림이 더 잘 맞습니다.

### 2-3. 그래프 순회와 BFS/DFS

#### 미로 속에서 출구를 찾는 두 가지 전략

친구와 함께 커다란 미로에 들어갔다고 생각해봅시다. 미로의 모든 방(정점)을 빠짐없이 둘러보거나, 특정 방(목표)을 찾아야 합니다. 이때 쓸 수 있는 전략은 크게 두 가지입니다.

```
[그래프 순회]
   │
   ├─ DFS(Depth-First Search) — "한 우물만 끝까지 판다"
   │     - 한 방향으로 갈 수 있는 데까지 깊이 들어갔다가, 막다른 길이면 되돌아 나옴
   │     - 스택(재귀) 기반, 미로 탐색·위상정렬·사이클 검출에 적합
   │
   └─ BFS(Breadth-First Search) — "가까운 방부터 한 켜씩 넓게 훑는다"
         - 시작 지점에서 가까운 방부터 한 단계(레벨)씩 순서대로 탐색
         - 큐 기반, 최단경로(비가중치 그래프)·레벨 탐색에 적합
```

DFS는 한 명이 손전등을 들고 한쪽 복도 끝까지 파고들어가며, 갈림길을 만날 때마다 지나온 길을 기억(스택)해두었다가 막히면 되돌아 나오는 방식입니다. 반면 BFS는 시작 지점에서 물결이 퍼지듯이, 가까운 방부터 한 층씩 동심원 모양으로 넓게 탐색합니다. **BFS는 가중치 없는 그래프에서 "최단경로(최소 간선 수)"를 항상 보장하는 유일한 순회 방식**이라는 점이 핵심입니다.

#### BFS 탐색 과정 실제 예시 (1번 방에서 시작해 6번 방 찾기)

```
   1 ── 2
   │    │
   3 ── 4 ── 5 ── 6
인접리스트: 1:{2,3}, 2:{1,4}, 3:{1,4}, 4:{2,3,5}, 5:{4,6}, 6:{5}
```

BFS는 큐(줄서기 통로)를 사용해서, 방을 발견하는 즉시 줄 맨 뒤에 세우고 맨 앞부터 순서대로 처리합니다.

| 단계 | Dequeue | 인접 탐색·Enqueue | 큐 상태 | 방문집합 |
|------|---------|---------------------|----------|----------|
| 0 | - | 1 Enqueue | [1] | {1} |
| 1 | 1 | 2,3 방문 | [2,3] | {1,2,3} |
| 2 | 2 | 4 방문 | [3,4] | {1,2,3,4} |
| 3 | 3 | 4 이미 방문 | [4] | {1,2,3,4} |
| 4 | 4 | 5 방문 | [5] | {1,2,3,4,5} |
| 5 | 5 | 6 방문 | [6] | {1,2,3,4,5,6} |
| 6 | 6 | 목표 발견, 종료 | [] | {1,2,3,4,5,6} |

방문 순서는 **1→2→3→4→5→6**이며, 목표인 6번 방까지 최단 홉 수는 **4단계**(1-2-4-5-6 또는 1-3-4-5-6)입니다. 큐는 항상 "레벨 순서"대로 쌓이기 때문에, Dequeue(꺼내는) 순서가 자연스럽게 시작점으로부터의 거리(홉 수) 오름차순을 보장합니다.

#### DFS vs BFS 비교

| 구분 | DFS | BFS |
|------|-----|-----|
| 자료구조 | 스택(재귀) | 큐 |
| 탐색 순서 | 깊이 우선 | 레벨(너비) 우선 |
| 최단경로 보장 | 불가 | 가능(비가중치 그래프) |
| 대표 활용 | 위상정렬, 사이클 검출 | 최단 홉 탐색, 레벨 순회 |

> ⚠️ **방문 표시를 깜빡하면 벌어지는 일**
> 미로 탐색 중 "이미 가본 방"을 기록해두지 않으면 같은 방을 계속 왔다 갔다 하며 영원히 빠져나오지 못합니다. 그래프 순회에서도 마찬가지로, Enqueue(또는 재귀 호출) 시점에 즉시 방문 표시를 하지 않으면 무한루프에 빠질 수 있습니다. SNS 친구 추천처럼 그래프가 매우 큰 경우에는 양방향 BFS나 분산 그래프 프레임워크(Pregel 등)를 활용해 메모리 폭증(OOM)도 함께 대비해야 합니다.

### 2-4. 트리 알고리즘 (B트리, 이진트리 순회, AVL트리)

#### B트리 — 도서관 서가에 책을 정리하는 규칙

거대한 도서관을 상상해봅시다. 책이 한 칸에 한 권씩만 꽂혀 있다면 서가(책장)의 층수가 어마어마하게 높아져서 원하는 책을 찾으려면 계단을 수백 번 오르내려야 합니다. 그래서 사서들은 **한 칸(노드)에 여러 권의 책(키)을 정렬해서 함께 꽂는** 전략을 씁니다. 이것이 바로 **B트리**의 핵심 아이디어입니다. 디스크 I/O를 최소화하려는 RDBMS 인덱스(InnoDB B+Tree)나 파일시스템이 B트리 계열을 근간으로 삼는 이유가 여기에 있습니다.

```
[B 트리(차수 m=3) 제약]
  - 노드당 키 개수: 1~2개(루트는 1개 이상)
  - 노드당 자식 개수: 0(리프) 또는 2~3개
  - 모든 리프는 동일 레벨(높이 균형 보장)
```

**삽입**은 "책을 꽂을 자리를 찾아 정렬된 위치에 끼워 넣는" 과정입니다. 다만 한 칸에 넣을 수 있는 책 수(m-1권)를 넘어서면(오버플로우) 그 칸의 한가운데 책(중앙값)을 상위 칸으로 승격시키고, 나머지 책들을 좌우로 쪼갭니다(분할). 상위 칸도 넘치면 이 과정이 재귀적으로 위로 전파되며, 맨 꼭대기(루트)까지 넘치면 서가 전체의 층수(트리 높이)가 하나 늘어납니다.

```
1. 루트에서 키 값 비교로 삽입할 리프 노드 탐색
2. 리프에 정렬 위치로 키 삽입
3. 키 개수가 m-1(=2) 초과 시 오버플로우
4. 분할: 중앙값(Median) 부모로 승격, 나머지 좌/우 분리
5. 부모도 오버플로우 시 재귀 분할(루트 전파 시 높이+1)
```

**삭제**는 반대로 책을 빼냈을 때 그 칸이 최소 권수(⌈m/2⌉-1권) 밑으로 떨어지면(언더플로우), 옆 칸(형제)에서 여유 책을 빌려오거나(회전), 그마저 안 되면 옆 칸과 아예 합쳐버립니다(병합).

예를 들어 차수 3인 B트리에 26, 57, 5, 33, 72, 45를 순서대로 삽입하면 다음과 같은 트리가 만들어집니다.

```
최종 삽입 결과:        [26,57]
                      /   |    \
                   [5] [33,45] [72]
```

이후 72, 33, 45를 순서대로 삭제하면:

| 삭제 키 | 처리 | 결과 |
|---------|------|------|
| 72 | 리프 언더플로우 → 좌형제[33,45]에서 회전(57 하강, 45 승격) | [26,45] / [5]\|[33]\|[57] |
| 33 | 리프 언더플로우 → 형제 여유 없어 [5]+26+빈노드 병합 | [45] / [5,26]\|[57] |
| 45 | 내부노드 키 → 선행자 26으로 대체, 리프[5,26]에서 26 삭제 | [26] / [5]\|[57] |

최종적으로 루트 [26], 좌측 자식 [5], 우측 자식 [57]로 정리됩니다.

> 💡 **회전 vs 병합, 무엇이 먼저인가**
> 옆 칸(형제)에 여유 책이 있으면 부모의 책 한 권을 내려보내고 형제의 책 한 권을 부모로 올리는 **회전**으로 끝냅니다. 하지만 형제마저 최소 권수만 겨우 채우고 있어 빌려줄 여유가 없다면, 부모의 분리 키를 아예 끌어내려 두 칸을 하나로 합치는 **병합**을 해야 합니다.

#### 이진트리 순회 — 집안 청소 순서에 비유하기

이진트리의 모든 방(노드)을 청소해야 한다고 생각해봅시다. 각 방에는 왼쪽 방(L)과 오른쪽 방(R)이 딸려 있고, 방 자체(N, 루트)를 "언제 청소하느냐"에 따라 세 가지 순회 방식이 나뉩니다.

```
[순회 3요소]  N(방 자체), L(왼쪽 서브트리), R(오른쪽 서브트리)

  전위순회(Preorder)  : N → L → R   ("이 방부터 치우고 왼쪽, 오른쪽 순서로")
  중위순회(Inorder)   : L → N → R   ("왼쪽 다 치우고, 이 방, 그다음 오른쪽")
  후위순회(Postorder) : L → R → N   ("왼쪽·오른쪽 다 치우고 나서 마지막에 이 방")
```

| 구분 | 방문 순서 | 대표 활용 |
|------|-----------|-----------|
| 전위순회 | 루트→왼쪽→오른쪽 | 트리 구조 복제, 디렉터리 상위→하위 출력 |
| 중위순회 | 왼쪽→루트→오른쪽 | BST의 오름차순 정렬 출력 |
| 후위순회 | 왼쪽→오른쪽→루트 | 트리/디렉터리 삭제, 후위표기식 계산 |

세 방식 모두 왼쪽 방을 오른쪽 방보다 먼저 들르는 것은 동일하고, "이 방 자체는 언제 청소하는가"만 다릅니다. 다음 예시 트리를 봅시다.

```
                 F
               /   \
              B      G
            /   \       \
           A     D        I
                / \       /
               C   E     H
```

| 순회 방식 | 방문 순서 |
|-----------|-----------|
| 전위순회 | F-B-A-D-C-E-G-I-H |
| 중위순회 | A-B-C-D-E-F-G-H-I |
| 후위순회 | A-C-E-D-B-H-I-G-F |

이 트리는 중위순회 결과가 A부터 I까지 알파벳 순서로 정렬되는데, 이는 이 트리가 **BST(이진탐색트리) 성질**을 만족하기 때문입니다. 즉, 왼쪽 서브트리는 항상 더 작은 값, 오른쪽 서브트리는 항상 더 큰 값을 담고 있어서 "왼쪽→나→오른쪽" 순서가 곧 오름차순이 됩니다.

> ⚠️ **삭제할 때는 왜 후위순회를 써야 할까?**
> 만약 집을 철거할 때 방(루트)부터 부수고 나서 그 안의 가구(자식 노드)를 치우려 한다면, 이미 문이 무너져 접근할 수 없는 참사가 벌어집니다. 트리나 디렉터리를 삭제할 때는 반드시 **자식(L, R)을 먼저 정리한 뒤 마지막에 루트를 정리하는 후위순회**를 표준으로 써야 참조가 끊기거나 메모리가 새는 사고를 막을 수 있습니다.

#### AVL트리 — 시소처럼 균형을 잡는 나무

일반 이진탐색트리(BST)는 데이터가 들어오는 순서에 따라 한쪽으로 심하게 치우친 "편향 트리"가 될 수 있습니다. 마치 시소의 한쪽에만 계속 사람이 올라타면 반대쪽이 하늘 높이 들려버리는 것과 같습니다. 이렇게 되면 트리의 높이가 O(n)까지 늘어나 탐색 성능이 배열 검색과 다를 바 없이 나빠집니다.

**AVL트리**는 이 시소가 항상 수평에 가깝게 유지되도록, 노드를 삽입하거나 삭제할 때마다 균형을 자동으로 점검하고 필요하면 즉시 바로잡는 자기균형 이진탐색트리입니다.

| 구분 | BST | AVL Tree |
|------|-----|----------|
| 균형 보장 | 없음(편향 가능) | 회전으로 항상 균형 유지 |
| 최악 높이 | O(n) | O(log n) |
| 탐색 성능 | 최선 O(log n), 최악 O(n) | 항상 O(log n) |
| 부가 비용 | 없음 | 회전 연산 오버헤드 |

이 균형을 수치로 재는 잣대가 **균형인수(BF, Balance Factor)**입니다. `BF = height(왼쪽) - height(오른쪽)`으로 계산하며, AVL트리는 모든 노드에서 `|BF| ≤ 1`을 항상 유지합니다. 시소가 한쪽으로 |BF|=2 이상 기울면, 즉시 **회전(Rotation)**이라는 교정 동작을 발동시켜 시소를 다시 수평으로 되돌립니다.

#### 4가지 회전 유형

| 유형 | 발생 조건 | 처리 방법 |
|------|-----------|-----------|
| LL | 왼쪽 자식의 왼쪽으로 삽입 | 단순 우회전(Right Rotation) 1회 |
| RR | 오른쪽 자식의 오른쪽으로 삽입 | 단순 좌회전(Left Rotation) 1회 |
| LR | 왼쪽 자식의 오른쪽으로 삽입 | 좌회전 후 우회전(2단계) |
| RL | 오른쪽 자식의 왼쪽으로 삽입 | 우회전 후 좌회전(2단계) |

LL과 RR은 시소 한쪽 끝에 무게추가 일직선으로 쌓인 경우라 한 번만 회전시키면 바로 평형이 잡힙니다. 반면 LR과 RL은 무게추가 "지그재그"로 쌓인 경우라서, 먼저 자식을 한 번 돌려 LL이나 RR 모양으로 바꾼 뒤(1단계) 다시 한번 회전(2단계)해야 하는 **이중 회전(Double Rotation)**이 필요합니다.

#### 실제 삽입 트레이스: 2, 1, 8, 9, 7, 3, 6, 4, 5 순서로 삽입하기

| 삽입 | 불균형 검사 | 케이스 | 처리 결과 |
|------|-------------|--------|-----------|
| 2,1,8,9,7 | 각 단계 균형 | - | 2(L:1, R:8(L:7, R:9)) |
| 3 | 노드2 BF=-2 | RL(8의 BF=+1) | **7이 새 루트**: 7(L:2(L:1,R:3), R:8(R:9)) |
| 6 | 전 노드 균형 | - | 7(L:2(L:1,R:3(R:6)), R:8(R:9)) |
| 4 | 노드2 BF=-2 | RR(3의 BF=-1) | **4가 노드2 자리 대체**: 7(L:4(L:2(L:1),R:3), R:8(R:9)) |
| 5 | 전 노드 균형 | - | 회전 없이 완료 |

`3`을 삽입하는 순간을 자세히 들여다보면, 노드2의 BF가 0-2=-2로 기울어지고, 그 오른쪽 자식인 8의 BF는 +1입니다. 부모(-2)와 자식(+1)의 부호가 서로 다른 "지그재그" 패턴이므로 이것이 바로 **RL 케이스**입니다. 8을 먼저 우회전시킨 뒤 2를 좌회전시키면, 7이 새로운 루트로 승격됩니다.

**최종 완성된 AVL 트리:**

```
              7
           /     \
          4         8
        /   \         \
       2     6           9
      / \   /
     1   3 5
```

검증해보면 노드7 BF=1, 노드4 BF=0, 노드2 BF=0, 노드6 BF=1, 노드8 BF=-1로, 모든 노드가 |BF|≤1을 만족합니다.

> 💡 **LR/RL을 LL/RR로 착각하면 벌어지는 일**
> 부모의 BF만 보고 "왼쪽이 기울었으니 무조건 우회전"이라고 단순하게 판단하면, 지그재그로 쌓인 LR/RL 케이스에서 트리가 오히려 더 망가집니다. 반드시 **부모의 BF와 함께 자식의 BF까지 확인**해서 4가지 케이스 중 어디에 해당하는지 판별하는 로직을 단위테스트로 꼼꼼히 검증해야 합니다.

> ⚠️ **AVL트리는 만능이 아닙니다**
> 회전 연산은 삽입/삭제마다 추가 비용을 발생시킵니다. 조회가 압도적으로 많은 워크로드라면 AVL트리가 유리하지만, 삽입·삭제가 빈번하다면 균형 조건이 조금 느슨한 Red-Black Tree가 더 나은 선택일 수 있습니다. 또한 AVL트리는 메모리(In-Memory) 상에서 빠른 조회를 위한 구조이며, 디스크 기반 인덱스에는 한 번에 여러 키를 읽어 I/O 횟수를 줄이는 B트리 계열이 훨씬 적합합니다.

## Part 3. 기본 자료구조와 정렬

### 3-1. 선형 자료구조: 스택, 큐, 리스트

#### 접시 쌓기 vs 놀이공원 줄서기: 스택과 큐는 뭐가 다를까?

주방에서 설거지를 마친 접시를 쌓아 올린다고 생각해 봅니다. 접시는 항상 맨 위에 새로 쌓고, 필요할 때도 맨 위 접시부터 집어 씁니다. 맨 밑에 깔린 접시를 쓰려면 위에 쌓인 접시를 전부 치워야 합니다. 이렇게 **가장 나중에 넣은 것이 가장 먼저 나오는** 구조가 바로 **스택(Stack)**이고, 이 원리를 **후입선출(LIFO, Last In First Out)**이라 부릅니다.

반면 놀이공원 인기 놀이기구 앞에 줄을 선다고 생각해 봅니다. 먼저 줄을 선 사람이 먼저 타고, 나중에 온 사람은 줄 맨 뒤에 서서 순서를 기다립니다. 새치기가 없다면 **가장 먼저 들어온 사람이 가장 먼저 나가는** 구조입니다. 이것이 **큐(Queue)**이며, **선입선출(FIFO, First In First Out)** 원리로 동작합니다.

마지막으로 **리스트(List)**는 접시 쌓기나 줄서기처럼 입출력 위치가 정해져 있지 않습니다. 마치 책장에 꽂힌 책처럼, 원하는 위치 아무 곳에나 책을 꽂거나 뺄 수 있는 **임의 위치 접근**이 가능한 범용 선형구조입니다.

```
[선형 자료구조]
   │
   ├─ 스택(Stack)  : 한쪽 끝(Top)에서만 삽입/삭제 → LIFO (접시 쌓기)
   ├─ 큐(Queue)    : Rear 삽입, Front 삭제 → FIFO (놀이공원 줄서기)
   └─ 리스트(List) : 임의 위치 삽입/삭제 가능 → 책장에 책 꽂기(배열형/연결형)
```

#### 스택의 Push/Pop 의사코드

스택에 물건을 넣는 동작을 **Push**, 꺼내는 동작을 **Pop**이라 부릅니다. 접시를 너무 많이 쌓으면 넘쳐서 무너지듯, 스택도 정해진 크기(K)를 넘어서 쌓으려 하면 **Overflow**가 발생합니다. 반대로 접시가 하나도 없는데 꺼내려 하면 **Underflow**입니다.

```
Push(S, K, Top, Item) 알고리즘
1. Top ← Top + 1
2. If Top > K then
3.      Print "Overflow"; Top ← Top - 1
4. Else
5.      S[Top] ← Item

Pop(S, Top) 알고리즘
1. If Top = 0 then
2.      Print "Underflow"
3. Else
4.      Item ← S[Top]; Top ← Top - 1
5. Return Item
```

> ⚠️ **순서를 반드시 지켜야 하는 이유**
> Push는 "포인터를 먼저 올리고 범위를 검사"하고, Pop은 "범위를 먼저 검사하고 값을 꺼내는" 순서로 동작합니다. 만약 순서를 뒤바꾸면 배열 범위를 벗어난 자리에 값을 쓰거나 읽는 사고(버퍼 오버런)로 이어질 수 있습니다.

크기가 K=3인 스택에 실제로 접시를 쌓고 빼보면 다음과 같이 동작합니다.

| 연산 | Top 변화 | 스택 상태 | 결과 |
|------|----------|-----------|------|
| 초기 | Top=0 | (empty) | - |
| Push(10) | 0→1 | [10] | 정상 삽입 |
| Push(20) | 1→2 | [10,20] | 정상 삽입 |
| Push(30) | 2→3 | [10,20,30] | 정상 삽입 |
| Push(40) | 3→4(4>K) | [10,20,30] | Overflow, Top 원복(3) |
| Pop() | 3→2 | [10,20] | Item=30 |
| Pop() | 2→1 | [10] | Item=20 |
| Pop() | 1→0 | (empty) | Item=10 |
| Pop() | Top=0 | (empty) | Underflow |

접시 4개를 쌓으려다 3개짜리 선반에서 Overflow가 발생하고, 다 빼낸 뒤 한 번 더 빼려 하면 Underflow가 발생하는 모습을 그대로 확인할 수 있습니다.

#### 세 자료구조의 입출력 원리 비교

| 구분 | 스택 | 큐 | 리스트 |
|------|------|-----|--------|
| 입출력 원리 | LIFO | FIFO | 임의 위치(순서 무관) |
| 삽입/삭제 | Push/Pop(Top) | Enqueue(Rear)/Dequeue(Front) | Insert/Delete(임의 위치) |
| 접근 지점 | 1곳(Top) | 2곳(Front, Rear) | 전체(순차/포인터 탐색) |
| 대표 활용 | 함수 호출 스택, Undo | 프로세스 스케줄링, 메시지 큐, BFS | LRU 캐시, 텍스트 편집기 |

> 💡 **실생활 감각으로 기억하기**
> 스택은 "마지막에 쌓은 접시부터", 큐는 "먼저 줄 선 사람부터", 리스트는 "책장 아무 칸이나"로 외워두면 실무에서 자료구조를 고를 때 헷갈리지 않습니다.

### 3-2. 순환큐와 배열 큐의 한계

#### 배열로 큐를 만들면 생기는 "가짜 Overflow" 문제

배열로 큐를 구현하면 아주 이상한 일이 벌어집니다. 5칸짜리 주차장을 상상해 봅니다. 차 3대(A, B, C)가 순서대로 들어와 1~3번 칸에 주차했습니다. 그런데 A와 B가 차례로 빠져나갔습니다. 1번과 2번 칸은 분명히 비어 있는데도, 새 차가 들어올 때는 "다음 빈 칸"인 4번, 5번 칸에만 주차하도록 규칙이 정해져 있다면 어떻게 될까요? 4번, 5번 칸마저 꽉 차면 1, 2번 칸이 텅 비어 있어도 더 이상 주차할 수 없는 **가짜 Overflow**가 발생합니다.

```
초기:  [   ][   ][   ][   ][   ]     Front=Rear=0
Enqueue(A,B,C): [ A ][ B ][ C ][   ][   ]   Front=0, Rear=3
Dequeue() x2  : [   ][   ][ C ][   ][   ]   Front=2, Rear=3
                  ↑↑↑ 사용 불가 공간(낭비) 발생
```

이것이 바로 **배열 기반 큐(Linear Queue)**의 근본적인 단점입니다. Rear가 배열 끝에 도달하면, 앞쪽에 이미 비워진 공간이 있어도 더 이상 Enqueue를 할 수 없는 구조적 한계가 있습니다.

| 단점 | 원인 | 영향 |
|------|------|------|
| 가공 오버플로우 | Dequeue로 비워진 앞쪽 공간 미재사용 | 여유 공간 있어도 Enqueue 실패 |
| 고정 크기(정적 할당) | 배열 크기가 초기화 시 고정 | 데이터량 예측 실패 시 진짜 Overflow |
| 중간 삽입/삭제 시 원소 이동 | 인덱스 연속성 유지 필요 | O(n) 비용, 성능 저하 |

#### 시계 바늘처럼 도는 순환큐: 모듈러 연산 트릭

이 문제를 아주 우아하게 해결하는 방법이 **순환큐(Circular Queue)**입니다. 아이디어는 간단합니다. 배열의 마지막 칸(5번) 다음을 다시 첫 번째 칸(1번)으로 이어 붙여서, 마치 시계 바늘이 12시를 지나면 다시 1시로 돌아가듯 인덱스가 **원형으로 순환**하도록 만드는 것입니다.

```
        Front
          ↓
      ┌───┬───┬───┬───┬───┐
      │ A │ B │ C │   │   │   Capacity=5
      └───┴───┴───┴───┴───┘
                    ↑
                   Rear
   Rear = (Rear+1) % Capacity 로 순환 이동
```

시계에서 "11시 + 2시간 = 13시"가 아니라 "1시"가 되는 것처럼, 순환큐에서도 인덱스가 배열 끝에 닿으면 나머지(%) 연산을 통해 다시 처음으로 돌아갑니다. 이 **모듈러(%) 연산** 한 줄이 앞서 살펴본 가짜 Overflow 문제를 완전히 해결해 줍니다.

| 상태 | 조건식 | 설명 |
|------|--------|------|
| 공백(Empty) | Front == Rear | 전단/후단이 동일 위치 |
| 포화(Full) | (Rear+1)%Capacity == Front | 1칸 손실 방식으로 공백과 구분 |

> 💡 **왜 1칸을 일부러 비워둘까요?**
> 원소를 모두 채워서 Front와 Rear가 다시 같은 위치가 되어 버리면, 이 상태가 "공백"인지 "포화"인지 구별할 수 없게 됩니다. 그래서 순환큐는 일부러 한 칸을 항상 비워두고, `(Rear+1)%Capacity == Front`가 될 때를 포화 상태로 약속합니다.

실제 C 언어로 구현하면 다음과 같습니다. Enqueue는 Rear를 먼저 한 칸 옮긴 뒤 값을 저장하고, Dequeue는 Front를 먼저 한 칸 옮긴 뒤 값을 꺼내는 대칭적인 구조입니다.

```c
void CQ_Enqueue(CircularQueue* Queue, ElementType Data)
{
    if ((Queue->Rear + 1) % Queue->Capacity == Queue->Front) {
        printf("Queue is Full (Overflow)\n");
        return;
    }
    Queue->Rear = (Queue->Rear + 1) % Queue->Capacity;
    Queue->Nodes[Queue->Rear] = Data;
}

ElementType CQ_Dequeue(CircularQueue* Queue)
{
    ElementType Item;
    if (Queue->Front == Queue->Rear) {
        printf("Queue is Empty (Underflow)\n");
        return NULL;
    }
    Queue->Front = (Queue->Front + 1) % Queue->Capacity;
    Item = Queue->Nodes[Queue->Front];
    return Item;
}
```

순환큐 외에도 큐의 한계를 극복하는 방법은 몇 가지가 더 있습니다.

```
순환 큐     : Rear=(Rear+1)%Capacity  → 앞쪽 공간 재사용
연결리스트 큐 : 노드 단위 동적 할당 → 고정 크기 제약 제거
동적 배열 큐  : 포화 시 2배 재할당(Resize) → 상환 O(1) 성능 유지
```

| 해결 방법 | 오버플로우 해결 | 구현 복잡도 | 적합 상황 |
|-----------|------------------|--------------|-----------|
| 순환 큐 | 가공 오버플로우 해결 | 낮음(모듈러 연산) | 용량 예측 가능한 임베디드/버퍼 |
| 연결리스트 큐 | 완전 해결 | 중간(포인터 오버헤드) | 데이터량 변동 폭 큰 애플리케이션 |
| 동적 배열 큐 | 재할당으로 해결 | 중간(일시적 2배 메모리) | 상환 성능 중요한 범용 라이브러리 |

> ⚠️ **순환큐도 만능은 아닙니다**
> 순환큐는 정해진 Capacity 안에서 공간을 알뜰하게 재사용할 뿐, 애초에 배열 크기 자체를 늘려주지는 못합니다. 트래픽이 폭증하는 대규모 스트리밍 환경에서는 Kafka나 RabbitMQ 같은 분산 메시지 큐로 확장하는 것이 현실적인 해법입니다.

### 3-3. 정렬 알고리즘: 선택정렬, 삽입정렬, 퀵정렬

#### 카드를 정렬하는 세 가지 방식

손에 쥔 트럼프 카드를 크기순으로 정렬하는 상황을 떠올려 봅니다. 사람마다 카드를 정리하는 방식이 다릅니다.

* **선택정렬(Selection Sort):** 흩어진 카드 더미를 쭉 훑어보며 **가장 작은 카드를 찾아** 맨 앞자리와 맞바꾸는 방식입니다. 이 과정을 정렬되지 않은 나머지 구간에 대해 반복합니다.
* **삽입정렬(Insertion Sort):** 이미 손에 가지런히 정렬해 둔 카드 묶음에, **새로 뽑은 카드를 알맞은 자리에 끼워 넣는** 방식입니다. 브릿지 게임에서 카드를 정리할 때 흔히 쓰는 방법입니다.
* **퀵정렬(Quick Sort):** 카드 더미에서 **기준이 되는 카드(피벗) 한 장을 뽑아**, 그보다 작은 카드는 왼쪽 무더기로 큰 카드는 오른쪽 무더기로 나눈 뒤, 각 무더기를 같은 방식으로 또 나누어(재귀) 정렬하는 방식입니다.

```
선택정렬: [최솟값 탐색] → [맨앞과 교환] → 미정렬 구간 축소, 반복
삽입정렬: [현재 원소] → [정렬 구간 삽입 위치 탐색] → 이동 후 삽입, 반복
퀵정렬  : [피벗 선정] → [작은/큰 그룹 분할] → 분할정복 재귀 정렬
```

세 가지 모두 "미정렬 데이터를 특정 기준(최솟값/삽입위치/피벗)으로 정렬한다"는 공통점이 있지만, 전략은 전혀 다릅니다. 선택정렬은 "최솟값을 찾아 앞으로", 삽입정렬은 "새 값을 알맞은 자리로", 퀵정렬은 "기준값으로 나눠서 재귀"라는 방식으로 요약할 수 있습니다.

| 구분 | 선택정렬 | 삽입정렬 | 퀵정렬 |
|------|----------|----------|--------|
| 핵심 동작 | 최솟값 찾아 맨앞 교환 | 정렬구간에 알맞은 위치 삽입 | 피벗 기준 좌/우 분할 후 재귀 |
| 평균 시간복잡도 | O(n²) | O(n²) | O(n log n) |
| 최악 시간복잡도 | O(n²) | O(n²) | O(n²) |
| 안정성 | 불안정 | 안정 | 불안정 |
| 추가 메모리 | O(1) | O(1) | O(log n)(재귀 스택) |

> 💡 **안정성(Stability)이란?**
> 값이 같은 카드 두 장(예: 같은 숫자의 하트와 스페이드)이 있을 때, 정렬 후에도 원래의 앞뒤 순서가 유지되면 "안정 정렬"입니다. 삽입정렬은 안정적이지만, 선택정렬과 퀵정렬은 교환 과정에서 순서가 뒤바뀔 수 있어 불안정 정렬로 분류됩니다.

#### 퀵정렬의 분할 과정을 직접 따라가 보기

배열 `[50, 80, 20, 90, 40, 10, 30, 60]`(n=8)을 피벗 50으로 오름차순 정렬한다고 해봅니다. 피벗은 첫 번째 값인 `arr[0]=50`이며, Hoare 방식으로 왼쪽에서 오른쪽으로 훑는 인덱스 `i`와 오른쪽에서 왼쪽으로 훑는 인덱스 `j`를 각각 움직입니다.

| 단계 | i 탐색 | j 탐색 | 교환 | 배열 상태 |
|------|--------|--------|------|-----------|
| 초기 | i=1(80) | j=7(60) | - | [50,80,20,90,40,10,30,60] |
| 1회전 | arr[1]=80≥50 정지 | j=6(30)≤50 정지 | swap(80,30) | [50,30,20,90,40,10,80,60] |
| 2회전 | i=3(90)≥50 정지 | j=5(10)≤50 정지 | swap(90,10) | [50,30,20,10,40,90,80,60] |
| 3회전 | i=5(90)≥50 정지 | j=4(40)≤50 정지 | i≥j 종료 | [50,30,20,10,40,90,80,60] |
| 피벗배치 | - | - | swap(arr[0],arr[4]) | [40,30,20,10,50,90,80,60] |

분할이 끝나면 피벗 50은 인덱스 4에 정확히 자리 잡습니다. 왼쪽 무더기 `[40,30,20,10]`은 모두 50보다 작은 카드들이고, 오른쪽 무더기 `[90,80,60]`은 모두 50보다 큰 카드들입니다. 이제 이 두 무더기 각각에 대해 똑같은 분할 과정을 재귀적으로 반복하면, 최종적으로 `[10,20,30,40,50,60,80,90]`이라는 완전한 오름차순 정렬 결과를 얻게 됩니다.

> ⚠️ **퀵정렬이 항상 빠르지는 않습니다**
> 만약 카드 더미가 이미 정렬되어 있거나 완전히 역순이라면, 매번 가장 작은(또는 가장 큰) 카드가 피벗으로 뽑혀 무더기가 한쪽으로만 치우치게 됩니다. 이 경우 O(n²)까지 성능이 떨어지고 재귀 깊이도 급증해 스택 오버플로우 위험이 생깁니다. 실무에서는 피벗을 무작위로 고르거나 Median-of-Three 기법을 적용해 이런 최악의 경우를 회피합니다.

## Part 4. 전통 머신러닝

### 4-1. 기계학습이란? 지도학습·비지도학습·강화학습

#### 기계학습(Machine Learning): "경험이 쌓일수록 똑똑해지는 시스템"

기계학습을 한 줄로 정의하면 이렇습니다. "**명시적으로 프로그래밍하지 않아도, 데이터를 스스로 들여다보며 패턴을 찾아내는 AI의 하위 분야**"입니다. 톰 미첼(Tom Mitchell)이라는 학자는 이를 더 엄밀하게 표현했습니다. "경험(E)을 쌓을수록 특정 과업(T)에 대한 성능지표(P)가 향상되는 시스템"이라고요.

```
[학습 데이터] → [특징 추출/전처리] → [모델 학습(가설함수 최적화)]
                                            ↓
                                     [손실함수 최소화]
                                            ↓
                                  [학습된 모델] → 예측/분류
```

기계학습이 배우는 방식은 사람이 무언가를 배우는 세 가지 방식과 꼭 닮았습니다.

* **지도학습(Supervised Learning) — "선생님과 함께 정답을 맞춰가며 배우기"**
  문제지와 정답지를 함께 받아 공부하는 학생과 같습니다. "이 사진은 고양이", "이 이메일은 스팸"처럼 입력과 정답(Label)이 쌍으로 주어지고, 모델은 이 정답을 최대한 맞히도록 학습합니다. 새로운 문제(데이터)를 만나도 그동안 배운 패턴으로 정답을 예측·분류합니다.
* **비지도학습(Unsupervised Learning) — "혼자서 비슷한 것끼리 그룹 나눠보기"**
  정답지 없이 사진 더미만 잔뜩 던져주고 "비슷한 것끼리 알아서 모아봐"라고 시키는 것과 같습니다. 레이블이 없으므로 데이터 자체의 구조와 패턴(군집, 차원)을 스스로 발견해야 합니다.
* **강화학습(Reinforcement Learning) — "시행착오를 겪으며 몸으로 배우기"**
  게임을 처음 하는 사람이 이렇게 저렇게 눌러보다가 점수가 오르면 "이 행동이 좋았구나" 하고 스스로 감을 잡는 과정과 같습니다. 정답을 알려주는 사람은 없지만, 대신 '보상(Reward)'이라는 지연된 피드백을 받아가며 누적 보상을 최대화하는 행동 전략(정책)을 익힙니다.

| 구분 | 지도학습(Supervised) | 비지도학습(Unsupervised) | 강화학습(Reinforcement) |
|------|----------------------|---------------------------|--------------------------|
| 데이터 | 입력-정답(Label) 쌍 | 레이블 없는 데이터 | 상태-행동-보상 시퀀스 |
| 목적 | 예측·분류 함수 학습 | 구조·패턴 발견 | 누적보상 최대화 정책 학습 |
| 학습기술 | 회귀, SVM, CNN/RNN | 군집화, 차원축소(PCA) | Q-Learning, DQN, Policy Gradient |
| 예시 | 주차 수요 예측, 스팸 필터 | 고객 세분화, 이상탐지 | 신호등 제어, 로봇 경로학습 |

기계학습의 기본 알고리즘들도 목적에 따라 4갈래로 나뉩니다.

| 구분 | 대표 알고리즘 | 핵심 원리 |
|------|-------------|----------|
| 회귀 | 선형회귀, 릿지/라쏘 | 오차제곱합(SSE) 최소화 |
| 분류 | 로지스틱회귀, SVM, 결정트리 | 결정경계·정보이득 기반 분류 |
| 군집 | K-means, DBSCAN | 거리·밀도 기반 그룹화 |
| 앙상블 | Random Forest, XGBoost | 다수 약학습기 결합 |

> 💡 **준지도학습과 자기지도학습**
> 현실에서는 정답 레이블을 다는 작업(라벨링)이 매우 비쌉니다. 그래서 "소량의 레이블 데이터 + 대량의 레이블 없는 데이터"를 함께 활용하는 **준지도학습**, 데이터 스스로 정답을 만들어 학습하는 **자기지도학습(Self-Supervised Learning)**이 라벨링 비용을 줄이는 절충안으로 각광받고 있습니다.

예를 들어 주차 문제 예측 시스템을 만든다면, 초기에는 비지도학습(군집화)으로 "출퇴근 시간대 이용 패턴"을 먼저 발견한 뒤, 데이터가 충분히 쌓이면 지도학습(회귀/분류)으로 넘어가 실제 주차 가능 대수를 예측하는 단계적 접근이 실무적으로 효과적입니다.

---

### 4-2. 분류와 군집화: KNN, K-means, DBSCAN, SVM

#### K-NN(K-Nearest Neighbor): "판단이 어려우면 가까운 이웃에게 물어보세요"

새로운 동네로 이사 온 사람이 자기가 어느 상권에 속하는지 궁금할 때, 가장 쉬운 방법은 "**우리 집에서 가장 가까운 이웃 K명이 주로 어느 상권을 이용하는지**"를 물어 다수결로 정하는 것입니다. K-NN이 정확히 이런 방식으로 동작하는 지도학습 알고리즘입니다.

```
[K-NN]
   ●
  ● ○ ●   ← 새 데이터 분류
   ●
   K=3 이웃 다수결 → 분류
```

K-NN은 미리 모델을 만들어 두지 않고, 예측이 필요한 순간에야 전체 데이터를 뒤져 가까운 이웃을 찾는 **게으른 학습(Lazy Learning)**입니다. 그래서 학습은 빠르지만 예측 시점의 계산 비용(O(N))이 크다는 특징이 있습니다.

#### K-means: "동네마다 중심을 잡고 가까운 집을 끌어모으기"

K-means는 정반대의 접근을 취합니다. "**우리 도시를 K개의 구역으로 나눈다면, 각 구역의 중심(Centroid)은 어디일까?**"를 반복적으로 찾아가는 비지도학습입니다. 처음에는 중심 위치를 대충 찍어두고, ① 각 데이터를 가장 가까운 중심에 배정 → ② 배정된 데이터들의 평균으로 중심을 다시 계산 → ③ 더 이상 중심이 움직이지 않을 때까지 반복합니다.

```
[K-means]
   ●   ●
  ●  [C1]  ●
             ○ ○ [C2] ○ ○
반복적으로 중심점 갱신 → 군집화
```

| 구분 | K-NN(K-Nearest Neighbor) | K-means |
|------|---------------------------|---------|
| 학습 방식 | 지도학습(Supervised) | 비지도학습(Unsupervised) |
| 목적 | 분류(Classification)/회귀 | 군집화(Clustering) |
| K의 의미 | 참조할 이웃의 개수 | 생성할 군집의 개수 |
| 학습 과정 | Lazy Learning(예측 시 전체 탐색) | Eager Learning(반복적 중심점 갱신) |
| 알고리즘 절차 | 거리계산→K개 이웃선정→다수결/평균 | 초기중심설정→할당→중심갱신 반복 |
| 정답 레이블 | 필요(Label 존재) | 불필요(Label 없음) |
| 대표 활용 | 추천시스템 유사도 분류, 이상탐지 | 고객 세분화, 이미지 압축 |

> ⚠️ 두 알고리즘 모두 "K"라는 글자를 쓰지만, K-NN의 K는 "참조할 이웃의 수"이고 K-means의 K는 "만들 군집의 개수"로 의미가 완전히 다릅니다. K값이 너무 작으면 K-NN은 노이즈에 민감해져 과적합, 너무 크면 경계가 뭉개져 과소적합에 빠집니다. K-means는 K값 선정을 위해 엘보우 기법이나 실루엣 계수를 활용합니다.

#### DBSCAN: "구역을 미리 정하지 말고, 사람들이 몰려 있는 동네를 찾아보세요"

K-means의 약점은 "군집이 항상 둥근 모양이고, 개수(K)를 미리 정해야 한다"는 것입니다. 하지만 현실의 동네는 원형이 아니라 구불구불한 골목을 따라 밀집해 있을 수 있습니다. **DBSCAN**은 "**사람이 밀집해 있으면 동네, 뜸하면 그냥 빈 땅(노이즈)**"이라는 밀도 기반 사고로 군집을 찾습니다.

```
[K-means]                    [DBSCAN]
  구형 군집만 탐색               임의 모양 군집 탐색
   ● ●  ○ ○                    ●●●●        ○○
  ●[C1]● ○[C2]○                ●●●●○○    ○○○
   ● ●  ○ ○                     ●●●     ×  (노이즈로 분류)
```

```
DBSCAN 점 분류:
  Core Point   : 반경 ε 내 MinPts 이상의 이웃 보유
  Border Point : Core Point의 이웃이나 자신은 MinPts 미달
  Noise Point  : 어느 군집에도 속하지 않는 이상치
```

| 구분 | K-Means | DBSCAN |
|------|---------|--------|
| 군집화 방식 | 중심점(Centroid) 기반 분할 | 밀도(Density) 기반 확장 |
| 필요 파라미터 | 군집 개수 K | 반경 ε(epsilon), 최소점 MinPts |
| 군집 개수 사전 지정 | 필요 | 불필요(자동 결정) |
| 군집 형태 | 원형/구형(Convex) 유리 | 임의 형태(비선형 경계) 탐색 가능 |
| 이상치(Noise) 처리 | 모든 점을 강제 군집 할당 | 밀도 낮은 점을 노이즈로 별도 분류 |
| 대표 활용 | 고객 세분화, 이미지 색상 압축 | 지리공간 데이터 군집, 이상거래 탐지 |

K-means는 이상치도 어쩔 수 없이 가장 가까운 중심에 강제로 편입시켜 버려 중심이 왜곡될 수 있지만, DBSCAN은 밀도가 낮은 점을 아예 노이즈로 떼어내므로 이상치에 훨씬 강건합니다.

#### SVM(Support Vector Machine): "가장 안전하게 두 진영을 가르는 경계선 긋기"

두 팀을 갈라놓는 선을 그어야 한다고 상상해 봅니다. 아무 데나 선을 그어도 두 팀은 나뉘겠지만, 새로운 사람이 경계선 바로 근처에 서 있다면 잘못 분류되기 쉽습니다. **SVM**은 "**양쪽 팀에서 가장 가까이 있는 사람(서포트 벡터)들로부터 거리(마진)를 최대한 넓게 벌리는 경계선(초평면)**"을 찾는 지도학습 분류기입니다.

```
      ●   ●         ○   ○
    ●   ●   ★     ★   ○   ○
  ─────────────┼─────────────  ← 최적 결정경계(초평면)
    ●   ★         ★   ○
      ●               ○
   ★ = 서포트 벡터(경계 결정에 기여하는 데이터만)
```

마진이 넓을수록 처음 보는 데이터가 들어와도 오분류될 가능성이 낮아지므로 일반화 성능이 좋아집니다.

##### 하드 마진 vs 소프트 마진

현실 데이터는 노이즈와 이상치가 섞여 있어서 완벽하게 두 진영을 갈라놓을 수 없는 경우가 대부분입니다. 이에 따라 SVM의 마진 분류 방법은 두 가지로 나뉩니다.

```
        ●          ○
      ●   ●      ○   ○
  ─────────┼─────────────  ← 결정 경계(Hyperplane)
      ●   ●      ○   ○
   ↑margin↑    ↑margin↑
   서포트벡터가 경계선까지의 최단거리 = 마진
```

| 구분 | 하드 마진(Hard Margin) | 소프트 마진(Soft Margin) |
|------|--------------------------|----------------------------|
| 정의 | 오분류를 전혀 허용 않고 완벽 분리하는 마진 | 일부 오분류(여유변수)를 허용하는 마진 |
| 전제조건 | 데이터가 선형적으로 완벽 분리 가능 | 노이즈·이상치가 존재하는 현실 데이터 |
| 목적함수 | min(1/2)‖w‖² s.t. yᵢ(w·xᵢ+b)≥1 | min(1/2)‖w‖²+C·Σξᵢ s.t. yᵢ(w·xᵢ+b)≥1-ξᵢ, ξᵢ≥0 |
| 여유변수 | 없음 | 슬랙 변수(Slack Variable, ξ) 도입 |
| 규제 파라미터 | 없음 | C(패널티 계수)로 오분류 허용 정도 제어 |
| 실무 적용성 | 낮음(현실 데이터는 노이즈 포함) | 높음(대부분 실무 SVM은 소프트 마진) |

> 💡 **규제 파라미터 C의 의미**
> C는 "마진을 최대한 넓게 벌릴 것이냐" vs "오분류를 최대한 줄일 것이냐" 사이의 저울추입니다. C가 크면 오분류에 엄격해져 마진이 좁아지고 과적합 위험이 커지며(하드 마진에 근접), C가 작으면 오분류를 너그럽게 허용해 마진이 넓어지지만 과소적합 위험이 커집니다. 최적 C값은 교차검증(Grid Search)으로 탐색합니다.

##### 커널 트릭: 선을 못 그으면 차원을 높여서라도 그으면 됩니다

두 진영이 직선(평면)으로는 도저히 갈라지지 않는 경우도 있습니다. 이때 SVM은 **커널 트릭(Kernel Trick)**을 사용해 데이터를 더 높은 차원으로 옮겨서 그곳에서 선형으로 갈라버리는 전략을 씁니다.

```
저차원(선형 분리 불가) --φ(x) 매핑(커널 트릭)--> 고차원(선형 분리 가능)
      ○●○●                        ●●●  ○○○
      ●○●○         →              ●●●  ○○○
```

| 커널 함수 | 특징 | 활용 |
|-----------|------|------|
| Linear | 선형 분리 데이터 | 텍스트 분류 |
| Polynomial | 다항식 형태 경계 | 이미지 특징 |
| RBF(Gaussian) | 비선형 복잡 경계, 가장 범용적 | 대부분의 비선형 문제 |
| Sigmoid | 신경망과 유사한 경계 | 특수 목적 |

커널 트릭의 핵심은 데이터를 실제로 고차원에 옮기지 않고도, 커널 함수(내적) 계산만으로 마치 옮긴 것과 같은 효과를 얻어 계산량을 크게 줄인다는 데 있습니다. SVM은 딥러닝 시대에도 고차원·소량 데이터(텍스트, 유전자 데이터) 환경에서는 여전히 우수한 일반화 성능을 보이며, 스팸 필터링, 얼굴 인식, 유전자 발현 데이터 기반 암 진단 등에 폭넓게 쓰입니다. 다만 대용량 데이터에서는 학습 속도가 O(N²)~O(N³)까지 늘어나는 것이 약점입니다.

### 4-3. 강화학습과 마르코프 결정 프로세스

#### 강화학습(Reinforcement Learning): "게임 캐릭터가 시행착오로 실력을 키우는 방법"

처음 해보는 게임에서 어떻게 움직여야 점수가 오르는지 아무도 알려주지 않아도, 이리저리 시도해보며 "이 행동을 하니 점수가 올랐다"는 것을 스스로 깨우쳐 나가는 캐릭터를 떠올려 봅니다. 강화학습은 정확히 이런 구조입니다. **에이전트(Agent)**가 **환경(Environment)**과 계속 상호작용하며, 지도학습처럼 정답을 바로 알려주는 대신 **보상(Reward)**이라는 지연된 피드백만으로 누적 보상을 최대화하는 행동 전략(정책)을 학습합니다.

```
        ┌─────────────┐  Action(aₜ)
        │   Agent     │ ──────────────►┐
        │ (정책 π)     │                │
        └─────────────┘ ◄──────────────┘
              ▲            State(sₜ₊₁), Reward(rₜ₊₁)
              │        ┌─────────────┐
              └────────│ Environment │
                       └─────────────┘
```

| 구성요소 | 설명 |
|----------|------|
| Agent | 학습 및 행동 주체 |
| Environment | 에이전트가 상호작용하는 대상 |
| State(s) | 현재 환경의 상태 |
| Action(a) | 에이전트가 취하는 행동 |
| Reward(r) | 행동에 대한 환경의 피드백(보상) |
| Policy(π) | 상태에서 행동을 결정하는 전략(확률분포) |

#### 마르코프 결정 프로세스(MDP): 게임의 규칙을 수학으로 적어보기

강화학습이 풀어야 하는 문제를 수학적으로 정형화한 틀이 **MDP(Markov Decision Process)**입니다. "미래는 과거 이력과 무관하게 오직 현재 상태만으로 결정된다"는 **마르코프 특성**을 전제로, MDP는 다음 5가지 요소의 튜플 (S, A, P, R, γ)로 표현됩니다.

| 구성요소 | 기호 | 설명 |
|----------|------|------|
| 상태집합 | S | 가능한 모든 상태 |
| 행동집합 | A | 가능한 모든 행동 |
| 전이확률 | P(s'\|s,a) | 상태 s에서 행동 a 시 s'로 전이될 확률 |
| 보상함수 | R(s,a) | 상태·행동에 대한 즉각 보상 |
| 할인율 | γ(0≤γ≤1) | 미래 보상을 현재가치로 환산하는 계수 |

```
MDP 순환 구조:
  s₀ --a₀--> (P, R) --> s₁ --a₁--> (P, R) --> s₂ --> ...
       r₀                    r₁
목표: 누적 보상 기대값 최대화
  Gₜ = rₜ + γrₜ₊₁ + γ²rₜ₊₂ + ... = Σ γᵏrₜ₊ₖ
```

#### 가치함수와 벨만방정식: "지금부터 게임이 끝날 때까지 얼마나 딸 수 있을까?"

에이전트가 좋은 결정을 내리려면 "이 상태(혹은 이 행동)가 앞으로 얼마나 좋은 결과를 가져다줄지"를 수치로 평가할 수 있어야 합니다. 이를 위한 두 함수가 **상태가치함수 V(s)**와 **액션가치함수 Q(s,a)**입니다.

| 구분 | 상태가치함수 V(s) | 액션가치함수 Q(s,a) |
|------|---------------------|------------------------|
| 정의 | 상태 s에서 정책 π를 따랐을 때 기대 누적보상 | 상태 s에서 행동 a 이후 정책 π를 따랐을 때 기대 누적보상 |
| 수식 | Vπ(s)=Eπ[Gₜ\|Sₜ=s] | Qπ(s,a)=Eπ[Gₜ\|Sₜ=s,Aₜ=a] |
| 관계 | Vπ(s)=Σₐπ(a\|s)·Qπ(s,a) | Qπ(s,a)=R(s,a)+γΣP(s'\|s,a)Vπ(s') |
| 활용 | 정책 평가(현재 정책 가치 측정) | 행동 선택(정책 개선의 직접 기준) |

이 가치함수를 재귀적으로 풀어 쓴 것이 **벨만방정식**입니다. "지금 상태의 가치 = 즉각 보상 + 할인된 다음 상태의 가치"라는 아주 직관적인 식입니다.

```
[벨만기대방정식] - 정책 π 하의 가치 평가
  V(s) = Σₐ π(a|s) Σₛ' P(s'|s,a) [ R(s,a) + γV(s') ]
  Q(s,a) = E[ R(s,a) + γ Σₐ' π(a'|s')Q(s',a') ]

[벨만최적방정식] - 최적 정책 π*의 가치(최댓값 선택)
  V*(s) = maxₐ [ R(s,a) + γ Σₛ' P(s'|s,a) V*(s') ]
  Q*(s,a) = R(s,a) + γ Σₛ' P(s'|s,a) maxₐ' Q*(s',a')
```

| 구분 | 벨만기대방정식 | 벨만최적방정식 |
|------|----------------|-----------------|
| 목적 | 정책 π의 가치평가(Policy Evaluation) | 최적 정책 탐색(Policy Optimization) |
| 연산 | 정책에 따른 기대값(Σπ(a\|s)) 계산 | 모든 행동 중 최댓값(max) 선택 |
| 선형성 | 선형 방정식(연립방정식 직접 풀이) | 비선형(max 연산, 반복적 근사 필요) |
| 대표 알고리즘 | 정책반복(Policy Iteration)의 평가단계 | 가치반복(Value Iteration), Q-Learning |

> 💡 **모델 기반 vs 모델 프리**
> 전이확률 P와 보상함수 R을 미리 알고 있다면 **모델 기반(Model-Based)** 강화학습(가치반복, 정책반복)으로 곧바로 최적 정책을 계산할 수 있습니다. 하지만 실세계 대부분은 P, R을 알 수 없으므로, 경험(시행착오)으로 이를 추정해가는 **모델 프리(Model-Free)** 방식인 Q-Learning, SARSA, DQN, Policy Gradient가 실무에서 널리 쓰입니다.

### 4-4. CNN vs RNN

#### "사진을 보는 눈(CNN) vs 순서를 기억하는 귀(RNN)"

같은 신경망이라도 데이터의 성격에 따라 걸맞은 구조가 다릅니다. 사진 한 장을 볼 때는 "이 픽셀 주변에 어떤 모양이 있는가"라는 **공간적** 패턴이 중요하고, 문장이나 음성을 들을 때는 "지금 들은 단어가 방금 전에 들은 단어와 어떤 순서로 이어지는가"라는 **시간적** 순서가 중요합니다. CNN은 눈처럼 공간을 훑고, RNN은 귀처럼 순서를 기억합니다.

```
[CNN 구조]                              [RNN 구조]
입력이미지 → Conv → Pool → Conv → Pool     x₁ → [h₁] → x₂ → [h₂] → x₃ → [h₃]
   → FC → 출력(분류)                          ↑ 이전 은닉상태가 다음 입력에 영향
   (공간적 지역 특징을 계층적으로 추출)          (시간적 순서 의존성을 기억)
```

| 구분 | CNN | RNN |
|------|-----|-----|
| 핵심 연산 | 합성곱(Convolution) | 순환(Recurrence, 은닉상태 전달) |
| 구성 계층 | Convolution/Pooling/FC Layer | Input/Hidden/Output Layer(시점별 반복) |
| 주요 기술요소 | 필터(Kernel), Stride, Padding, Pooling | 은닉상태(Hidden State), 게이트, BPTT |
| 파라미터 공유 | 필터가 전체 이미지에 공유 | 모든 시점에서 동일 가중치 공유 |
| 대표 파생모델 | ResNet, VGG, Inception, EfficientNet | LSTM, GRU, Bi-RNN |
| 주요 한계 | 순서 정보 처리 부적합 | 기울기 소실/폭주 |
| 한계 극복 기술 | Batch Normalization, Skip Connection | LSTM 셀 상태+3-게이트(입력/망각/출력) |
| 적용분야 | 이미지 분류, 객체 탐지, 의료영상 진단 | 자연어처리, 음성인식, 주가예측 |

RNN은 문장이 길어질수록 앞부분의 기억이 옅어지는 "기울기 소실" 문제를 겪는데, 이를 극복하기 위해 등장한 것이 **LSTM**입니다.

```
LSTM 게이트 구조:
  Forget Gate → 과거 정보 중 버릴 것 결정
  Input  Gate → 새로운 정보 중 반영할 것 결정
  Output Gate → 다음 은닉상태로 내보낼 정보 결정
```

> 💡 **최근 트렌드**
> 최근에는 Attention 기반 **Transformer**가 RNN의 순차 처리(병렬화 불가) 한계를 극복하며 자연어처리의 표준으로 자리 잡았고, 이미지 분야에서도 **Vision Transformer(ViT)**가 CNN의 대안으로 부상하고 있습니다.

### 4-5. 모델 평가와 일반화: k-fold, 혼동행렬, 언더피팅/오버피팅

#### k-fold 교차검증: "모의고사를 여러 번 쳐서 진짜 실력을 가늠하기"

문제집 한 권으로만 시험을 준비하고 그 문제집에서 다시 시험을 보면 당연히 점수가 잘 나옵니다. 하지만 그것이 진짜 실력인지는 알 수 없습니다. **k-fold 교차검증**은 전체 데이터를 k개 조각(Fold)으로 나눈 뒤, 매번 한 조각씩 돌아가며 "이번엔 이 조각으로 모의고사(검증)를 보고, 나머지로 공부(학습)하자"를 k번 반복하는 검증 기법입니다.

```
전체 데이터를 5개 Fold로 분할 (k=5)
Round1: [검증][학습][학습][학습][학습]
Round2: [학습][검증][학습][학습][학습]
Round3: [학습][학습][검증][학습][학습]
Round4: [학습][학습][학습][검증][학습]
Round5: [학습][학습][학습][학습][검증]
   → 5회 평가 결과의 평균/표준편차로 최종 성능 산정
```

| 구분 | 설명 |
|------|------|
| 목적 | 데이터 분할 운(Sampling Bias)에 따른 성능 편차 최소화, 일반화 성능 추정 |
| 장점 | 전체 데이터를 학습·검증에 모두 활용, 소량 데이터에서 특히 유용 |
| 단점 | k번 반복 학습으로 계산 비용 증가 |
| 변형 기법 | Stratified k-fold(클래스 비율 유지), Leave-One-Out(k=N), Time Series Split |

```
[전체 데이터]
   ├── Train Set ─── k-fold Cross Validation으로 하이퍼파라미터 튜닝
   ├── Validation Set ─── 모델 선택/튜닝 시 사용
   └── Test Set ─── 최종 1회만 사용, 실서비스 성능 추정
```

> ⚠️ 테스트셋은 모델을 고르거나 튜닝하는 과정에서 절대 들여다보면 안 되고, 최종 모델이 정해진 후 딱 한 번만 사용해야 합니다(데이터 누수 방지). 시계열 데이터에 일반 k-fold를 그대로 적용하면 미래 데이터로 과거를 검증하는 데이터 누수가 생기므로, 시간 순서를 지키는 Time Series Split(Walk-Forward Validation)을 써야 합니다.

#### 혼동행렬(Confusion Matrix): 모델의 성적표를 4칸으로 쪼개보기

모델이 "맞다/틀리다"를 예측하는 이진 분류 문제에서, 실제값과 예측값을 교차해 정리한 표가 혼동행렬입니다.

```
                    예측(Predicted)
                  Positive    Negative
실제  Positive      TP           FN
(Actual) Negative   FP           TN

TP(True Positive)  : 실제 양성을 양성으로 올바르게 예측
TN(True Negative)  : 실제 음성을 음성으로 올바르게 예측
FP(False Positive) : 실제 음성을 양성으로 잘못 예측(1종 오류)
FN(False Negative) : 실제 양성을 음성으로 잘못 예측(2종 오류)
```

이 4개의 숫자만 있으면 대부분의 분류 평가지표를 계산할 수 있습니다.

| 지표 | 수식 | 의미 |
|------|------|------|
| 정확도(Accuracy) | (TP+TN)/(TP+TN+FP+FN) | 전체 예측 중 맞춘 비율 |
| 정밀도(Precision) | TP/(TP+FP) | 양성 예측 중 실제 양성 비율 |
| 재현율(Recall,TPR) | TP/(TP+FN) | 실제 양성 중 양성으로 맞춘 비율 |
| 특이도(Specificity,TNR) | TN/(TN+FP) | 실제 음성 중 음성으로 맞춘 비율 |
| F1-Score | 2·(Precision·Recall)/(Precision+Recall) | 정밀도·재현율의 조화평균 |
| FPR | FP/(FP+TN) | 실제 음성을 양성으로 오판한 비율 |

> 💡 **정밀도 vs 재현율, 무엇이 더 중요할까?**
> 스팸 필터처럼 정상 메일을 스팸으로 잘못 거르는(FP, 1종 오류) 것이 치명적인 경우는 **정밀도**가 중요하고, 암 진단처럼 실제 환자를 놓치는(FN, 2종 오류) 것이 치명적인 경우는 **재현율**이 중요합니다. 정밀도와 재현율은 임계값(Threshold)을 조절하면 한쪽이 오르면 다른 쪽이 내려가는 트레이드오프 관계입니다.

#### 언더피팅 vs 오버피팅: 공부 부족과 문제집만 암기의 함정

* **언더피팅(과소적합) — "공부를 너무 안 해서 기본기조차 없는 상태"**
  모델이 지나치게 단순해서 학습 데이터의 패턴조차 제대로 익히지 못한 상태입니다.
* **오버피팅(과대적합) — "문제집을 통째로 외워서 정작 새 문제는 못 푸는 상태"**
  모델이 학습 데이터의 노이즈까지 세세히 암기해버려서, 정작 처음 보는 데이터에는 오히려 성능이 떨어지는 상태입니다.

```
[언더피팅]           [적절한 적합]          [오버피팅]
  ／‾‾‾‾＼               곡선이 데이터           구불구불하게
 직선이 데이터를          패턴을 적절히          모든 점을 통과
 제대로 못 지남           따라감(일반화 우수)     (노이즈까지 암기)
  ●  ●                    ●  ●                    ●╲ ╱●
     ●   ●              ●    ●                  ●   V   ●
```

| 구분 | 언더피팅 | 오버피팅 |
|------|----------|----------|
| 원인 | 모델 복잡도 부족, 학습 부족, 특징 부족 | 모델 복잡도 과다, 데이터 부족, 과도한 학습 |
| 학습 오차 | 높음 | 낮음 |
| 검증 오차 | 높음 | 높음(학습 오차와 큰 격차) |
| Bias-Variance | 높은 편향(High Bias) | 높은 분산(High Variance) |

```
전체 오차 = Bias² + Variance + 불가피한 노이즈(Irreducible Error)

모델 복잡도 낮음 ──────────────────→ 모델 복잡도 높음
   Bias 큼   Variance 작음                Bias 작음   Variance 큼
   (언더피팅 구간)        최적 지점       (오버피팅 구간)
```

| 구분 | 언더피팅 극복 방안 | 오버피팅 극복 방안 |
|------|----------------------|----------------------|
| 모델 구조 | 복잡도 증가(레이어/파라미터 추가) | 모델 단순화, Early Stopping |
| 특징(Feature) | 특징 추가, 다항 특징 생성 | Feature Selection, 차원축소 |
| 정규화 | 정규화 강도 완화 | L1/L2 정규화, Dropout |
| 데이터 | 학습 데이터·에폭 증가 | 데이터 증강(Augmentation) |
| 앙상블 | 부스팅(Boosting)으로 편향 감소 | 배깅(Bagging)으로 분산 감소 |

> ⚠️ 모델 복잡도를 높이면 편향(Bias)은 줄지만 분산(Variance)은 커지는 트레이드오프 관계입니다. 학습곡선에서 학습 오차와 검증 오차의 격차를 보면 지금 모델이 언더피팅인지 오버피팅인지 진단할 수 있습니다.

### 4-6. 모델 재활용: 연합학습과 전이학습

#### 연합학습(Federated Learning): "각자 집에서 공부하고, 요약본만 학교에 제출하기"

병원마다 환자 데이터를 갖고 있지만, 개인정보 문제로 이 데이터를 한곳에 모아 학습시킬 수는 없습니다. 그렇다면 "**원본 데이터는 각자 집(디바이스)에 그대로 두고, 학습한 결과(가중치)만 학교(중앙 서버)에 제출**"하면 어떨까요? 이것이 연합학습의 핵심 아이디어입니다. "데이터는 머물고, 모델이 이동한다"는 원칙입니다.

```
[중앙 서버: 글로벌 모델]
        │  ① 초기 모델 배포
   ┌────┼────┬────────┐
   ▼         ▼         ▼
[Device A] [Device B] [Device C]
 로컬학습    로컬학습    로컬학습
 (원본데이터 미이동)
   │         │         │
   └────┬────┴─────────┘
        ▼ ② 가중치/그래디언트만 전송
[중앙 서버: 가중치 집계(Aggregation, 예: FedAvg)]
        │ ③ 통합 모델 갱신 후 재배포
```

| 단계 | 내용 |
|------|------|
| ① 모델 배포 | 중앙 서버가 초기 글로벌 모델을 각 클라이언트에 전송 |
| ② 로컬 학습 | 각 디바이스가 자체 보유 데이터로 로컬 모델 학습 |
| ③ 파라미터 전송 | 원본 데이터 대신 학습된 가중치/그래디언트만 서버로 전송 |
| ④ 집계(Aggregation) | 서버가 각 클라이언트 결과를 집계(FedAvg 등)해 글로벌 모델 갱신 |
| ⑤ 반복 | 갱신된 모델을 재배포하여 수렴할 때까지 반복 |

| 핵심 기술 | 설명 |
|-----------|------|
| FedAvg(연합평균) | 데이터 수 비례 가중평균으로 클라이언트 가중치 집계 |
| 차등 프라이버시 | 그래디언트에 노이즈 추가해 역추론 공격 방지 |
| Secure Aggregation | 개별 클라이언트 값을 서버가 알 수 없도록 안전 합산 |

구글 Gboard의 온디바이스 학습, 여러 병원이 데이터를 공유하지 않고도 공동으로 의료 AI를 개발하는 사례가 대표적입니다.

#### 전이학습(Transfer Learning): "밑바닥부터 배우지 말고, 이미 잘하는 사람의 지식을 빌리기"

새로운 언어를 배울 때, 모국어 문법 감각을 완전히 무시하고 처음부터 시작하지는 않습니다. 이미 익힌 언어 감각을 새 언어에 응용하는 것이 훨씬 빠릅니다. **전이학습**도 마찬가지입니다. 대규모 데이터(예: ImageNet 1400만 장)로 미리 학습해둔 모델의 지식(가중치)을, 데이터가 적은 새로운 목표 과제(예: 특정 질병 X-ray 500장)에 그대로 재사용합니다.

```
[Source Task: 대규모 데이터(예: ImageNet 1400만장)]
        ↓ Pre-training (범용 특징 학습: 엣지, 텍스처, 형태 등)
   [사전학습 모델(Pre-trained Model)]
        ↓ 가중치 이전(Weight Transfer)
[Target Task: 소량 데이터(예: 특정 질병 X-ray 500장)]
        ↓ Fine-tuning (일부 계층만 재학습)
   [목표 태스크에 특화된 모델]
```

전이학습을 적용하는 방법은 크게 두 가지입니다.

| 구분 | Feature Extraction | Fine-tuning |
|------|---------------------|--------------|
| 방법 | 사전학습 계층 고정(Freeze), 출력층만 새로 학습 | 사전학습 가중치를 초기값으로 전체(일부) 재학습 |
| 목표 데이터 양 | 매우 적을 때 유리 | 어느 정도 확보되었을 때 유리 |
| 학습 비용 | 낮음(출력층만 학습) | 상대적으로 높음(다수 계층 학습) |
| 과적합 위험 | 낮음 | 목표 데이터 적으면 위험 증가 |

```
CNN 계층별 전이학습 적용 전략:
  하위 계층(엣지, 색상 등 범용 특징) → 고정(Freeze) 유지
  상위 계층(도메인 특화 고차 특징)   → 재학습(Fine-tuning) 대상
```

| 데이터량 \ 도메인 유사도 | 유사도 높음 | 유사도 낮음 |
|--------------------------|-------------|-------------|
| 목표 데이터 적음 | Feature Extraction | 전이학습 효과 제한적, 신중 적용 |
| 목표 데이터 많음 | 전체 Fine-tuning | 사전학습 가중치를 초기값 삼아 전체 재학습 |

> ⚠️ 도메인 유사도가 낮은데도 무분별하게 사전학습 가중치를 재사용하면 오히려 성능이 떨어지는 **부정적 전이(Negative Transfer)**가 발생할 수 있습니다. 최근 LLM 시대에는 모델 전체를 재학습하는 대신 일부 파라미터만 효율적으로 조정하는 **LoRA, Prompt Tuning** 같은 PEFT(Parameter-Efficient Fine-Tuning) 기법이 널리 쓰입니다.

> 💡 **연합학습과 전이학습의 차이**
> 두 기법 모두 "모델(지식)을 재활용한다"는 공통점이 있지만, 연합학습은 **여러 주체가 데이터를 공유하지 않고 하나의 모델을 함께 만드는** 협업 학습이고, 전이학습은 **이미 만들어진 하나의 모델을 다른 과제에 재사용**하는 기법이라는 점에서 목적이 다릅니다.

## Part 5. 딥러닝 학습 원리

### 5-1. LSTM과 GRU — 기억하는 신경망

#### "메모를 남기며 일기 쓰기"

일반적인 순환신경망(RNN)은 문장을 한 단어씩 읽어가며 앞의 내용을 은닉 상태(hidden state) 하나에 욱여넣습니다. 문제는 문장이 길어질수록 맨 앞에서 읽은 내용이 뒤로 갈수록 희미해진다는 점입니다. 마치 하루 종일 있었던 일을 머릿속으로만 기억하려다가 저녁이 되면 아침에 뭘 먹었는지 가물가물해지는 것과 같습니다. 이를 **기울기 소실(Vanishing Gradient)** 문제라 부르며, RNN이 먼 과거의 정보를 활용하지 못하는 "장기 의존성(Long-term Dependency)" 한계로 이어집니다.

**LSTM(Long Short-Term Memory)**은 이 문제를 아주 실용적인 방법으로 해결합니다. 머릿속으로만 기억하지 말고, **수첩(셀 상태, Cell State)에 메모를 남기며 일기를 쓰자**는 아이디어입니다. 수첩에는 중요한 내용만 남기고 불필요한 내용은 지우며(Forget Gate), 새로 들어온 정보 중 적을 만한 것만 골라 적고(Input Gate), 필요할 때 수첩에서 꺼내 보고합니다(Output Gate).

```
[RNN]  h(t-1) → tanh(W·[h(t-1),x(t)]) → h(t)   (기울기 반복 곱 → 소실)

[LSTM] C(t-1) ──────────⊕────────────→ C(t)   (셀 상태, 덧셈 경로로 기울기 보존)
                 ↑Forget  ↑Input
        h(t-1),x(t) → [Gate 연산] → h(t)
```

핵심은 셀 상태를 곱셈이 아니라 **덧셈(⊕)**으로 갱신한다는 점입니다. 곱셈 경로는 반복될수록 값이 0으로 수렴하기 쉽지만, 덧셈 경로는 기울기를 잘 보존해 먼 과거의 정보도 살아남을 수 있게 해줍니다.

#### LSTM의 3개 게이트 — 문지기 세 명

수첩(셀 상태)을 관리하는 3명의 문지기가 있다고 상상하면 쉽습니다.

| 게이트 | 수식 | 역할 |
|--------|------|------|
| Forget Gate | f_t = σ(W_f·[h_{t-1},x_t]+b_f) | 이전 셀 상태 중 잊을 정보 비율 결정 |
| Input Gate | i_t = σ(W_i·[..]+b_i), C̃_t = tanh(W_c·[..]+b_c) | 새 정보 후보와 반영 비율 결정 |
| 셀 상태 갱신 | C_t = f_t⊙C_{t-1} + i_t⊙C̃_t | 망각·입력 결과 합산 |
| Output Gate | o_t = σ(W_o·[..]+b_o), h_t = o_t⊙tanh(C_t) | 출력할 정보 비율 결정 |

σ(시그모이드)는 "얼마나 열고 닫을지"를 0~1 사이 비율로 정하는 수도꼭지 역할이고, tanh는 "어떤 내용을 적을지" 후보값의 방향(-1~1)을 정합니다.

> 💡 **왜 게이트가 3개나 필요할까?**
> 잊을 것(Forget)과 새로 기록할 것(Input)을 따로 판단해야 정확한 메모가 남고, 마지막에 무엇을 꺼내 보여줄지(Output)까지 별도로 결정해야 상황에 맞는 답을 낼 수 있기 때문입니다.

#### GRU — 문지기를 2명으로 줄인 경량화 버전

**GRU(Gated Recurrent Unit)**는 LSTM의 셀 상태와 은닉 상태를 하나로 합치고, 3개였던 게이트를 2개(Reset, Update)로 줄인 간소화 버전입니다.

| 게이트 | 수식 | 역할 |
|--------|------|------|
| Reset Gate | r_t = σ(W_r·[h_{t-1},x_t]) | 과거 정보 무시 정도 결정 |
| Update Gate | z_t = σ(W_z·[h_{t-1},x_t]) | 이전 상태 유지 vs 신규 반영 비율 |
| 은닉 상태 갱신 | h_t=(1-z_t)⊙h_{t-1}+z_t⊙h̃_t | Forget/Input을 z_t 하나로 결합 |

| 구분 | LSTM | GRU |
|------|------|-----|
| 게이트 수 | 3개(Forget/Input/Output) | 2개(Reset/Update) |
| 상태 | 셀 상태+은닉 상태 분리 | 은닉 상태 단일 |
| 파라미터 수 | 상대적으로 많음 | LSTM 대비 약 25% 적음 |
| 적용 예 | 기계번역, 음성인식 초기모델 | 임베디드, 실시간 스트리밍 |
| 한계 | 긴 시퀀스도 병렬화 어려움(Transformer 대비 느림) | 복잡 패턴에서 LSTM 대비 정확도 열세 가능 |

> ⚠️ **최근 트렌드**
> 초장문·대규모 병렬 처리가 필요한 과제는 Attention/Transformer가 우선 검토 대상이 되었고, LSTM/GRU는 저지연·온디바이스 환경처럼 가벼움이 중요한 곳에서 여전히 선택되고 있습니다.

### 5-2. 파라미터 vs 하이퍼파라미터, 그리고 튜닝

#### "레시피 재료 vs 오븐 온도 설정"

요리를 할 때 두 종류의 결정이 있습니다. 하나는 요리 도중 간을 보면서 소금을 조금씩 더 넣는 것처럼 **재료의 양(파라미터)**을 조정하는 일이고, 다른 하나는 요리를 시작하기 전에 미리 정해두는 **오븐 온도, 굽는 시간(하이퍼파라미터)**입니다.

* **파라미터(Parameter):** 학습 과정에서 모델이 스스로, 자동으로 결정하는 값입니다. 대표적으로 가중치(Weight)와 편향(Bias)이 있으며, 매 학습 스텝마다 경사하강법으로 갱신됩니다.
* **하이퍼파라미터(Hyperparameter):** 학습을 시작하기 전에 사람(또는 탐색 알고리즘)이 미리 정해두는 값입니다. 학습률, 배치 크기, epoch 수, 은닉층 수 등이 여기에 해당하며, 학습 과정 자체를 통제합니다.

```
[하이퍼파라미터 설정] → [학습 프로세스 제어] → [파라미터(W,b) 최적화] → [모델 성능]
   Learning Rate              Forward/Backward         Weight, Bias
   Batch Size                 Gradient Descent
   Epoch, Optimizer 종류
```

즉 오븐 온도(하이퍼파라미터)를 잘못 정하면 아무리 요리사가 손맛(파라미터 자동 학습)을 발휘해도 요리가 타거나 설익습니다. 하이퍼파라미터가 먼저 학습 과정을 통제하고, 그 결과로 파라미터가 자동 결정되는 순서입니다.

| 구분 | 파라미터(Parameter) | 하이퍼파라미터(Hyperparameter) |
|------|----------------------|----------------------------------|
| 결정 주체 | 학습 알고리즘(역전파)이 자동 결정 | 사람 또는 튜닝 알고리즘이 사전 결정 |
| 예시 | 가중치(Weight), 편향(Bias) | 학습률, 배치 크기, 은닉층 수, epoch |
| 변경 시점 | 매 학습 스텝마다 갱신 | 학습 시작 전 고정(탐색 시 반복 조정) |
| 최적화 방법 | 경사하강법(Gradient Descent) | Grid/Random Search, Bayesian Optimization 등 |

하이퍼파라미터도 성격에 따라 다시 나눠볼 수 있습니다.

| 분류 | 예시 | 설명 |
|------|------|------|
| 학습 제어 | 학습률, Batch Size, Epoch | 수렴 속도·안정성 결정 |
| 모델 구조 | 은닉층 수, 노드 수, 커널 크기 | 모델 표현력·용량 결정 |
| 정규화 | Dropout 비율, L1/L2 계수 | 과적합 방지 |
| 최적화 알고리즘 | Optimizer 종류, Momentum 계수 | 파라미터 갱신 방식 결정 |

#### 오븐 온도를 어떻게 찾을까 — 하이퍼파라미터 튜닝 3형제

가장 좋은 오븐 온도를 어떻게 찾을까요? 세 가지 전략이 있습니다.

* **Grid Search(전수 탐색):** "150도, 160도, 170도... 시간도 10분, 20분, 30분..." 처럼 미리 정해둔 값들의 모든 조합을 하나씩 다 구워보는 방식입니다. 확실하지만 조합이 늘어날수록(차원이 커질수록) 시도 횟수가 폭발적으로 늘어납니다.
* **Random Search(무작위 탐색):** 격자 전체를 다 시도하지 않고, 그 범위 안에서 무작위로 몇 개만 골라 시도합니다. Grid보다 효율적이고 병렬로 여러 개를 동시에 시도하기도 좋지만, 최적점을 찾는다는 보장은 없습니다.
* **베이지안 최적화(Bayesian Optimization):** "다음에 어디를 시도할지 똑똑하게 추천받기"라고 생각하면 됩니다. 지금까지 구워본 결과들을 바탕으로 "이 근처 온도가 유망해 보인다"는 확률 모델을 세워두고, 그 모델이 가장 그럴듯한 다음 시도 지점을 추천해줍니다.

```
[초기 랜덤 샘플 관측] → [대리모델(Surrogate) 적합]
        ↓                        ↓
  [획득함수로 다음 탐색점 x* 선정] ← [사후분포(Posterior) 갱신]
        ↓
  [f(x*) 실제 평가(모델 학습)] → 반복(Iteration)
```

베이지안 최적화는 목적함수 f(x)의 실제 모양을 모르는 "블랙박스" 상황에서, 베이즈 정리 기반의 확률 모델(**대리모델, Surrogate Model**)로 함수를 근사하고, **획득함수(Acquisition Function)**로 다음에 시도해볼 가장 유망한 지점을 결정해 최소한의 시도로 전역 최적점에 가까이 다가갑니다.

| 대리모델 | 특징 | 적합한 상황 |
|----------|------|--------------|
| Gaussian Process(GP) | 불확실성 정량화 우수, 저차원 적합 | 하이퍼파라미터 5~20개 내외 |
| Random Forest(SMAC) | 고차원·범주형 변수에 강건 | 대규모 조합형 탐색 공간 |
| TPE | 조건부 분포 기반, 계산 효율적 | 대규모 반복 탐색(Optuna 등) |

| 획득함수 | 수식 개념 | 특징 |
|----------|-----------|------|
| Expected Improvement(EI) | 현재 최적값 대비 기대 개선량 최대화 | 가장 널리 사용, 안정적 |
| Probability of Improvement(PI) | 현재 최적값 개선 확률 최대화 | 보수적, 과도한 활용 경향 |
| Upper Confidence Bound(UCB) | μ(x)+κ·σ(x) 최대화 | κ로 탐색/활용 비율 직접 조절 |

즉 "이미 맛있었던 온도 근처를 더 파볼까(활용, Exploitation)", "아직 안 구워본 낯선 온도도 시도해볼까(탐색, Exploration)"의 균형을 수치로 계산해 다음 시도를 정하는 것입니다.

이 외에도 대규모 딥러닝에서는 **Hyperband/ASHA**처럼 성능이 낮아 보이는 후보를 조기에 잘라내는 조기 종료 기법도 함께 사용됩니다.

| 기법 | 방식 | 장점 | 단점 |
|------|------|------|------|
| Grid Search | 사전 정의 값 조합 전수 탐색 | 구현 단순, 재현성 높음 | 차원 증가 시 비용 폭증 |
| Random Search | 탐색 공간 무작위 샘플링 | Grid 대비 효율적, 병렬화 용이 | 최적점 보장 안 됨 |
| Bayesian Optimization | 대리모델로 성능 예측 후 유망 지점 탐색 | 적은 시도로 효율적 수렴 | 구현 복잡, 병렬화 제약 |
| Hyperband/ASHA | 조기 종료로 저성능 후보 제거 | 자원 효율적, 대규모 탐색 적합 | 짧은 평가로 조기 판단 오류 가능 |

> 💡 **실무 전략: Coarse-to-Fine**
> 탐색마다 전체 학습을 반복하면 GPU 비용이 폭증하므로, 먼저 Random Search로 넓은 범위를 훑고(Coarse) 유망한 영역을 찾으면 그 주변을 베이지안 최적화로 정밀 탐색(Fine)하는 2단계 전략이 실무에서 널리 쓰입니다. 고차원(수십 개 이상)에서는 GP의 계산 복잡도가 급증하므로 TPE 기반 도구(Optuna)를 활용합니다.

> ⚠️ **주의점**
> 수십~수백 번의 실험을 진행하다 보면 어떤 하이퍼파라미터 조합이 어떤 성능을 냈는지 재현하기 어려워집니다. MLflow나 W&B 같은 도구로 하이퍼파라미터-성능을 자동 로깅하고 시드(Seed)를 고정해두어야 합니다.

### 5-3. 머신러닝 파이프라인과 MLOps/AIOps/LLMOps

#### 공장의 생산라인처럼 모델을 찍어내기

주먹구구식으로 노트북 파일 하나에 데이터 불러오기, 전처리, 학습, 평가 코드를 순서 없이 뒤섞어 놓으면, 다음 사람이 재현하기도 어렵고 어제 잘 됐던 실험이 오늘은 실패하는 일이 반복됩니다. 마치 자동차를 만들 때마다 작업자가 그때그때 손으로 부품을 조립하면 품질이 들쭉날쭉한 것과 같습니다.

**머신러닝 파이프라인(ML Pipeline)**은 데이터 수집부터 모델 배포·모니터링까지 전 과정을 공장의 컨베이어 벨트처럼 표준화된 단계로 자동화해, 누가 언제 돌려도 같은 결과가 재현되도록 만든 워크플로우입니다.

```
[데이터 수집] → [데이터 전처리] → [피처 엔지니어링] → [모델 학습]
      ↓                                                    ↓
[모니터링] ← [배포/서빙] ← [모델 평가/검증] ← [하이퍼파라미터 튜닝]
      ↓
[Drift 감지 → 재학습 트리거] (파이프라인 순환)
```

| 단계 | 주요 작업 | 대표 도구 |
|------|-----------|-----------|
| 데이터 수집(Ingestion) | 배치/스트리밍 데이터 적재 | Kafka, Airbyte, Fivetran |
| 데이터 전처리 | 결측치 처리, 이상치 제거, 정규화 | Pandas, Spark |
| 피처 엔지니어링 | 파생 변수 생성, 피처 저장·재사용 | Feature Store(Feast) |
| 모델 학습 | 알고리즘 선택, 하이퍼파라미터 탐색 | TensorFlow, PyTorch, Kubeflow |
| 모델 평가 | 검증 데이터 성능 측정, 기준 통과 판정 | MLflow, TensorBoard |
| 배포 | 모델 서빙, API화, 카나리·블루그린 배포 | Kubernetes, Seldon, TorchServe |
| 모니터링 | 성능·Drift 감시, 알림 | Prometheus, Grafana, Evidently |

특히 배포 이후에도 파이프라인은 끝나지 않습니다. 시간이 지나면 실제 세상의 데이터 분포가 학습 때와 달라지는 **Drift(드리프트)**가 발생하는데, 이를 감지해 자동으로 재학습을 트리거하는 순환 구조가 MLOps의 핵심입니다.

| 구분 | 수작업(Ad-hoc) | 오케스트레이션 기반 파이프라인 |
|------|------------------|-------------------------------|
| 실행 방식 | 노트북/스크립트 수동 실행 | DAG 기반 자동 실행 |
| 재현성 | 낮음(환경·순서 의존) | 높음(버전 관리·컨테이너화) |
| 확장성 | 소규모 실험에 적합 | 대규모 운영·재학습 자동화 적합 |
| 대표 도구 | Jupyter Notebook | Kubeflow Pipelines, Airflow, Vertex AI Pipelines |

#### MLOps / AIOps / LLMOps — 이름은 비슷해도 방향이 다릅니다

DevOps가 "개발과 운영을 통합해 빠르고 안정적으로 소프트웨어를 배포하자"는 철학이었다면, AI 시대에 들어서면서 이 철학이 세 갈래로 분화되었습니다. 이름이 비슷해서 헷갈리기 쉽지만, "AI를 대상으로 운영하는 기술"과 "AI로 운영을 돕는 기술"은 방향이 정반대입니다.

```
DevOps (SW 개발/배포 자동화)
   ├─ MLOps   : "머신러닝 모델"을 운영 대상으로 자동화 (모델 개발→배포→모니터링)
   ├─ AIOps   : "IT 운영 자체"에 AI를 적용 (로그/메트릭 분석, 장애 예측)
   └─ LLMOps  : "LLM"에 특화된 MLOps 확장 (프롬프트/컨텍스트/평가 관리)
```

* **MLOps(Machine Learning Operations):** 모델 개발-학습-배포-모니터링-재학습 전 과정을 자동화·표준화합니다. 데이터/모델 버전관리, CI/CD/CT(지속적 학습)가 핵심 활동이며 MLflow, Kubeflow, SageMaker, Vertex AI 등을 씁니다.
* **AIOps(AI for IT Operations):** 반대로 IT 운영 데이터(로그·메트릭·트레이스)를 AI/ML로 분석해 이상 탐지, 알림 노이즈 제거, 근본원인분석(RCA), 장애 자동 복구를 수행합니다. Datadog, Splunk ITSI, Dynatrace 등이 대표적입니다.
* **LLMOps(Large Language Model Operations):** LLM에 특화된 MLOps의 확장판으로, 파인튜닝뿐 아니라 프롬프트 버전관리, RAG 파이프라인 운영, 응답 품질·환각·비용 관리를 다룹니다. LangSmith, PromptLayer, Guardrails AI 등을 씁니다.

| 구분 | MLOps | AIOps | LLMOps |
|------|-------|-------|--------|
| 대상 | ML 모델 전반 | IT 운영 시스템 | LLM 특화 모델 |
| AI의 역할 | 운영 대상(Object) | 운영 주체(Agent) | 운영 대상의 특수형 |
| 핵심 지표 | 정확도, 재현율, Drift | MTTR, 알림 정확도 | 응답 품질, 환각률, 토큰 비용 |
| 재학습 주기 | 데이터 변화에 따라 정기적 | 실시간 지속 학습 | 프롬프트/파인튜닝 갱신 |

> 💡 **관계 정리**
> MLOps가 큰 우산이라면, LLMOps는 그 아래 LLM에 특화된 하위 영역이고, AIOps는 완전히 다른 축에서 "AI로 운영 인프라 자체를 돕는" 개념입니다.

> ⚠️ **도입 시 유의점**
> 생성형 AI가 보편화되면서 전통적인 MLOps 지표만으로는 LLM의 환각(Hallucination)이나 토큰 비용을 포착하지 못합니다. RAG 정합성 평가, 유해 콘텐츠 필터링 같은 LLM 전용 가드레일을 추가해야 하며, AIOps의 자동 복구는 오탐(False Positive) 위험이 있으므로 초기에는 사람이 개입하는 반자동 검증(Human-in-the-loop)으로 시작해 점진적으로 자동화 범위를 넓히는 것이 안전합니다.

### 5-4. 신경망 학습의 핵심: 비용함수, 최적화, 경사하강법, 활성화함수

#### "산에서 눈 감고 가장 낮은 곳 찾아 내려가기"

안개가 자욱하게 낀 산 정상에서 눈을 감고, 발밑의 기울기만 느껴가며 가장 낮은 계곡을 찾아 한 걸음씩 내려가야 한다고 상상해봅니다. 전체 지형(비용함수)을 한눈에 볼 수는 없지만, 지금 서 있는 자리의 경사(기울기)를 느끼고 그 반대 방향으로, 즉 가장 가파르게 내려가는 방향으로 발을 내딛는 것이 **경사하강법(Gradient Descent)**입니다.

```
[예측값 ŷ] vs [실제값 y]
        ↓
   비용함수 L(ŷ,y) 계산
        ↓
   역전파(Backpropagation)로 ∂L/∂W 계산
        ↓
   옵티마이저가 W ← W - η·∂L/∂W 형태로 파라미터 갱신 (η: 학습률)
```

여기서 "얼마나 큰 보폭으로 내려갈 것인가"가 바로 **학습률(η)**입니다.

```
갱신식:  W_new = W_old - η · ∇J(W_old)

η(학습률) 크기에 따른 수렴 양상:
  η 너무 작음 → 수렴은 하나 매우 느림 (Local optimum 근처서 정체 가능)
  η 적정      → 안정적으로 최소점 수렴
  η 너무 큼   → 최소점을 지나쳐 진동/발산 (Overshooting)
```

보폭이 너무 작으면 산 아래까지 내려가는 데 세월이 걸리고, 너무 크면 계곡을 훌쩍 건너뛰어 반대편 산비탈로 넘어가 버릴(오버슈팅) 수 있습니다.

한 걸음(1스텝)을 내딛기 위해 지형 전체를 다 살펴볼지, 눈앞의 좁은 범위만 볼지에 따라 방식이 나뉩니다.

| 종류 | 갱신 단위 | 특징 |
|------|-----------|------|
| Batch GD | 전체 데이터 | 안정적이나 느림, 메모리 부담 |
| SGD | 데이터 1건 | 빠르나 진동(Noise) 큼 |
| Mini-batch GD | 소규모 배치(32~256 등) | 속도·안정성 절충, 실무 표준 |

#### 비용함수(Cost Function) — 얼마나 틀렸는지 재는 자

산의 높낮이, 즉 "지금 예측이 얼마나 틀렸는가"를 수치화하는 것이 비용함수입니다. 어떤 문제를 푸느냐에 따라 다른 자를 사용합니다.

| 비용함수 | 수식 | 적용 태스크 |
|----------|------|-------------|
| MSE | (1/n)Σ(y-ŷ)² | 회귀(Regression) |
| MAE | (1/n)Σ\|y-ŷ\| | 회귀, 이상치에 강건 |
| Binary Cross-Entropy | -(1/n)Σ[y·log(ŷ)+(1-y)log(1-ŷ)] | 이진 분류 |
| Categorical Cross-Entropy | -(1/n)ΣΣ y_ij·log(ŷ_ij) | 다중 클래스 분류 |
| Huber Loss | \|e\|≤δ: 0.5e² / \|e\|>δ: δ(\|e\|-0.5δ) | 회귀, MSE·MAE 절충 |

숫자를 예측하는 회귀 문제는 MSE나 MAE, 카테고리를 맞히는 분류 문제는 Cross-Entropy 계열을 기본으로 쓰고, 이상치에 너무 민감한 것이 걱정되면 둘을 절충한 Huber Loss를 씁니다.

#### 옵티마이저(Optimizer) 계보 — 더 똑똑하게 내려가는 법

단순히 현재 기울기만 보고 내려가면 골짜기 벽에 부딪혀 좌우로 튕기며 시간을 낭비하는 경우가 많습니다. 이를 개선하기 위한 옵티마이저의 발전 계보가 있습니다.

```
GD(Batch) → SGD → Momentum ─┐
                              ├─ Adam (Momentum + RMSProp 결합)
              AdaGrad → RMSProp ┘
```

| 옵티마이저 | 핵심 아이디어 | 특징 |
|------------|----------------|------|
| GD | 전체 데이터로 1회 갱신 | 안정적이나 느리고 메모리 부담 큼 |
| SGD | 미니배치 단위로 갱신 | 빠르나 진동(Noise) 발생 |
| Momentum | 이전 기울기 방향 관성 누적 | 진동 완화, 수렴 가속 |
| AdaGrad | 파라미터별 학습률을 누적 기울기 제곱에 반비례 조정 | 희소 데이터 유리, 학습률 과소수렴 문제 |
| RMSProp | 누적 기울기를 지수이동평균으로 대체 | 학습률 급감 문제 완화 |
| Adam | Momentum(1차 모멘트)+RMSProp(2차 모멘트) 결합 | 가장 널리 사용, 빠른 수렴·안정성 |

**Momentum**은 스키를 타고 내려갈 때 관성이 붙어 작은 언덕은 그냥 타고 넘어가는 것과 비슷합니다. 이전에 내려가던 방향의 관성을 누적해 진동을 줄이고, 얕은 지역 최소점(Local Minimum)도 관성의 힘으로 통과합니다. **Adam**은 이 관성(Momentum)과 파라미터마다 보폭을 다르게 주는 적응적 학습률(RMSProp)을 결합해, 실무에서 가장 널리 쓰이는 기본 선택지가 되었습니다.

#### 오버슈팅과 지역 최소점 — 산행에서 만나는 두 가지 함정

**오버슈팅(Overshooting)**은 보폭(학습률)이 너무 커서 목표 지점을 훌쩍 지나쳐 버리는 현상입니다.

| 기법 | 방식 | 효과 |
|------|------|------|
| 학습률 감소(LR Decay) | Epoch/Step 진행에 따라 η 점차 축소 | 초반 빠르게, 후반 정밀 수렴 |
| 적응적 학습률 | AdaGrad/RMSProp/Adam이 파라미터별 학습률 자동 조정 | 파라미터별 최적 보폭 확보 |
| 워밍업(Warm-up) | 초기 학습률을 작게 시작해 서서히 증가 | 학습 초기 불안정성 방지 |
| 그래디언트 클리핑 | 기울기가 임계값 초과 시 스케일 조정 | 기울기 폭주로 인한 급격한 갱신 방지 |
| 배치 정규화 | 층별 입력 분포 정규화 | 손실 지형을 완만하게 해 큰 학습률에도 안정 |

**지역 최소점(Local Minimum)**은 산속의 작은 웅덩이에 빠져 진짜 낮은 계곡(전역 최소점)을 찾지 못하고 멈춰버리는 현상입니다.

| 기법 | 방식 | 효과 |
|------|------|------|
| Momentum | 이전 기울기 방향을 관성처럼 누적 | 얕은 지역 최소점을 관성으로 통과 |
| SGD(확률적 특성) | 미니배치마다 노이즈 섞인 기울기 사용 | 국소 지형 요철을 무작위성으로 탈출 |
| Warm Restart(SGDR) | 주기적으로 학습률을 크게 재상승 | 정체된 지점에서 재탐색 유도 |
| 다중 초기화 | 서로 다른 초기 가중치로 복수 학습 후 최적 선택 | 초기값 의존성 완화 |
| Adam 등 2차 모멘텀 | 파라미터별 적응적 스텝으로 평탄 구간 통과 가속 | 정체 구간 빠른 통과 |

> ⚠️ **고차원 신경망의 진짜 함정은 지역 최소점이 아니다**
> 고차원 공간에서는 사방이 다 오르막인 진짜 지역 최소점보다, 어떤 방향으로는 오르막이고 어떤 방향으로는 내리막인 **안장점(Saddle Point)**에서 기울기가 0에 가까워져 정체되는 경우가 훨씬 흔합니다. Momentum이나 Adam 계열 옵티마이저가 이 안장점 구간을 관성의 힘으로 효과적으로 통과시켜줍니다.

#### 활성화 함수(Activation Function) — 신경망에 표현력을 주는 비틀기

가중합만 계속 쌓으면(선형변환의 연속) 아무리 층을 깊게 쌓아도 결국 하나의 선형변환으로 뭉쳐져 버립니다. 이를 막고 신경망이 복잡한 곡선, 즉 비선형 패턴을 학습할 수 있게 "비틀어주는" 함수가 활성화 함수입니다.

```
입력(x) → 가중합 z = Σ(w·x)+b → 활성화 함수 f(z) → 출력(다음 층으로 전달)

[활성화 함수 없을 경우]                 [활성화 함수 있을 경우]
 f(x) = Wn·...·W2·W1·x+b                f(x) = σ(Wn·σ(...σ(W1·x+b1)...)+bn)
 = 단일 선형변환으로 축약(표현력 상실)    = 비선형 조합으로 복잡한 함수 근사 가능
```

| 역할 | 설명 |
|------|------|
| 비선형성 도입 | 층을 깊게 쌓아도 표현력이 증가하도록 보장 |
| 출력 범위 제어 | 값의 범위를 제한(0~1, -1~1 등)해 학습 안정화 |
| 기울기 전달 | 역전파 시 미분값을 통해 가중치 갱신 신호 전달 |
| 희소성 유도 | ReLU 등은 음수 입력을 0으로 만들어 희소 표현 형성 |

대표적인 활성화 함수들과 그 수식은 다음과 같습니다.

| 함수 | 수식 | 미분(도함수) | 출력 범위 |
|------|------|--------------|-----------|
| Sigmoid | σ(x)=1/(1+e^-x) | σ(x)(1-σ(x)) | (0, 1) |
| Tanh | tanh(x)=(e^x-e^-x)/(e^x+e^-x) | 1-tanh²(x) | (-1, 1) |
| ReLU | f(x)=max(0,x) | x>0: 1, x≤0: 0 | [0, ∞) |
| Leaky ReLU | x>0: x, x≤0: αx (α≈0.01) | x>0: 1, x≤0: α | (-∞, ∞) |
| GELU | x·Φ(x) (Φ: 표준정규 누적분포함수) | 근사식, 매끄러운 곡선 | (-∞, ∞) 근사 |

활성화 함수는 계속 진화해왔습니다.

```
Sigmoid/Tanh (초기, 기울기 소실 취약)
      ↓
   ReLU (2012~, 계산 단순·기울기 소실 완화, but Dying ReLU)
      ↓
Leaky ReLU / PReLU / ELU (Dying ReLU 보완)
      ↓
   GELU / Swish (2018~, Transformer 계열 표준, 매끄러운 비선형)
```

| 구분 | Sigmoid | Tanh | ReLU | GELU |
|------|---------|------|------|------|
| 기울기 소실 | 심함(양끝 포화) | 있음(양끝 포화) | 양수 구간 없음 | 거의 없음 |
| 계산 비용 | 지수 연산 필요 | 지수 연산 필요 | 매우 낮음 | 상대적으로 높음 |
| 주요 문제 | Vanishing Gradient | Vanishing Gradient(완화) | Dying ReLU | 문제 적음, 연산량 소폭 증가 |
| 주요 사용처 | 이진분류 출력층 | RNN 은닉층(과거) | CNN 은닉층 표준 | Transformer(BERT, GPT 등) |

> 💡 **은닉층 vs 출력층, 다른 함수를 씁니다**
> 은닉층은 ReLU 계열이 기본값이고 최신 대규모 모델은 매끄러운 GELU/Swish를 표준으로 씁니다. 반면 출력층은 목적에 따라 달라져, 이진분류는 Sigmoid, 다중분류는 Softmax, 회귀는 항등함수(Identity)를 사용합니다.

> ⚠️ **Dying ReLU 주의**
> ReLU는 음수 입력을 전부 0으로 만들기 때문에, 학습률이나 초기화가 부적절하면 다수의 뉴런이 영영 죽어버리는 Dying ReLU 현상이 발생할 수 있습니다. He 초기화를 병행하고 활성화 값 분포를 모니터링하다가 필요하면 Leaky ReLU/PReLU로 전환하는 것이 안전합니다.

이처럼 비용함수로 오차를 재고, 경사하강법과 옵티마이저로 그 오차를 줄이는 방향과 보폭을 정하고, 활성화 함수로 신경망 전체에 비선형 표현력을 불어넣는 이 네 가지가 맞물려 돌아가는 것이 바로 딥러닝 학습의 핵심 원리입니다.

## Part 6. 자연어처리와 트랜스포머

### 6-1. 단어를 숫자로: 워드 임베딩 (TF-IDF, Word2Vec)

#### "단어의 좌표를 지도 위에 찍기"

컴퓨터는 숫자만 계산할 수 있습니다. "고양이"라는 글자를 아무리 들여다봐도 컴퓨터는 그것이 "강아지"와 비슷한 개념인지, "자동차"와 비슷한 개념인지 전혀 알지 못합니다. 그래서 자연어 처리의 첫걸음은 항상 **단어를 실수 벡터라는 좌표로 지도 위에 찍는 일**입니다. 이렇게 단어의 의미와 문맥적 유사도를 벡터 공간상의 거리(코사인 유사도)로 표현하는 기법을 **워드 임베딩(Word Embedding)**이라고 부릅니다.

```
[말뭉치] → 토큰화 → [단어] → [임베딩] → [벡터]
                                 ↑
                희소 표현(Sparse) ↔ 분산 표현(Dense)
```

지도에 좌표를 찍는 방식에는 두 가지 전통이 있습니다.

| 구분 | 희소 표현 (Sparse) | 분산 표현 (Dense) |
|------|-----------|-----------|
| 정의 | 단어를 고차원 원-핫 벡터로 표현 | 저차원 실수 벡터에 의미를 분산 저장 |
| 대표 기법 | One-Hot, TF-IDF, BoW | Word2Vec, GloVe, FastText |
| 차원/유사도 | 수만~수십만 차원, 유사도 미반영 | 100~300차원, 코사인 유사도 반영 |

> 💡 희소 표현은 "이 단어가 몇 번 등장했는가"라는 **통계적 빈도**에만 의존하는 넓고 텅 빈 지도이고, 분산 표현은 신경망이 학습을 통해 **의미를 압축**해 촘촘하게 채워 넣은 지도입니다.

#### TF-IDF — "모두가 아는 말은 중요하지 않다"

도서관에서 어떤 책이 "특별히" 다루는 주제를 찾고 싶다면 어떻게 해야 할까요? 그 책에 자주 등장하면서도(TF), 다른 책들에서는 잘 등장하지 않는(IDF) 단어를 찾으면 됩니다. **TF-IDF**는 바로 이 아이디어를 수식으로 만든 통계 기반 가중치 기법입니다.

```
TF-IDF(t,d) = TF(t,d) × IDF(t)
TF(t,d) = 문서 d 내 단어 t 등장 횟수 / d의 전체 단어 수
IDF(t)  = log( N / df(t) )   ※ N: 전체 문서 수, df(t): t가 등장한 문서 수
```

| 구분 | 항목 | 설명 |
|------|------|------|
| TF | Term Frequency | 문서 내 등장 빈도가 높을수록 값이 커져 중요 단어를 강조 |
| IDF | Inverse Document Frequency | 여러 문서에 흔한 단어일수록 값이 작아져 불용어를 억제 |
| 결과 | 희소 행렬 | 문서×어휘 크기의 행렬, 문서 분류/검색 랭킹에 활용 |

예를 들어 "그리고", "이다" 같은 불용어는 거의 모든 문서에 등장하기 때문에 df(t)가 커져서 IDF 값이 낮아지고, 결과적으로 TF-IDF 점수가 자동으로 낮게 깔려 중요도에서 제외됩니다. 반면 특정 논문에서만 반복되는 전문 용어는 IDF가 높아 도드라지게 됩니다.

#### Word2Vec — "친구를 보면 그 사람을 알 수 있다"

TF-IDF는 단어의 빈도만 셀 뿐 "고양이"와 "강아지"가 의미상 가깝다는 것은 전혀 알지 못합니다. **Word2Vec**은 "친구를 보면 그 사람을 알 수 있다"는 언어학적 직관(분포 가설)을 신경망으로 구현한 예측 기반 기법입니다. 즉, 어떤 단어의 의미는 그 단어의 주변에 어떤 단어들이 함께 나타나는지를 보면 알 수 있다는 것이죠. 얕은 신경망이 주변 문맥으로 단어를 예측하도록 학습시킨 뒤, 그 은닉층의 가중치를 단어의 분산 표현 벡터로 재활용합니다.

```
CBOW: 주변단어 → 중심단어 예측         Skip-gram: 중심단어 → 주변단어 예측
[w(t-2)..w(t+2)] → 은닉층 → w(t)       w(t) → 은닉층 → [w(t-2)..w(t+2)]
```

| 구분 | CBOW | Skip-gram |
|------|------|-----------|
| 학습 방향 | 주변 단어들을 보고 중심 단어를 예측 | 중심 단어를 보고 주변 단어들을 예측 |
| 속도/데이터 | 빠름, 소규모 데이터에 적합 | 느림, 대규모/희소 단어에 강함 |
| 최적화 | Negative Sampling, Hierarchical Softmax 공통 적용 | 동일 |

> 💡 Negative Sampling이란 전체 어휘를 대상으로 Softmax를 계산하는 대신, 정답이 아닌 오답 단어 몇 개만 무작위로 뽑아 "이건 정답이 아니다"라고 가볍게 학습시키는 지름길입니다. 덕분에 수십만 개 단어를 가진 어휘도 빠르게 학습할 수 있습니다.

Word2Vec으로 학습된 벡터는 놀랍게도 벡터 연산만으로 의미 관계를 표현합니다. 유명한 예시가 `vec(King) - vec(Man) + vec(Woman) ≈ vec(Queen)`입니다. "왕에서 남성성을 빼고 여성성을 더하면 여왕이 된다"는 관계가 좌표 공간의 덧셈·뺄셈으로 그대로 성립하는 것입니다.

#### TF-IDF vs Word2Vec, 그리고 그 다음

| 구분 | TF-IDF | Word2Vec |
|------|--------|----------|
| 표현 방식 | 희소/통계 기반 | 분산/예측 기반 |
| 의미 반영 | 빈도 기반, 문맥 의미 미반영 | 신경망 학습, 문맥적 의미 반영 |
| 한계 | 차원의 저주, 신조어(OOV) 대응 곤란 | 다의어 구분 불가(정적 임베딩) |
| 실무 활용 | 1차 검색/필터링 baseline | 임베딩 기반 유사도/추천 |

> ⚠️ Word2Vec은 한 단어에 벡터 하나만 고정 배정하는 **정적 임베딩**이라, "배(먹는 배)"와 "배(타는 배)"를 구분하지 못합니다. 이 한계를 넘어선 것이 바로 문맥에 따라 벡터가 달라지는 BERT 같은 **문맥적 임베딩(Contextual Embedding)**이고, 그 심장부에 있는 기술이 다음 절에서 다룰 **Self-Attention**입니다.

### 6-2. Self-Attention — "문장 속에서 서로를 바라보기"

#### Query, Key, Value — "질문, 이름표, 내용물"

다음 문장을 봅시다.

> "The animal didn't cross the street because **it** was tired."

여기서 "it"은 무엇을 가리킬까요? 사람은 문맥을 보고 "animal"이라고 즉시 알아채지만, 컴퓨터에게는 "it"이라는 단어 자체에는 그 정보가 없습니다. 문장 속 다른 모든 단어를 돌아보며 "누가 나와 관련이 깊지?"를 물어야 합니다. 이렇게 **시퀀스 내 각 단어가 자신을 포함한 모든 단어와의 연관도(Attention Score)를 계산하고, 그 가중합으로 새로운 표현(Context Vector)을 만들어내는 메커니즘**이 바로 **Self-Attention**입니다.

이 과정을 도서관에서 자료를 찾는 상황에 비유해 봅시다.

* **Query(질문지)**: "it"이 손에 들고 있는 질문지입니다. "나와 관련된 정보를 가진 사람 있나요?"
* **Key(이름표/열쇠 구멍)**: 문장 속 모든 단어들이 각자 달고 있는 이름표입니다. Query와 얼마나 잘 맞는 열쇠 구멍인지를 나타냅니다.
* **Value(실제 내용물/자물쇠 속 보물)**: Key라는 이름표 뒤에 진짜로 담겨 있는 알맹이 정보입니다.

"it"의 Query가 문장 속 모든 단어의 Key와 하나씩 맞춰보며 궁합(내적 유사도)을 점수로 매기고, 그 점수가 높은 단어(animal)의 Value를 더 많이 끌어와 "it"의 새로운 벡터에 섞어 넣습니다.

```
Q = X·W_Q,  K = X·W_K,  V = X·W_V   (X: 입력 임베딩)

"it was tired" → "it" 이 무엇을 가리키는가?
→ 문장 내 모든 단어와 연관도 계산 → "animal"에 높은 가중치
→ "it" 벡터에 "animal" 의미 반영해 재구성
```

> 💡 RNN은 단어를 왼쪽에서 오른쪽으로 한 줄로 세워 순서대로 정보를 전달했기 때문에 문장이 길어지면 앞쪽 정보가 희미해졌습니다(장거리 의존성 문제). Self-Attention은 줄을 세우지 않고 모든 단어 쌍을 동시에 마주 보게 하여 이 문제를 해결합니다.

#### Scaled Dot-Product Attention — 계산 흐름도

Self-Attention의 계산을 수식 하나로 표현하면 다음과 같습니다.

```
Attention(Q,K,V) = softmax( Q·K^T / √d_k ) · V
```

```
[입력] → h개 Head 분할 → Head별 Scaled Dot-Product Attention 병렬 수행
       → Concat(head_1,...,head_h) → 선형변환(W_O) → 출력
```

| 구분 | 항목 | 설명 |
|------|------|------|
| Q·K^T | 내적(유사도) | 모든 단어 쌍의 Attention Score 산출 |
| √d_k | 스케일링 | 값 폭주로 인한 softmax 기울기 소실 방지 |
| softmax·V | 가중합 | 확률 분포화한 뒤 Value에 곱해 Context Vector 생성 |
| Multi-Head | h개 부분공간 병렬 | 문법/의미/위치 등 다각도 관계를 동시에 학습 |

한 사람(단일 Head)이 문장을 한 가지 관점으로만 훑는 것보다, 여러 전문가(Multi-Head)가 각자 문법 담당, 의미 담당, 위치 담당으로 나뉘어 동시에 문장을 읽고 나중에 의견을 합치는 것이 훨씬 풍부한 이해를 만들어냅니다. 이것이 **Multi-Head Attention**입니다.

> ⚠️ Self-Attention은 모든 단어 쌍의 관계를 계산하기 때문에 문장 길이 n에 대해 연산량이 O(n²)로 폭증합니다. 그래서 최근에는 FlashAttention, Sparse/Sliding Window Attention 같은 경량화 기법과, 순서 정보가 없는 집합 연산이라는 약점을 보완하는 Positional Encoding, RoPE(상대 위치 인코딩) 등이 함께 쓰입니다. 또한 Attention Weight를 "모델의 판단 근거"로 과신하는 것은 위험하며, 별도의 SHAP/LIME 같은 설명가능 AI(XAI) 기법을 병행해야 합니다.

### 6-3. 트랜스포머 아키텍처와 MoE, 차등 트랜스포머

#### 트랜스포머 — Self-Attention을 쌓아 올린 공장

Self-Attention이라는 부품 하나를 손에 넣었다면, 이제 이를 여러 층으로 쌓아 완제품을 만들 차례입니다. **트랜스포머(Transformer)**는 RNN의 순차 연산을 완전히 배제하고 Self-Attention만으로 시퀀스 내 전역적 의존관계를 병렬 학습하는 Encoder-Decoder 기반 신경망 아키텍처입니다(Vaswani et al., 2017).

```
[Encoder] Input+PosEnc → (MH Self-Attn → Add&Norm → FFN → Add&Norm)×N
[Decoder] Output+PosEnc → (Masked MH Attn → Enc-Dec Attn → FFN)×N
→ Linear + Softmax → 출력 확률
```

| 구성 요소 | 역할 |
|-----------|------|
| Positional Encoding | 순서 정보가 없는 Attention에 위치 정보를 주입 |
| Multi-Head Self-Attention | 여러 관점에서 단어 간 연관도를 병렬 계산 |
| Add & Norm | 잔차 연결로 기울기 소실을 방지하고, LayerNorm으로 학습을 안정화 |
| Feed Forward Network | 각 위치별로 독립적인 비선형 변환(2단 완전연결)을 수행 |

> 💡 트랜스포머 공장 전체를 다 쓰지 않고 일부만 떼어 쓰는 변형들도 있습니다. GPT 계열은 Decoder만 사용해 "다음 단어를 계속 이어 쓰는" 생성에 특화되어 있고, BERT 계열은 Encoder만 사용해 "문장을 양방향으로 깊이 이해하는" 데 특화되어 있습니다.

#### MoE — "모든 문제를 팀장이 다 풀지 않고, 필요한 전문가만 호출한다"

트랜스포머를 점점 키워 성능을 올리다 보면 파라미터 수가 늘어날수록 연산 비용이 그대로 비례해서 폭증하는 문제에 부딪힙니다. 이때 등장한 아이디어가 **MoE(Mixture of Experts)**입니다. 회사에 비유하면, 모든 업무를 팀장 한 명이 다 처리하는 대신, 법무 전문가·회계 전문가·마케팅 전문가를 여러 명 채용해두고 안건이 들어올 때마다 **라우터(Router)가 그 안건에 맞는 전문가 한두 명만 호출**해 처리시키는 방식입니다.

```
정 의  • 트랜스포머 블록 내 단일 FFN을 다수의 전문가(Expert)로
         대체, 라우터(Router)가 토큰마다 일부 Expert만 선택적으로
         활성화(Sparse Activation)하는 구조

[입력 토큰] → Router(Gating) → Top-k Expert 선택
                  ↓
     [Expert1][Expert2][Expert3]...[ExpertN]  (FFN 다수)
                  ↓ 선택된 k개만 활성화
           가중합(Weighted Sum) → 출력
```

| 구분 | Dense Transformer | MoE Transformer |
|------|--------------------|--------------------|
| FFN 구조 | 단일 FFN을 전체가 통과 | 다수 Expert 중 Top-k만 통과 |
| 연산량 | 파라미터 수에 비례 | 활성화된 Expert 수에만 비례(절감) |
| 대표 모델 | GPT-3, T5 | Mixtral 8x7B, DeepSeek-V3 |
| 과제 | 스케일업 시 비용이 선형으로 증가 | 라우팅 불균형, 학습 불안정 |

> 💡 "총 파라미터는 크지만(예: 8×7B=56B), 실제로 매번 활성화되는 파라미터는 작은(예: 약 13B)" 구조라는 점이 MoE의 핵심입니다. 회사에 100명의 전문가가 있어도, 안건 하나당 실제로 회의에 부르는 사람은 2명뿐인 셈입니다. 다만 특정 전문가에게만 일감이 몰리는 "편애(Expert Collapse)"를 막기 위해 Load Balancing Loss나 Noisy Top-k Gating 같은 안전장치가 필요합니다.

#### 차등 트랜스포머 — "노이즈 캔슬링 이어폰처럼 잡음을 상쇄한다"

표준 Self-Attention은 softmax를 사용하기 때문에 관련 없는 토큰에도 항상 미세하게 양수의 가중치를 나눠 줍니다. 문장이 짧을 때는 무시할 만한 수준이지만, 문서가 아주 길어지면 이 "미세한 잡음"들이 쌓이고 쌓여 정작 중요한 정보를 흐리게 만듭니다.

**Differential Transformer(차등 트랜스포머)**는 이 문제를 노이즈 캔슬링 이어폰의 원리로 해결합니다. 노이즈 캔슬링 이어폰은 마이크 두 개로 소리를 받아, 두 신호 사이에 공통으로 섞인 배경 소음은 서로 빼서 상쇄시키고 진짜 음악 신호만 남깁니다. 차등 트랜스포머도 하나의 헤드를 **두 개의 독립적인 Softmax Attention Map**으로 계산한 뒤, 학습 가능한 스칼라 λ(람다)로 두 맵의 차(差)를 구해 공통 노이즈는 상쇄하고 유의미한 신호만 증폭시킵니다.

```
A1 = softmax(Q1K1^T/√d),  A2 = softmax(Q2K2^T/√d)
DiffAttn = (A1 - λ·A2) · V

[Q,K를 2배 폭 분할] → [Q1,K1],[Q2,K2] → softmax 각각 계산
                     → (A1-λA2) → ×V → 출력
```

| 구성 요소 | 역할 |
|-----------|------|
| Q1,K1 / Q2,K2 | 입력을 2그룹으로 분할해 독립적인 어텐션 맵 2개를 생성 |
| λ(학습 파라미터) | 두 맵의 차감 비율을 레이어/헤드별로 학습 |
| Differential Attention Map | A1-λ·A2로 공통 노이즈를 상쇄하고 신호를 부각 |
| GroupNorm | 헤드별 값 스케일 차이를 보정 |

| 구분 | 표준 Transformer | 차등 Transformer |
|------|--------------------|---------------------|
| 어텐션 맵 | 헤드당 1개 | 헤드당 2개(차감 연산) |
| 노이즈 처리 | 무관 토큰에도 낮은 가중치가 잔존 | 공통 노이즈가 상쇄되어 무관 토큰 가중치가 0에 근접 |
| 긴 컨텍스트 | 길수록 정보 검색 정확도 저하 | Needle-in-Haystack 검색 정확도 향상 |
| 환각(Hallucination) | 무관 정보 참조로 발생 가능성 증가 | 핵심 토큰에 집중해 환각 감소 경향 |

> ⚠️ "노이즈를 제거하면 환각(Hallucination)이 완전히 해결된다"고 오해하기 쉽지만, 이는 어텐션 스코어 상의 잡음을 줄이는 것일 뿐입니다. 사실 관계 오류까지 없애려면 RAG(검색 증강 생성), Fact-Checking 파이프라인을 함께 병행해야 합니다. 또한 λ 초기화는 논문에서 제시한 스케줄(λ_init = 0.8 - 0.6e^(-0.3·layer))을 기반으로 도메인별 A/B 검증이 필요하며, 기존 BERT/GPT 가중치를 그대로 이식할 수 없어 법률/장문 요약 등 특화 도메인에 선별 적용하는 것이 현실적입니다.

### 6-4. PLM에서 LLM으로 — 사전학습부터 정렬까지

#### "기본 교양 쌓기 → 전공 공부 → 예의범절 배우기"

지금까지 만든 트랜스포머라는 몸체는 아직 "글자를 이해하고 다음 단어를 잘 예측하는 능력"만 가진 백지 상태입니다. 이 백지 상태의 모델을 우리가 대화하는 ChatGPT 같은 똑똑한 비서로 키우려면, 마치 한 사람이 성장하듯 세 단계의 교육 과정을 거쳐야 합니다.

* **1단계, 기본 교양 쌓기 (Pre-training)**: 도서관에 있는 거의 모든 책을 닥치는 대로 읽으며 세상 지식과 언어의 통계적 패턴을 몸에 익히는 단계입니다.
* **2단계, 전공 공부 (SFT, Instruction Tuning)**: "질문에는 이런 형식으로 답해야 한다"는 지시-응답 예시들을 모아 전공 수업을 듣듯 구체적으로 훈련받는 단계입니다.
* **3단계, 예의범절 배우기 (RLHF)**: 아무리 아는 게 많고 형식을 잘 지켜도, 사람들이 "이 대답은 별로다", "이 대답이 더 좋다"고 매긴 선호도를 바탕으로 예의 바르고 유용하며 안전하게 답하는 태도를 익히는 단계입니다.

#### PLM(사전학습 언어모델)의 특성

**PLM(Pre-trained Language Model)**은 레이블 없는 대규모 텍스트 말뭉치로 **자기지도학습(Self-Supervised Learning)**을 통해 언어의 통계적 패턴과 문맥 지식을 사전 습득한 범용 언어모델입니다(예: BERT, GPT, T5).

```
[대규모 비정형 텍스트] → Self-Supervised Learning
     → [PLM] → Fine-tuning(Downstream Task별)
     → 감성분석/개체명인식/번역 등
```

| 특성 | 설명 |
|------|------|
| 자기지도학습 | 레이블 없는 원시 텍스트에서 학습 신호를 스스로 만들어냄 |
| 학습 목표 | MLM(BERT, 양방향으로 빈칸 채우기), CLM(GPT, 단방향으로 다음 단어 예측) |
| 범용성/전이학습 | 특정 태스크에 종속되지 않고, 사전학습된 가중치를 다운스트림 작업에 전이 |
| 한계 | 지시 이해력·대화 능력이 부족해 태스크마다 별도의 Fine-tuning이 필요 |

> 💡 초기 PLM은 마치 "책은 엄청나게 많이 읽었지만 대화 예절은 배운 적 없는 학자"와 같아서, 질문 형식에 맞춰 정중히 답하는 능력이 없었습니다. 이 한계를 넘기 위한 것이 바로 다음의 PLM → LLM 파이프라인입니다.

#### PLM → LLM 훈련 파이프라인

PLM을 기반으로 지시 이해력과 인간 선호 정렬 능력을 순차적으로 추가 학습시켜, 범용 대화·추론이 가능한 **LLM(Large Language Model)**으로 완성하는 과정입니다.

```
1단계 Pre-training → 2단계 SFT(Instruction Tuning) → 3단계 RLHF/Alignment
(TB급 비정형 텍스트)   (지시-응답 쌍, 수만~수십만건)   (인간 선호 데이터, Reward Model)
     ↓                        ↓                          ↓
 Base PLM 생성        Instruction-tuned Model        RLHF 정렬 LLM
```

| 단계 | 목적 | 학습 방식 |
|------|------|-----------|
| ① Pre-training | 언어 통계 구조와 세계 지식 습득 | 자기지도학습(MLM/CLM), 전체 훈련 비용의 90% 이상을 차지 |
| ② SFT | 지시 이해와 형식 준수를 조정 | 지도학습(지시-모범답변 쌍) |
| ③ RLHF | 인간 선호(유용함/안전함)에 정렬 | Reward Model 학습 + PPO/DPO 강화학습 |

이 3단계를 거치며 모델은 "다음 단어를 예측하는 통계 기계"에서 "사람이 원하는 방식으로 답하는 대화 상대"로 진화합니다.

| 구분 | PLM(Base) | LLM(정렬 후) |
|------|-----------|---------------|
| 능력 | 언어 패턴/세계 지식 습득 | 지시 이해 + 대화 + 선호 정렬 |
| 활용 | 태스크별 Fine-tuning 필요 | 범용 지시 수행(Zero/Few-shot) |
| 리스크 | 다운스트림 적응 비용이 높음 | 보상 해킹, 정렬 왜곡 가능성 |

> ⚠️ RLHF 과정에서 모델이 Reward Model을 "속여서" 장황하고 그럴듯하지만 실제로는 무의미한 답변으로 높은 점수를 받으려는 **보상 해킹(Reward Hacking)** 현상이 발생할 수 있습니다. 이를 막기 위해 SFT 모델에서 너무 멀리 벗어나지 않도록 **KL 페널티**로 제약을 걸며, 최근에는 별도의 Reward Model 학습 없이도 선호 데이터를 직접 활용하는 저비용 **DPO(Direct Preference Optimization)**도 널리 채택되고 있습니다.

> 💡 **실무 시사점**: 웹크롤링 데이터의 편향과 오류는 환각(Hallucination)의 근본 원인이 되므로 필터링/중복제거/품질 스코어링과 RAG 결합이 필요합니다. 사내에서 LLM을 직접 구축할 때는 처음부터 Pre-training을 수행하기보다, LLaMA·Qwen 같은 오픈소스 Base 모델 위에 도메인 특화 SFT/DPO를 집중하는 경량 정렬 전략이 현실적입니다.

## Part 7. AI 트렌드, 보안, 거버넌스

### 7-1. 피지컬 AI와 로봇의 시대 (VLA, 에이전틱 AI)

#### 피지컬 AI: "AI가 드디어 몸을 갖게 되다"

지금까지의 생성형 AI는 채팅창 안에서만 살았습니다. 질문을 던지면 텍스트나 그림으로 답할 뿐, 컵 하나 옮기지도 못했습니다. 하지만 이제 AI는 카메라로 세상을 보고(눈), 언어로 지시를 이해하고(귀와 뇌), 로봇 팔과 다리로 실제로 움직이는(손발) 존재로 진화하고 있습니다. 이렇게 **물리적 실세계를 인지·판단·행동하며 자율적으로 작동하는 체화(Embodied) AI 기술**을 **피지컬 AI(Physical AI)**라고 부릅니다.

```
[물리 세계]
   ↓ 센서(카메라·LiDAR·IMU)
 인 지 (Perception)  → 3D 공간 인식, 객체·상황 이해
   ↓
 판 단 (Reasoning/Planning) → 행동 계획 수립, VLA 모델
   ↓
 행 동 (Action)  → 액추에이터 제어, 모터·그리퍼 구동
   ↓
[물리 세계 피드백] → 재학습(Sim-to-Real)
```

생성형 AI가 디지털 공간의 문제를 웬만큼 풀어낸 지금, 업계는 "다음 AI 물결"로 물리 세계와의 상호작용에 주목합니다. 인지-판단-행동이 실시간·저지연으로 끊임없이 맞물려 돌아가는 **폐루프(Closed-loop)** 구조가 핵심입니다.

**피지컬 AI를 이루는 5대 기술요소**

| 구분 | 기술요소 | 설명 |
|------|---------|------|
| 인지 | 멀티모달 센서 퓨전 | 카메라·LiDAR·레이더·IMU 데이터 융합, 3D 공간 매핑(SLAM) |
| 판단 | VLA/파운데이션 모델 | 시각·언어 입력을 행동으로 바꾸는 모델(아래 참조) |
| 판단 | World Model | 물리 세계의 인과·동역학을 예측하는 시뮬레이션 모델 |
| 학습 | Sim-to-Real | 가상 시뮬레이터(Isaac Sim 등)에서 대량 학습 후 실환경 전이 |
| 행동 | 로보틱스 제어 | 모션 플래닝, 강화학습 기반 정밀 제어 |

국외는 NVIDIA Isaac(GR00T, Omniverse), Tesla Optimus, Waymo처럼 파운데이션 모델과 시뮬레이션 플랫폼을 주도하고, 국내는 삼성 레인보우로보틱스, 현대차·보스턴다이내믹스, 네이버 클라우드 로봇 플랫폼(ARC) 등 제조·모빌리티 대기업 중심으로 응용이 확산되고 있습니다.

> ⚠️ **Sim-to-Real Gap**
> 시뮬레이터 속에서는 완벽하게 걷던 로봇이 실제 바닥의 미세한 마찰이나 조명 차이 때문에 넘어지는 경우가 흔합니다. 이 "가상과 현실의 간극"을 줄이기 위해 도메인 랜덤화와 실환경 소량 데이터 파인튜닝, 디지털 트윈 검증 파이프라인이 함께 쓰입니다.

---

#### VLA 모델: AI가 눈(Vision) + 말(Language) + 손(Action)을 한 몸에 갖다

피지컬 AI의 '두뇌'에 해당하는 것이 바로 **VLA(Vision-Language-Action) 모델**입니다. 이름 그대로 카메라로 본 것(Vision)과 사람의 말(Language)을 함께 이해해서, 곧바로 로봇의 물리적 동작(Action)으로 번역해내는 통합 파운데이션 모델입니다.

기존 로봇 제어는 "인지 → 계획 → 제어"를 서로 다른 모듈이 따로따로 처리하는 파이프라인 방식이었습니다. VLA는 이를 하나의 모델이 처음부터 끝까지(End-to-End) 담당하도록 통합했습니다.

```
[카메라 이미지] ─┐
                 ├─▶  VLA 모델 (Transformer 기반)  ─▶  [행동 토큰]
[자연어 명령]   ─┘        (VLM 백본 + Action Head)        (관절각/속도 등)
```

* **비유:** 사람이 "저기 빨간 컵 좀 가져다줘"라는 말을 듣고, 눈으로 빨간 컵을 찾은 뒤, 팔을 뻗어 손가락을 오므리는 과정을 하나의 두뇌가 매끄럽게 연결해서 처리하는 것과 같습니다. VLA는 언어모델이 "다음 단어"를 예측하듯, 로봇의 "다음 관절 움직임"을 토큰처럼 예측합니다.

| 구분 | 구성요소 | 설명 |
|------|---------|------|
| 입력 | 멀티모달 인코더 | 이미지·자연어를 공통 임베딩 공간으로 인코딩(ViT+LLM) |
| 중간 | 백본(Backbone) | 사전학습된 대규모 VLM(PaLI-X, PaLM-E 등) 활용 |
| 출력 | 액션 토큰화 | 연속적 로봇 제어값을 이산 토큰으로 변환해 언어모델처럼 예측 |
| 학습 | 로봇 시연 데이터 | 원격조작(Teleoperation), Open X-Embodiment 등 대규모 로봇 데이터셋 |

| 구분 | RT-2 (Google DeepMind) | GR00T (NVIDIA) | OpenVLA (오픈소스) |
|------|------------------------|-----------------|---------------------|
| 특징 | 웹 지식 전이, VQA 결합 학습 | 휴머노이드 특화, 시뮬레이션 연계 | 오픈소스 7B 파라미터 |
| 강점 | 새로운 물체·명령 일반화 | Isaac 플랫폼과 통합 파이프라인 | 접근성, 커스터마이징 용이 |
| 한계 | 폐쇄형, 실시간성 제약 | 특정 하드웨어 종속 | 상용 모델 대비 성능 격차 |

로봇 시연 데이터 부족은 시뮬레이션 합성 데이터나 오픈 데이터셋으로, 실시간 처리 지연은 고수준(VLA)·저수준(경량 컨트롤러)의 계층적 제어 구조로 대응하는 것이 실무의 정석입니다.

---

#### 에이전틱 AI: 자율성이 커질수록 위협도 커진다

VLA가 "몸을 가진 AI"라면, **에이전틱 AI(Agentic AI)**는 "스스로 일하는 AI"입니다. 목표만 던져주면 계획을 세우고, 도구(API, DB, 파일시스템)를 호출하고, 실행하고, 결과를 평가해 다시 계획을 수정하는 것까지 사람 개입 없이 반복합니다.

```
[목표 입력] → 계획(Plan) → 도구 호출(Tool/API) → 실행(Act)
                 ↑                                    │
                 └───── 평가·재계획(Reflect/Loop) ◀────┘
                              (Memory 저장)
```

단순 챗봇형 생성 AI는 질문에 답만 하고 끝나지만, 에이전틱 AI는 실제 **실행 권한**을 갖고 다단계 작업을 처리합니다. 국가정보원이 "AI 보안 가이드북"까지 배포한 이유가 여기 있습니다 — 자율성이 커질수록 사고가 났을 때의 파급력도 커지기 때문입니다.

> 💡 **에이전틱 AI 보안 위협의 3축**
> ```
> [축1: 입력/추론 조작]        [축2: 권한/실행 남용]        [축3: 데이터/신뢰 붕괴]
> • 프롬프트 인젝션            • 과도한 권한 위임            • 메모리/맥락 유출
> • 환각 기반 오작동           • 툴 체이닝 익스플로잇        • 다중 에이전트 오염
> ```
> 마치 문서 속에 몰래 숨겨둔 지시문을 에이전트가 "명령"으로 착각해 실행하거나(프롬프트 인젝션), 여러 도구 호출을 우회적으로 연쇄시켜(툴 체이닝) 민감한 작업까지 벌이는 식입니다. 여기에 파일 삭제나 결제 같은 실제 권한이 얹히면 챗봇 수준의 실수와는 차원이 다른 피해로 번집니다.

**관리적·기술적 보안 대책 (2×2 결합)**

| 구분 | 관리적 대책 | 기술적 대책 |
|------|------------|------------|
| 권한 통제 | 최소권한 원칙(PoLP) 정책 수립 | 도구별 세분화된 권한·스코프 제어(RBAC) |
| 입력 검증 | 프롬프트/도구 사용 가이드라인 제정 | 입력 필터링, 프롬프트 인젝션 탐지 모델 적용 |
| 모니터링 | 실행 이력 감사 체계 구축 | 행동 로깅, 이상행위 탐지 |
| 승인 절차 | 고위험 작업 인간 승인(Human-in-the-loop) | 민감 작업(삭제·결제 등) 자동 승인 게이트 |
| 격리 | 업무별 에이전트 분리 운영 정책 | 샌드박스 실행환경, 네트워크 세그멘테이션 |
| 데이터 보호 | 메모리 보존기간·파기 정책 | 메모리 암호화, PII 마스킹 |

업무 위험도에 따라 완전자동/반자동(승인)/수동 3단계로 자율성 등급을 나누는 거버넌스와, MCP 서버·플러그인 화이트리스트·서명 검증 같은 공급망 관리를 병행하는 것이 최근 흐름입니다.

### 7-2. 최신 AI 기법: 머신 언러닝과 양자 머신러닝

#### 머신 언러닝: "배운 걸 선택적으로 잊어버리기"

사람은 잊고 싶은 기억을 노력해서 지울 수 있지만, AI 모델은 그렇지 않습니다. 한 번 학습한 데이터는 모델의 수억 개 가중치 전체에 안개처럼 흩뿌려져 저장됩니다. 그런데 "내 개인정보를 지워달라"는 요청(GDPR의 잊힐 권리, 개인정보보호법 삭제권)이 들어오면 어떻게 해야 할까요? 원본 데이터 파일만 지운다고 모델이 그 사람을 "잊는" 것은 아닙니다.

이 문제를 푸는 기술이 **머신 언러닝(Machine Unlearning)**입니다. **이미 학습이 끝난 모델에서 특정 데이터의 영향만 효율적으로 제거해, 마치 그 데이터를 처음부터 학습하지 않은 것과 같은 상태로 모델을 되돌리는 기술**입니다.

```
[원본 데이터셋 D] → 학습 → [모델 M]
        │(삭제 요청 데이터 Df 발생)
        ▼
[D - Df]  ──언러닝──▶  [모델 M'] ≈ [D-Df로 처음부터 학습한 모델]
```

가장 확실한 방법은 삭제 대상 데이터를 뺀 나머지로 처음부터 다시 학습시키는 것(Exact Unlearning)이지만, 대규모 모델일수록 재학습 비용이 어마어마합니다. 그래서 다양한 절충 기법이 등장했습니다.

| 구분 | 기법 | 설명 |
|------|------|------|
| 완전 재학습 | Exact Unlearning | 삭제 데이터 제외 후 처음부터 재학습, 정확하지만 고비용 |
| 분할 학습 | SISA (Sharded, Isolated, Sliced, Aggregated) | 데이터를 샤드로 쪼개 서브모델을 학습, 삭제 시 해당 샤드만 재학습 |
| 근사적 삭제 | Gradient/Influence 기반 | 삭제 데이터의 영향함수를 역산해 가중치를 보정 |
| 근사적 삭제 | Fisher Information 기반 | 파라미터 중요도를 활용해 선택적으로 가중치를 스크러빙(문지르듯 제거) |
| 지식 증류 | Teacher-Student Unlearning | 삭제 데이터를 제외한 지식만 학생 모델로 증류 |
| 검증 | Membership Inference 검증 | 언러닝 후 해당 데이터가 실제로 사라졌는지 멤버십 추론 공격으로 재확인 |

> 💡 **비유: 케이크에서 특정 재료만 빼기**
> 이미 구워진 케이크(모델)에서 특정 재료(데이터)의 맛만 빼내는 것은 원래 불가능합니다. Exact Unlearning은 그 재료를 뺀 반죽으로 케이크를 통째로 다시 굽는 방식이고, SISA는 애초에 케이크를 여러 조각으로 나눠 구워서 문제 있는 조각만 다시 구우면 되게 설계해 둔 방식입니다.

완전 재학습은 정확하지만 비싸고, 근사적 기법은 저렴하지만 "정말로 다 지워졌는지" 검증이 어렵다는 트레이드오프가 있습니다. 이 때문에 삭제 완료 여부를 제3자가 검증할 수 있는 인증·감사 체계, 표준 벤치마크 개발이 향후 과제로 꼽힙니다. LLM 시대에는 LoRA 같은 경량 파인튜닝과 프롬프트 레벨 필터링을 결합한 하이브리드 언러닝도 확산되고 있습니다.

#### 양자 머신러닝(QML): 양자컴퓨팅의 힘을 빌린 AI

**양자 머신러닝(QML, Quantum Machine Learning)**은 양자컴퓨팅의 두 가지 특별한 성질 — **중첩(Superposition)**과 **얽힘(Entanglement)** — 을 빌려 머신러닝 연산을 가속하거나, 고전 컴퓨터로는 다루기 힘든 고차원 특징 공간을 탐색하려는 융합 기술입니다.

일반 비트가 0 또는 1 중 하나만 표현하는 반면, 큐비트(qubit)는 0과 1을 동시에 표현하는 중첩 상태를 가질 수 있습니다. 큐비트가 n개 있으면 표현 가능한 공간이 2ⁿ으로 기하급수적으로 커지는데, 이 거대한 특징 공간을 잘 활용하면 특정 계산을 극적으로 빠르게 할 수 있다는 것이 QML의 이론적 기대입니다.

```
[고전 데이터] → 양자 인코딩(Encoding) → [큐비트 상태]
                                            ↓
                              양자 게이트 연산(변분회로)
                                            ↓
                          측정(Measurement) → [고전 출력]
                                            ↓
                    고전 옵티마이저가 파라미터 업데이트 (Hybrid Loop)
```

현재 기술 수준에서는 순수 양자 컴퓨터만으로 학습을 완결하지 못하고, 대부분 **양자-고전 하이브리드** 구조로 구현됩니다. 양자 회로가 일부 연산을 맡고, 결과를 측정해 고전 컴퓨터의 옵티마이저가 파라미터를 갱신하는 식입니다.

| 구분 | 알고리즘/기술 | 설명 |
|------|--------------|------|
| 데이터 인코딩 | 양자 특징 맵 | 고전 데이터를 큐비트 상태로 인코딩, 고차원 힐베르트 공간 활용 |
| 분류 | 양자 서포트벡터머신(QSVM) | 커널트릭을 양자 회로로 계산 |
| 최적화 | 변분양자회로(VQC/VQE) | 파라미터화된 양자회로 + 고전 옵티마이저의 하이브리드 학습 |
| 최적화 | QAOA | 조합 최적화 문제에 특화 |
| 신경망 | 양자 신경망(QNN) | 양자게이트를 뉴런처럼 배열해 학습 가능한 회로 구성 |
| 생성모델 | 양자 GAN(QGAN) | 양자 생성자·판별자로 확률분포 학습 |

**고전 머신러닝 vs QML 한눈에 비교**

| 구분 | 고전 머신러닝 | 양자 머신러닝(QML) |
|------|--------------|---------------------|
| 연산 단위 | 비트(0 또는 1) | 큐비트(0과 1 동시 표현) |
| 특징공간 | 다항식적 확장 | 큐비트 수에 지수적으로 확장(2ⁿ) |
| 하드웨어 | GPU/TPU 등 | 양자 컴퓨터(초전도, 이온트랩 등), 현재 NISQ 수준 |
| 강점 분야 | 범용적, 대규모 데이터 성숙 | 조합 최적화, 고차원 커널 계산 |
| 성숙도 | 상용화 완료 | 연구·PoC 단계 |
| 한계 | 대규모 연산 시 시간·전력 소모 | 큐비트 잡음, 디코히런스, 확장성 제약 |

> ⚠️ 현재는 **NISQ(Noisy Intermediate-Scale Quantum)**라 불리는, 잡음이 많고 규모가 작은 양자컴퓨터 시대입니다. 이론적으로는 조합 최적화나 고차원 커널 계산에서 우위가 기대되지만, 실질적으로 고전 컴퓨터를 압도하는 "양자 우위(Quantum Advantage)"를 입증한 사례는 아직 제한적입니다.

### 7-3. AI 보안: 적대적 공격과 방어

#### "그림에 사람 눈에는 안 보이는 노이즈를 몰래 심어 AI를 속이기"

판다 사진에 사람 눈으로는 전혀 알아챌 수 없는 미세한 노이즈를 살짝 얹으면, AI는 그 사진을 99% 확신으로 "긴팔원숭이"라고 오인식합니다. 이것이 **적대적 머신러닝(Adversarial Machine Learning)**이 보여주는 섬뜩한 현실입니다. AI가 금융·의료·자율주행처럼 사람의 안전과 직결된 영역에 쓰이면서, 모델 자체를 겨냥한 공격이 새로운 보안 위협으로 떠올랐습니다.

```
[학습 데이터] ──▶ 오염공격(Poisoning)
      │
      ▼
   [모델 학습] ──▶ (모델 자산)
      │
      ▼
   [배포/서비스] ──▶ 회피공격(Evasion), 추출공격(Extraction), 전도공격(Inversion)
```

모델의 생명주기(수집 → 학습 → 배포 → 서비스) 전 단계가 공격 표면이 됩니다. 학습 단계는 오염 공격이, 서비스(추론) 단계는 회피·추출·전도 공격이 주로 발생합니다.

**적대적 공격 4유형과 방어기법**

| 공격 유형 | 공격 시점 | 공격 방법 | 방어기법 |
|-----------|----------|-----------|----------|
| 회피 공격 (Evasion) | 추론(서비스) 단계 | 입력에 미세 노이즈를 추가해 오분류 유도(적대적 예제) | 적대적 학습(Adversarial Training), 입력 전처리(Denoising), 그래디언트 마스킹 |
| 오염 공격 (Poisoning) | 학습 단계 | 악성 데이터를 학습셋에 주입해 성능 저하 또는 백도어 삽입 | 데이터 검증·정제(Sanitization), 이상치 탐지, 데이터 출처 검증 |
| 모델 추출 공격 (Extraction) | 추론(API 질의) 단계 | 반복 질의-응답으로 모델의 파라미터·기능을 복제 | 질의 횟수 제한(Rate Limiting), 출력 확률 마스킹, 워터마킹 |
| 모델 전도 공격 (Inversion) | 추론(API 질의) 단계 | 모델 출력을 역산해 학습에 쓰인 원본 데이터·민감정보 추론 | 차등 프라이버시(Differential Privacy), 출력 정보량 제한, 접근 통제 |

> 💡 **비유로 정리하면**
> * **회피 공격**은 얼굴에 특수 화장을 하고 CCTV를 속여 지나가는 것.
> * **오염 공격**은 요리 재료(학습 데이터)에 몰래 이상한 향신료를 섞어 요리(모델) 자체의 맛을 망치는 것.
> * **추출 공격**은 자판기에 수천 번 다른 조합으로 돈을 넣어보며 내부 가격표(모델)를 역산해내는 것.
> * **전도 공격**은 완성된 요리를 맛보고 재료 목록(원본 학습 데이터)을 거꾸로 추리해내는 것입니다.

공격이 노리는 목표를 CIA(기밀성·무결성·가용성) 관점으로 보면, 회피·오염 공격은 **무결성**을, 추출·전도 공격은 **기밀성**을 침해합니다. 대규모 질의를 통한 자원 고갈은 가용성 침해(DoS)로도 이어질 수 있습니다.

실무적으로는 어느 한 가지 방어만으로는 부족합니다. 적대적 학습·입력 검증·이상행위 탐지를 층층이 겹쳐 쌓는 **심층방어(Defense in Depth)**와, 데이터 수집부터 배포까지 전 단계에 보안 게이트를 심는 **MLSecOps**가 표준적인 대응 방향입니다. 최근에는 NIST AI RMF나 ISO/IEC 42001과 연계해 조직의 AI 보안 성숙도를 평가하는 흐름도 커지고 있습니다.

### 7-4. AI 윤리와 거버넌스

#### AI 윤리기준: 3대 원칙과 10대 핵심요건

AI가 사람의 삶에 깊숙이 들어올수록, "이 AI를 만들고 써도 되는가?"에 대한 사회적 합의가 필요해집니다. 과학기술정보통신부는 2020년 12월, AI 개발부터 활용까지 전 과정에서 지켜야 할 최고 가치로 **'인간성(Humanity)'**을 내세우고, 이를 실현할 **3대 기본원칙**과 **10대 핵심요건**을 제시했습니다. 법적 구속력은 없는 자율 규범(Soft Law)이지만, EU의 신뢰할 수 있는 AI 가이드라인·OECD AI 원칙 등 국제 흐름과 궤를 같이합니다.

```
        [최고 가치: 인간성(Humanity)]
                    │
   ┌────────────────┼────────────────┐
 인간 존엄성       사회의 공공선      기술의 합목적성
  원칙              원칙               원칙
   │                 │                 │
   └────────── 10대 핵심요건으로 구체화 ──────┘
```

| 원칙 | 설명 |
|------|------|
| 인간 존엄성 원칙 | 인간의 생명과 존엄을 보호하고, AI는 인간의 삶과 행복을 지원하는 도구로 활용 |
| 사회의 공공선 원칙 | AI가 사회 전체의 공익과 후생 증진에 기여하고, 다양한 계층의 접근성을 보장 |
| 기술의 합목적성 원칙 | AI 개발·활용이 인류 후생 증진이라는 목적에 부합하도록 설계·운영 |

3대 원칙이 상위 지향점이라면, 10대 핵심요건은 이를 실무에서 적용 가능한 행동 기준으로 세분화한 것입니다.

| 핵심 요건 | 설명 |
|-----------|------|
| 인권 보장 | 인간의 존엄성과 자유·평등 등 기본적 인권 보장 |
| 프라이버시 보호 | 개인정보를 안전하게 처리하고 자기결정권 보장 |
| 다양성 존중 | 다양한 집단의 특성을 반영하고 편향·차별 방지 |
| 침해금지 | AI를 인간에게 해를 끼치는 목적으로 활용 금지 |
| 공공성 | 사회 공동체 이익과 공공성 증진에 기여 |
| 연대성 | 다양한 이해관계자 간 협력과 미래세대에 대한 책임 고려 |
| 데이터 관리 | 학습데이터의 편향·품질을 관리하고 적법하게 수집·활용 |
| 책임성 | AI 개발·활용 주체의 책임소재를 명확히 함 |
| 안전성 | 예상 가능한 위험에 대비해 안전을 지속적으로 확보 |
| 투명성 | AI 활용 사실과 의사결정 과정을 확인 가능하도록 공개 |

> ⚠️ **선언만으로는 지켜지지 않습니다**
> 이런 윤리기준은 "우리도 이 원칙을 지킵니다"라고 벽에 액자로 걸어두는 것만으로는 실행력을 갖지 못합니다. AI 윤리위원회 구성, 프로젝트 착수 전 10대 요건 체크리스트 의무화, 고위험(의료·금융) 분야는 강한 요건을 적용하고 저위험 분야는 간소화하는 위험기반 차등 적용이 뒤따라야 합니다.

#### AI 개발·적용 과정의 윤리 이슈와 거버넌스 모형

AI 윤리 이슈는 데이터 수집부터 운영까지 생명주기 전 단계에서 나타납니다.

| 단계 | 윤리 이슈 | 설명 |
|------|----------|------|
| 데이터 수집 | 프라이버시 침해, 저작권 침해 | 동의 없는 개인정보·저작물 무단 수집 |
| 학습 | 편향(Bias) 및 차별 | 편향된 학습데이터로 인한 특정 집단 차별 결과 |
| 설계 | 설명가능성 부족 | 블랙박스 모델로 의사결정 근거 파악 불가 |
| 배포 | 오남용 및 안전성 | 딥페이크, 허위정보 생성 등 악용 가능성 |
| 운영 | 책임소재 불명확 | 사고 발생 시 개발자·운영자·이용자 간 책임 귀속 모호 |
| 사회적 영향 | 일자리 대체, 디지털 격차 | 자동화로 인한 고용 충격, 접근성 불균형 |

이런 이슈를 관리하고 규제하기 위한 틀이 **AI 거버넌스**입니다. 마치 도로 교통 규칙처럼, 규제 강도에 따라 세 단계로 나눌 수 있습니다.

```
[규제 강도]
 낮음 ─────────────────────────▶ 높음
자율규제  →  공동규제  →  정부(경성)규제
(업계 자체)  (민관협력)    (법적 구속력)
```

| 구분 | 자율규제 | 공동규제 | 정부규제 |
|------|---------------------------|--------------------------|-------------------------------|
| 주체 | 기업·업계 자율 | 정부-민간 협력 | 정부 주도 법제화 |
| 특징 | 윤리강령, 자율점검 | 인증제도, 가이드라인+법 | 강행규정, 처벌조항 |
| 장점 | 신속한 대응, 혁신 저해 최소화 | 유연성과 실효성 균형 | 강한 이행력, 형평성 확보 |
| 단점 | 실효성 담보 어려움 | 조율 비용 발생 | 혁신 속도 저해 가능 |
| 사례 | 기업 AI 윤리원칙 선언 | ISO/IEC 42001 인증 체계 | EU AI Act |

의료·채용·사법처럼 위험도가 높은 응용일수록 강한 규제를, 저위험 응용은 자율규제로 대응하는 **위험 기반 계층적 거버넌스**가 국제적 흐름입니다. 실효적인 거버넌스는 다음 다섯 가지가 유기적으로 결합되어야 완성됩니다.

| 구성요소 | 설명 |
|----------|------|
| 조직 체계 | AI 윤리위원회, CAIO(Chief AI Officer) 등 책임 조직 지정 |
| 정책·기준 | 윤리원칙, 개발 가이드라인, 리스크 평가 기준 수립 |
| 프로세스 | 개발단계별 윤리 검토(Ethics by Design), 영향평가 절차 |
| 감사·모니터링 | 배포 후 지속적 성능·편향 모니터링, 외부 감사 |
| 이해관계자 참여 | 시민사회·전문가·이용자 의견 수렴 체계 |

#### ISO/IEC 42001: AI 버전의 ISO 27001

정보보안을 다뤄본 사람이라면 ISO 27001(ISMS)이 익숙할 것입니다. **ISO/IEC 42001**은 그 AI 버전이라 할 수 있습니다. 조직이 AI 시스템을 책임감 있게 개발·제공·활용하기 위해 갖춰야 할 **AI 경영시스템(AIMS)**의 요구사항을 규정한, 세계 최초의 AI 경영시스템 국제표준입니다. 2023년 12월 제정되었고, ISO 9001/27001과 동일한 공통 상위구조(HLS)를 기반으로 합니다.

```
[Plan]  AI 정책 수립, 위험평가       ┐
[Do]    AI 시스템 개발·운영          │  PDCA 순환
[Check] 모니터링, 내부심사           │  (지속적 개선)
[Act]   경영검토, 시정조치           ┘
```

**내용 구성**

| 구분 | 구성요소 | 설명 |
|------|---------|------|
| 본문(HLS) | 조직상황(4)~성과평가(9)~개선(10) | ISO 경영시스템 공통 10개 조항 구조 |
| 리더십 | 최고경영진 책임, AI 정책 | 조직 내 AI 책임 체계와 정책 수립 요구 |
| 기획 | AI 위험 및 기회 평가 | AI 특유 리스크(편향, 투명성 등) 식별·평가 |
| 지원 | 자원, 역량, 인식, 문서화 | AI 인력 역량 확보, 문서화된 정보 관리 |
| 운용 | AI 시스템 생명주기 관리 | 개발·검증·배포·모니터링 전 단계 통제 |
| 부속서(Annex A) | AI 관리목적 및 통제항목 | 데이터 거버넌스, 투명성, 영향평가 등 통제 항목 카탈로그 |
| 부속서(Annex B~D) | 구현 지침, 통제 매핑, 적용 예시 | 실무 적용 가이드 |

ISO 27001의 ISMS 구조와 매우 닮아 있어, 이미 정보보안경영체계를 갖춘 조직이라면 두 인증을 하나의 통합경영시스템(IMS)으로 묶어 구축하기 수월합니다.

**AI 위험평가 vs 위험처리 요건**

| 구분 | AI 위험평가(Risk Assessment) | AI 위험처리(Risk Treatment) |
|------|-----------------------------------|-------------------------------------|
| 대상 식별 | 생명주기 전반의 위험원(데이터·모델·활용) 식별 | 위험별 처리 옵션(회피/경감/전가/수용) 결정 |
| 평가 기준 | 발생가능성 × 영향도, AI 고유 요소(편향·설명가능성·안전성) 반영 | 통제항목(Annex A) 매핑을 통한 구체적 대응조치 수립 |
| 이해관계자 | 개발자·운영자·이용자·영향받는 주체 관점 포함 | 이해관계자별 잔여위험(Residual Risk) 수용 여부 확인 |
| 문서화 | 위험평가 결과서, AI 위험대장(Risk Register) 유지 | 위험처리계획서(RTP) 작성 및 경영진 승인 |
| 주기성 | 정기적 재평가 및 시스템 변경 시 재평가 | 처리조치의 효과성 모니터링 및 지속적 개선 |

일반적인 정보보안 위험관리(ISO 27005)와 가장 다른 점은, 편향·공정성·설명가능성 같은 **AI 고유 속성**을 위험 요소로 명시적으로 다룬다는 것입니다.

#### AI 신뢰성: 정확도 하나로는 부족합니다

AI 모델의 좋고 나쁨을 정확도(Accuracy) 하나로만 판단하던 시절은 지나갔습니다. **AI 신뢰성(Trustworthiness)**은 AI 시스템이 의도한 목적에 맞게 일관되고 안전하게 작동하며, 그 결과와 의사결정 과정을 사람이 이해·검증·통제할 수 있는 **다차원적 속성의 집합**입니다.

```
        [인공지능 신뢰성]
   ┌───────┬───────┬───────┬───────┬───────┐
 강건성   설명가능성  공정성   안전성   프라이버시
(Robust) (Explain)  (Fair)  (Safety) (Privacy)
```

| 속성 | 설명 | 관련 기법/예시 |
|------|------|-----------------|
| 강건성(Robustness) | 노이즈·적대적 입력·환경 변화에도 안정적 성능 유지 | 적대적 학습, 스트레스 테스트 |
| 설명가능성(Explainability) | 모델의 판단 근거를 사람이 이해할 수 있도록 제시 | XAI(SHAP, LIME), 어텐션 시각화 |
| 투명성(Transparency) | AI 활용 사실, 데이터·모델 정보를 공개 | 모델 카드(Model Card), 데이터시트 |
| 공정성(Fairness) | 특정 집단에 대한 편향·차별 없이 공평한 결과 산출 | 편향 탐지·완화 알고리즘, 균형 데이터셋 |
| 안전성(Safety) | 오작동 시에도 인명·재산 피해를 최소화 | 페일세이프 설계, 안전 검증 테스트 |
| 프라이버시(Privacy) | 학습·추론 과정에서 개인정보 보호 | 차등 프라이버시, 연합학습, 머신 언러닝 |
| 책임성(Accountability) | 문제 발생 시 책임 주체와 소재를 명확히 규명 가능 | 감사로그, 거버넌스 체계 |

> 💡 **속성끼리 서로 다투기도 합니다**
> 설명가능성을 높이려고 모델을 단순하게 만들면 정확도가 떨어지고, 프라이버시를 보호하려고 노이즈를 추가하면(차등 프라이버시) 강건성이나 정확도가 흔들립니다. 신뢰성은 이런 트레이드오프를 종합적으로 관리하는 문제입니다.

신뢰성은 설계 단계부터 반영하는 **Trustworthy by Design**, 정량 지표 기반 검증, 배포 후 드리프트 탐지를 포함한 지속 모니터링, 그리고 ISO/IEC 42001 같은 조직 차원의 거버넌스와 연계될 때 비로소 완성됩니다.

### 7-5. 국가 AI 정책: 컴퓨팅 인프라와 영향평가

#### 국가 AI 컴퓨팅센터: 대한민국의 "AI 반도체 곳간"

AI 모델 하나를 제대로 학습시키려면 수천 개의 고성능 GPU가 몇 주씩 쉬지 않고 돌아가야 합니다. 문제는 이 GPU가 전 세계적으로 품귀 현상을 빚고 있고, 소수 글로벌 기업이 공급을 좌우한다는 점입니다. 이런 상황에서 국내 연구기관과 스타트업이 각자 GPU를 구하러 다니는 것은 비효율적입니다.

**국가AI컴퓨팅센터**는 국가 차원의 AI 연구개발·산업 활용을 위해 대규모 GPU/AI 반도체 클러스터와 데이터센터 인프라를 정부와 민간이 공동으로 투자해 구축·운영하는 국책 인프라입니다. 특정 국가나 기업에 종속되지 않는 자체 AI 역량, 즉 **Sovereign AI(자국 AI 주권)** 확보가 궁극적인 목표입니다.

```
[정부]  재정 지원, 정책·인허가       ┐
                                     ├──▶  국가AI컴퓨팅센터
[민간기업]  GPU 조달, 운영 투자      ┘        (공동 소유·운영)
```

| 추진배경 | 설명 |
|----------|------|
| GPU 자원 부족 | 국내 기업·연구기관의 고성능 GPU 확보 경쟁 심화, 해외 의존도 심화 |
| AI 주권 확보 | 특정 국가·기업에 종속되지 않는 자체 AI 인프라·모델 개발 역량 필요 |
| 민간 투자 유치 | 정부 단독 재정투자의 한계를 민관합작(PPP)으로 보완 |
| 산업 파급효과 | 스타트업·중소기업의 컴퓨팅 자원 접근성 제고를 통한 AI 생태계 활성화 |

**기술적 구성요소** — 단순히 GPU만 잔뜩 쌓아놓는다고 되는 것이 아닙니다.

| 구분 | 구성요소 | 설명 |
|------|---------|------|
| 컴퓨팅 | GPU/AI 반도체 클러스터 | 대규모 GPU 팜(H100/B200급 등), NPU 등 국산 AI 반도체 병행 |
| 네트워크 | 고속 인터커넥트 | InfiniBand/NVLink 등 노드 간 초저지연 통신망 |
| 스토리지 | 고성능 분산 스토리지 | 대용량 학습데이터 처리를 위한 병렬 파일시스템 |
| 전력·냉각 | 데이터센터 인프라 | 고밀도 전력 공급, 액체냉각 등 고효율 냉각 시스템 |
| 소프트웨어 | 클러스터 오케스트레이션 | Kubernetes, Slurm 등 대규모 작업 스케줄링·자원관리 |
| 보안 | 격리·접근통제 | 연구기관·기업별 워크로드 격리, 국가 보안등급별 망 분리 |

이렇게 큰 인프라를 지속 가능하게 운영하려면 관리적 고려사항도 함께 챙겨야 합니다.

| 구분 | 고려사항 |
|------|----------|
| 자원 배분 | 연구기관·스타트업·대기업 간 GPU 사용 우선순위·과금 체계 수립 |
| 운영 거버넌스 | 정부-민간 공동운영위원회 등 의사결정 체계와 책임소재 명확화 |
| 지속가능성 | 전력 소비 증가에 따른 에너지 수급 계획, 탄소중립 대응 |
| 보안·안보 | 국가 안보 관련 워크로드와 민간 워크로드 분리, 데이터 주권 보호 |
| 투자 회수 | 민간 투자자의 수익모델(사용료·서비스 판매) 설계 |
| 지역 균형 | 데이터센터 입지에 따른 지역경제 파급효과, 전력망 인프라 연계 |

> ⚠️ 민관 역할 분담이 불명확하면 갈등이 생깁니다. 특수목적법인(SPC)을 세워 지분과 운영 권한을 계약으로 명확히 정리하는 방식이 실무적으로 활용됩니다.

#### AI 영향평가: 배포 전에 미리 부작용을 점검하는 절차

개인정보를 다루는 시스템을 만들 때 "개인정보 영향평가(PIA)"를 먼저 하듯이, AI 시스템도 배포 전에 미리 위험을 점검하자는 것이 **AI 영향평가**입니다. AI 시스템의 개발·도입 전 또는 운영 중 발생할 수 있는 인권·안전·편향·사회적 부작용 등의 위험을 사전에 식별·평가하고 완화 방안을 마련하는 절차적 평가 제도로, 의료·채용·신용평가·공공행정 같은 **고위험 AI**를 주요 대상으로 합니다.

```
[AI 시스템 기획/도입] ──▶ 영향평가 대상 여부 판단
          │
          ▼
   [영향평가 수행] ──▶ 위험식별 → 평가 → 완화방안 → 보고서
          │
          ▼
   [운영·모니터링] ──▶ 주기적 재평가
```

| 목적 | 설명 |
|------|------|
| 위험 사전예방 | 배포 이후가 아닌 기획·개발 단계에서 부작용 선제 차단 |
| 신뢰성 확보 | 이용자·사회에 대한 AI 서비스의 신뢰 기반 마련 |
| 규제 순응 | AI 기본법 등 관련 법령상 의무 이행 수단 |
| 책임성 강화 | 평가 결과 문서화를 통한 사업자 책임 소재 명확화 |

개인정보 영향평가(PIA)의 "사전예방" 아이디어를 AI 전반으로 확장한 것이며, 평가 대상이 개인정보를 넘어 인권·안전·사회적 영향 전반으로 넓어진 것이 PIA와의 차이점입니다.

**7단계 수행 절차**

| 단계 | 주요 활동 | 고려사항 |
|------|----------|----------|
| 1. 대상 판별(Screening) | AI 시스템의 위험등급 분류 | 고위험 분야 해당 여부, 이용자 규모, 자동화된 의사결정 여부 |
| 2. 사전 준비 | 평가팀 구성, 자료 수집 | 개발·법무·윤리 전문가 등 다분야 참여, 시스템 설계문서 확보 |
| 3. 위험 식별 | 잠재적 부작용 목록화 | 편향·차별, 프라이버시 침해, 안전사고, 설명가능성 부족 등 |
| 4. 위험 분석·평가 | 발생가능성·심각도 산정 | 영향받는 이해관계자 범위, 취약계층에 대한 차등적 영향 |
| 5. 완화방안 수립 | 위험 저감 대책 마련 | 데이터 보정, 인간 검토 절차(Human-in-the-loop) 삽입 등 |
| 6. 보고 및 공개 | 평가결과 문서화 | 결과보고서 작성, 필요시 이용자·감독기관 공개 |
| 7. 사후 모니터링 | 운영 중 재평가 | 성능·편향 지표 추적, 중대 변경 시 재평가 트리거 |

평가 결과는 문서 캐비닛에 그냥 묻히면 의미가 없습니다. 고위험 AI의 배포 승인 조건, 신뢰 인증 마크 부여, 감독기관 보고, 이용자에 대한 정보 제공 등 **실질적인 규제 수단**으로 연계되어야 제도가 살아 움직입니다.

> 💡 최근 AI 기본법 시행과 맞물려, 고위험 AI 대상 영향평가 의무화와 위험등급별 차등 적용이 확대되는 추세입니다. 평가가 서류상 형식에 그치지 않으려면 평가 결과를 개발 백로그와 연계한 이행관리 체계, 표준 템플릿과 자동화 도구 지원이 함께 필요합니다.
