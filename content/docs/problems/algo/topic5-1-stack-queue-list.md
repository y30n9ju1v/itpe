## 문제

선형 자료 구조인 스택, 큐, 리스트의 자료 입출력 원리를 설명하시오.

## 모범답안

1. 선형 자료구조 개요

    정 의  • 데이터 원소들이 순차적(1:1 관계)으로 나열되는 자료구조의 총칭
           - 스택/큐는 삽입삭제 위치가 제한된 제약형, 리스트는 임의 위치 접근이
             가능한 범용 선형구조

    ```
    [선형 자료구조]
       │
       ├─ 스택(Stack)  : 한쪽 끝(Top)에서만 삽입/삭제 → LIFO
       ├─ 큐(Queue)    : Rear 삽입, Front 삭제 → FIFO
       └─ 리스트(List) : 임의 위치 삽입/삭제 가능(배열형/연결형)
    ```

    - 함수 호출 스택, 메시지 큐, LRU 캐시 등 실무 시스템 설계 전반의 근간.

2. 자료구조별 입출력 원리

    1) 스택/큐 동작 트레이스

    ```
    스택: Push(A)→Push(B)→Push(C)→Pop()→Pop()
          Top: A→A,B→A,B,C→A,B→A , Pop() 결과: C,B (LIFO)

    큐  : Enqueue(A)→Enqueue(B)→Enqueue(C)→Dequeue()→Dequeue()
          Front→Rear: A→A,B→A,B,C→B,C→C , Dequeue() 결과: A,B (FIFO)
    ```

    2) 자료구조별 입출력 원리 비교

    | 구분 | 스택 | 큐 | 리스트 |
    |------|------|-----|--------|
    | 입출력 원리 | LIFO | FIFO | 임의 위치(순서 무관) |
    | 삽입/삭제 | Push/Pop(Top) | Enqueue(Rear)/Dequeue(Front) | Insert/Delete(임의 위치) |
    | 접근 지점 | 1곳(Top) | 2곳(Front,Rear) | 전체(순차/포인터 탐색) |
    | 대표 활용 | 호출 스택, Undo | 스케줄링, 메시지 큐, BFS | LRU 캐시, 텍스트 편집기 |

    - 리스트는 배열 기반(인덱스 O(1) 접근, 중간 삽입 O(n))과 연결형(포인터 재연결 O(1), 탐색 O(n))으로 구현.

3. 배열 구현 vs 연결리스트 구현 비교

    | 구분 | 배열 기반 | 연결리스트 기반 |
    |------|-----------|------------------|
    | 메모리 할당 | 정적(고정 크기) | 동적(노드 단위) |
    | 접근 속도 | O(1) 임의 접근 | O(n) 순차 접근 |
    | 삽입/삭제 | 중간 위치 시 이동 필요 O(n) | 포인터 재연결 O(1) |
    | 캐시 효율 | 연속 메모리로 적중률 높음 | 분산 메모리로 적중률 낮음 |

    - 조회 위주 워크로드는 배열, 삽입/삭제 위주 워크로드는 연결리스트가 유리.

4. 실무 적용 시 고려사항

    | 이슈 | 대응방안 |
    |------|----------|
    | 재귀 깊이 과다로 StackOverflow 발생 | 반복문+명시적 스택 전환, 꼬리 재귀 최적화 활용 |
    | 분산 메시지 큐 확장 시 FIFO 순서 보장 붕괴 | 동일 파티션 키 라우팅으로 순서 유지 |
    | 워크로드 패턴 무시한 리스트 구현 선택 | 조회/삽입 패턴 분석 후 ArrayList·LinkedList 선택 |

    - 최근 분산 메시징(Kafka 등) 기반 비동기 아키텍처에서 자료구조 특성 기반 설계 중요성 증대 예상.  "끝"
