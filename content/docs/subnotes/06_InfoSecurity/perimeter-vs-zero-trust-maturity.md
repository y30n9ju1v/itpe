# 경계 기반 보안 vs 제로 트러스트 성숙도 모델 2.0 (CISA) 서브노트

> **두음 머리에 박기 🧠**
> - **ID·디·네·앱·데** (CISA ZT 성숙도모델 5대 기둥: **ID**(신원), **디**바이스, **네**트워크, **앱**플리케이션·워크로드, **데**이터)
> - **전·초·고·최** (ZT 성숙도 4단계: **전**통(경계기반) → **초**기(ZT일부도입) → **고**급(전사ZT정책) → **최**적(완전자동화 AI기반))
> - **모·위·세·동·모2** (NIST SP 800-207 제로트러스트 5대 원칙: **모**든자원간주, **위**치무관보호, **세**션단위허가, **동**적정책결정, **모2**니터링(무결성상태))

| **토픽명** | **경계 기반 보안(Perimeter Security)과 제로 트러스트 성숙도 모델 2.0 (CISA, 2023)** |
| **정의** | 내부·외부를 물리적 경계로 구분해 내부 전면신뢰하는 **경계 기반 보안**의 한계 극복 → "절대신뢰 금지·항상검증" 제로트러스트 원칙 단계적 정착시키는 CISA **5개 기둥(ID·디·네·앱·데) × 4단계 성숙도(전·초·고·최)** 평가모델 |
| **키워드** | Perimeter Security, CISA Maturity Model 2.0, 5 Pillars, Micro-segmentation, IAM/SASE, UEBA/XDR |
| **개념도** | **[ ZT 성숙도 4단계 진화 경로 (5개 기둥 각각에 적용) ]**<br>`[ 1.전통(Traditional) ] 경계기반·수동운영`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 2.초기(Initial) ] ZT 일부도입·사용자접근제어 시작 ▼`<br>`[ 3.고급(Advanced) ] 전사 ZT정책·자동화탐지 ▼`<br>`[ 4.최적(Optimal) ] 완전자동화·AI기반 동적정책`<br>&nbsp;&nbsp;`(ID/디바이스/네트워크/앱워크로드/데이터 5개 기둥 각각 독립적으로 단계 평가)` |
| **구성요소** | 1. **경계 기반 보안의 구조적 한계**: 내부망 진입 시 전면신뢰 → 동-서(East-West) 트래픽 자유통신 허용 → 측면이동으로 전사 피해확산<br>2. **NIST SP 800-207 5대 원칙**: 모든 데이터·서비스 리소스 간주, 위치무관 통신보호, 세션단위 접근허가, 클라이언트ID·상태기반 동적정책, 자산무결성 지속 모니터링<br>3. **CISA 5개 기둥**: ID(강력한 MFA), 디바이스(컴플라이언스 지속검증), 네트워크(마이크로세분화), 앱·워크로드(앱별 접근제어), 데이터(분류·암호화·DLP)<br>4. **4단계 성숙도**: 전통(경계기반·수동) → 초기(ZT 일부·사용자 접근제어) → 고급(전사 ZT정책·자동화탐지) → 최적(완전자동화·AI 동적정책) |
| **비교** | **경계 기반 보안**<br>- 인증시점: 경계 진입 시 1회 인증<br>- 클라우드 적합성: 낮음(고정 물리경계 전제) — 원격근무·SaaS 확산 시 무력화<br><br>**제로 트러스트 (최적 단계)**<br>- 인증시점: 매 세션·리소스 접근마다 재검증<br>- 클라우드 적합성: 높음(위치독립적 검증) — 마이크로세분화로 내부 측면이동까지 차단 |
| **차별화** | **CISA 성숙도 모델 기반 단계적 ZT 전환 로드맵**<br>1. **기둥별 비대칭 성숙도 관리**: 5개 기둥 동시 최적화 어려움 → ID(MFA)·디바이스(컴플라이언스검증) 등 고ROI 기둥 우선 고급단계, 데이터·앱워크로드는 후속 배치<br>2. **IAM 강화 + SASE 결합**: RBAC·MFA를 전사 IAM에 통합 + SASE(보안+네트워크 통합 클라우드) 도입 → 마이크로세분화를 소프트웨어적으로 구현, 초기→고급 전환 가속<br>3. **SIEM/UEBA/XDR 연동으로 최적단계 자동화**: 전사 로그 SIEM·UEBA·XDR 통합분석 → 이상징후 시 정책엔진(PE)이 실시간 접근권한 자동조정하는 폐루프 체계 구축 |
