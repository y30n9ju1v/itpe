# 전자봉투(Digital Envelope) 및 이중서명(Dual Signature) 서브노트

> **두음 머리에 박기 🧠**
> - **세·대·봉** (전자봉투 생성 3단계: **세**션키 랜덤 생성, **대**칭키로 평문 암호화, 수신자 공개키로 세션키 암호화해 **봉**투 완성)
> - **주·결·연·서** (이중서명 생성 절차: **주**문정보 해시, **결**제정보 해시, 두 해시 **연**결 후 재해시, 고객 개인키로 **서**명)
> - **상·은** (이중서명으로 정보를 분리 열람하는 두 주체: **상**점은 주문정보만, **은**행은 결제정보만 확인)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **전자봉투(Digital Envelope)와 이중서명(Dual Signature)** |
| **정의** | 대칭키 속도 + 비대칭키 키배송 안전성 결합 → 세션키를 수신자 공개키로 암호화·전달하는 하이브리드 암호기법 **전자봉투** + SET 프로토콜에서 주문·결제정보를 하나의 서명으로 연결 → 상점·은행 각자 필요정보만 검증하는 **이중서명** |
| **키워드** | 하이브리드 암호화, 세션키, 공개키 암호화, SET, 이중서명(DS), POMD, 프라이버시 보호, 부인방지 |
| **개념도** | **[ 전자봉투 생성/개봉 ]**<br>`송신자: 평문(M) → ①세션키(K) 생성 → ②K로 M 대칭키 암호화 → 암호문(C)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`└──➔ ③수신자 공개키(PUB_B)로 K 암호화 → 봉투(E)`<br>`전송: C + E ──➔ 수신자`<br>`수신자: E를 개인키(PRV_B)로 복호화 → K, K로 C 복호화 → M`<br><br>**[ 이중서명 생성/검증 ]**<br>`고객: H(OI)=OIMD, H(PI)=PIMD → POMD=H(OIMD‖PIMD) → DS=E(POMD, 고객개인키)`<br>`상점 수신(OI+PIMD+DS): H(OI)→OIMD', H(OIMD'‖PIMD)→POMD', D(DS,공개키)→POMD, 일치 시 유효`<br>`은행 수신(PI+OIMD+DS): H(PI)→PIMD', H(OIMD‖PIMD')→POMD', D(DS,공개키)→POMD, 일치 시 유효` |
| **구성요소** | 1. **세션키(Session Key)**: 매 통신마다 임의생성 대칭키 → 대용량 평문 암호화<br>2. **봉투(Envelope, E)**: 세션키를 수신자 공개키로 암호화한 값 → 수신자 개인키로만 개봉<br>3. **주문정보(OI)**: 상점이 확인해야 할 구매상품·수량 정보<br>4. **결제정보(PI)**: 은행이 확인해야 할 카드·결제금액 정보<br>5. **POMD**: 주문정보해시(OIMD)+결제정보해시(PIMD) 연결(concatenate) 후 재해시한 연결 다이제스트<br>6. **이중서명(DS)**: POMD를 고객 개인키로 암호화 → 상점·은행 각자 절반정보+상대측 다이제스트 조합으로 동일서명 검증 |
| **비교** | **전자봉투(Digital Envelope)**<br>- 목적: 대칭키 속도문제(비대칭 연산과부하) + 비대칭키 키배송문제 동시해결<br>- 적용: S/MIME, PGP, TLS 핸드셰이크 세션키 전달<br><br>**이중서명(Dual Signature)**<br>- 목적: 전자상거래에서 상점엔 결제정보 비노출, 은행엔 주문정보 비노출 → 두 정보 연결 무결성 보장<br>- 적용: SET 프로토콜 핵심 서명기법 |
| **차별화** | **전자상거래 보안 아키텍처 적용 전략**<br>1. **전자봉투 기반 이메일/통신 보안 강화**: S/MIME 적용 시 전자봉투로 본문·첨부파일 암호화 + 디지털서명 병행 → 발신자 인증 동시제공<br>2. **이중서명 원리의 현대적 응용(토큰화)**: SET은 비주류화, "정보분리 검증" 철학은 PG가 카드정보 관리·상점은 거래토큰만 수신하는 토큰화(Tokenization)로 계승 → 데이터 최소화 원칙 실현<br>3. **연결 다이제스트(POMD) 설계 시사점**: 다자간 트랜잭션(공급망 다단계 계약 등)에서 부분정보 검증+전체 무결성 보장 → 해시연결·분리검증 패턴 응용 가능 |
