# 해시 자료구조 — 해시함수 종류 및 충돌·오버플로우 해결기법 서브노트

> **두음 머리에 박기 🧠**
> - **나·제·폴·문** (자료구조 관점 해시 함수 4종: **나**머지연산법, **제**곱연산법, **폴**딩법, **문**자열해싱)
> - **체·개** (해시 충돌 해결 2대 방법론: **체**이닝(개방 해싱), **개**방 주소법(폐쇄 해싱))
> - **선·이·이** (개방 주소법/오버플로우 탐사 3기법, 클러스터링이 줄어드는 순서: **선**형 조사, **이**차 조사, **이**중 해싱)
> - **정·동·확·선** (해싱 유형 4종: **정**적 해싱, **동**적 해싱, **확**장 가능 해싱, **선**형 해싱)

| **토픽명** | **해시 자료구조(Hashing) — 해시함수 종류 및 충돌(Collision)·오버플로우(Overflow) 해결기법** |
| **정의** | 탐색키를 해시함수로 변환 → 해시테이블 버킷주소에 O(1) 저장·검색하는 자료구조 기법, 동일버킷 충돌 및 슬롯포화 **오버플로우**를 체이닝·개방주소법 등으로 해결 |
| **키워드** | 해시함수(나머지/제곱/폴딩법), 버킷/슬롯/동거자, 체이닝, 개방주소법, 선형·이차·이중 탐사, 오버플로우 영역, 로드팩터 |
| **개념도** | **[ 해시 충돌 해결 2대 방법 ]**<br>`체이닝: 버킷0 → [key1]→[key5]→null   버킷1 → [key2]→null   버킷2 → [key3]→[key6]→null`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(각 버킷을 연결리스트로 확장)`<br>`개방주소법: h(k) 충돌 시 ──➔ 선형조사 h(k)+1,+2… ──➔ 이차조사 h(k)+1²,+2² ──➔ 이중해싱(2번째 해시함수로 간격 결정)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(빈 버킷을 테이블 내에서 직접 탐사, 클러스터링 점차 감소)` |
| **구성요소** | 1. 해시함수(자료구조 관점): 나머지연산법 h(k)=k mod m(m 소수 시 분산 우수), 제곱연산법(k² 중간비트 추출), 폴딩법(분할 XOR/덧셈, 긴키 적합), 문자열해싱(Horner's Method 등 다항식)<br>2. 해시테이블 구성요소: 해시테이블(버킷집합), 버킷(레코드 저장단위), 슬롯(버킷 내 저장공간), 동거자(Synonyms, 동일버킷 공유 키집합)<br>3. 체이닝(개방해싱): 버킷을 연결리스트로 구성, 충돌 시 노드추가 → 버킷수 초과 저장 가능하나 포인터 오버헤드·캐시미스 발생<br>4. 개방주소법(폐쇄해싱): 선형조사(순차탐색, 클러스터링 심함) → 이차조사(i²,2i² 간격, 1차클러스터링 완화) → 이중해싱(2차 해시함수로 간격결정, 분산 최대)<br>5. 오버플로우 해결기법: 오버플로우영역(별도예약구역, DB파일구조 활용), 버킷분할(동적해싱에서 오버플로우 시 재배치)<br>6. 해싱 유형: 정적해싱(크기고정, 확장 시 전체재해싱), 동적해싱(증가에 따라 확장), 확장가능해싱(디렉터리+버킷분할, DB인덱스), 선형해싱(디렉터리 없이 순차 버킷분할, 분산DB) |
| **비교** | **자료구조 관점 해시충돌 해결**<br>- 목적: 탐색성능 O(1) 유지, 저장공간 효율 확보<br>- 기법: 체이닝·개방주소법(선형/이차/이중탐사)·오버플로우영역·버킷분할<br><br>**보안(암호학적) 관점 해시충돌**<br>- 목적: 서로 다른 입력의 동일 해시값 방지 → 충돌저항성 확보<br>- 기법: SHA-256/SHA-3 등 검증된 알고리즘 채택, MD5·SHA-1(충돌취약)은 폐기 |
| **차별화** | **고성능 해시 테이블 설계 실무 전략**<br>1. 로드팩터 관리: 클러스터링 심화 시 O(1)→O(n) 저하 → 로드팩터 0.7 이하 유지, 초과 시 자동 리해싱(Java HashMap)<br>2. 탐사기법 선택: 구현단순성 우선 시 선형조사, 클러스터링 최소화 우선 시 이중해싱 채택<br>3. 분산캐시(Redis) 핫스팟 대응: Redis Cluster 16384개 해시슬롯 노드별 균등분배 + 핫키에 랜덤접미사 붙여 다중슬롯 분산하는 키 해시태그 전략<br>4. DB 인덱스 구조 선택: 등치검색 위주는 해시인덱스(확장가능/선형해싱)로 O(1) 조회, 범위검색 필요 시 B-Tree 인덱스 |
