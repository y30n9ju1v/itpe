# 해시 자료구조 — 해시함수 종류 및 충돌·오버플로우 해결기법 서브노트

> **두음 머리에 박기 🧠**
> - **나·제·폴·문** (자료구조 관점 해시 함수 4종: **나**머지연산법, **제**곱연산법, **폴**딩법, **문**자열해싱)
> - **체·개** (해시 충돌 해결 2대 방법론: **체**이닝(개방 해싱), **개**방 주소법(폐쇄 해싱))
> - **선·이·이** (개방 주소법/오버플로우 탐사 3기법, 클러스터링이 줄어드는 순서: **선**형 조사, **이**차 조사, **이**중 해싱)
> - **정·동·확·선** (해싱 유형 4종: **정**적 해싱, **동**적 해싱, **확**장 가능 해싱, **선**형 해싱)

| 항목 | 내용 |

| **토픽명** | **해시 자료구조(Hashing) — 해시함수 종류 및 충돌(Collision)·오버플로우(Overflow) 해결기법** |
| **정의** | 탐색키를 해시 함수로 변환하여 해시 테이블의 버킷 주소에 O(1)로 저장·검색하는 자료구조 기법으로, 서로 다른 키가 동일 버킷을 가리키는 **충돌**과 버킷 슬롯이 가득 차는 **오버플로우**를 체이닝·개방주소법 등으로 해결 |
| **키워드** | 해시함수(나머지/제곱/폴딩법), 버킷/슬롯/동거자, 체이닝, 개방주소법, 선형·이차·이중 탐사, 오버플로우 영역, 로드팩터 |
| **개념도** | **[ 해시 충돌 해결 2대 방법 ]**<br>`체이닝: 버킷0 → [key1]→[key5]→null   버킷1 → [key2]→null   버킷2 → [key3]→[key6]→null`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(각 버킷을 연결리스트로 확장)`<br>`개방주소법: h(k) 충돌 시 ──➔ 선형조사 h(k)+1,+2… ──➔ 이차조사 h(k)+1²,+2² ──➔ 이중해싱(2번째 해시함수로 간격 결정)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(빈 버킷을 테이블 내에서 직접 탐사, 클러스터링 점차 감소)` |
| **구성요소** | 1. **해시 함수(자료구조 관점)**: 나머지연산법 h(k)=k mod m(m을 소수로 설정 시 분산 우수), 제곱연산법(k²의 중간 비트 추출), 폴딩법(키를 분할해 XOR/덧셈, 긴 키에 적합), 문자열 해싱(Horner's Method 등 다항식 기반)<br>2. **해시 테이블 구성요소**: 해시 테이블(버킷 집합), 버킷(레코드 저장 단위), 슬롯(버킷 내 저장 공간), 동거자(Synonyms, 동일 버킷 주소 공유 키 집합)<br>3. **체이닝(Chaining, 개방 해싱)**: 버킷을 연결 리스트로 구성해 충돌 시 노드 추가 — 버킷 수보다 많은 데이터 저장 가능하나 포인터 오버헤드·캐시 미스 발생<br>4. **개방 주소법(Open Addressing, 폐쇄 해싱)**: 선형 조사(다음 버킷 순차 탐색, 클러스터링 심함) → 이차 조사(i², 2i² 간격, 1차 클러스터링 완화) → 이중 해싱(2번째 해시함수로 탐사 간격 결정, 분산 최대)<br>5. **오버플로우(Overflow) 해결 기법**: 오버플로우 영역(별도 예약 구역, DB 파일 구조에 활용), 버킷 분할(Bucket Splitting, 동적 해싱에서 오버플로우 시 버킷 분할·재배치)<br>6. **해싱 유형**: 정적 해싱(테이블 크기 고정, 확장 시 전체 재해싱), 동적 해싱(데이터 증가에 따라 크기 확장), 확장 가능 해싱(디렉터리+버킷 분할, DB 인덱스), 선형 해싱(디렉터리 없이 순서대로 버킷 분할, 분산 DB) |
| **비교** | **자료구조 관점 해시 충돌 해결**<br>- **목적**: 탐색 성능 O(1) 유지, 저장 공간 효율 확보<br>- **기법**: 체이닝·개방주소법(선형/이차/이중 탐사)·오버플로우 영역·버킷 분할<br><br>**보안(암호학적) 관점 해시 충돌**<br>- **목적**: 서로 다른 입력이 동일 해시값을 갖지 못하도록 하는 충돌 저항성(Collision Resistance) 확보<br>- **기법**: SHA-256/SHA-3 등 충돌 저항성이 검증된 알고리즘 채택, MD5·SHA-1(충돌 취약)은 폐기 |
| **차별화** | **고성능 해시 테이블 설계 실무 전략**<br>1. **로드 팩터(Load Factor) 관리**: 클러스터링이 심화되면 탐색 성능이 O(1)에서 O(n)으로 저하되므로 로드 팩터를 0.7 이하로 유지하고, 초과 시 자바 HashMap처럼 자동 리해싱(Rehashing)을 구현.<br>2. **탐사 기법 선택 기준**: 구현 단순성이 중요하면 선형 조사, 클러스터링 최소화가 중요하면 이중 해싱을 우선 채택.<br>3. **분산 캐시(Redis) 핫스팟 대응**: Redis Cluster의 16384개 해시 슬롯을 노드별로 균등 분배하고, 특정 키에 트래픽이 몰리는 핫 키(Hot Key)에는 랜덤 접미사를 붙여 여러 슬롯으로 분산하는 키 해시태그 전략을 적용.<br>4. **DB 인덱스 구조 선택**: 등치(Equality) 검색 위주 워크로드는 해시 인덱스(확장 가능/선형 해싱)로 O(1) 조회를, 범위 검색이 필요하면 B-Tree 인덱스를 사용하는 방식으로 구분 적용. |
