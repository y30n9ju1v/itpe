# 개인정보 보호 거버넌스 — PbD·ISO 29100/27701·PIA 서브노트

> **두음 머리에 박기 🧠**
> - **예·기·설·완·전·가·사** (PbD 7대 원칙: **예**방적·사전적, **기**본값으로서의 프라이버시, **설**계에 내재화, **완**전한 기능, **전** 수명주기 보호, **가**시성·투명성, **사**용자 중심)
> - **최·분·추·숨·알·통·집·시** (PbD 8대 전략: **최**소화 Minimise, **분**리 Separate, **추**상화 Abstract, **숨**기기 Hide, **알**리기 Inform, **통**제 Control, **집**행 Enforce, **시**연 Demonstrate)
> - **사·영·검·제·이·기** (PIA 평가 절차 6단계: **사**전준비 → **영**향평가 수행 → **검**토 → **제**출 → **이**행확인 → **기**록유지)

| **토픽명** | **PbD(Privacy by Design)·ISO/IEC 29100·27701·PIA(개인정보 영향평가) 개인정보 보호 거버넌스** |
| **정의** | 시스템 설계 단계부터 프라이버시를 내재화하는 방법론 **PbD**(7대 원칙·8대 전략), 개인식별정보(PII) 처리를 위한 국제 프라이버시 프레임워크 **ISO/IEC 29100**(11대 원칙)과 이를 ISO 27001 위에 인증 체계로 구현한 **ISO/IEC 27701**(PIMS), 그리고 정보시스템 구축·변경 시 개인정보 침해 위험을 사전 평가하는 **PIA(개인정보 영향평가)**와 신규 서비스 출시 전 적법성·안전성을 검토받는 **개인정보 사전적정성 검토제**를 설계·표준·평가 관점에서 통합한 개인정보 보호 거버넌스 체계 |
| **키워드** | GDPR 제25조·제35조, 개인정보보호법 제3조·제8조의2·제33조, PIMS, ISO/IEC 29134, DPIA |
| **개념도** | **[ 개인정보 보호 거버넌스 3층 구조 ]**<br>`① 설계 원칙: [ PbD 7대 원칙 + 8대 전략 ] ── 시스템 아키텍처에 프라이버시 내재화`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`② 표준·인증: [ ISO/IEC 29100(11대 원칙, 프레임워크) ] → [ ISO/IEC 27701(PIMS, 인증) ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`③ 사전 평가: [ PIA(구축·변경 시) ] ↔ [ 사전적정성 검토(신규 서비스 출시 전) ] ── GDPR DPIA와 대응` |
| **구성요소** | 1. **PbD 7대 원칙**: 사전적·예방적, 기본값으로서의 프라이버시, 설계에 내재화, 완전한 기능(보안 AND 프라이버시), 전 수명주기 보호, 가시성·투명성, 사용자 중심<br>2. **PbD 8대 전략**: (데이터 지향) 최소화·분리·추상화·숨기기, (프로세스 지향) 알리기·통제·집행·시연 — 개인정보보호법 제3조 각 항과 매핑<br>3. **ISO/IEC 29100 11대 원칙**: 동의 및 선택, 목적 적법성 및 명확화, 수집 제한, 데이터 최소화, 이용·유지·공개 제한, 정확성 및 품질, 공개·투명성·통지, 개인 참여 및 접근, 책임성, 정보 보안, 프라이버시 준수<br>4. **ISO/IEC 27701(PIMS)**: ISO 27001 요구사항에 PII 처리자·수탁자 요구사항을 추가한 인증 표준, Annex D로 GDPR 직접 매핑, 갭분석→PIMS구축→내부심사→인증기관심사(Stage1/2)→인증서 발급(3년 유효) 절차<br>5. **PIA**: 개인정보보호법 제33조 근거, 공공기관 5만 명(민감·고유식별정보 포함 시 50만 명) 이상 처리 시스템 신규구축·변경 시 의무, 사전준비→영향평가수행→결과검토→위원회제출→개선이행→기록유지(5년 이상 보관)의 6단계, ISO/IEC 29134(준비·수행·보고 3단계)와 대응<br>6. **개인정보 사전적정성 검토제**: 개인정보보호법 제8조의2 근거(2023년 개정, 2024년 3월 고시 제정), 신규 서비스·기술 도입 전 개인정보보호위원회에 적법성·안전성 검토 신청 → 60일 이내 적정/부적정/조건부 적정 의견 통보, GDPR DPIA와 유사한 사전예방형 제도로서 PIA(구축·변경 대상)와 상호 보완 |
| **비교** | **PIA (개인정보 영향평가)**<br>- **적용 시점/근거**: 정보시스템 구축·변경 시 · 개인정보보호법 제33조<br>- **대상/성격**: 공공기관(5만/50만 명 기준), 법적 의무 · 시스템 관점 위험 평가, 결과 위원회 제출 의무<br><br>**개인정보 사전적정성 검토제**<br>- **적용 시점/근거**: 신규 서비스·기술 도입 전 · 개인정보보호법 제8조의2(2023 개정)<br>- **대상/성격**: 전 개인정보처리자, 자율 신청 · 서비스 관점 적법성·안전성 검토, 60일 이내 의견 통보(강제력 없는 의견) |
| **차별화** | **PbD → ISO 표준 → 사전 평가로 이어지는 거버넌스 파이프라인 구축 전략**<br>1. **설계 단계 PbD 체크리스트를 ISO 29100 11대 원칙에 매핑**: 애자일 스프린트의 "Privacy Backlog"에 PbD 8대 전략 항목을 ISO 29100 원칙 번호와 1:1 대응시켜, 설계 산출물이 곧 표준 준수 근거 문서가 되도록 이중 활용.<br>2. **ISO 27701 인증과 PIA/사전적정성 검토 근거 자료 재사용**: ISO 27701 갭분석·PIMS 구축 시 산출되는 위험평가 문서를 PIA의 개인정보 흐름도·위험분석 단계에 재사용하여 중복 문서화 비용 절감.<br>3. **신규 AI 서비스는 사전적정성 검토 → PIA 순차 적용**: 기획 단계에서 사전적정성 검토로 위원회 의견을 조기에 반영하고, 실제 시스템 구축·변경 시점에 PIA를 수행하여 두 제도의 시점 차이(기획 전 vs 구축 시)를 활용한 이중 안전판 확보. |
