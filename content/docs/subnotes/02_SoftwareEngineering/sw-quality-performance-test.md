# 소프트웨어 품질성능 평가시험 서브노트

> **두음 머리에 박기 🧠**
> - **기·성·호·사·신·보·유·이** (ISO/IEC 25010 8대 품질 특성: **기**능적합성, **성**능효율성, **호**환성, **사**용성, **신**뢰성, **보**안성, **유**지보수성, **이**식성)
> - **신·접·기·성·보·결·재·심·인** (GS인증 절차: **신**청 → **접**수·심사계획 → **기**능시험+**성**능시험+**보**안시험 → **결**함수정·재시험 → **심**의위원회 → **인**증서발급)

| **토픽명** | **소프트웨어 품질성능 평가시험과 GS인증(Good Software)** |
| **정의** | SW 기능·비기능 품질요구 충족여부 → **ISO/IEC 25010(SQuaRE)** 모델 기반 시험·인증 제도, 국내 TTA **GS인증** 대표 → 공공 SW조달 품질보증 활용 |
| **키워드** | ISO/IEC 25010, SQuaRE, GS인증(TTA), 소프트웨어 진흥법, 공공 조달 |
| **개념도** | `[ 신청(SW 개발사) ]` → `[ 접수·심사 계획(TTA) ]` → `[ 기능시험 + 성능시험 + 보안시험 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 결함 수정 → 재시험(필요시) ]` → `[ 심의위원회 ]` → `[ GS 1등급 / 2등급 인증서 발급 ]` → `[ 공공 조달 가산점 ]` |
| **구성요소** | 1. **ISO/IEC 25010 8대 품질특성**: 기능적합성, 성능효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성<br>2. **법적 근거**: 소프트웨어 진흥법 제20조<br>3. **GS인증 시험 3종**: 기능 시험, 성능 시험, 보안 시험<br>4. **GS등급**: 1등급(전항목 통과), 2등급(기능 항목만 통과, 성능·보안 일부 제외)<br>5. **공공 조달 연계**: 나라장터 조달 시 가산점, 소프트웨어 진흥법상 우선 구매 권고 |
| **비교** | **제품 품질 평가 (GS인증)**<br>- **대상**: 완성된 SW 제품 자체의 기능·성능·보안<br>- **목적**: 조달 시 소비자 선택 정보 제공<br><br>**프로세스 품질 인증 (SP인증)**<br>- **대상**: SW를 만드는 개발 조직의 프로세스 성숙도<br>- **목적**: 개발 역량·신뢰성 증명 |
| **차별화** | **GS인증 활용 조달 전략 및 품질 내재화 방안**<br>1. **ISO 25010 조기 내재화**: 8대 품질특성 요구사항 명세단계 체크리스트화 → 재시험 리스크 사전 최소화<br>2. **1등급 목표 설계**: SAST/DAST 등 보안 자동화 도구 선적용 → 성능·보안 시험 통과율 제고<br>3. **SP인증 병행 전략**: 제품품질(GS) + 프로세스품질(SP) 동시추진 → 공공사업 수주 시 이중신뢰 확보 |
