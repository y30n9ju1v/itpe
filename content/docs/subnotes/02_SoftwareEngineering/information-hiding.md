# 소프트웨어 설계 원리 서브노트

> **두음 머리에 박기 🧠**
> - **추·정·단·모** (SW 4대 설계 원리 순서: **추**상화 → **정**보은닉 → **단**계적분해 → **모**듈화)
> - **P·R·P·P** (접근 제어자 4종: **P**rivate, package(default), **P**rotected, **P**ublic — 범위가 좁은 순)
> - **변·결·재·보·테** (정보은닉의 5대 장점: **변**경 용이성, **결**합도 감소, **재**사용성, **보**안성, **테**스트 용이성)
> - **기·순·통·절·시·논·우** (응집도 강한순: **기**능적>**순**차적>**통**신적>**절**차적>**시**간적>**논**리적>**우**연적)
> - **자·스·제·외·공·내** (결합도 약한순: **자**료<**스**탬프<**제**어<**외**부<**공**통<**내**용)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 설계 4대 원리 (추상화·정보은닉·단계적분해·모듈화)** |
| **정의** | SW 복잡성관리·품질확보 4대 설계원칙: 핵심본질 추출 **추상화** → Parnas(1972) 제안, 인터페이스 뒤 내부구현 은폐 **정보은닉** → 상위~하위 점진분할 **단계적분해** → 독립SW단위 형상화 **모듈화** → 유지보수성·재사용성 기반 |
| **키워드** | 추상화(기능/자료/제어), Parnas 정보은닉, 단계적분해(Top-Down), 모듈화(응집도/결합도), 캡슐화, Repository 패턴 |
| **개념도** | `[복잡한 현실 문제]` → `추상화`(핵심 본질만 추출) → `정보은닉`(세부 구현 은폐, 인터페이스만 공개) → `단계적분해`(상위→하위 점진 분할) → `모듈화`(독립 SW 단위로 형상화)<br>&nbsp;&nbsp;&nbsp;&nbsp;`[ 외부 호출자 ]` ── 인터페이스(public)로만 접근 ──▶ `[ 모듈 공개 인터페이스 ]` → `▼(내부 은닉)` → `[ 변경 가능성 높은 내부 구현(private) ]` |
| **구성요소** | 1. **추상화**: 기능/자료/제어 추상화 → 불필요특성 제거, 복잡성 감소 (예: `obj.getName()`)<br>2. **정보은닉**: 캡슐화(묶는 것) 수단 → 내부구현 은폐(감추는 것); 접근제어자 private(클래스내)/protected(상속)/package(동일패키지)/public(전체공개)<br>3. **단계적분해**: 하향식(Top-Down) 추상화수준별 점진분할 → 복잡성 분할관리<br>4. **모듈화**: 응집도↑/결합도↓ 기준 재사용성·유지보수성↑ (응집도: 기능>순차>통신>절차>시간>논리>우연, 결합도: 자료<스탬프<제어<외부<공통<내용)<br>5. **정보은닉 위반사례**: public필드 직접노출, 로직없는 getter/setter 남용, 구현클래스 반환타입 노출 |
| **비교** | **추상화 vs 정보은닉**<br>- 추상화: 불필요특성 제거, 핵심본질 파악 (기능/자료/제어 추상화)<br>- 정보은닉: 내부구현 외부은폐 (캡슐화/인터페이스 정의)<br><br>**단계적분해 vs 모듈화**<br>- 단계적분해: 상위→하위 점진분할, Top-Down, 복잡성 분할관리<br>- 모듈화: 독립SW단위 구성, 응집도·결합도·Fan-In/Out 측정<br><br>**캡슐화 vs 정보은닉**<br>- 캡슐화: 데이터+행위 결합(목적) / 정보은닉: 내부 비가시화(수단) |
| **차별화** | **설계원리 현대적 재해석 및 확장 적용 전략**<br>1. **MSA 재해석**: 추상화→Open API, 정보은닉→DB-per-Service, 모듈→독립배포서비스, 응집도/결합도→서비스간 느슨결합으로 계승<br>2. **Repository 패턴 DB교체 유연성**: DB접근로직 인터페이스뒤 은닉 → MySQL→NoSQL 전환 시 호출자코드 무변경, 마이그레이션 리스크 최소화<br>3. **과도한 추상화(Over-Engineering) 경계**: YAGNI 병행 → 변화확실 임계영역만 선택적 고차추상화, 모듈세분도는 통합비용과 트레이드오프 고려해 SW생명주기 총비용 최저점 산정 |
