# 형상관리와 기준선 서브노트

> **두음 머리에 박기 🧠**
> - **식·통·기·감** (형상관리 4대 활동: **식**별, **통**제, **기**록(상태 기록), **감**사)
> - **기·할·제** (기준선 3유형: **기**능 기준선(요구분석 완료), **할**당 기준선(설계 완료), **제**품 기준선(개발·시험 완료))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **형상관리(Configuration Management)와 기준선(Baseline)** |
| **정의** | SW 전생명주기 산출물(형상항목) 변경을 체계관리 → 무결성·추적성 보장하는 프로세스 **형상관리**, 검토·승인된 특정시점 형상항목 집합인 **기준선**은 이후 변경의 기준점 |
| **키워드** | 형상항목(CI), CCB, 변경요청(CR), 기능/할당/제품 기준선, 형상 감사, Git/SVN |
| **개념도** | `[ 변경요청(CR) ]` → `[ 영향도 분석 ]` → `[ CCB 검토/승인 ]` → `[ 구현 ]` → `[ 검증 ]` → `[ 기준선 갱신 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▲`<br>`[ 기능 기준선(SRS) ]` → `[ 할당 기준선(설계서) ]` → `[ 제품 기준선(소스·실행파일) ]` |
| **구성요소** | 1. **형상항목(CI)**: 소스코드·설계문서·테스트케이스·빌드스크립트 등 관리대상 단위<br>2. **형상 식별**: 형상항목 목록·ID 정의, 계층구조화<br>3. **형상 통제**: CR → 검토 → 승인/거부 → 구현<br>4. **형상 상태기록**: 이력·상태를 형상관리DB에 문서화<br>5. **형상 감사**: 기준선-실제형상 일치여부 검증<br>6. **CCB**: 변경승인 의사결정기구 |
| **비교** | **형상관리 (프로세스 관점)**<br>- 범위: 산출물 전생명주기 변경통제 절차<br>- 핵심산출물: 변경이력, 감사결과<br><br>**기준선 (스냅샷 관점)**<br>- 범위: 특정시점 승인된 형상항목 정지집합<br>- 핵심산출물: 기능/할당/제품 기준선 문서 |
| **차별화** | **DevOps/Git 환경 형상관리 자동화 전략**<br>1. **Git 태그 기반 기준선 관리**: 릴리스시점마다 태그로 제품기준선 자동스냅샷 → CI/CD가 태그기반 재현가능 빌드 보장<br>2. **CCB 경량화**: 애자일/DevOps 환경 → PR 승인절차로 CCB 기능 대체, 통제속도·안정성 동시확보<br>3. **SBOM 연계 형상감사**: 제품기준선 내 오픈소스 구성요소 → SBOM 자동추출, 라이선스·취약점까지 함께검증 |
