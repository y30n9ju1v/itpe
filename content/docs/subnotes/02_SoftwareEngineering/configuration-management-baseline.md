# 형상관리와 기준선 서브노트

> **두음 머리에 박기 🧠**
> - **식·통·기·감** (형상관리 4대 활동: **식**별, **통**제, **기**록(상태 기록), **감**사)
> - **기·할·제** (기준선 3유형: **기**능 기준선(요구분석 완료), **할**당 기준선(설계 완료), **제**품 기준선(개발·시험 완료))

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **형상관리(Configuration Management)와 기준선(Baseline)** |
| **정의** | 소프트웨어 개발 전 생명주기에 걸쳐 산출물(형상항목)의 변경을 체계적으로 관리하여 무결성과 추적성을 보장하는 프로세스가 **형상관리**이며, **기준선**은 정식으로 검토·승인된 특정 시점의 형상항목 집합으로 이후 모든 변경의 기준점이 된다 |
| **키워드** | 형상항목(CI), CCB, 변경요청(CR), 기능/할당/제품 기준선, 형상 감사, Git/SVN |
| **개념도** | `[ 변경요청(CR) ]` → `[ 영향도 분석 ]` → `[ CCB 검토/승인 ]` → `[ 구현 ]` → `[ 검증 ]` → `[ 기준선 갱신 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▲`<br>`[ 기능 기준선(SRS) ]` → `[ 할당 기준선(설계서) ]` → `[ 제품 기준선(소스·실행파일) ]` |
| **구성요소** | 1. **형상항목(CI)**: 소스코드, 설계문서, 테스트케이스, 빌드 스크립트 등 관리 대상 단위<br>2. **형상 식별**: 형상항목 목록·ID 정의, 계층 구조화<br>3. **형상 통제**: CR → 검토 → 승인/거부 → 구현 절차<br>4. **형상 상태 기록**: 이력·상태를 형상관리 DB에 문서화<br>5. **형상 감사**: 기준선과 실제 형상의 일치 여부 검증<br>6. **CCB(Configuration Control Board)**: 변경 승인 의사결정 기구 |
| **비교** | **형상관리 (프로세스 관점)**<br>- **범위**: 산출물 전 생명주기의 변경 통제 절차<br>- **핵심 산출물**: 변경 이력, 감사 결과<br><br>**기준선 (스냅샷 관점)**<br>- **범위**: 특정 시점에 승인된 형상항목의 정지된 집합<br>- **핵심 산출물**: 기능/할당/제품 기준선 문서 |
| **차별화** | **DevOps/Git 환경에서의 형상관리 자동화 전략**<br>1. **Git 태그 기반 기준선 관리**: 릴리스 시점마다 Git 태그로 제품 기준선을 자동 스냅샷하고, CI/CD 파이프라인이 태그 기반으로 재현 가능한 빌드를 보장.<br>2. **CCB의 경량화(Lightweight CCB)**: 애자일/DevOps 환경에서는 PR(Pull Request) 승인 절차 자체를 CCB 기능으로 대체하여 변경 통제 속도와 안정성을 동시 확보.<br>3. **SBOM 연계 형상 감사**: 제품 기준선에 포함된 오픈소스 구성요소를 SBOM으로 자동 추출하여 형상 감사 시 라이선스·취약점까지 함께 검증. |
