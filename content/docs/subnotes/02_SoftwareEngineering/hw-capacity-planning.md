# ITA 기반 H/W 용량산정 서브노트

> **두음 머리에 박기 🧠**
> - **피·목·동·트·데** (H/W 용량산정 5대 결정점: **피**크배율, **목**표CPU활용률, **동**시사용자수, **트**랜잭션당 자원소비량, **데**이터증가율)
> - **서·스·네** (규모산정 3대 대상: **서**버(Web·WAS·DB), **스**토리지(데이터·백업·아카이브), **네**트워크(스위치·방화벽))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **ITA(정보기술아키텍처) 기반 H/W 용량산정 (Capacity Planning)** |
| **정의** | 목표시스템 업무처리능력 요구 충족 CPU·Memory·Storage·Network 최소규모 정량산출 프로세스 → ITA공공사업에서 예산편성 공식근거 |
| **키워드** | TPS, 피크 배율, 목표 CPU 활용률, tpmC(TPC-C), IOPS, 클라우드 오토스케일링 |
| **개념도** | `[업무 요구사항 분석]`(일 최대 트랜잭션, 동시사용자) → `[TPS 산정]`(=일 최대 거래건수÷유효시간×피크배율) → `[자원별 용량 계산]`(CPU/Memory/Disk) → `[여유율·이중화 반영]`(N+1, DR) → `[최종 H/W 사양 결정]` |
| **구성요소** | 1. **CPU용량**: 필요CPU = TPS×트랜잭션당 CPU처리시간 ÷ 목표활용률(통상 60~70%)<br>2. **Memory용량**: 동시사용자수×세션당메모리 + OS/WAS/DB버퍼 + 여유(20~30%)<br>3. **Disk용량**: 초기데이터 + (연간증가량×보존기간) + 인덱스(20~30%) + RAID오버헤드 × 여유율(1.2~1.5)<br>4. **규모산정 대상**: 서버(Web·WAS·DB·배치/연계), 스토리지(데이터·백업·아카이브), 네트워크(L4스위치·방화벽·IDS/IPS)<br>5. **성능 기준지**: tpmC(TPC-C 분당 신규주문 트랜잭션, CPU비교), IOPS(초당 I/O수, 스토리지기준), 처리량(MB/s), 응답시간(ms) |
| **비교** | **On-Premise 용량산정**<br>- 단위: 서버대수·코어수·GB (Scale-up 중심)<br>- 비용: 초기CAPEX 집중, 피크기준 과잉프로비저닝<br><br>**클라우드(IaaS/PaaS) 용량산정**<br>- 단위: 인스턴스유형(t3.xlarge 등), Scale-out 용이<br>- 비용: 사용량기반 OPEX, 오토스케일링 탄력대응 — Baseline 선정 위한 초기산정은 클라우드도 필수 |
| **차별화** | **비용통제·정확도 향상 용량산정 전략**<br>1. **기준인스턴스+오토스케일링 이중접근**: 클라우드도 Baseline산정 후 Upper bound(비용상한) 병행설정 → 예산 통제불능 방지<br>2. **2단계 피크배율 검증**: 유사도메인 트래픽패턴 참조 초기산정 → 부하테스트 결과로 재검증 → 주관적 오류 최소화<br>3. **Year1/Year2~3 분리구성**: 3년증가분 일괄 프로비저닝 지양 → 초기구축비 과다·저활용률 방지, 클라우드는 오토스케일링·On-Prem은 블레이드 증설로 단계확장 |
