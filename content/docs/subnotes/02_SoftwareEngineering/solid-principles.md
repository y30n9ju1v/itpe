# 객체지향 5대 설계 원칙과 다형성, 의존성 주입 서브노트

> **두음 머리에 박기 🧠**
> - **단·개·리·인·의**: SRP·OCP·LSP·ISP·DIP
> - **오·오**: 오버로딩(컴파일 시점)·오버라이딩(실행 시점)
> - **생·세·메**: 생성자·세터·메서드 주입

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **SOLID, 다형성, 의존성 주입(DI)** |
| **정의** | 유지보수성과 확장성을 높이는 객체지향 설계 원칙(SOLID), 구현체를 교체 가능하게 하는 다형성, 그리고 DIP를 구현하는 DI 방식 |
| **키워드** | SRP, OCP, LSP, ISP, DIP, Overloading, Overriding, DI, IoC |
| **개념도** | **[ OCP + DIP ]**<br>`고수준 모듈 → 인터페이스(추상화) ← 구현체 A / 구현체 B`<br>고수준 모듈은 구현체가 아닌 추상화에 의존하고, 구현체 추가로 기능을 확장한다. |
| **구성요소** | 1. **SRP**: 하나의 모듈은 하나의 변경 이유를 갖게 한다.<br>2. **OCP**: 기존 코드 수정은 닫고, 추상화·다형성으로 확장은 연다.<br>3. **LSP**: 하위 타입은 상위 타입의 계약을 깨지 않고 대체 가능해야 한다.<br>4. **ISP**: 클라이언트가 쓰지 않는 메서드에 의존하지 않도록 인터페이스를 분리한다.<br>5. **DIP**: 고수준 정책과 저수준 구현 모두 추상화에 의존한다.<br>6. **다형성**: 오버로딩은 시그니처가 다른 정적 바인딩, 오버라이딩은 상속·인터페이스를 통한 동적 바인딩이다.<br>7. **DI**: 생성자 주입은 필수 의존성과 불변성을 명확히 해 기본 선택으로 적합하다. 세터는 선택 의존성, 메서드는 일회성 의존성에 사용한다. |
| **비교** | **OCP**: 기능 추가 시 기존 코드 변경을 줄이는 확장성 원칙<br>**DIP**: 상위 정책과 하위 구현의 결합도를 낮추는 의존성 원칙<br><br>**오버로딩**: 상속 불필요, 컴파일 시점 선택<br>**오버라이딩**: 상속·인터페이스 필요, 실행 시점 선택 |
| **차별화** | 1. Spring 컨테이너는 인터페이스 기반 구현체 주입으로 DIP·OCP를 지원한다.<br>2. LSP가 의심되면 상속보다 합성을 우선 검토한다.<br>3. 큰 인터페이스는 클라이언트 역할별로 분리한다.<br>4. 생성자 주입으로 순환 의존성과 누락된 필수 의존성을 조기에 드러낸다. |
