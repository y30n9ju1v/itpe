# 소프트웨어 테일러링 서브노트

> **두음 머리에 박기 🧠**
> - **특·정·정·승·문** (테일러링 수행 절차: 프로젝트 **특**성 정의 ➔ **정**합성 분석 ➔ 테일러링안 **정**의 ➔ **승**인 ➔ **문**서화)
> - **내·외** (테일러링 고려 요인: **내**부적 요인(기술/인력/규모), **외**부적 요인(법적규제/발주처))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 테일러링 (Software Tailoring)** |
| **정의** | 조직의 표준 개발방법론을 특정 프로젝트의 특성(규모, 위험, 기술, 기간 등)에 부합하도록 최적화하여 가공하고 맞춤 적용하는 **엔지니어링 활동** |
| **키워드** | 방법론 커스터마이징, 테일러링 절차(특·정·정·승·문), 고려 요인(내·외), 산출물 조정 |
| **개념도** | `[ 조직 표준 개발방법론 ]` (기본 프레임워크)<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`├───────── [ 분석 ] ➔ 내부 요인 (인력/기술/규모) & 외부 요인 (법적규제/발주처 요구)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 테일러링 매트릭스 작성 ] ➔ [ 승인 및 문서화 ] ➔ [ 프로젝트 특화 방법론 적용 및 피드백 ]` |
| **구성요소** | 1. **테일러링 절차 (특·정·정·승·문)**: 특성정의 ➔ 정합성분석 ➔ 테일러링안 정의 ➔ 승인 ➔ 문서화<br>2. **내부 요인**: 기술 환경(프레임워크), 참여 인력 역량, 프로젝트 기간/비용, 복잡도 및 위험 수준<br>3. **외부 요인**: 법적/제도적 규제(소프트웨어진흥법, 전자정부 표준), 발주처의 요구사항<br>4. **테일러링 대상**: 개발 생명주기(SDLC), 산출물의 종류 및 분량, 세부 이행 프로세스 및 승인 절차 |
| **비교** | **테일러링 (Tailoring)**<br>- **무게중심**: 개발 "방법론" 및 "프로세스" 자체를 최적화<br>- **방법**: 표준 방법론에서 불필요한 산출물을 배제하거나 필수 절차를 병합/조정<br><br>**커스터마이징 (Customizing)**<br>- **무게중심**: 기성 "SW 제품" 이나 "모듈"의 설정 최적화<br>- **방법**: 패키지 솔루션의 소스코드 수정 또는 Configuration 설정을 통한 맞춤화 |
| **차별화** | **품질 보증 및 프로젝트 실패 방지를 위한 실무 테일러링 거버넌스**<br>1. **핵심 품질 게이트(Quality Gate) 보존**: 기한 압박으로 산출물을 축소하더라도, 형상 통제 절차 및 통합/인수 테스트 계획 등의 통제 요소는 생략 불가능하도록 하드 컨스트레인트(Hard Constraint)로 지정.<br>2. **동적 가변형 스프린트 테일러링**: 애자일 적용 시 고정 주기를 탈피하여, 아키텍처 리스크가 높은 프로젝트 초반은 1주, 양산 개발 단계는 2주, 검증 단계는 3주로 주기를 가변 적용.<br>3. **테일러링 피드백 루프**: 프로젝트 종료 단계에서 실제 적용된 변경 사항을 수집하여 차기 표준 방법론 갱신에 피드백하는 프로세스 자산화(OPAs) 구현. |
