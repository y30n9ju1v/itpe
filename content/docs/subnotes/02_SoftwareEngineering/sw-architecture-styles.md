# 소프트웨어 아키텍처 스타일 서브노트

> **두음 머리에 박기 🧠**
> - **논·구·프·배·유**: 4+1 뷰 — 논리·구현·프로세스·배포 뷰 + 유스케이스
> - **계·이·파·마**: Layered·Event-Driven·Pipe-Filter·MSA
> - **감·트·위·비**: ATAM 산출물 — 감도점·트레이드오프점·위험점·비위험점

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 아키텍처 스타일 및 4+1 아키텍처 뷰** |
| **정의** | 시스템의 주요 구성요소·관계·제약을 정하는 **아키텍처 스타일**과, 이해관계자 관점별로 구조를 명세·검증하는 **4+1 뷰** |
| **키워드** | Layered, Event-Driven, Pipe-Filter, 4+1 View, ATAM, CBAM |
| **개념도** | **[ 4+1 View ]** `논리·프로세스·개발·물리 뷰` ← `유스케이스 시나리오`로 정합성 검증<br>**[ Pipe & Filter ]** `데이터 소스 → 필터 A(정제) → 필터 B(변환) → 데이터 싱크` |
| **구성요소** | 1. **논리 뷰**: 설계자 관점의 기능·도메인 구조<br>2. **프로세스 뷰**: 런타임 흐름·동시성·성능<br>3. **개발 뷰**: 모듈·패키지·소스 배치<br>4. **물리 뷰**: 노드·VM·네트워크 배포<br>5. **유스케이스 뷰**: 시나리오로 네 뷰를 검증<br>6. **ATAM**: 품질속성 시나리오와 유틸리티 트리로 접근법을 분석해 감도점·트레이드오프점·위험을 찾음<br>7. **분석 방향**: 정방향(요구사항→설계 사전검증) / 역방향(구현→구조복원) |
| **비교** | **Layered**: 관심사 분리·변경 용이, 계층 통과 비용 유의<br>**Event-Driven**: 느슨한 결합·확장성, 순서·추적 복잡성 유의<br>**Pipe-Filter**: 처리 단계 재사용·병렬화, 상태 공유 제약<br>**MSA**: 독립 배포·확장, 분산 운영 복잡성 증가<br><br>**SA 평가**: SAAM은 단일 품질속성, ATAM은 다중 속성의 트레이드오프, CBAM은 ATAM에 경제성 분석을 결합 |
| **차별화** | 1. 품질속성 시나리오를 먼저 만들고 ATAM으로 트레이드오프를 확인한다.<br>2. 변경안의 비용·가치는 CBAM으로 비교한다.<br>3. 4+1 뷰에는 다이어그램뿐 아니라 설계 배경·결정·대안을 기록한다.<br>4. 레거시는 역방향 분석으로 구조를 복원한 뒤 현대화 후보를 정한다. |
