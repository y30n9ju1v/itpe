# 소프트웨어 개발방법론의 발전과정 서브노트

> **두음 머리에 박기 🧠**
> - **구·정·객·C·애** (SW 개발방법론 5대 발전 흐름: **구**조적(1970s) → **정**보공학(1980s) → **객**체지향(1990s) → **C**BD(2000s) → **애**자일(2000s~))
> - **프·데·객·컴·사** (각 방법론의 중심축: **프**로세스, **데**이터, **객**체, **컴**포넌트, **사**람) |

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 개발방법론의 발전과정 (구조적 → 정보공학 → 객체지향 → CBD → 애자일)** |
| **정의** | SDLC 전과정 생산성·품질제고 위한 절차·방법·산출물·기법·도구 체계, 개발중심축 **프로세스(구조적)→데이터(정보공학)→객체(객체지향)→컴포넌트(CBD)→사람(애자일)** 순 진화, 통제중심→불확실성 수용중심 패러다임 계보 |
| **키워드** | 구조적 방법론(DFD/DD), 정보공학(ERD), 객체지향(UML/SOLID), CBD(IDL), 애자일(Scrum/XP), Water-Scrum-Fall |
| **개념도** | `[1970s 구조적]`(프로세스 중심, 하향식 DFD) → `[1980s 정보공학]`(데이터 중심, ERD/ISP) → `[1990s 객체지향]`(데이터+프로세스 융합, UML) → `[2000s CBD]`(컴포넌트 조립, IDL) → `[2000s~ 애자일]`(불확실성 수용, Scrum/XP) |
| **구성요소** | 1. **구조적 방법론(1970s)**: 하향식(Top-Down) 기능 분할, DFD/DD/소단위명세서, 폭포수 모델 — 한계: 변경 시 전 단계 재작업<br>2. **정보공학(1980s)**: 전사적 데이터 자원 모델링, ERD/CRUD, 전략계획→분석→설계→구축 4단계 — 한계: 환경 변화 대응 지연<br>3. **객체지향(1990s)**: 데이터+행위 결합 객체 모델링, UML(4+1 View), SOLID 설계원칙 — 한계: 추상화 학습곡선<br>4. **CBD(2000s)**: 독립 컴포넌트 저장·재조합, 도메인공학(개발)+응용공학(조립) 이원 공정, IDL 명세 — 한계: 컴포넌트 유통 생태계 미성숙<br>5. **애자일(2000s~)**: 사람·소통 중심, Scrum/XP(스프린트·TDD·CI/CD), 스토리포인트·Velocity — 한계: 대규모 프로젝트 거버넌스·문서화 부족 |
| **비교** | **방법론별 재사용 단위 비교**<br>- 구조적: 서브루틴 / 정보공학: 논리 데이터모델 / 객체지향: 클래스 / CBD: 바이너리 컴포넌트 / 애자일: 프레임워크·패턴<br><br>**개발 모델 비교**<br>- 구조적: 폭포수(순차) / 정보공학: 순차적 4단계 / 객체지향: 반복점진 / CBD: 아키텍처 중심 / 애자일: 이터레이티브(반복) |
| **차별화** | **하이브리드 방법론 테일러링 및 AI시대 대응전략**<br>1. **Water-Scrum-Fall 모순 극복**: 예산·범위고정 계약/거버넌스 영역 → 예측형(정보공학/CBD계열), 가변적 비즈니스로직/UI 영역 → 적응형(애자일), 하이브리드 테일러링 기준 수립<br>2. **테일러링 거버넌스 공식화**: 착수 시 테일러링매트릭스 작성 → CMMI OPD기준 QA승인 → 방법론 커스터마이징 공식절차화, 획일적 도그마 방지<br>3. **AI-Augmented SDLC 진화**: 생성형AI가 코드·명세서 자동생성 → 절차 슬림화(Lean), 인간은 AI산출물 오케스트레이션·위험통제(지속적명세화)에 집중 |
