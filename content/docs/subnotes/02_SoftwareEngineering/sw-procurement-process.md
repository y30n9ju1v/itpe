# SW사업 단계별 발주제도와 상용 SW 직접구매 서브노트

> **두음 머리에 박기 🧠**
> - **계·산·발·검·발** (단계별 발주 표준 프로세스: 사업**계**획 → 1단계(**분**석) 발주 → 산출물 **검**수 → 2단계(설계/구현) **발**주)
> - **직·분·단·P·G** (공공 SW 발주 생태계 4대 제도: **직**접구매, **분**리발주, **단**계별발주, PMO, GS인증) |

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어사업 단계별 발주제도 및 상용 SW 직접구매 제도** |
| **정의** | **단계별 발주제도**: SW개발사업 → 기획/분석·설계/구현 단계분리 → 단계별 별도계약, 요구사항 불확실성 리스크 단계관리(행안부 지침) / **상용SW 직접구매**: 상용SW를 HW·SI사업 미포함 → 나라장터·디지털서비스몰 통해 SW사와 직접계약, 공공조달 방식. 양자 모두 SI종속·불공정 하도급 개선하는 공공SW 발주혁신 제도 |
| **키워드** | 단계별 발주(행안부 지침), 분리발주, 나라장터(G2B), 디지털서비스몰, GS인증, SaaS/구독 라이선스 |
| **개념도** | `[사업계획 수립]`(1·2단계 예산 분리) → `[1단계 계약: 분석/ISP]` → `[1단계 산출물 검수]`(요구사항명세서) → `[2단계 계약: 설계/구현/테스트]` → `[최종 납품·검수]`<br>&nbsp;&nbsp;&nbsp;&nbsp;직접구매: `SW제조사` → (나라장터/디지털서비스몰 직접계약) → `수요기관` — 중간 마진(SI/대리점) 제거 |
| **구성요소** | 1. **단계별 발주 핵심 원칙**: 단계별 계약, 산출물 기반 검수, 발주자 책임 강화 (법적근거: 「SW사업 계약 및 관리감독에 관한 지침」)<br>2. **일반발주 vs 단계별발주**: 계약구조(1건 vs 복수), 위험부담(수급자 집중 vs 분산), 발주자 관여도(낮음 vs 높음)<br>3. **직접구매 절차**: 구매계획 수립 → 제품 검색·선정(G2B/디지털서비스몰) → 내부결재 → 계약체결 → 납품·검수 → 사후관리(유지보수)<br>4. **라이선스 유형**: 영구(Perpetual, CAPEX) / 구독(Subscription, OPEX) / SaaS(디지털서비스몰) / 동시사용자 / Named User<br>5. **조달채널**: 나라장터(G2B, 패키지SW·HW, GS인증) vs 디지털서비스몰(클라우드·SaaS·AI, 보안/클라우드 인증) |
| **비교** | **단계별 발주 (시간적 분리)**<br>- **분리 기준**: 분석/설계/구현의 시간적 단계<br>- **목적**: 요구사항 명확화, 발주자 통제권 강화<br><br>**분리발주 (기능별 분리)**<br>- **분리 기준**: HW/SW/네트워크 등 기능 영역<br>- **목적**: 전문 업체 활용, 독점 방지<br><br>**직접구매 (유통 단계 분리)**<br>- **분리 기준**: 상용SW를 SI 사업에서 분리해 SW사와 직접 계약<br>- **목적**: 중간 마진 제거, 가격 투명성, SW기업 수익 보호 |
| **차별화** | **제도 실효성 확보 실무전략**<br>1. **단계별발주-애자일 하이브리드**: 1단계(분석/아키텍처)는 단계별발주, 2단계(구현)는 타임박스 애자일계약 → 폭포수 전제와 스프린트계약 충돌완화. 1단계 계약에 2단계 우선협상 옵션계약 명시 → 계약공백 최소화<br>2. **직접구매 SaaS 예산리스크 관리**: 연간CAPEX 구조 vs SaaS OPEX구독 충돌 → 다년도계약으로 완화, SAM도구로 라이선스 과소/과다배포 실시간 모니터링<br>3. **4대 제도 연계운용**: 직접구매(가격투명성)→분리발주(전문업체선택)→단계별발주(요구사항명확화)→PMO(발주자역량 보완) 상호보완, 공공SW 발주생태계 품질개선 |
