# 품질보증(QA)/품질통제(QC)와 QC 7도구 서브노트

> **파·특·히·산·체·층·관** (구 QC 7도구: **파**레토도, **특**성요인도, **히**스토그램, **산**점도, **체**크시트, **층**별, **관**리도)
> - **친·연·계·매·PDPC·애·매** (신 QC 7도구: **친**화도, **연**관도, **계**통도, **매**트릭스도, **PDPC**, **애**로우다이어그램, **매**트릭스 데이터 해석)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **품질보증(QA)/품질통제(QC)의 구분과 QC 7도구** |
| **정의** | **QA**는 소프트웨어가 품질 목표를 달성하도록 개발 프로세스를 계획·수행·감시하는 예방 중심 활동(프로세스 지향), **QC**는 산출물이 품질 기준을 충족하는지 검사하여 결함을 발견·수정하는 활동(제품 지향)이며, **QC 7도구**는 QC 수행 시 품질 데이터를 수집·시각화·분석하는 구 7도구(수치)와 신 7도구(언어)의 통계적 기법 집합 |
| **키워드** | QA(프로세스), QC(제품), Barry Boehm 결함비용법칙, 파레토도, 특성요인도, 관리도, Shift-Left |
| **개념도** | `[품질 계획]` → `[QA: 프로세스 감시]`("올바른 방법으로 개발하는가?") → `[개발/테스트/빌드]` → `[QC: 결과물 검사]`("올바른 것을 만들었는가?") → `[품질 개선 PDCA]`<br>&nbsp;&nbsp;&nbsp;&nbsp;QC 7도구 흐름: `체크시트(수집)` → `파레토도(우선순위 80-20)` → `특성요인도(근본원인)` → `관리도(지속 모니터링)` |
| **구성요소** | 1. **QA 주요 활동**: 프로세스 감사, 요구사항/설계 검토, 테스트 계획 검토, 형상 감사 (독립 QA팀, ISO 9001/90003)<br>2. **QC 주요 기법**: 인스펙션(Fagan), 워크스루, 테스팅(동적), 정적 분석<br>3. **결함 수정 비용 법칙(Boehm)**: 요구사항×1 → 설계×5 → 구현×10 → 테스트×25 → 릴리즈후×100<br>4. **구 QC 7도구(수치)**: 파레토도(우선순위), 특성요인도/피시본(근본원인), 히스토그램(분포), 산점도(상관관계), 체크시트(집계), 층별(그룹분리), 관리도(UCL/CL/LCL 이상탐지)<br>5. **신 QC 7도구(언어)**: 친화도(KJ법), 연관도, 계통도, 매트릭스도(QFD), PDPC(리스크 대응), 애로우다이어그램(PERT/CPM), 매트릭스 데이터 해석(유일한 수치 분석) |
| **비교** | **QA (품질보증)**<br>- **대상/시점**: 프로세스 / 개발 전 과정, 능동적(Proactive)<br>- **비용 효과**: 조기 예방 → 저비용<br><br>**QC (품질통제)**<br>- **대상/시점**: 제품·산출물 / 산출물 완성 후, 수동적(Reactive)<br>- **비용 효과**: 후기 발견 → 고비용 — QA·QC는 상호 보완 관계 |
| **차별화** | **애자일/DevSecOps 환경의 QA·QC 자동화 통합 전략**<br>1. **CI/CD 파이프라인 내재화**: SonarQube Quality Gate·SAST/DAST를 코드 push마다 자동 실행하여 QA(표준 준수)와 QC(결함 탐지)를 동시 자동 수행하고, 스프린트 회고를 QA 프로세스 개선 채널로 활용.<br>2. **QC 7도구의 DevOps 도구 대체**: Jira/GitHub Issues 태그 통계로 파레토도를 자동 생성하고 Grafana/Datadog으로 관리도를 실시간 구현하여 수작업 데이터 수집 한계를 극복.<br>3. **Shift-Left를 통한 품질비용 절감**: TDD/BDD로 QC 활동을 요구사항·설계 단계로 앞당겨 Boehm의 결함비용 법칙에 따른 후행 비용 폭증을 차단, 특성요인도를 5-Why 기반 RCA 템플릿으로 연계해 장애 재발 방지. |
