# 소프트웨어 기술 부채 서브노트

> **두음 머리에 박기 🧠**
> - **코·설·테·문·인·보** (기술 부채 6대 유형: **코**드 부채, **설**계 부채, **테**스트 부채, **문**서 부채, **인**프라 부채, **보**안 부채)
> - **의·신 / 의·무·신·무** (Fowler 기술부채 사분면 축: **의**도적×**신**중한=출시후 정리계획, **의**도적×**무**모한=설계할 시간없음, 비**의**도적×**신**중한=더나은 설계 발견, 비**의**도적×**무**모한=레이어 개념 모름)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 기술 부채(SW Technical Debt)** |
| **정의** | Ward Cunningham 제시 개념 → 단기편의 위해 차선 설계·구현 선택 시 미래 추가작업(이자) 발생을 금융부채에 비유, 의도적/비의도적 원인·6대 유형 분류, 측정·리팩토링으로 관리 |
| **키워드** | Ward Cunningham, Boy Scout Rule, SonarQube, Fowler 사분면, 리팩토링 백로그 |
| **개념도** | `[ 단기 편의적 설계/구현 선택 ]` → `[ 기술 부채 발생(원금) ]` → `[ 시간 경과 시 이자(유지보수 비용) 누적 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 측정(SonarQube) ] → [ 우선순위화 ] → [ 리팩토링(Boy Scout Rule) ] → [ 예방(코드리뷰) ] → [ 레지스트리 추적 ]` |
| **구성요소** | 1. **6대 유형**: 코드 부채, 설계 부채, 테스트 부채, 문서 부채, 인프라 부채, 보안 부채<br>2. **발생 원인**: 의도적(일정 압박, 의식적 타협), 비의도적(역량 부족, 레거시 축적, 기술 진화)<br>3. **관리 방법**: 측정(정적분석) → 우선순위(비즈니스 영향도) → 리팩토링(Boy Scout Rule) → 예방(코드리뷰/페어프로그래밍) → 추적(레지스트리)<br>4. **Fowler 기술부채 사분면**: 의도적×신중한(출시 후 정리 계획), 의도적×무모한(설계 시간 없음), 비의도적×신중한(더 나은 설계 발견), 비의도적×무모한(레이어 개념 부재) |
| **비교** | **의도적 기술 부채**<br>- 특징: 일정압박 하 의식적 타협, 추적·계획 가능<br>- 관리: 백로그 등록 후 계획적 상환<br><br>**비의도적 기술 부채**<br>- 특징: 역량부족·레거시 누적으로 인지조차 못함<br>- 관리: 정적분석 도구 발견 후 사후 대응 |
| **차별화** | **Error Budget과 연계한 기술 부채 상환 거버넌스**<br>1. **정량적 가시화 기반 스프린트 편성**: SonarQube 부채지표 + SRE 오류예산 소진속도 연계 → 소진 빠른 영역 우선 리팩토링 강제전환<br>2. **의도적 부채 계획관리**: 신중한(Deliberate&Prudent) 유형은 출시직후 정리일정 백로그 명문화 → 무모한 부채화 방지<br>3. **Boy Scout Rule 문화정착**: 코드리뷰 시 "발견 전보다 깨끗하게" 원칙 → 매 커밋 점진적 소규모 리팩토링, 대규모 재공학 필요성 축소 |
