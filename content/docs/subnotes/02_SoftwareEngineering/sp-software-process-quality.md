# 소프트웨어 프로세스(SP) 품질인증 서브노트

> **두음 머리에 박기 🧠**
> - **프·프·개·형·품·위** (6대 프로세스 영역: **프**로세스 관리, **프**로젝트 관리, **개**발, **형**상관리, **품**질보증, **위**험관리)
> - **관·정·정·최** (4단계 성숙도 등급: **관**리 ➔ **정**의 ➔ **정**량적 관리 ➔ **최**적화)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 프로세스 (SP, Software Process) 품질인증** |
| **정의** | SW 개발 및 관리 프로세스 역량 수준을 공인 기준(CMMI/SPICE)에 따라 평가하여 등급을 부여하는 **SW진흥법 기반의 국내 프로세스 품질인증 제도** |
| **키워드** | SW진흥법, 프로세스 영역 (프·프·개·형·품·위), 심사 등급 (관·정·정·최), SPICE, CMMI, TTA |
| **개념도** | `[조직 표준 프로세스]` (Level 3: 정의)<br>&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ Tailoring`<br>`[프로젝트 수행]` (Level 2: 관리) ➔ `[형상/품질/위험 관리]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ 제3자 심사 (TTA)`<br>`[SP 품질인증 획득]` (공공 입찰 가점 최대 6점 부여) |
| **구성요소** | 1. **프로세스 관리**: 표준 프로세스 정의, 문서화 및 지속적 개선 활동<br>2. **프로젝트 관리**: 프로젝트 계획, 일정, 비용 및 자원 관리<br>3. **개발 프로세스**: 요구사항 개발, 설계, 구현, IT 테스트 수행 체계<br>4. **형상 관리**: 산출물 버전 관리, 형상 통제 및 변경 관리<br>5. **품질 보증**: 프로세스 이행 여부 감사 및 산출물 제품 품질 검토<br>6. **위험 관리**: 프로젝트 위험 식별, 분석 및 완화/대응 계획 수립 |
| **비교** | **SP 인증 (Process)**<br>- **대상**: SW 개발/관리 프로세스 체계<br>- **표준**: ISO/IEC 15504 (SPICE)<br>- **혜택**: 공공입찰 가점(최대 6점)<br><br>**GS 인증 (Product)**<br>- **대상**: SW 완제품 자체 (기능, 성능 등)<br>- **표준**: ISO/IEC 25010<br>- **혜택**: 우선구매제도, 수의계약 허용 |
| **차별화** | **현실적 ROI 기반의 품질 내재화 방안**<br>1. **단계적 접근**: 중소기업은 비용 대비 효과가 큰 국내 SP 2등급을 우선 획득한 후, 글로벌 진출 시 CMMI Level 3로 연계하여 비용 절감.<br>2. **DevOps/Agile 융합**: 스프린트 회고(Retrospective)를 프로세스 개선 활동에 매핑하고, CI/CD 메트릭을 정량 관리 데이터로 활용하여 문서화 오버헤드 극복.<br>3. **지속성 확보**: 3년 만료 전 연 1회 내부 프로세스 감사(Internal Process Audit) 및 신임 PM 대상 프로세스 온보딩 정례화. |
