# MCDC & 커버리지 서브노트

> **두음 머리에 박기 🧠**
> - **구·결·조·조건결·M·다** (화이트박스 커버리지 강도: **구**문 ➔ **결**정 ➔ **조**건 ➔ **조**건/**결**정 ➔ **M**CDC ➔ **다**중조건)
> - **N + 1** (MCDC 테스트 케이스 수: 개별 조건 수 $n$개일 때 필요한 최소 테스트 케이스 수는 $n+1$개)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **변경 조건/결정 커버리지 (MCDC, Modified Condition/Decision Coverage)** |
| **정의** | 복합 조건식에서 각 개별 조건(Condition)이 다른 조건들의 영향을 받지 않고 **전체 결정(Decision) 결과에 독립적으로 영향을 미치는 경로를 검증**하는 고신뢰성 화이트박스 커버리지 기술 |
| **키워드** | 구문/결정/조건 커버리지, MCDC ($n+1$ 케이스), 독립적 영향력, DO-178C Level A, ISO 26262 ASIL D |
| **개념도** | `[ 결정 식 : (A or B) and C ]`  (개별 조건 A, B, C 총 3개 ➔ 다중 조건 조합 2³ = 8개 필요)<br>&nbsp;&nbsp;&nbsp;&nbsp;`│ MCDC 적용 (n+1 = 4개 케이스 도출)`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>| 번호 | A | B | C | 결과 | 독립성 검증 타겟 |<br>|:---:|:---:|:---:|:---:|:---:|:---|<br>| ① | **T** | F | **T** | **T** | (①, ③) 쌍으로 A의 독립적 결정 영향 증명 |<br>| ② | F | **T** | **T** | **T** | (②, ③) 쌍으로 B의 독립적 결정 영향 증명 |<br>| ③ | **F** | **F** | T | **F** | A와 B가 F일 때 결과 F |<br>| ④ | T | F | **F** | **F** | (①, ④) 쌍으로 C의 독립적 결정 영향 증명 | |
| **구성요소** | 1. **구문 커버리지 (Statement)**: 소스코드 내 모든 실행문이 최소 1회 실행되도록 설계<br>2. **결정 커버리지 (Decision/Branch)**: 각 결정문(IF 등)의 참(True)과 거짓(False)이 최소 1회 실행되도록 설계<br>3. **조건 커버리지 (Condition)**: 결정문 내 개별 조건식의 참(True)과 거짓(False)이 최소 1회 실행되도록 설계<br>4. **MCDC 조건**: 각 개별 조건 $n$개에 대해 독립적 영향력을 검증하는 테스트 케이스 세트 $n+1$개 구성 |
| **비교** | **결정 커버리지 (Decision)**<br>- **초점**: 분기문 전체 결과(T/F) 만족 여부<br>- **단점**: 개별 조건의 오류가 묻힐 가능성 존재<br><br>**조건 커버리지 (Condition)**<br>- **초점**: 개별 조건식 각각의 T/F 만족 여부<br>- **단점**: 개별 조건은 만족해도 전체 결정문 결과는 한쪽만 실행 가능<br><br>**MCDC (변경 조건/결정)**<br>- **초점**: 개별 조건의 독립적 영향력 증명<br>- **단점**: 테스트 케이스 개수($n+1$) 제어로 조합 폭발 방지 및 최고 수준 품질 보증 |
| **차별화** | **고신뢰성 임베디드 SW 표준 컴플라이언스 및 도구 연계 전략**<br>1. **국제 표준 컴플라이언스 만족**: 자동차 기능안전 표준(ISO 26262)의 최고 등급인 ASIL D, 항공 우주 소프트웨어 표준인 DO-178C Level A, 원자력 IEC 60880 등에서 MCDC 커버리지 100% 만족을 의무 규정으로 명시.<br>2. **정적/동적 검증 도구(VectorCAST, LDRA) 활용 자동화**: 수작업으로 제어 흐름 그래프(CFG)를 그려 MCDC 테스트 케이스 쌍을 도출하는 병목을 해결하기 위해, 상용 도구를 IDE에 연동하여 컴파일 타임에 MCDC 미충족 경로 자동 탐지.<br>3. **테스트 데이터 주입(TFI, SFI)과 결합**: 하드웨어 가상 결함 주입(Software Fault Injection) 테스트 시 MCDC로 커버된 경로 위주로 결함을 주입하여 예외 처리(Exception Handling) 로직의 강건성(Robustness) 동시 검증. |
