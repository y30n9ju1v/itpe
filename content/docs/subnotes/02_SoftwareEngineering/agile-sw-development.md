# 애자일 개발방법론 서브노트

> - **개·동·고·변** (애자일 4대 가치: **개**인과 상호작용, **동**작하는 SW, **고**객 협력, **변**화 대응)
> - **계·스·일·데·회** (스크럼 5대 의식: 스프린트 **계**획, **스**프린트, **일**일 스크럼, **데**모(리뷰), **회**고)
> - **용·단·의·피·존** (XP 5대 가치: **용**기, **단**순성, **의**사소통, **피**드백, **존**중)

| **토픽명** | **애자일 개발방법론 (Agile Software Development)** |
| **정의** | 불확실성이 높은 환경에서 짧은 개발 주기(Sprint)를 반복하며 작동 가능한 소프트웨어를 신속하게 인도하고, 고객 피드백을 상시 반영하는 **고객/인간 중심 개발방법론** |
| **키워드** | 애자일 4대 선언, 스크럼(계·스·일·데·회), XP(용·단·의·피·존), 대규모 애자일(SAFe), CBD vs Agile |
| **개념도** | `[제품 백로그]` (요구사항 우선순위화)<br>&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[스프린트 계획회의]` ➔ `[스프린트 (1~4주)]` (일일 데일리 스크럼 15분) ➔ `[잠재적 인도 가능 제품]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▲&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`└───────────────── [리뷰 및 회고] ──────────────────────┘` |
| **구성요소** | 1. **스크럼 3대 역할**: 제품 책임자(PO - 백로그 관리), 스크럼 마스터(SM - 장애 제거), 개발팀<br>2. **스크럼 5대 의식**: 스프린트 계획, 스프린트(수행), 일일 스크럼, 스프린트 리뷰(데모), 스프린트 회고<br>3. **XP 5대 가치**: 용기, 단순성, 의사소통, 피드백, 존중<br>4. **XP 주요 실천법**: TDD(테스트 주도), 짝 프로그래밍, 리팩토링, 공동 소유권, 지속적 통합(CI)<br>5. **SAFe (Scaled Agile Framework)**: Portfolio ➔ Large Solution ➔ Program ➔ Team 레벨 전사 확장 프레임워크 |
| **비교** | **애자일 (Agile) 방법론**<br>- **무게중심**: 고객 협력 및 유연성 극대화<br>- **접근방식**: 점진적/적응형 기획 및 반복 개발<br>- **도메인**: 요구사항 변동성이 극도로 높은 웹/모바일/AI 서비스<br><br>**CBD (Component Based Development) 방법론**<br>- **무게중심**: 컴포넌트 재사용 및 설계의 정밀함<br>- **접근방식**: 체계적 도메인 분석 및 설계 기반 아키텍처 우선 구축<br>- **도메인**: 안정성과 확장성이 중요한 엔터프라이즈 및 공공 대형 시스템 |
| **차별화** | **대규모 애자일(SAFe) 도입 시 계약/조직 차원의 한계 및 극복 방안**<br>1. **동적 예산제도(Lean Budgeting) 전환**: 전통적 공공/엔터프라이즈의 연간 고정 예산 구조를 탈피하여 가치 스트림(Value Stream) 단위로 분기별 예산을 유연하게 재조정하는 펀딩 모델 적용.<br>2. **LACE(Lean-Agile Center of Excellence) 조직 신설**: 기존 통제 위주의 PMO를 애자일 코칭 및 리스크 제거를 지원하는 서비스형 LACE 조직으로 개편하여 조직 저항 최소화.<br>3. **하이브리드 모델(Water-Scrum-Fall)의 현실적 적용**: 기획(법률/인허가)과 배포(인프라 검증)는 폭포수 방식을 취하되, 핵심 개발 영역에서 스크럼을 고수하여 현실적 규제 장벽 우회. |
