# 소프트웨어 품질보증(SQA)과 인스펙션 서브노트

> **두음 머리에 박기 🧠**
> - **계·개·준·회·재·후** (Fagan 인스펙션 6단계: **계**획, **개**요 설명, **준**비(개별 검토), **회**의, **재**작업, **후**속 조치)
> - **중·작·검·기** (인스펙션 4대 참여 역할: **중**재자 Moderator, **작**성자 Author, **검**토자 Reviewer, **기**록자 Recorder)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 품질보증(SQA)과 인스펙션(Fagan Inspection)** |
| **정의** | **SQA**는 소프트웨어 개발 프로세스와 산출물이 정해진 품질 기준을 만족하는지 체계적으로 확인하는 활동이며, **인스펙션**은 SQA의 핵심 정적 검토 기법으로 요구사항·설계·코드 산출물을 구조화된 절차로 검토해 테스트 단계 대비 1/10의 비용으로 결함을 조기 제거한다 |
| **키워드** | ISO/IEC 25010, Fagan Inspection, 정적 검토, 워크스루, 동료검토, 결함 조기 발견 |
| **개념도** | `[ 계획 ]` → `[ 개요 설명 ]` → `[ 개별 준비 ]` → `[ 인스펙션 회의(결함 식별) ]` → `[ 재작업 ]` → `[ 후속 조치 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(회의 단계는 결함 "식별"만, "해결"은 재작업 단계)` |
| **구성요소** | 1. **SQA 목적**: 결함 예방, 조기 발견, 개발 프로세스 개선<br>2. **SQA 기능**: 품질 계획 수립, 표준 적용 검토, 감사, 메트릭 수집·분석, 개선 권고<br>3. **ISO/IEC 25010 품질**: 프로세스 품질 + 제품 품질 + 사용 품질의 통합<br>4. **인스펙션 6단계**: 계획 → 개요 설명 → 개별 준비 → 회의 → 재작업 → 후속 조치<br>5. **참여 역할**: 중재자(진행), 작성자(산출물 작성), 검토자(결함 발견), 기록자(결함 기록) |
| **비교** | **인스펙션 (정형 리뷰)**<br>- **절차**: 구조화된 6단계 프로세스, 역할 고정<br>- **목적**: 정량적 결함 데이터 수집·프로세스 개선<br><br>**워크스루/동료검토 (비정형 리뷰)**<br>- **절차**: 작성자 주도의 비형식적 검토 회의<br>- **목적**: 빠른 피드백, 절차 부담 최소화 |
| **차별화** | **테스트 전 결함 조기 제거를 위한 SQA 실무 전략**<br>1. **비용 효과 기반 우선순위화**: 인스펙션 결함 수정 비용이 테스트 단계의 1/10임을 근거로, 요구사항·설계 산출물에 인스펙션을 의무화하여 후행 결함 유입을 원천 차단.<br>2. **메트릭 기반 프로세스 개선**: 인스펙션에서 수집된 결함 유형·빈도 데이터를 SQA 메트릭으로 축적해, 반복되는 결함 패턴에 대한 코딩 표준·체크리스트를 지속 개선.<br>3. **경량화 적용**: 소규모 애자일 프로젝트에서는 전체 6단계 인스펙션 대신 페어 프로그래밍·동료검토로 대체하되, 안전 필수 모듈에는 정형 인스펙션을 유지하는 선택적 적용. |
