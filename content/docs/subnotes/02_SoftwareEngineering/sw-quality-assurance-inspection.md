# 소프트웨어 품질보증(SQA)과 인스펙션 서브노트

> **두음 머리에 박기 🧠**
> - **계·개·준·회·재·후** (Fagan 인스펙션 6단계: **계**획, **개**요 설명, **준**비(개별 검토), **회**의, **재**작업, **후**속 조치)
> - **중·작·검·기** (인스펙션 4대 참여 역할: **중**재자 Moderator, **작**성자 Author, **검**토자 Reviewer, **기**록자 Recorder)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **소프트웨어 품질보증(SQA)과 인스펙션(Fagan Inspection)** |
| **정의** | **SQA**: SW 개발프로세스·산출물 → 정해진품질기준 충족여부 체계적 확인활동 / **인스펙션**: SQA 핵심 정적검토기법, 요구사항·설계·코드 산출물 구조화절차 검토 → 테스트단계 대비 1/10 비용으로 결함 조기제거 |
| **키워드** | ISO/IEC 25010, Fagan Inspection, 정적 검토, 워크스루, 동료검토, 결함 조기 발견 |
| **개념도** | `[ 계획 ]` → `[ 개요 설명 ]` → `[ 개별 준비 ]` → `[ 인스펙션 회의(결함 식별) ]` → `[ 재작업 ]` → `[ 후속 조치 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`(회의 단계는 결함 "식별"만, "해결"은 재작업 단계)` |
| **구성요소** | 1. **SQA 목적**: 결함예방, 조기발견, 개발프로세스 개선<br>2. **SQA 기능**: 품질계획 수립, 표준적용 검토, 감사, 메트릭 수집·분석, 개선권고<br>3. **ISO/IEC 25010 품질**: 프로세스품질+제품품질+사용품질 통합<br>4. **인스펙션 6단계**: 계획→개요설명→개별준비→회의→재작업→후속조치<br>5. **참여역할**: 중재자(진행), 작성자(산출물작성), 검토자(결함발견), 기록자(결함기록) |
| **비교** | **인스펙션(정형 리뷰)**<br>- 절차: 구조화 6단계, 역할고정<br>- 목적: 정량적 결함데이터 수집·프로세스개선<br><br>**워크스루/동료검토(비정형 리뷰)**<br>- 절차: 작성자주도 비형식적 검토회의<br>- 목적: 빠른피드백, 절차부담 최소화 |
| **차별화** | **테스트前 결함조기제거 SQA 실무전략**<br>1. **비용효과 기반 우선순위화**: 인스펙션 결함수정비용=테스트단계 1/10 근거 → 요구사항·설계 산출물 인스펙션 의무화, 후행결함 유입차단<br>2. **메트릭 기반 프로세스개선**: 인스펙션 결함유형·빈도 데이터 → SQA메트릭 축적, 반복결함 패턴 대응 코딩표준·체크리스트 지속개선<br>3. **경량화 적용**: 소규모 애자일프로젝트 → 6단계 대신 페어프로그래밍·동료검토 대체, 안전필수모듈은 정형인스펙션 유지 선택적용 |
