# 스토리지 가상화 서브노트

> **두음 머리에 박기 🧠**
> - **블·파·오·클** (스토리지 가상화 4대 유형: **블**록 레벨, **파**일 레벨, **오**브젝트 스토리지, **클**라우드 가상화)
> - **씬·오·스·중** (스토리지 가상화 4대 핵심 기술: **씬** 프로비저닝, **오**토 티어링, **스**냅샷, **중**복제거)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **스토리지 가상화 (Storage Virtualization)** |
| **정의** | 물리적으로 분산된 이기종 스토리지 장치를 하나의 논리적 스토리지 풀(Pool)로 통합 관리하는 기술로, 관리 복잡성 감소·활용률 향상·무중단 마이그레이션을 목표로 함 |
| **키워드** | 블록/파일/오브젝트/클라우드 가상화, SAN/NAS, LUN, 인밴드/아웃밴드, 씬 프로비저닝, 오토 티어링 |
| **개념도** | `[ 이기종 물리 스토리지 (SAN/NAS/오브젝트) ]`<br>`→ [ 가상화 계층 (블록: LUN 매핑 / 파일: 단일 네임스페이스 / 오브젝트: REST API) ]`<br>`→ [ 논리적 스토리지 풀 ] → 애플리케이션에는 단일 저장소처럼 제공` |
| **구성요소** | 1. **블록 레벨 가상화**: SAN 스위치·컨트롤러로 물리 블록을 논리 블록으로 추상화, 고성능·저지연, DBMS 등에 적용, LUN 매핑·씬 프로비저닝<br>2. **파일 레벨 가상화**: NAS 게이트웨이로 여러 NAS를 단일 네임스페이스로 통합, 서버 재구성 없이 이동 가능<br>3. **오브젝트 스토리지**: 데이터+메타데이터+고유ID로 저장, REST API(HTTP) 접근, 무한 확장(AWS S3 등)<br>4. **클라우드 스토리지 가상화**: 퍼블릭 클라우드와 온프레미스 통합, 스토리지 게이트웨이(AWS Storage Gateway) |
| **비교** | **인밴드 (In-band)**<br>- **데이터 경로**: 가상화 장치를 통과<br>- **성능**: 병목 가능성 존재<br>- **관리**: 단순<br><br>**아웃밴드 (Out-of-band)**<br>- **데이터 경로**: 메타데이터만 가상화 장치 경유, 실 데이터는 직접 흐름<br>- **성능**: 데이터 흐름 간섭 없음<br>- **관리**: 복잡 (별도 메타데이터 서버 필요) |
| **차별화** | **워크로드 특성별 가상화 유형 선택과 효율화 기술 결합 전략**<br>1. **워크로드 기반 유형 선정**: 고성능 트랜잭션 DB는 블록 레벨을, 파일 공유·협업 환경은 파일 레벨을, 대용량 비정형 데이터(이미지·로그·백업)는 오브젝트 스토리지를 선택하는 계층적 설계.<br>2. **자동 계층화(Auto-Tiering)로 비용 최적화**: 접근 빈도가 높은 핫 데이터는 SSD, 콜드 데이터는 HDD·테이프로 자동 이동시켜 성능과 비용을 동시에 최적화.<br>3. **씬 프로비저닝과 중복제거 결합**: 실제 사용량만큼만 공간을 할당하는 씬 프로비저닝에 중복제거(Dedup)를 결합하면, 특히 백업·VDI 환경에서 물리 스토리지 소요량을 대폭 절감. |
