# 서버·네트워크 이중화 실무 (L4/SW/공공망 사례) 서브노트

> **두음 머리에 박기 🧠**
> - **RR·LC·IP·WRR** (L4 로드밸런싱 4대 알고리즘: **R**ound **R**obin, **L**east **C**onnection, **IP** Hash, **W**eighted **R**ound **R**obin)
> - **인·백·이** (공공망 인프라 장애 대응 3대 관점: **인**프라 관리, **백**업복구, **이**중화)
> - **3·2·1** (백업 원칙: **3**개 복사본, **2**가지 매체, **1**개는 오프사이트)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **서버·네트워크 이중화 (L4 스위치/소프트웨어 기반) 및 공공망 백업복구 실무** |
| **정의** | 단일 서버 장애로 인한 서비스 중단을 방지하는 **서버 이중화(L4 스위치 기반 vs 소프트웨어 기반)**와, 배터리 화재 등 공공망 인프라 장애에 대비한 **인프라관리·백업복구·이중화 3대 관점의 대응 체계** |
| **키워드** | VIP/Health Check, HAProxy/Keepalived(VRRP), 로드밸런싱 알고리즘, RTO/RPO, 3-2-1 백업 원칙, N+1 이중화 |
| **개념도** | `[ L4 스위치 기반 ]`<br>`클라이언트 → [L4 Switch(VIP)] → 서버1/서버2/서버3 (Health Check로 장애서버 자동 제외)`<br>`[ 소프트웨어 기반 ]`<br>`[HAProxy1] ← Keepalived(Master, VIP보유)` / `[HAProxy2] ← Keepalived(Backup)`<br>`→ Master 장애 시 VRRP로 VIP를 Backup에 자동 이관` |
| **구성요소** | 1. **L4 스위치 기반**: VIP(단일 진입점), Health Check(장애서버 자동 제외), 세션 유지(IP/Cookie 기반), 로드밸런싱 알고리즘(RR/LC/IP Hash/WRR)<br>2. **소프트웨어 기반**: HAProxy(고성능 오픈소스 LB), Keepalived(VRRP 기반 VIP 이관), Nginx(리버스프록시 LB), Pacemaker/Corosync(클러스터 리소스 관리)<br>3. **공공망 대응 - 인프라관리**: BMS(배터리관리시스템) 모니터링, 정기 절연저항 점검, 화재 예방(온도경보·자동소화)<br>4. **공공망 대응 - 백업복구/이중화**: RTO/RPO 설정, 다중 전원 공급(한전+발전기+UPS 삼중화), 3-2-1 백업 원칙, Active-Active 구성, 지리적 이중화(50km 이상), N+1 이중화 |
| **비교** | **L4 스위치 기반 이중화**<br>- **비용**: 고가(전용 장비)<br>- **성능**: 높음(하드웨어 처리)<br>- **유연성**: 낮음(펌웨어 의존)<br>- **적합 환경**: 대규모 온프레미스<br><br>**소프트웨어 기반 이중화**<br>- **비용**: 저렴(오픈소스)<br>- **성능**: 중간(CPU 사용)<br>- **유연성**: 높음(코드 수정 가능)<br>- **적합 환경**: 클라우드·컨테이너 |
| **차별화** | **단일 장애점(SPOF) 제거를 위한 다층 이중화 실무 전략**<br>1. **RTO/RPO 목표 기반 이중화 수준 결정**: 서비스별로 허용 가능한 복구시간(RTO)·데이터손실(RPO)을 먼저 정의한 뒤, 이를 만족하는 최소 비용의 이중화 방식(L4 스위치 vs SW, Active-Active vs Standby)을 역산하여 설계.<br>2. **공공망 장애 사례에서 드러난 SPOF 패턴**: 배터리(ESS/UPS) 노후화 모니터링 부재, 단일 공급 경로, 지리적 분산 부재가 반복되는 실패 패턴이므로, BMS 실시간 모니터링과 삼중 전원 확보, 지리적 이중화를 표준 대응 체계로 수립.<br>3. **3-2-1 원칙과 정기 훈련의 결합**: 기술적 이중화(L4/SW, 다중 전원)만으로는 부족하며, 3-2-1 백업 원칙(3개 복사본·2개 매체·1개 오프사이트)과 연 1회 이상 BCP/DR 실전 훈련을 병행해야 실제 장애 시 복구 절차의 실효성을 검증할 수 있음. |
