# 시스템 버스와 버스 중재 서브노트

> **두음 머리에 박기 🧠**
> - **주·데·제** (시스템 버스 3대 구성: **주**소 버스(단방향), **데**이터 버스(양방향), **제**어 버스(양방향))
> - **데·폴·독** (집중식 버스 중재 3방식: **데**이지 체인 Daisy Chain, **폴**링 Polling, **독**립 요청 Independent Request)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **시스템 버스 (System Bus) 구성 및 버스 중재 (Bus Arbitration)** |
| **정의** | CPU·메모리·I/O 장치 간 주소·데이터·제어 신호를 전달하는 공유 통신 경로인 **시스템 버스**와, 공유 자원인 버스에 대한 동시 접근 충돌을 방지하기 위한 **버스 중재 메커니즘** |
| **키워드** | 주소/데이터/제어 버스, 집중식/분산식 중재, 데이지 체인, 폴링, 독립 요청, 버스 대역폭 |
| **개념도** | `[ 집중식 중재 - 데이지 체인 ]`<br>`CPU(중재기) → 장치1 → 장치2 → 장치3 (직렬 Bus Grant 전달)`<br>`[ 집중식 중재 - 독립 요청 ]`<br>`장치1 ─(개별 요청/허가선)─→ 중재기 ←─(개별 요청/허가선)─ 장치2`<br>`[ 분산식 중재 ]`<br>`각 장치가 자체 ID 비교로 최고 우선순위 자기 선택 (중재기 없음)` |
| **구성요소** | 1. **주소 버스**: CPU→장치 단방향, 메모리·I/O 주소 전송<br>2. **데이터 버스**: 양방향, 실제 데이터 전송(8/16/32/64비트)<br>3. **제어 버스**: 양방향, 읽기/쓰기·인터럽트·버스 요청 신호<br>4. **버스 성능 지표**: 버스 대역폭 = 버스 폭(bit) × 클럭(Hz) / 8, 버스 점유율 = 사용 시간/전체 시간 |
| **비교** | **데이지 체인 (Daisy Chain)**<br>- **구조**: 직렬 연결, 우선순위 고정(장치1 우선)<br>- **장점**: 단순, 배선 적음<br>- **단점**: 후순위 장치의 기아(Starvation) 발생 가능<br><br>**독립 요청 (Independent Request)**<br>- **구조**: 장치별 개별 요청/허가선, 중재기가 우선순위 결정<br>- **장점**: 빠른 응답<br>- **단점**: 배선 수 많음 |
| **차별화** | **버스 중재 방식별 적용 환경과 기아 문제 해결 전략**<br>1. **데이지 체인 기아 문제 완화**: 후순위 장치가 만성적으로 버스를 획득하지 못하는 문제를 해결하기 위해, 대기 시간에 비례하여 우선순위를 격상하는 에이징(Aging) 정책을 중재 로직에 결합.<br>2. **분산식 중재의 현대적 적용**: 중재기 없이 각 장치가 자체 ID 비교로 우선순위를 결정하는 자기 선택 방식은 IEEE 1394(FireWire), SPI 버스 등 소규모·저지연 요구 인터페이스에 적합.<br>3. **DMA와 버스 중재의 연계**: DMA 컨트롤러는 스스로 버스 마스터가 되어 CPU와 버스 점유권을 경쟁하므로, DMA 전송 중 CPU의 버스 요구가 지연(Hold)되는 현상을 고려한 버스 중재 우선순위 설계가 필요. |
