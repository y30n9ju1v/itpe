# 파이프라인 및 해저드 서브노트

> **두음 머리에 박기 🧠**
> - **구·데·제** (파이프라인 3대 해저드: **구**조적 해저드 Structural, **데**이터 해저드 Data, **제**어 해저드 Control)
> - **알·오·더블유** (데이터 해저드 RAW: **R**ead **A**fter **W**rite - 아직 쓰지 않은 레지스터를 읽으려 할 때의 해저드)
> - **아·디·이·엠·더블유** (MIPS 5단계 파이프라인: **I**F 명령어 인출 ➔ **I**D 명령어 해독 ➔ **E**X 실행 ➔ **M**EM 메모리 액세스 ➔ **W**B 쓰기 되돌리기)

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **CPU 명령어 파이프라이닝 (Pipelining) 및 파이프라인 해저드 (Hazard)** |
| **정의** | CPU의 명령어 처리 과정을 여러 단계(IF-ID-EX-MEM-WB)로 나누어 동시에 중첩 실행하는 **병렬 처리 기술(파이프라이닝)**과, 명령어 간 의존성에 의해 파이프라인이 멈추는 **해저드(구·데·제) 통제 기술** |
| **키워드** | 5단계 파이프라인, 구조적/데이터/제어 해저드, 포워딩 (Fowarding), 지연 분기, 분기 예측, 1사이클 클록 |
| **개념도** | **[ 5단계 파이프라인 중첩 실행 구조 및 해저드 버블(Stall) ]**<br>시간 (Time) ➔<br>명령어 1: `[ IF ] ➔ [ ID ] ➔ [ EX ] ➔ [ MEM ] ➔ [ WB ]`<br>명령어 2: &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`[ IF ] ➔ [ ID ] ➔ [ EX ] ➔ [ MEM ] ➔ [ WB ]`<br>명령어 3: &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`[ IF ] ➔ [  Bubble (Stall)  ] ➔ [ ID ] ➔ [ EX ] ➔ [ MEM ] ➔ [ WB ]` (의존성 발생으로 지연) |
| **구성요소** | 1. **MIPS 5단계**: IF(명령어 인출), ID(명령어 해독/레지스터 읽기), EX(연산 실행), MEM(메모리 참조), WB(레지스터 기록)<br>2. **구조적 해저드**: 두 개 이상의 명령어가 동일한 하드웨어 자원(예: 메모리 버스)을 동시에 요구할 때 발생 (해결: 메모리/캐시 분리)<br>3. **데이터 해저드**: 이전 명령어의 연산 결과가 반영되기 전에 다음 명령어가 참조하려 할 때 발생 (RAW, WAR, WAW)<br>4. **제어 해저드**: 분기 명령어(Branch)에 의해 다음에 실행할 명령어 주소가 결정되지 않았을 때 발생 (Stall 유발) |
| **비교** | **구조적 해저드 해결책**<br>- **기법**: 하드웨어 자원 분리<br>- **방법**: 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)로 물리적 분리<br><br>**데이터 해저드 해결책**<br>- **기법**: 포워딩(Forwarding) / 우회(Bypassing)<br>- **방법**: WB 단계까지 기다리지 않고 EX 단계 연산 결과를 다음 EX로 직접 바이패스<br><br>**제어 해저드 해결책**<br>- **기법**: 분기 예측(Branch Prediction) / 지연 분기<br>- **방법**: 분기 결과를 가정하여 실행하거나 지연 슬롯(Delay Slot) 활용 |
| **차별화** | **고성능 비순차 실행(Out-of-Order Execution) 아키텍처 및 분기 예측 고도화 방안**<br>1. **토마술로 알고리즘 (Tomasulo Algorithm) 기반 동적 스케줄링**: 데이터 해저드(WAR, WAW)를 방지하기 위해 하드웨어적인 레지스터 리네이밍(Register Renaming)과 예약 스테이션(Reservation Stations)을 도입하여, 명령어들이 순서와 상관없이 실행 가능한 즉시 실행되도록 통제.<br>2. **하이브리드 분기 예측기 (Hybrid Branch Predictor)**: 1-Bit/2-Bit 전역 예측기의 한계를 극복하기 위해, 지역 분기 이력(Local History)과 글로벌 분기 이력(Global History)을 혼합하여 토너먼트식으로 동적 선택하는 2단계 예측 알고리즘 적용.<br>3. **소프트웨어 루프 풀기 (Loop Unrolling) 기법**: 루프 조건 제어(제어 해저드 발생 빈도 높음)에 의한 분기 오버헤드를 낮추기 위해, 컴파일러 단에서 루프 내부 코드를 복사 전개하여 조건 분기 횟수 자체를 정적으로 수축. |
