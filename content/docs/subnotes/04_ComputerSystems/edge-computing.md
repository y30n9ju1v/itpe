# 엣지 컴퓨팅과 클라우드 컴퓨팅 비교 서브노트

> **두음 머리에 박기 🧠**
> - **디·로·리** (Cloud-Edge Continuum 3계층: **디**바이스 엣지(온디바이스), **로**컬 엣지(공장게이트웨이·기지국 MEC), **리**전 엣지(AWS Outposts))
> - **레·대·프** (엣지 컴퓨팅 3대 이점: **레**이턴시 감소, **대**역폭 절감, **프**라이버시 보호(로컬 처리))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **엣지 컴퓨팅(Edge Computing)과 클라우드 컴퓨팅(Cloud Computing) 비교** |
| **정의** | 데이터생성 지점(엣지) 근처에서 연산 수행 → 레이턴시·대역폭소비 최소화하는 분산컴퓨팅 패러다임, 중앙클라우드→말단디바이스 근처로 연산위치 이동 → 실시간성·프라이버시 대응 |
| **키워드** | Cloud-Edge Continuum, MEC(Multi-access Edge Computing), 레이턴시, TinyML, KubeEdge |
| **개념도** | `클라우드(중앙): ML모델 학습, 장기분석, 글로벌정책`<br>`&nbsp;&nbsp;&nbsp;&nbsp;↕ 모델 배포·집계 데이터`<br>`엣지(중간계층): 데이터 전처리, AI 추론, 실시간 집계`<br>`&nbsp;&nbsp;&nbsp;&nbsp;↕ 원시 데이터 일부`<br>`디바이스(말단): 센서 수집, 임계치 반응, TinyML` |
| **구성요소** | 1. **엣지 3계층**: 디바이스엣지(온디바이스 처리), 로컬엣지(공장게이트웨이·기지국 MEC), 리전엣지(AWS Outposts)<br>2. **핵심 비교지표**: 처리위치(원격데이터센터 vs 생성지점 근처), 레이턴시(수십~수백ms vs 수ms이하), 대역폭소비(전체전송 vs 필요데이터만), 네트워크의존성(높음 vs 낮음/오프라인가능)<br>3. **주요 적용사례**: 자율주행(200ms지연 시 100km/h서 5.5m 추가이동 → 차량내 엣지로 1ms 즉시처리), 스마트팩토리(엣지AI서버 10ms이내 불량판정), 5G MEC(기지국서버 1ms이하 AR/VR)<br>4. **관련 기술/표준**: AWS Outposts, Azure Stack Edge, ETSI MEC, KubeEdge, EdgeX Foundry, TinyML |
| **비교** | **클라우드 컴퓨팅**<br>- **처리위치**: 원격 데이터센터<br>- **레이턴시**: 높음(수십~수백ms)<br>- **컴퓨팅자원**: 거의 무한<br>- **관리복잡도**: 낮음(중앙화)<br><br>**엣지 컴퓨팅**<br>- **처리위치**: 데이터생성 지점 근처<br>- **레이턴시**: 낮음(수ms 이하)<br>- **컴퓨팅자원**: 제한적<br>- **관리복잡도**: 높음(분산관리, 물리보안 취약) |
| **차별화** | **클라우드-엣지 하이브리드 아키텍처 설계 실무**<br>1. **스마트팩토리 하이브리드**: 다수카메라 초당60프레임 전체전송 시 대역폭비용 폭증 → 엣지AI서버(GPU) 즉시불량판정(10ms이내) 후 불량이미지·통계(원본 1~5%)만 클라우드 전송 → 비용 90%절감<br>2. **엣지 디바이스 보안**: 물리탈취·해킹 취약 → TPM기반 HW보안, TLS 양방향인증, OTA 자동패치<br>3. **엣지-클라우드 데이터 일관성**: 네트워크단절 시 오프라인싱크 문제 → 이벤트소싱으로 순서보장큐 저장·복구 시 자동동기화, 충돌해결정책(최신시간우선) 사전정의 |
