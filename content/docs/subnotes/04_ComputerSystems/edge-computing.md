# 엣지 컴퓨팅과 클라우드 컴퓨팅 비교 서브노트

> **두음 머리에 박기 🧠**
> - **디·로·리** (Cloud-Edge Continuum 3계층: **디**바이스 엣지(온디바이스), **로**컬 엣지(공장게이트웨이·기지국 MEC), **리**전 엣지(AWS Outposts))
> - **레·대·프** (엣지 컴퓨팅 3대 이점: **레**이턴시 감소, **대**역폭 절감, **프**라이버시 보호(로컬 처리))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **엣지 컴퓨팅(Edge Computing)과 클라우드 컴퓨팅(Cloud Computing) 비교** |
| **정의** | 데이터 생성 지점(엣지)에 가까운 곳에서 컴퓨팅을 수행해 레이턴시와 대역폭 소비를 최소화하는 분산 컴퓨팅 패러다임으로, 중앙 집중형 클라우드 처리에서 말단 디바이스 근처로 연산 위치를 이동시켜 실시간성·프라이버시 요구에 대응함 |
| **키워드** | Cloud-Edge Continuum, MEC(Multi-access Edge Computing), 레이턴시, TinyML, KubeEdge |
| **개념도** | `클라우드(중앙): ML모델 학습, 장기분석, 글로벌정책`<br>`&nbsp;&nbsp;&nbsp;&nbsp;↕ 모델 배포·집계 데이터`<br>`엣지(중간계층): 데이터 전처리, AI 추론, 실시간 집계`<br>`&nbsp;&nbsp;&nbsp;&nbsp;↕ 원시 데이터 일부`<br>`디바이스(말단): 센서 수집, 임계치 반응, TinyML` |
| **구성요소** | 1. **엣지 3계층**: 디바이스 엣지(온디바이스 처리), 로컬 엣지(공장 게이트웨이·기지국 MEC), 리전 엣지(AWS Outposts)<br>2. **핵심 비교지표**: 처리위치(원격 데이터센터 vs 생성지점 근처), 레이턴시(수십~수백ms vs 수ms 이하), 대역폭 소비(모든 데이터 전송 vs 필요 데이터만), 네트워크 의존성(높음 vs 낮음/오프라인 가능)<br>3. **주요 적용사례**: 자율주행(200ms 지연 시 100km/h에서 5.5m 추가 이동 → 차량 내 엣지로 1ms 즉시 처리), 스마트팩토리(엣지 AI 서버로 10ms 이내 불량 판정), 5G MEC(기지국 내 서버로 1ms 이하 AR/VR 처리)<br>4. **관련 기술/표준**: AWS Outposts, Azure Stack Edge, ETSI MEC, KubeEdge, EdgeX Foundry, TinyML |
| **비교** | **클라우드 컴퓨팅**<br>- **처리위치**: 원격 데이터센터<br>- **레이턴시**: 높음(수십~수백ms)<br>- **컴퓨팅 자원**: 거의 무한<br>- **관리 복잡도**: 낮음(중앙화)<br><br>**엣지 컴퓨팅**<br>- **처리위치**: 데이터 생성 지점 근처<br>- **레이턴시**: 낮음(수ms 이하)<br>- **컴퓨팅 자원**: 제한적<br>- **관리 복잡도**: 높음(분산 관리, 물리적 보안 취약 가능) |
| **차별화** | **클라우드-엣지 하이브리드 아키텍처 설계 실무**<br>1. **스마트 팩토리 하이브리드 설계**: 카메라 다수가 초당 60프레임 촬영 시 전체 영상을 클라우드로 전송하면 대역폭 비용이 폭증하므로, 엣지 AI 서버(GPU)에서 즉시 불량 판정(10ms 이내) 후 불량품 이미지·통계(원시 영상의 1~5%)만 클라우드로 전송해 네트워크 비용을 90% 절감.<br>2. **엣지 디바이스 보안 강화**: 엣지는 물리적 탈취·해킹에 취약하므로 TPM 기반 하드웨어 보안, TLS 양방향 인증, OTA 업데이트로 보안 패치를 자동화.<br>3. **엣지-클라우드 데이터 일관성**: 네트워크 단절 시 오프라인 싱크 문제가 발생하므로 이벤트 소싱 패턴으로 순서 보장 큐에 저장 후 복구 시 자동 동기화하고, 충돌 해결 정책(최신 시간 우선 등)을 사전 정의. |
