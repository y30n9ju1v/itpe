# 인터미턴트 컴퓨팅 서브노트

> **두음 머리에 박기 🧠**
> - **상·체·예** (인터미턴트 컴퓨팅 3대 기술 과제: **상**태 일관성 State Consistency, **체**크포인팅 Checkpointing, **예**측 어려움 에너지 Prediction)
> - **태·알·진·열** (에너지 하베스팅 4대 소스: **태**양광, **알**RF, **진**동/압전, **열**전)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **인터미턴트 컴퓨팅 (Intermittent Computing)** |
| **정의** | 태양광·RF·진동 등 주변 환경에서 수확한 에너지(Energy Harvesting)로 간헐적으로 동작하는 컴퓨팅 패러다임으로, 배터리가 없거나 충전 불가능한 극한 환경 IoT 센서에 적용되며 전원 중단 후 재개 시 연산 일관성 유지가 핵심 과제 |
| **키워드** | 에너지 하베스팅, 비휘발성 메모리(FRAM/MRAM), 체크포인팅, 상태 일관성, WAR 해저드, Task-based 프로그래밍 |
| **개념도** | `[ 에너지 하베스팅 (태양광/RF/진동/열전) ] → [ 커패시터 충전 ]`<br>`→ 임계치 도달 시 [ 간헐적 실행 시작 ] → 진행 상태를 비휘발성 메모리(FRAM/MRAM)에 체크포인팅`<br>`→ 전원 부족 시 [ 전원 차단 ] → 에너지 재충전 후 [ 체크포인트에서 복원·재개 ]` |
| **구성요소** | 1. **간헐적 실행**: 에너지가 충분할 때만 실행, 부족 시 전원 차단<br>2. **비휘발성 메모리 활용**: FRAM/MRAM 등으로 전원 차단 후에도 실행 상태 보존<br>3. **체크포인팅**: 실행 진행 상태를 주기적으로 저장하고 재개 시 복원<br>4. **실행 비결정성**: 전원 차단 시점 예측 불가로 트랜잭셔널 보장이 어려움 |
| **비교** | **일반 저전력 컴퓨팅 (배터리 기반)**<br>- **전원**: 배터리로 연속 공급 (유한하지만 지속적)<br>- **실행 모델**: 연속 실행, 상태 일관성 문제 없음<br><br>**인터미턴트 컴퓨팅 (에너지 하베스팅 기반)**<br>- **전원**: 환경 에너지로 간헐적 공급 (불규칙, 예측 불가)<br>- **실행 모델**: 전원 차단·재개 반복, WAR 해저드 등 상태 불일치 위험 존재 |
| **차별화** | **배터리리스 IoT 실무 설계를 위한 기술 과제 대응 전략**<br>1. **상태 일관성 확보를 위한 트랜잭셔널 설계**: 읽기 후 쓰기 도중 전원이 차단되는 WAR(Write-After-Read) 해저드를 방지하기 위해, 연산을 멱등성(Idempotent) 단위로 설계하거나 트랜잭셔널 메모리 기법을 적용해 재실행 시에도 결과 일관성을 보장.<br>2. **적응형 체크포인팅으로 오버헤드 최소화**: 너무 잦은 체크포인팅은 에너지를 낭비하고 너무 드문 체크포인팅은 재실행 비용을 키우므로, 배터리(커패시터) 잔량을 기준으로 저장 주기를 동적 조정.<br>3. **Task 기반 프로그래밍 모델 채택**: 에너지 가용성을 사전 예측하기 어려운 한계를 극복하기 위해 Mementos·TICS·Alpaca와 같이 작업을 에너지 단위로 분할·재시작 가능한 태스크로 설계하는 프로그래밍 모델을 적용. |
