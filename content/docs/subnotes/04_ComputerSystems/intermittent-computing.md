# 인터미턴트 컴퓨팅 서브노트

> **두음 머리에 박기 🧠**
> - **상·체·예** (인터미턴트 컴퓨팅 3대 기술 과제: **상**태 일관성 State Consistency, **체**크포인팅 Checkpointing, **예**측 어려움 에너지 Prediction)
> - **태·알·진·열** (에너지 하베스팅 4대 소스: **태**양광, **알**RF, **진**동/압전, **열**전)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **인터미턴트 컴퓨팅 (Intermittent Computing)** |
| **정의** | 태양광·RF·진동 등 주변 환경에서 수확한 에너지(Energy Harvesting)로 간헐적으로 동작하는 컴퓨팅 패러다임으로, 배터리가 없거나 충전 불가능한 극한 환경 IoT 센서에 적용되며 전원 중단 후 재개 시 연산 일관성 유지가 핵심 과제 |
| **키워드** | 에너지 하베스팅, 비휘발성 메모리(FRAM/MRAM), 체크포인팅, 상태 일관성, WAR 해저드, Task-based 프로그래밍 |
| **개념도** | `[ 에너지 하베스팅 (태양광/RF/진동/열전) ] → [ 커패시터 충전 ]`<br>`→ 임계치 도달 시 [ 간헐적 실행 시작 ] → 진행 상태를 비휘발성 메모리(FRAM/MRAM)에 체크포인팅`<br>`→ 전원 부족 시 [ 전원 차단 ] → 에너지 재충전 후 [ 체크포인트에서 복원·재개 ]` |
| **구성요소** | 1. **간헐적 실행**: 에너지 충분 시만 실행, 부족 시 전원차단<br>2. **비휘발성 메모리 활용**: FRAM/MRAM → 전원차단 후에도 실행상태 보존<br>3. **체크포인팅**: 실행상태 주기적 저장 → 재개 시 복원<br>4. **실행 비결정성**: 전원차단 시점 예측불가 → 트랜잭셔널 보장 곤란 |
| **비교** | **일반 저전력 컴퓨팅 (배터리 기반)**<br>- 전원: 배터리 연속공급 (유한·지속적)<br>- 실행모델: 연속실행, 상태일관성 문제 없음<br><br>**인터미턴트 컴퓨팅 (에너지 하베스팅 기반)**<br>- 전원: 환경에너지 간헐공급 (불규칙·예측불가)<br>- 실행모델: 전원차단·재개 반복, WAR해저드 등 상태불일치 위험 |
| **차별화** | **배터리리스 IoT 실무설계 기술과제 대응전략**<br>1. **상태일관성 확보 트랜잭셔널 설계**: WAR(Write-After-Read) 해저드 방지 → 연산 멱등성(Idempotent) 단위 설계 or 트랜잭셔널 메모리 → 재실행 시 결과일관성 보장<br>2. **적응형 체크포인팅 → 오버헤드 최소화**: 과빈번=에너지낭비, 과희소=재실행비용↑ → 커패시터 잔량기준 저장주기 동적조정<br>3. **Task 기반 프로그래밍 모델 채택**: 에너지가용성 예측난 극복 → Mementos·TICS·Alpaca식 에너지단위 분할·재시작 태스크 설계 |
