# 정보시스템 하드웨어 규모산정 방법 서브노트

> **두음 머리에 박기 🧠**
> - **기·유·용** (HW 규모산정 3대 방법: **기**준 성능법 Benchmark, **유**사 시스템 기준법 Reference, **용**량 계획법 Capacity Planning)
> - **피·성·가·여** (규모산정 시 4대 고려사항: **피**크 부하, **성**장률, **가**용성 요건, **여**유율)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **정보시스템 하드웨어 규모산정 방법 (TTAK.KO-10.0292/R3)** |
| **정의** | 공공기관 정보시스템 구축 시 CPU·메모리·스토리지 등 하드웨어 규모를 산정하기 위한 TTA 단체표준으로, **기준 성능법·유사 시스템 기준법·용량 계획법** 3가지 방법으로 적정 HW 규모를 도출 |
| **키워드** | TPC-C/SPEC CPU 벤치마크, 유사 시스템 보정 계수, 피크 부하, 여유율(30~50%), RAID 오버헤드 |
| **개념도** | `업무 분석 → 피크 부하 산정 → [ 기준 성능법 / 유사 시스템 기준법 / 용량 계획법 ] → 자원 요구량 계산 → 여유율 적용 → 최종 HW 규모`<br>`CPU 코어 수 = (최대 TPS × 평균 CPU 사용 시간) / (1 - 여유율)`<br>`스토리지 = (일 데이터 증가량 × 보존 기간) × (1 + RAID 오버헤드) × 여유율` |
| **구성요소** | 1. **기준 성능법**: TPC-C·SPEC CPU 벤치마크 → 업무 트랜잭션 환산 비교, 객관적이나 실워크로드와 차이 존재<br>2. **유사 시스템 기준법**: 기구축 유사시스템 성능데이터 → 보정계수 조정 참조, 현실적이나 참조시스템 확보 곤란<br>3. **용량 계획법**: 업무량(TX·사용자·데이터량) 분석 → 피크부하 산정 → 자원요구량 계산 → 여유율 적용<br>4. **여유율 기준**: CPU 30~40%, 메모리 30%, 스토리지 20~30%, 고부하시스템 40~50% |
| **비교** | **기준 성능법 / 유사 시스템 기준법**<br>- 근거: 표준 벤치마크치 / 기구축 실적데이터<br>- 장점: 객관적 비교 가능 / 실운영데이터 기반<br>- 단점: 벤치마크-실환경 워크로드 괴리 / 적합 참조사례 확보 곤란<br><br>**용량 계획법**<br>- 근거: 자체 업무량 정량분석(피크부하 등)<br>- 장점: 조직 고유요구사항 반영<br>- 단점: 초기데이터 부재 시 추정오차 발생가능 |
| **차별화** | **HA 이중화·클라우드 환경 연계 규모산정 실무전략**<br>1. **HA 구성 시 자원 추가반영**: Active-Active·Standby 이중화 → 기본규모×이중화배수 = 실조달규모<br>2. **RAID 오버헤드 포함 스토리지 산정**: 논리 데이터증가량 + RAID효율((N-1)/N 등) 물리오버헤드 반영 → 실필요용량 일치<br>3. **클라우드 오토스케일링 관계**: 온프레미스=사전 고정자원 확보 / 클라우드=오토스케일링으로 여유율 실시간 동적대체 → 초기산정 부담 완화 |
