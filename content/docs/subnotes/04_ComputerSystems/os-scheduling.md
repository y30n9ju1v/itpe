# 운영체제 스케줄링 (CPU·디스크·실시간) 서브노트

> **두음 머리에 박기 🧠**
> - **에프·에스·라·엠** (주요 CPU 스케줄링 4종: **F**CFS, **S**JF/**S**RT, **R**ound **R**obin, **M**LQ/MLFQ)
> - **S·S·T·F·vs·S·L·T·F** (디스크 스케줄링 2대 기준: **S**hortest **S**eek **T**ime **F**irst(탐색시간) vs **S**hortest **L**atency **T**ime **F**irst(회전지연))
> - **알·이** (실시간 스케줄링 2종: **R**ate Monotonic(정적 우선순위), **E**arliest **D**eadline **F**irst(동적 우선순위))

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **운영체제 스케줄링 (CPU 스케줄링·디스크 스케줄링·실시간 스케줄링 RM/EDF)** |
| **정의** | 제한된 CPU·디스크 자원을 여러 프로세스·I/O 요청에 효율적으로 배분하는 정책으로, CPU 스케줄링은 프로세스 실행 순서를, 디스크 스케줄링은 I/O 요청 처리 순서(탐색시간·회전지연)를 결정하며, 실시간 스케줄링(RM/EDF)은 마감 시간(Deadline) 준수를 최우선 목표로 우선순위를 부여 |
| **키워드** | SJF/SRT, FCFS, Round Robin, MLQ/MLFQ, SSTF/SLTF, 기아(Starvation), Aging, RM/EDF, WCET |
| **개념도** | `[ CPU 스케줄링 ]`<br>`FCFS(도착순) → SJF(최단작업, 비선점) → SRT(SJF 선점형) → Round Robin(시간할당량 순환) → MLFQ(다단계 큐)`<br>`[ 디스크 스케줄링 ]`<br>`현재 헤드 위치 → SSTF(탐색시간 최소 트랙 선택) → SLTF(동일 트랙 내 회전지연 최소 섹터 선택)`<br>`[ 실시간 스케줄링 ]`<br>`태스크 τ=(C,T,D) → RM(주기 짧을수록 고정 우선순위↑) / EDF(마감 임박 순 동적 우선순위)` |
| **구성요소** | 1. **SJF (Shortest Job First)**: CPU 버스트 최단 우선, 비선점형, 평균 대기시간 최적이나 긴 프로세스 기아 발생<br>2. **SRT (Shortest Remaining Time)**: SJF의 선점형 버전, 새 프로세스 도착 시 남은시간 비교 선점, 더 낮은 평균대기시간이나 잦은 컨텍스트 스위칭<br>3. **SSTF**: 헤드에서 탐색시간 최소 요청 우선, 원거리 요청 기아 가능<br>4. **SLTF**: SSTF로 트랙 선택 후 동일 트랙 내 회전지연 최소 섹터 순서 결정<br>5. **RM(Rate Monotonic)**: 주기(T)가 짧을수록 높은 정적 우선순위, 활용률 상한 U≤n(2^(1/n)-1)(n→∞ 시 ln2≈69.3%)인 충분조건, WCET 정적 분석 용이<br>6. **EDF(Earliest Deadline First)**: 마감 시간이 가장 임박한 태스크에 동적 우선순위, 활용률 상한 U=Σ(Ci/Ti)≤1인 필요충분조건(이론적 최적), 구현 복잡도 높음 |
| **비교** | **SJF (비선점)**<br>- **기준**: 전체 CPU 버스트 시간<br>- **오버헤드**: 낮음<br>- **평균 대기시간**: 낮음<br><br>**SRT (선점)**<br>- **기준**: 남은 CPU 버스트 시간<br>- **오버헤드**: 높음 (빈번한 컨텍스트 스위칭)<br>- **평균 대기시간**: SJF보다 더 낮음 (이론적 최적)<br><br>**RM (정적)**<br>- **우선순위**: 주기 기반 고정<br>- **최대 활용률**: ~69.3%(n→∞)<br>- **적합**: Hard Real-Time(정적 분석 용이, 항공기·에어백)<br><br>**EDF (동적)**<br>- **우선순위**: 마감시간 기반 동적 재계산<br>- **최대 활용률**: 100%<br>- **적합**: Firm/Soft Real-Time(활용률 최대화, Linux SCHED_DEADLINE) |
| **차별화** | **기아 현상 방지와 스케줄링 정책 조합 전략**<br>1. **기아(Starvation)와 Aging 대응**: SJF·SSTF·Priority 스케줄링 모두 특정 프로세스·요청이 계속 밀리는 기아 문제를 공통적으로 안고 있어, 대기 시간에 비례해 우선순위를 점진적으로 높이는 Aging 기법을 결합해 보완.<br>2. **CPU와 디스크 스케줄링의 목적 차이 인식**: CPU 스케줄링은 CPU 사용률·응답시간 최적화가 목표인 반면 디스크 스케줄링은 기계적 탐색시간·회전지연 최소화가 목표이므로, 답안 작성 시 두 영역을 먼저 구분한 뒤 세부 알고리즘을 비교.<br>3. **MLFQ를 통한 실무 절충**: 다단계 피드백 큐(MLFQ)는 짧은 작업에는 SJF와 유사한 이점을, 긴 작업에는 Round Robin의 공정성을 부여하는 방식으로 이론적 알고리즘의 한계를 절충하여 현대 범용 OS(Linux CFS 등)에 적용.<br>4. **Hard Real-Time에서 이론적 열세인 RM 선호 이유**: 자율주행 ECU(ISO 26262 ASIL-D) 등에서는 활용률이 EDF보다 낮음에도 WCET 정적 분석·과부하 시 예측 가능한 동작 때문에 RM을 채택하고, Linux SCHED_DEADLINE(EDF 구현)은 CBS(Constant Bandwidth Server)로 과부하 태스크를 격리해 다른 태스크의 마감을 보호. |
