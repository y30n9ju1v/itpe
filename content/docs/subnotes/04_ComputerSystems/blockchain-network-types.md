# 블록체인 네트워크 유형 (퍼블릭/프라이빗/컨소시엄) 서브노트

> **두음 머리에 박기 🧠**
> - **퍼·프·컨** (블록체인 네트워크 3대 유형: **퍼**블릭 Public, **프**라이빗 Private, **컨**소시엄 Consortium)
> - **PoW·PoS·PBFT·PoA** (합의 알고리즘 4종: **PoW** 작업증명, **PoS** 지분증명, **PBFT** 비잔틴장애허용, **PoA** 권위증명)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **블록체인 네트워크 유형 (퍼블릭·프라이빗·컨소시엄 블록체인)** |
| **정의** | 블록체인을 참여 범위·권한 제어 방식에 따라 누구나 참여 가능한 **퍼블릭**, 허가된 자만 참여하는 **프라이빗**, 허가된 다수 기관이 공동 운영하는 **컨소시엄**으로 구분한 네트워크 아키텍처 |
| **키워드** | 탈중앙화 수준, PoW/PoS/PBFT/PoA, 트랜잭션 속도(TPS), 익명성/투명성, Hyperledger Fabric/R3 Corda |
| **개념도** | `[ 탈중앙화 ↑, 성능 ↓, 익명성 ↑ ] 퍼블릭 (Bitcoin, Ethereum)`<br>`[ 중간 ] 컨소시엄 (R3 Corda, Quorum - 금융 컨소시엄)`<br>`[ 중앙화 ↑, 성능 ↑, 투명성 ↓ ] 프라이빗 (Hyperledger Fabric - 기업 내부)` |
| **구성요소** | 1. **퍼블릭 블록체인**: 누구나 참여, 완전 탈중앙, PoW/PoS 합의, 느린 TPS(7~20), 높은 익명성, Bitcoin/Ethereum<br>2. **프라이빗 블록체인**: 허가된 자만 참여, 완전 중앙화, PBFT/Raft 합의, 빠른 TPS(수천), 낮은 익명성, Hyperledger Fabric<br>3. **컨소시엄 블록체인**: 허가된 기관만 참여, 부분 탈중앙, PBFT/PoA 합의, 금융 컨소시엄·공급망에 적용, R3 Corda/Quorum<br>4. **합의 알고리즘**: PoW(해시 경쟁, 에너지 소모 큼), PoS(지분 기반), PBFT(2/3 이상 노드 합의), PoA(신뢰된 검증자 목록) |
| **비교** | **퍼블릭 블록체인**<br>- **참여/권한**: 누구나 / 권한 제어 없음<br>- **성능**: 느림(7~20 TPS)<br>- **투명성**: 완전 공개<br>- **에너지**: 높음(PoW 기준)<br><br>**프라이빗 블록체인**<br>- **참여/권한**: 허가된 자만 / 완전 중앙화<br>- **성능**: 빠름(수천 TPS)<br>- **투명성**: 비공개<br>- **에너지**: 낮음 |
| **차별화** | **CBDC 등 실무 도입 시 네트워크 유형 선정 전략**<br>1. **CBDC(중앙은행 디지털화폐)의 유형 선택 근거**: 완전 익명성의 퍼블릭 블록체인은 자금세탁방지(AML)·고객확인(KYC) 요건과 충돌하므로, 중앙은행이 제어하는 프라이빗 또는 허가형(Permissioned) 블록체인을 채택해 신원 확인 가능 구조를 유지.<br>2. **컨소시엄 블록체인의 금융권 협업 적합성**: 여러 금융기관이 경쟁과 협업을 동시에 수행해야 하는 무역금융·증권결제 영역에서는, 어느 한 기관에 권한이 집중되지 않으면서도 성능·거버넌스가 확보되는 컨소시엄 구조가 적합.<br>3. **성능-탈중앙화 트레이드오프 인식**: 블록체인 트릴레마(탈중앙화-보안성-확장성)에 따라 퍼블릭은 탈중앙·보안에, 프라이빗/컨소시엄은 확장성(TPS)에 무게를 둔 설계 선택임을 답안에서 명시. |
