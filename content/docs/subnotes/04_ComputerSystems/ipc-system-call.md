# IPC(프로세스 간 통신) 및 시스템 콜 서브노트

> **두음 머리에 박기 🧠**
> - **공·메·파** (IPC 3대 주요 기법: **공**유 메모리 Shared Memory, **메**시지 패싱 Message Passing, **파**이프 Pipe)
> - **프·파·장·정·통** (시스템 콜 5대 분류: **프**로세스 제어, **파**일 관리, **장**치 관리, **정**보 유지, **통**신)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **IPC (Inter Process Communication) 및 시스템 콜 (System Call)** |
| **정의** | 독립된 메모리 공간을 가진 프로세스들이 데이터를 교환·동기화하는 OS 수준 메커니즘인 **IPC**와, 사용자 프로그램이 커널 서비스를 요청하기 위해 사용자 모드→커널 모드로 전환하는 유일한 합법적 경로인 **시스템 콜** |
| **키워드** | 공유메모리/메시지패싱/파이프/소켓/시그널, 뮤텍스/세마포어/모니터, 소프트웨어 인터럽트, 사용자모드 vs 커널모드, libc 래퍼 |
| **개념도** | `사용자 프로그램 → 시스템 콜 요청(예: read())`<br>`→ 소프트웨어 인터럽트(int 0x80 / syscall) → 사용자모드→커널모드 전환`<br>`→ 인터럽트 벡터 테이블에서 핸들러 탐색 → 커널이 요청 처리(IPC 포함)`<br>`→ 결과 반환 후 커널모드→사용자모드 복귀` |
| **구성요소** | 1. **IPC 3대 기법**: 공유 메모리(직접 접근, 빠르나 동기화 필요), 메시지 패싱(커널 경유 send/receive, 안전하나 느림), 파이프(단방향 스트림, 부모-자식 제한)<br>2. **추가 IPC 기법**: 소켓(네트워크/로컬 양방향), 시그널(이벤트 알림 SIGTERM 등), 세마포어(공유자원 동기화)<br>3. **시스템 콜 5대 분류**: 프로세스 제어(fork/exec/exit/wait), 파일 관리(open/read/write/close), 장치 관리(ioctl), 정보 유지(getpid), 통신(pipe/socket)<br>4. **libc 래퍼 관계**: printf()→write(), malloc()→brk()/mmap(), fopen()→open() |
| **비교** | **공유 메모리 (Shared Memory)**<br>- **속도**: 빠름 (커널 개입 최소, 직접 접근)<br>- **안전성**: 낮음 (레이스 컨디션 위험, 별도 동기화 필요)<br><br>**메시지 패싱 (Message Passing)**<br>- **속도**: 느림 (커널을 통한 send/receive)<br>- **안전성**: 높음 (구현 간단, 동기화 자동 보장) |
| **차별화** | **IPC 안전성 확보와 시스템 콜 오버헤드 최소화 전략**<br>1. **임계 구역 3조건과 동기화 기법 결합**: 공유 메모리 기반 IPC는 상호배제·진행·유한대기 3조건을 만족해야 하므로 뮤텍스(단일 접근)·세마포어(N개 허용)·모니터(객체 수준)·스핀락(짧은 대기) 중 상황에 맞는 동기화 기법을 병행 적용.<br>2. **시스템 콜 오버헤드 절감 기법**: 빈번한 시스템 콜 호출은 사용자-커널 모드 전환 비용을 누적시키므로, vDSO(가상 동적 공유 객체)나 배치(batching) I/O 요청으로 전환 횟수 자체를 줄이는 최적화 적용.<br>3. **IPC 기법 선택 기준**: 대용량·고속 데이터 교환이 필요한 동일 머신 내 프로세스는 공유 메모리를, 안전성과 이식성이 중요한 경우 메시지 패싱·소켓을, 부모-자식 관계의 단순 데이터 흐름은 파이프를 선택하는 실무 판단 기준 수립. |
