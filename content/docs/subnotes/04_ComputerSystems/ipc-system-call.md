# IPC(프로세스 간 통신) 및 시스템 콜 서브노트

> **두음 머리에 박기 🧠**
> - **공·메·파** (IPC 3대 주요 기법: **공**유 메모리 Shared Memory, **메**시지 패싱 Message Passing, **파**이프 Pipe)
> - **프·파·장·정·통** (시스템 콜 5대 분류: **프**로세스 제어, **파**일 관리, **장**치 관리, **정**보 유지, **통**신)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **IPC (Inter Process Communication) 및 시스템 콜 (System Call)** |
| **정의** | 독립된 메모리 공간을 가진 프로세스들이 데이터를 교환·동기화하는 OS 수준 메커니즘인 **IPC**와, 사용자 프로그램이 커널 서비스를 요청하기 위해 사용자 모드→커널 모드로 전환하는 유일한 합법적 경로인 **시스템 콜** |
| **키워드** | 공유메모리/메시지패싱/파이프/소켓/시그널, 뮤텍스/세마포어/모니터, 소프트웨어 인터럽트, 사용자모드 vs 커널모드, libc 래퍼 |
| **개념도** | `사용자 프로그램 → 시스템 콜 요청(예: read())`<br>`→ 소프트웨어 인터럽트(int 0x80 / syscall) → 사용자모드→커널모드 전환`<br>`→ 인터럽트 벡터 테이블에서 핸들러 탐색 → 커널이 요청 처리(IPC 포함)`<br>`→ 결과 반환 후 커널모드→사용자모드 복귀` |
| **구성요소** | 1. **IPC 3대 기법**: 공유메모리(직접접근, 빠름·동기화필요) / 메시지패싱(커널경유 send/receive, 안전·느림) / 파이프(단방향스트림, 부모-자식 제한)<br>2. **추가 IPC 기법**: 소켓(네트워크/로컬 양방향), 시그널(SIGTERM 등 이벤트알림), 세마포어(공유자원 동기화)<br>3. **시스템 콜 5대 분류**: 프로세스제어(fork/exec/exit/wait), 파일관리(open/read/write/close), 장치관리(ioctl), 정보유지(getpid), 통신(pipe/socket)<br>4. **libc 래퍼 관계**: printf()→write(), malloc()→brk()/mmap(), fopen()→open() |
| **비교** | **공유 메모리 (Shared Memory)**<br>- 속도: 빠름 (커널개입 최소, 직접접근)<br>- 안전성: 낮음 (레이스컨디션 위험, 별도동기화 필요)<br><br>**메시지 패싱 (Message Passing)**<br>- 속도: 느림 (커널경유 send/receive)<br>- 안전성: 높음 (구현간단, 동기화 자동보장) |
| **차별화** | **IPC 안전성 확보 + 시스템콜 오버헤드 최소화 전략**<br>1. **임계구역 3조건 + 동기화기법 결합**: 상호배제·진행·유한대기 만족 → 뮤텍스(단일접근)·세마포어(N개허용)·모니터(객체수준)·스핀락(짧은대기) 상황별 병행<br>2. **시스템콜 오버헤드 절감**: 빈번한 콜 호출 → 모드전환 비용 누적 → vDSO or 배치(batching) I/O로 전환횟수 축소<br>3. **IPC 기법 선택기준**: 대용량·고속=공유메모리 / 안전성·이식성=메시지패싱·소켓 / 부모-자식 단순흐름=파이프 |
