# 데이터 모델링: ERD, 슈퍼/서브타입, 식별자 관계 서브노트

> **두음 머리에 박기 🧠**
> - **개·속·관** (ERD 3대 구성요소: **개**체 Entity, **속**성 Attribute, **관**계 Relationship)
> - **배·포·완·부** (슈퍼/서브타입 4대 제약: 분할 제약의 **배**타적/**포**함적, 완전성 제약의 **완**전/**부**분)
> - **싱·플·개** (슈퍼/서브타입 물리 변환 3대 전략: **싱**글테이블 Single Table, **플**러스타입 Table per Type, **개**별타입 Table per Concrete Class)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **ERD(Entity Relationship Diagram)와 관계형 데이터 모델, 슈퍼/서브타입, 식별자·비식별자 관계** |
| **정의** | 업무규칙 → 개체·속성·관계 도출 ERD + PK/FK 기반 테이블 변환(관계형 모델링) → 공통속성(슈퍼타입)/개별속성(서브타입) 상속구조 + 식별자관계(부모PK→자식PK 전이) vs 비식별자관계(일반속성 FK 전이) 선택 |
| **키워드** | ERD, 카디널리티, PK/FK 전이, 슈퍼타입/서브타입, 변별자(Discriminator), 식별자/비식별자 관계, 물리 변환 전략 |
| **개념도** | `[업무 명제]` ➔ `[ERD: 개체·속성·카디널리티 분석]` ➔ `[PK의 FK 전이]` ➔ `[관계형 모델(테이블·제약조건)]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ (다형성 엔티티)`<br>`[슈퍼타입(공통속성)]` ── 상속 ──➔ `[서브타입1] [서브타입2] [서브타입3]` ── 물리변환(싱글/플러스/개별) ──➔ `[테이블]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ (부모-자식 PK 전이 방식)`<br>`[식별자 관계: 실선, 부모PK→자식PK 복합키] / [비식별자 관계: 점선, 부모PK→자식 FK(일반속성)]` |
| **구성요소** | 1. **ERD 3요소(개·속·관)**: 개체(Entity)·속성(Attribute)·관계(Relationship) + 카디널리티(1:1, 1:M, M:N)·선택성(Optionality)<br>2. **관계형 모델 변환**: 개체→테이블, 속성→컬럼, 부모PK → 자식테이블 FK 전이 → 참조무결성 형성<br>3. **슈퍼/서브타입 제약**: 분할제약(배타적-서브타입 1개만/포함적-복수 겸임), 완전성제약(완전-전체 서브타입 소속/부분-미분류 허용)<br>4. **물리 변환 3대 전략**: Single Table(전체통합, 조인불필요·Null양산), Table per Type(슈퍼+서브 분리, Null없음·잦은조인), Table per Concrete Class(공통속성 복사, 조인없음·중복저장)<br>5. **식별자/비식별자 관계**: 식별자관계=부모PK→자식PK 전이(복합키, CASCADE, 강한종속), 비식별자관계=부모PK→자식 일반속성 FK 전이(단일PK 유지, SET NULL 가능, 약한연관) |
| **비교** | **식별자 관계(Identifying)**<br>- ERD표기: 실선, FK Not Null, 복합키 구성<br>- 극단사용 시: 복합키 인플레이션(컬럼 5~6개↑), 클러스터드인덱스 집적도 저하<br><br>**비식별자 관계(Non-Identifying)**<br>- ERD표기: 점선, FK Null 허용, 단일PK 유지<br>- 극단사용 시: 징검다리 조인폭발(최상위→최하위 전구간 JOIN), 보조인덱스 중복비용 |
| **차별화** | **ERD·슈퍼타입·관계 설계 실무 적용 전략**<br>1. **도메인 성격별 관계유형 선택**: 독립적 수명주기(부서-사원) → 비식별자관계, 강한종속·이력성(주문-주문상세) → 식별자관계<br>2. **복합키 인플레이션 차단**: 식별자관계 3단계↑ 누적 시 대리키(Surrogate Key) 도입 → 비식별자관계 전환, JPA `@IdClass` 복잡도 회피 위해 비식별자관계 우선<br>3. **슈퍼/서브타입 변환 기준**: 통합조회 빈번 → Single Table, 컬럼수·Null비율 차이 큼 → Table per Type (저장공간-조인성능 트레이드오프 최적화)<br>4. **연결함정 방지**: ERD 설계단계에서 카디널리티·선택성을 CRUD매트릭스·비즈니스시나리오로 검증 → 팬트랩·캐즘트랩 원천차단 |
