# 분산 데이터베이스의 투명성 서브노트

> **두음 머리에 박기 🧠**
> - **위·분·복·병·장·성·확** (분산 DB 투명성 7종: **위**치, **분**할, **복**제, **병**행, **장**애, **성**능, **확**장)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **분산 데이터베이스의 투명성(Distributed DB Transparency)** |
| **정의** | 사용자가 데이터의 물리적 분산 구조를 의식하지 않고 마치 단일 DB처럼 접근할 수 있도록, 분산 시스템이 위치·분할·복제 등의 복잡성을 감추는 특성 |
| **키워드** | 위치 투명성, 분할 투명성, 복제 투명성, 병행 투명성, 장애 투명성, 전역 스키마, 2PC |
| **개념도** | `[사용자 단일 쿼리]` ➔ `[전역 스키마(Global Schema)]` ➔ `[분산 쿼리 최적화기: 위치·비용 고려]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[서울/부산/대구 사이트 분산 저장]` ➔ `[2PC로 원자성 보장]` ➔ `[단일 DB처럼 응답]` |
| **구성요소** | 1. **위치 투명성**: 데이터 소재 사이트를 몰라도 접근 가능<br>2. **분할 투명성**: 수평·수직 분할되어도 전체를 하나로 조회<br>3. **복제 투명성**: 여러 사이트 복제본을 단일 데이터처럼 접근<br>4. **병행/장애 투명성**: 동시 트랜잭션 직렬성 보장, 사이트 장애 시에도 서비스 지속<br>5. **성능/확장 투명성**: 최적 쿼리 수행을 사용자가 신경쓰지 않음, 사이트 추가 시 응용 수정 불필요 |
| **비교** | **집중형(Centralized) DB**<br>- 단일 사이트, 투명성 이슈 없음<br>- 장애 시 전체 서비스 중단(SPOF)<br><br>**분산 DB (Distributed DB)**<br>- 다중 사이트, 7대 투명성 구현 필요<br>- 일부 장애에도 서비스 지속 가능하나 통신 오버헤드 발생 |
| **차별화** | **분산 DB 투명성 구현을 위한 실무 아키텍처 전략**<br>1. **전역 스키마 기반 통합 조회**: 지자체 통합 DB처럼 다중 사이트 민원 데이터를 위치·분할 투명성으로 단일 쿼리 조회 가능하게 설계.<br>2. **2PC/SAGA로 병행·장애 투명성 확보**: 분산 트랜잭션의 원자성은 2단계 커밋(2PC)으로, 장기 실행 트랜잭션은 SAGA 패턴의 보상 트랜잭션으로 장애 투명성을 구현.<br>3. **투명성의 비용 트레이드오프**: 완전한 투명성 구현은 통신 오버헤드·복잡한 트랜잭션 관리 비용을 수반하므로, CAP/PACELC 관점에서 일관성·가용성·지연시간 간 우선순위를 결정. |
