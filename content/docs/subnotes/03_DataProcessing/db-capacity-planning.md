# DB 서버 용량 산정 서브노트

> **두음 머리에 박기 🧠**
> - **업·성·서·여·결** (하드웨어 용량 산정 5단계: **업**무량 분석 ➔ **성**능목표(SLA) 정의 ➔ **서**버별 용량 산정 ➔ **여**유율·피크계수 적용 ➔ **결**과 검토)
> - **T·C·M·D** (DB 서버 자원 산정 순서: **T**PS ➔ **C**PU ➔ **M**emory ➔ **D**isk)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **DB 서버 용량 산정(Database Server Capacity Planning)** |
| **정의** | 예상 업무량(Workload)과 데이터 증가율을 분석하여 CPU·Memory·Disk·Network 자원이 SLA(서비스 수준 목표)를 만족하는 최적 하드웨어 규모를 사전에 결정하는 공학적 프로세스로, 테이블별 건수·증가율·보존기간을 기초자료로 TPS→CPU→Memory→Disk 순서로 체계적으로 산출 |
| **키워드** | 업무량(Workload) 분석, SLA, TPS(Transactions Per Second), 피크 집중률, 여유율(Buffer Rate), BMT(Benchmark Test) |
| **개념도** | `[기초자료 수집: 테이블 정의서·업무 분석서]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[데이터 용량 산정 = Σ(건수×행크기×증가율) + 인덱스(20~30%) + 시스템여유(20%)]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[TPS 산정 = 일일 트랜잭션×피크집중률 / 피크지속시간]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[CPU 산정 = TPS×SQL당 처리시간 / 목표 CPU활용률]` ➔ `[Memory 산정 = Buffer Pool + SGA/PGA + 세션수×세션크기]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[최종 사양 = 산정치 × (1+여유율 20~30%)]` |
| **구성요소** | 1. **용량 산정 5단계(업·성·서·여·결)**: 업무량 분석(트랜잭션 목록화, 피크타임 처리량, 데이터 증가율)→성능목표 정의(응답시간·가용성·동시사용자수 SLA)→서버별 용량 산정(WEB/WAS는 TPS 기준, DB는 TPS·데이터용량 기준)→여유율·피크계수 적용→결과 검토(BMT, 유사사업 비교)<br>2. **DB 서버 기초자료 3종**: 테이블 정보(초기건수·증가율·보존기간·행크기), 트랜잭션 정보(일평균 건수·피크타임 배율·R/W 비율), 동시 사용자(평균/최대 동시 접속자 수)<br>3. **자원 산정 순서(T·C·M·D)**: TPS(피크 TPS = 일일 트랜잭션×피크집중률/피크지속시간) → CPU(TPS×SQL당 처리시간/목표 활용률) → Memory(Buffer Pool+SGA/PGA+세션×세션크기) → Disk(데이터 용량+인덱스 용량+여유공간)<br>4. **최종 사양 결정**: 산정치에 여유율(20~30%)과 피크 계수를 적용해 권고 사양 도출, BMT로 최종 검증 |
| **비교** | **과소 산정(Under-provisioning)**<br>- 초기 투자 비용 절감<br>- 운영 중 성능 저하·서비스 장애 리스크, 긴급 증설 비용 상승<br><br>**과대 산정(Over-provisioning)**<br>- 성능 여유·장애 대응력 확보<br>- 불필요한 하드웨어 투자 낭비, 공공사업에서는 예산 집행 타당성 문제 |
| **차별화** | **공공·클라우드 환경 용량 산정 실무 전략**<br>1. **정보시스템 감리 대응 근거자료화**: 행정안전부 지침에 따라 기초자료(테이블별 건수·증가율)와 산정 공식·결과를 문서화하여 감리 시 법적 의무 산출물로 제출.<br>2. **클라우드 환경의 탄력적 여유율 조정**: 온프레미스는 고정 여유율(20~30%)을 사전 확보해야 하나, 클라우드는 Auto Scaling으로 실시간 TPS 변화에 대응해 초기 산정 여유율을 낮추고 운영 중 탄력적으로 조정.<br>3. **BMT 기반 산정치 검증**: 이론적 산정 공식만 신뢰하지 않고 벤더 BMT(Benchmark Test)와 유사 사업 실측 사례를 비교 검증하여 산정 오차로 인한 운영 중 장애 리스크를 사전에 제거. |
