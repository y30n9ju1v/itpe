# DB 서버 용량 산정 서브노트

> **두음 머리에 박기 🧠**
> - **업·성·서·여·결** (하드웨어 용량 산정 5단계: **업**무량 분석 ➔ **성**능목표(SLA) 정의 ➔ **서**버별 용량 산정 ➔ **여**유율·피크계수 적용 ➔ **결**과 검토)
> - **T·C·M·D** (DB 서버 자원 산정 순서: **T**PS ➔ **C**PU ➔ **M**emory ➔ **D**isk)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **DB 서버 용량 산정(Database Server Capacity Planning)** |
| **정의** | 예상 업무량·데이터 증가율 분석 → CPU/Memory/Disk/Network가 SLA 만족하는 최적 H/W 규모 사전결정 공학프로세스, 건수·증가율·보존기간 기초자료 → TPS→CPU→Memory→Disk 순 산출 |
| **키워드** | 업무량(Workload) 분석, SLA, TPS(Transactions Per Second), 피크 집중률, 여유율(Buffer Rate), BMT(Benchmark Test) |
| **개념도** | `[기초자료 수집: 테이블 정의서·업무 분석서]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[데이터 용량 산정 = Σ(건수×행크기×증가율) + 인덱스(20~30%) + 시스템여유(20%)]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[TPS 산정 = 일일 트랜잭션×피크집중률 / 피크지속시간]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[CPU 산정 = TPS×SQL당 처리시간 / 목표 CPU활용률]` ➔ `[Memory 산정 = Buffer Pool + SGA/PGA + 세션수×세션크기]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[최종 사양 = 산정치 × (1+여유율 20~30%)]` |
| **구성요소** | 1. **용량 산정 5단계(업·성·서·여·결)**: 업무량 분석(트랜잭션 목록화·피크처리량·증가율)→성능목표(응답시간·가용성·동시사용자 SLA)→서버별 산정(WEB/WAS는 TPS, DB는 TPS·용량)→여유율·피크계수 적용→결과 검토(BMT·유사사업 비교)<br>2. **DB 서버 기초자료 3종**: 테이블정보(초기건수·증가율·보존기간·행크기), 트랜잭션정보(일평균건수·피크배율·R/W비율), 동시사용자(평균/최대 접속자수)<br>3. **자원 산정 순서(T·C·M·D)**: TPS(일일TX×피크집중률/피크지속시간) → CPU(TPS×SQL당처리시간/목표활용률) → Memory(BufferPool+SGA/PGA+세션×세션크기) → Disk(데이터+인덱스+여유공간)<br>4. **최종 사양 결정**: 산정치×여유율(20~30%)×피크계수 → 권고사양, BMT 최종검증 |
| **비교** | **과소 산정(Under-provisioning)**<br>- 초기 투자비 절감<br>- 성능저하·장애 리스크, 긴급증설 비용상승<br><br>**과대 산정(Over-provisioning)**<br>- 성능여유·장애대응력 확보<br>- 불필요 H/W 투자낭비, 공공사업 예산집행 타당성 문제 |
| **차별화** | **공공·클라우드 환경 용량 산정 실무 전략**<br>1. **감리 대응 근거자료화**: 행안부 지침 → 기초자료(건수·증가율)+산정공식·결과 문서화 → 감리 시 법적 의무 산출물 제출<br>2. **클라우드 탄력적 여유율**: 온프레미스=고정 여유율(20~30%) 사전확보 vs 클라우드=Auto Scaling → 초기 여유율 낮추고 운영 중 탄력조정<br>3. **BMT 기반 산정치 검증**: 이론공식만 신뢰 금지 → 벤더 BMT+유사사업 실측 비교검증 → 산정오차發 장애리스크 사전제거 |
