# 데이터베이스 ANSI/SPARC 3단계 아키텍처 서브노트

> **두음 머리에 박기 🧠**
> - **외·개·내** (ANSI/SPARC 3단계 스키마: **외**부 스키마 External, **개**념 스키마 Conceptual, **내**부 스키마 Internal)
> - **논·물** (2대 데이터 독립성: **논**리적 독립성(외부-개념 사상), **물**리적 독립성(개념-내부 사상))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **ANSI/SPARC 3단계 아키텍처(Three-Level Architecture)와 데이터 독립성(Data Independence)** |
| **정의** | 1975년 ANSI 산하 SPARC 위원회가 정의한 DBMS 표준 구조로, 데이터를 외부(사용자)·개념(전사)·내부(물리 저장)의 3단계로 격리·추상화하고 계층 간 사상(Mapping)을 통해 상위 단계 변경이 하위 단계에 영향을 주지 않는 데이터 독립성을 보장 |
| **키워드** | 외부 스키마(View), 개념 스키마, 내부 스키마, 논리적/물리적 사상, 데이터 독립성, DA/DBA 역할 분리 |
| **개념도** | `[사용자 A/B/C]` ➔ `[외부 단계: 외부 스키마(View) - 다수 공존]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ 외부-개념 사상(논리적 사상)`<br>`[개념 단계: 개념 스키마 - 전사 통합, 조직 내 1개]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ 개념-내부 사상(물리적 사상)`<br>`[내부 단계: 내부 스키마 - 인덱스·블록·압축·저장 레이아웃]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[물리적 저장 장치(HDD/SSD)]` |
| **구성요소** | 1. **외부 스키마(External Schema)**: 최종 사용자·응용 프로그래머 대상, 뷰(View)·서브스키마 형태로 다수 공존 가능<br>2. **개념 스키마(Conceptual Schema)**: DA·데이터 아키텍트 담당, 엔티티·관계·제약조건·접근권한을 전사 통합 관점에서 정의, 조직 내 유일하게 1개 존재<br>3. **내부 스키마(Internal Schema)**: DBA·시스템 엔지니어 담당, 인덱스 배치·데이터 압축·저장 레코드 레이아웃 등 물리 저장 구조 정의<br>4. **외부-개념 사상(논리적 사상)**: 개념 스키마가 변경되어도 사상 규칙만 수정하면 외부 스키마(응용 프로그램)는 불변 → 논리적 데이터 독립성 달성<br>5. **개념-내부 사상(물리적 사상)**: 내부 스키마(저장 장치, 인덱스 구조)가 변경되어도 개념 스키마는 불변 → 물리적 데이터 독립성 달성 |
| **비교** | **논리적 데이터 독립성**<br>- 대상: 외부 스키마 ↔ 개념 스키마 간 사상<br>- 효과: 테이블 구조·컬럼 추가 등 개념 스키마 변경이 응용 프로그램(View)에 영향 없음<br><br>**물리적 데이터 독립성**<br>- 대상: 개념 스키마 ↔ 내부 스키마 간 사상<br>- 효과: 저장 장치 교체, 인덱스 재구성 등 물리적 변경이 개념 스키마·응용 프로그램에 영향 없음 |
| **차별화** | **클라우드 네이티브 환경에서의 데이터 독립성 확장 적용**<br>1. **물리적 독립성과 스토리지 가상화 연계**: 클라우드 스토리지(EBS, Aurora Storage 등)로의 전환·확장 시 물리적 데이터 독립성 덕분에 개념 스키마·응용 로직 변경 없이 내부 스키마(저장 레이어)만 교체 가능하도록 설계.<br>2. **논리적 독립성과 MSA 뷰 계층 활용**: 서비스별로 상이한 외부 스키마(View)를 제공해 개념 스키마(전사 통합 모델) 변경 시에도 각 마이크로서비스의 데이터 접근 계약(API Contract)이 흔들리지 않도록 사상 계층을 완충재로 활용.<br>3. **DA/DBA 역할 분담 체계화**: 개념 스키마는 DA가 전사 데이터 표준·관계를 통제하고, 내부 스키마는 DBA가 성능·저장 효율을 통제하는 역할 분리 거버넌스를 통해 변경 영향도를 계층별로 격리 관리. |
