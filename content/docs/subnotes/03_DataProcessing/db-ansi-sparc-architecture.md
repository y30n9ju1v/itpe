# 데이터베이스 ANSI/SPARC 3단계 아키텍처 서브노트

> **두음 머리에 박기 🧠**
> - **외·개·내** (ANSI/SPARC 3단계 스키마: **외**부 스키마 External, **개**념 스키마 Conceptual, **내**부 스키마 Internal)
> - **논·물** (2대 데이터 독립성: **논**리적 독립성(외부-개념 사상), **물**리적 독립성(개념-내부 사상))

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **ANSI/SPARC 3단계 아키텍처(Three-Level Architecture)와 데이터 독립성(Data Independence)** |
| **정의** | 1975년 ANSI 산하 SPARC 위원회 정의 DBMS 표준구조 → 외부(사용자)·개념(전사)·내부(물리저장) 3단계 격리·추상화 + 계층간 사상(Mapping) → 상위변경이 하위 무영향(데이터 독립성) 보장 |
| **키워드** | 외부 스키마(View), 개념 스키마, 내부 스키마, 논리적/물리적 사상, 데이터 독립성, DA/DBA 역할 분리 |
| **개념도** | `[사용자 A/B/C]` ➔ `[외부 단계: 외부 스키마(View) - 다수 공존]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ 외부-개념 사상(논리적 사상)`<br>`[개념 단계: 개념 스키마 - 전사 통합, 조직 내 1개]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ 개념-내부 사상(물리적 사상)`<br>`[내부 단계: 내부 스키마 - 인덱스·블록·압축·저장 레이아웃]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[물리적 저장 장치(HDD/SSD)]` |
| **구성요소** | 1. **외부 스키마(External Schema)**: 최종사용자·응용프로그래머 대상, 뷰(View)·서브스키마 형태로 다수 공존<br>2. **개념 스키마(Conceptual Schema)**: DA 담당, 엔티티·관계·제약조건·접근권한 전사통합 정의, 조직 내 유일 1개<br>3. **내부 스키마(Internal Schema)**: DBA 담당, 인덱스배치·압축·저장레코드 레이아웃 등 물리구조 정의<br>4. **외부-개념 사상(논리적 사상)**: 개념스키마 변경 시 사상규칙만 수정 → 외부스키마 불변 → 논리적 독립성<br>5. **개념-내부 사상(물리적 사상)**: 내부스키마 변경 시 개념스키마 불변 → 물리적 독립성 |
| **비교** | **논리적 데이터 독립성**<br>- 대상: 외부↔개념 스키마 간 사상<br>- 효과: 테이블·컬럼 추가 등 개념스키마 변경 → 응용프로그램(View) 영향無<br><br>**물리적 데이터 독립성**<br>- 대상: 개념↔내부 스키마 간 사상<br>- 효과: 저장장치 교체·인덱스 재구성 → 개념스키마·응용프로그램 영향無 |
| **차별화** | **클라우드 네이티브 환경 데이터 독립성 확장 적용**<br>1. **물리적 독립성-스토리지 가상화 연계**: 클라우드 스토리지(EBS, Aurora) 전환·확장 시 개념스키마·응용로직 변경없이 내부스키마(저장레이어)만 교체<br>2. **논리적 독립성-MSA 뷰 계층 활용**: 서비스별 외부스키마(View) 제공 → 개념스키마 변경 시에도 각 MSA API Contract 무영향, 사상계층이 완충재<br>3. **DA/DBA 역할 분담 체계화**: 개념스키마=DA(전사표준·관계 통제), 내부스키마=DBA(성능·저장효율 통제) → 변경영향도 계층별 격리관리 |
