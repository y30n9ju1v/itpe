# 데이터 레이크와 데이터 패브릭 서브노트

> **두음 머리에 박기 🧠**
> - **카·통·가·거·지·AI** (데이터 패브릭 6대 구성요소: **카**탈로그, **통**합, **가**상화, **거**버넌스, **지**식그래프, **AI**/ML 엔진)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터 레이크(Data Lake)와 데이터 패브릭(Data Fabric)** |
| **정의** | 데이터 레이크: 스키마리스(schemaless) 원천데이터 대용량 저장소 + 데이터 패브릭: 이기종환경(온프레미스·클라우드·하이브리드) 능동적 메타데이터·AI/ML 기반 통합관리·분석 차세대 아키텍처 |
| **키워드** | Schema on Read, Data Swamp, 데이터 카탈로그, 데이터 가상화, 능동적 메타데이터, 멀티클라우드 |
| **개념도** | `[OLTP/ERP/CRM]`──ETL──▶`[DW]`◀──▶`[Data Lake]`◀──`[Devices/Web/Sensors/Social]`<br>`[온프레미스DB][클라우드DW][데이터레이크][SaaS]`▶`[데이터 패브릭 레이어: 메타데이터/카탈로그/거버넌스/보안]`▶`[분석가/데이터사이언티스트/AI-ML]` |
| **구성요소** | 1. **DW vs Data Lake**: DW=Schema on Write(저장 시 정형화)·정제데이터·BI, Data Lake=Schema on Read(활용 시 스키마부여)·원시데이터(Data Swamp 위험)·AI/ML<br>2. **빅데이터 요소기술 표준화**: 수집(Flume/Kafka/Sqoop)·저장(HDFS/HBase/NoSQL)·처리(MapReduce/Spark/Flink)·분석(Hive/Pig/Presto)·시각화(Tableau/Kibana)·보안(Ranger/Knox) 영역별 인터페이스·포맷 표준화<br>3. **데이터 패브릭 정의**: AI/ML 기반 능동적 메타데이터 → 발견·통합·거버넌스 자동화 이기종 통합관리 아키텍처<br>4. **데이터 패브릭 구성요소**: 카탈로그(메타데이터 중앙저장소)·통합(ETL/ELT)·가상화(물리이동 없는 통합뷰)·거버넌스(품질/보안/개인정보 중앙화)·지식그래프(관계 시각화)·AI/ML엔진(이상탐지·추천 자동화) |
| **비교** | **데이터 레이크(Data Lake)**<br>- 단일저장소, 정형+비정형 원시데이터 보관<br>- Schema on Read, 느슨한 거버넌스<br>- 유연성 높으나 Data Swamp 위험<br><br>**데이터 패브릭(Data Fabric)**<br>- 멀티클라우드/하이브리드 이기종환경 통합<br>- 메타데이터 자동화, 통합 거버넌스 자동화<br>- 유연성 매우높음 (물리이동 없는 가상화) |
| **차별화** | **데이터 레이크·패브릭 실무 적용 전략** <br>1. **Data Swamp 방지**: 레이크 도입 시 카탈로그·메타데이터 관리체계 선행구축 → 거버넌스 부재로 인한 신뢰성 상실 예방<br>2. **단계적 아키텍처 전환**: DW → Data Lakehouse → Data Fabric 순 점진전환 → 리스크 최소화<br>3. **표준화 우선순위**: 수집·저장 계층 인터페이스 표준화 우선 → 벤더 종속성 최소화<br>4. **데이터 사일로 해소**: 가상화·지식그래프·AI엔진 결합 → 전사 통합분석 + Lineage 추적·이상탐지 자동화 |
