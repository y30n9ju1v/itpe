# 데이터 레이크와 데이터 패브릭 서브노트

> **두음 머리에 박기 🧠**
> - **카·통·가·거·지·AI** (데이터 패브릭 6대 구성요소: **카**탈로그, **통**합, **가**상화, **거**버넌스, **지**식그래프, **AI**/ML 엔진)
> - **On-Write vs On-Read** (스키마 적용 시점: DW=쓸 때, Data Lake=읽을 때)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터 레이크(Data Lake)와 데이터 패브릭(Data Fabric)** |
| **정의** | 스키마 없이(schemaless) 원천 데이터(raw data)를 그대로 저장하는 대용량 저장소인 데이터 레이크와, 온프레미스·클라우드·하이브리드 등 이기종 환경의 모든 데이터를 능동적 메타데이터와 AI/ML 기반으로 통합 관리·분석하는 차세대 아키텍처인 데이터 패브릭을 포괄하는 빅데이터 저장·관리 체계 |
| **키워드** | Schema on Read, Data Swamp, 데이터 카탈로그, 데이터 가상화, 능동적 메타데이터, 멀티클라우드 |
| **개념도** | `[OLTP/ERP/CRM]`──ETL──▶`[DW]`◀──▶`[Data Lake]`◀──`[Devices/Web/Sensors/Social]`<br>`[온프레미스DB][클라우드DW][데이터레이크][SaaS]`▶`[데이터 패브릭 레이어: 메타데이터/카탈로그/거버넌스/보안]`▶`[분석가/데이터사이언티스트/AI-ML]` |
| **구성요소** | 1. **DW vs Data Lake**: DW는 Schema on Write(저장 시 정형화)·고품질 정제 데이터·BI 활용, Data Lake는 Schema on Read(활용 시 스키마 부여)·원시 데이터 포함(Data Swamp 위험)·AI/ML 활용<br>2. **빅데이터 요소기술 표준화**: 수집(Flume/Kafka/Sqoop)·저장(HDFS/HBase/NoSQL)·처리(MapReduce/Spark/Flink)·분석(Hive/Pig/Presto)·시각화(Tableau/Kibana)·보안(Ranger/Knox) 영역별 인터페이스·포맷 표준화<br>3. **데이터 패브릭 정의**: AI/ML 기반 능동적 메타데이터로 데이터 발견·통합·거버넌스를 자동화하는 이기종 통합 관리 아키텍처<br>4. **데이터 패브릭 구성요소**: 데이터 카탈로그(메타데이터 중앙 저장소)·데이터 통합(ETL/ELT 파이프라인)·데이터 가상화(물리 이동 없는 통합 뷰)·데이터 거버넌스(품질/보안/개인정보 정책 중앙화)·지식 그래프(데이터 관계 시각화)·AI/ML 엔진(이상탐지·추천 자동화) |
| **비교** | **데이터 레이크(Data Lake)**<br>- 단일 저장소, 정형+비정형 원시 데이터 보관<br>- Schema on Read, 느슨한 거버넌스<br>- 유연성 높으나 Data Swamp 위험<br><br>**데이터 패브릭(Data Fabric)**<br>- 멀티클라우드/하이브리드 이기종 환경 통합<br>- 메타데이터 자동화, 자동화된 통합 거버넌스<br>- 유연성 매우 높음(물리적 이동 없는 가상화) |
| **차별화** | **데이터 레이크·패브릭 실무 적용 전략** <br>1. **Data Swamp 방지**: 데이터 레이크 도입 시 데이터 카탈로그·메타데이터 관리 체계를 선행 구축해 거버넌스 부재로 인한 신뢰성 상실을 예방<br>2. **단계적 아키텍처 전환**: DW → Data Lakehouse → Data Fabric 순으로 점진적 전환 전략을 권장해 리스크를 최소화<br>3. **표준화 우선순위**: 수집·저장 계층의 인터페이스 표준화를 우선 적용해 벤더 종속성을 최소화<br>4. **데이터 사일로 해소**: 데이터 패브릭의 데이터 가상화·지식 그래프·AI 엔진 결합으로 전사 데이터 통합 분석과 데이터 계보(Lineage) 추적·이상 탐지 자동화 실현 |
