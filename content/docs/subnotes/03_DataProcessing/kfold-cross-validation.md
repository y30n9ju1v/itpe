# k-fold 교차검증과 머신러닝 모델 평가 절차 서브노트

> **두음 머리에 박기 🧠**
> - **S·L·T** (k-fold 변형 기법 3종: **S**tratified k-fold, **L**eave-One-Out, **T**ime Series Split)
> - **학·검·테** (데이터 분할 3단계: **학**습셋(Train)으로 학습, **검**증셋(Validation)으로 튜닝, **테**스트셋(Test)으로 최종 1회 평가)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **k-fold 교차검증(Cross Validation) 및 머신러닝 모델 평가방법** |
| **정의** | k-fold 교차검증은 전체 데이터를 k개 폴드(Fold)로 분할해 각 폴드를 한 번씩 검증셋, 나머지(k-1개)를 학습셋으로 사용하여 k번 학습·평가를 반복함으로써 데이터 분할에 따른 성능 편차를 줄이고 일반화 성능을 안정적으로 추정하는 검증 기법이며, 이를 회귀(MAE/RMSE/R²)·분류(정확도/정밀도/재현율/F1/ROC-AUC) 지표와 결합해 모델을 평가한다 |
| **키워드** | k-fold, Stratified k-fold, Leave-One-Out, Time Series Split, Train/Validation/Test, MAE/RMSE/R² |
| **개념도** | 전체 데이터를 5개 Fold로 분할(k=5)<br>`Round1: [검증][학습][학습][학습][학습]`<br>`Round2: [학습][검증][학습][학습][학습]`<br>`Round3: [학습][학습][검증][학습][학습]`<br>`Round4: [학습][학습][학습][검증][학습]`<br>`Round5: [학습][학습][학습][학습][검증]`<br>→ 5회 평가 결과의 평균/표준편차로 최종 성능 산정<br><br>`[전체 데이터]` ├ Train Set(k-fold로 하이퍼파라미터 튜닝) ├ Validation Set(모델 선택/튜닝) └ Test Set(최종 1회만 사용) |
| **구성요소** | 1. **k-fold 교차검증 목적**: 데이터 분할 운(Sampling Bias)에 따른 성능 편차 최소화, 전체 데이터를 학습·검증에 모두 활용(소량 데이터에 특히 유용)<br>2. **단점**: k번 반복 학습으로 계산 비용 증가<br>3. **변형 기법**: Stratified k-fold(클래스 비율을 원본과 동일하게 유지, 불균형 데이터에 유리), Leave-One-Out(k=N), Time Series Split(시간 순서 보존, Walk-Forward Validation)<br>4. **회귀 평가지표**: MAE(오차 절댓값 평균, 이상치에 덜 민감), MSE/RMSE(오차 제곱 평균, 큰 오차에 페널티), R²(모델이 설명하는 분산 비율)<br>5. **테스트셋 원칙**: 튜닝 과정에서 사용하지 않고 최종 모델 선정 후 단 한 번만 사용(데이터 누수 방지) |
| **비교** | **일반 k-fold**<br>- 데이터를 무작위로 k등분<br>- 클래스 균형 데이터·정형 데이터에 적합<br><br>**Stratified k-fold**<br>- 각 폴드의 클래스 비율을 원본과 동일하게 유지<br>- 불균형 데이터에서도 안정적 평가 보장<br><br>**Time Series Split(Walk-Forward Validation)**<br>- 시간 순서를 보존해 과거→미래 방향으로만 학습·검증 분할<br>- 일반 k-fold를 시계열에 적용 시 미래 데이터가 학습에 섞이는 데이터 누수 방지 |
| **차별화** | **모델 검증 신뢰성 확보를 위한 실무 전략**<br>1. **소량 데이터 대응**: 데이터가 부족할 때는 k-fold(특히 Leave-One-Out)로 학습·검증에 데이터를 모두 활용하되, 계산 비용 증가를 감안해 k값(보통 5~10)을 적절히 설정.<br>2. **시계열 데이터 예외 처리**: 시계열에 일반 k-fold를 적용하면 미래 정보가 과거 예측에 유입되는 데이터 누수가 발생하므로 반드시 Time Series Split(전진검증)을 채택.<br>3. **평가지표와 비즈니스 비용 연계**: 클래스 불균형에서는 정확도의 착시를 피해 비즈니스 비용 기준으로 Precision/Recall/F1/PR-AUC를 채택하고, 최종 배포 전 Test Set으로 단 한 번 실서비스 성능을 검증. |
