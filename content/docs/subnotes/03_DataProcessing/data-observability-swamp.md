# 데이터 옵저버빌리티와 데이터 늪 서브노트

> **두음 머리에 박기 🧠**
> - **프·디·볼·스·리** (데이터 옵저버빌리티 5대 지표(Five Pillars): **프**레시니스(신선도), **디**스트리뷰션(분포), **볼**륨, **스**키마, **리**니지(계보))
> - **메·거·무·접·리** (데이터 늪 5대 발생 원인: **메**타데이터 관리 부재, **거**버넌스 부재, **무**분별한 적재, **접**근 제어 부재, **리**니지 미관리)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터 관측가능성(Data Observability) 및 데이터 늪(Data Swamp)** |
| **정의** | 데이터 관측가능성은 파이프라인 전반의 상태·품질·흐름을 실시간으로 이해·진단하는 능력이며, 데이터 늪은 거버넌스 없이 운영된 데이터 레이크가 품질·접근성·신뢰성을 상실해 활용 가치가 없는 상태로 전락한 것 |
| **키워드** | Five Pillars(Freshness·Distribution·Volume·Schema·Lineage), 데이터 다운타임, 데이터 카탈로그, 데이터 메쉬, 레이크하우스 |
| **개념도** | `[데이터 레이크]` ➔ `{거버넌스 있음: 옵저버빌리티로 실시간 모니터링} / {거버넌스 없음: 무분별 적재→데이터 늪}`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼ (늪 탈출)`<br>`[데이터 카탈로그 구축] + [거버넌스 체계] + [옵저버빌리티 도입] + [데이터 메쉬]` ➔ `[신뢰 가능한 데이터 자산]` |
| **구성요소** | 1. **Five Pillars**: Freshness(신선도), Distribution(분포), Volume(볼륨), Schema(스키마), Lineage(계보)<br>2. **데이터 다운타임**: 데이터가 누락·부정확·오래된 상태로 있는 기간<br>3. **데이터 늪 발생 원인**: 메타데이터·거버넌스·접근제어·계보 관리 부재, 무분별한 적재<br>4. **탈출 방안**: 데이터 카탈로그(Apache Atlas, Collibra), 거버넌스 체계, 옵저버빌리티, 데이터 메쉬<br>5. **레이크하우스**: 레이크의 유연성+웨어하우스의 거버넌스 결합(Delta Lake, Iceberg) |
| **비교** | **데이터 품질 관리(Data Quality Management)**<br>- 정기 점검 시점, 저장된 데이터 대상<br>- 목적: 품질 측정<br><br>**데이터 관측가능성(Data Observability)**<br>- 실시간 모니터링, 파이프라인 전체 대상<br>- 목적: 이상 탐지·근본원인 분석 |
| **차별화** | **데이터 레이크 거버넌스 확립 전략**<br>1. **옵저버빌리티로 늪 조기 예방**: Lineage 추적을 통해 사용되지 않고 방치되는 데이터를 조기 식별하여 데이터 늪으로의 전락을 사전 차단.<br>2. **스키마 변경 자동 감지**: e-커머스 파이프라인에서 스키마 변경 발생 시 Lineage 기반으로 영향받는 하위 대시보드를 즉시 식별·알림.<br>3. **데이터 메쉬로 책임 분산**: 중앙집중형 레이크의 거버넌스 공백을 도메인별 분산 소유(Data Mesh) 구조로 전환하여 데이터 오너십과 품질 책임을 명확화. |
