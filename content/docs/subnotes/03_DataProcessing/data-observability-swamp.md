# 데이터 옵저버빌리티와 데이터 늪 서브노트

> **두음 머리에 박기 🧠**
> - **프·디·볼·스·리** (데이터 옵저버빌리티 5대 지표(Five Pillars): **프**레시니스(신선도), **디**스트리뷰션(분포), **볼**륨, **스**키마, **리**니지(계보))
> - **메·거·무·접·리** (데이터 늪 5대 발생 원인: **메**타데이터 관리 부재, **거**버넌스 부재, **무**분별한 적재, **접**근 제어 부재, **리**니지 미관리)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터 관측가능성(Data Observability) 및 데이터 늪(Data Swamp)** |
| **정의** | 데이터 관측가능성: 파이프라인 전반 상태·품질·흐름 실시간 이해·진단 능력 / 데이터 늪: 거버넌스 부재 운영 레이크가 품질·접근성·신뢰성 상실 → 활용가치 없는 상태 |
| **키워드** | Five Pillars(Freshness·Distribution·Volume·Schema·Lineage), 데이터 다운타임, 데이터 카탈로그, 데이터 메쉬, 레이크하우스 |
| **개념도** | `[데이터 레이크]` ➔ `{거버넌스 있음: 옵저버빌리티로 실시간 모니터링} / {거버넌스 없음: 무분별 적재→데이터 늪}`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼ (늪 탈출)`<br>`[데이터 카탈로그 구축] + [거버넌스 체계] + [옵저버빌리티 도입] + [데이터 메쉬]` ➔ `[신뢰 가능한 데이터 자산]` |
| **구성요소** | 1. **Five Pillars**: Freshness(신선도), Distribution(분포), Volume(볼륨), Schema(스키마), Lineage(계보)<br>2. **데이터 다운타임**: 데이터 누락·부정확·노후 상태 지속기간<br>3. **데이터 늪 발생 원인**: 메타데이터·거버넌스·접근제어·계보관리 부재 + 무분별 적재<br>4. **탈출 방안**: 데이터 카탈로그(Apache Atlas, Collibra), 거버넌스 체계, 옵저버빌리티, 데이터 메쉬<br>5. **레이크하우스**: 레이크 유연성+웨어하우스 거버넌스 결합 (Delta Lake, Iceberg) |
| **비교** | **데이터 품질 관리(Data Quality Management)**<br>- 정기점검 시점, 저장데이터 대상<br>- 목적: 품질 측정<br><br>**데이터 관측가능성(Data Observability)**<br>- 실시간 모니터링, 파이프라인 전체 대상<br>- 목적: 이상탐지·근본원인 분석 |
| **차별화** | **데이터 레이크 거버넌스 확립 전략**<br>1. **옵저버빌리티로 늪 조기예방**: Lineage 추적 → 방치데이터 조기식별 → 데이터늪 전락 사전차단<br>2. **스키마 변경 자동감지**: e커머스 파이프라인 스키마변경 시 Lineage 기반 → 영향 대시보드 즉시 식별·알림<br>3. **데이터 메쉬로 책임분산**: 중앙집중형 거버넌스 공백 → 도메인별 분산소유(Data Mesh) 전환 → 오너십·품질책임 명확화 |
