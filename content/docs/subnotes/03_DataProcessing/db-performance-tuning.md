# 데이터베이스 튜닝 서브노트

> **두음 머리에 박기 🧠**
> - **보·이·평** (DB 튜닝 3단계: **보**색(조사) ➔ **이**행(설계·적용) ➔ **평**가(효과검증))
> - **설·A·S·S** (튜닝 4계층 우선순위: **설**계 ➔ **A**pplication ➔ **S**erver ➔ **S**ystem)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터베이스 튜닝(DB Tuning)** |
| **정의** | DB 성능병목 체계적 진단·제거 → 최소비용 최대성능 최적화 활동. 보색(조사)→이행(적용)→평가(검증) 3단계 + 설계→App→Server→System 4계층 우선순위 절차 |
| **키워드** | 슬로우 쿼리, 대기 이벤트, 실행 계획(EXPLAIN), 설계/Application/Server/System 튜닝, 반정규화 |
| **개념도** | `[성능 문제 감지: SLA 위반, 슬로우 쿼리]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[① 보색: 병목 식별·원인분석]` ➔ `[② 이행: 튜닝 방안 설계·적용]` ➔ `[③ 평가: 효과 측정·검증(반복)]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`▼ (튜닝 4계층, 우선순위 순)`<br>`[1.설계: 효과 최대·재작업 큼] → [2.Application: SQL·인덱스] → [3.Server: DBMS 파라미터] → [4.System: H/W·OS·네트워크]` |
| **구성요소** | 1. **보색(조사) 단계**: 슬로우쿼리 분석(Slow Query Log·AWR·ASH), 대기이벤트(V$SESSION_WAIT·pg_stat_activity), 실행계획(EXPLAIN PLAN/ANALYZE), 자원사용률(CPU·I/O·메모리·네트워크) 진단<br>2. **이행(적용) 단계**: 설계튜닝(정규화/반정규화, 인덱스 재설계), App튜닝(SQL재작성-EXISTS→JOIN, 바인드변수, 페이징/배치), Server튜닝(버퍼풀·SGA/PGA 파라미터, 체크포인트 빈도), System튜닝(HDD→SSD, OS파라미터·I/O스케줄러)<br>3. **평가 단계**: 튜닝 전후 지표(응답시간·TPS·대기시간) 비교 → 재적용 반복<br>4. **튜닝 4계층 우선순위**: 설계(효과최대·재작업비용큼) → App(SQL·인덱스) → Server(DBMS 파라미터) → System(H/W·OS·네트워크, 최후수단) |
| **비교** | **설계/Application 튜닝**<br>- 근본적 구조개선(정규화수준·SQL로직·인덱스)<br>- 효과 크나 개발·검증비용, 재작업 리스크 높음<br><br>**Server/System 튜닝**<br>- 파라미터·H/W 조정으로 즉시적용 가능<br>- 근본원인 미해결 시 효과 제한적, 서버증설은 최후수단 |
| **차별화** | **체계적 DB 튜닝 거버넌스 전략**<br>1. **하향식 우선순위 준수**: System(서버증설)은 설계·App·Server 소진 후 최후수단 → 비용만 증가하는 안티패턴 방지<br>2. **보색 단계 정량적 근거**: AWR·ASH·EXPLAIN PLAN → 병목 근본원인(Full Table Scan·Lock대기·비효율 조인순서) 정량식별 후 이행단계 진입, 추측성 튜닝 배제<br>3. **평가-재적용 반복 사이클**: 튜닝 후 지표 재측정 → SLA 미달 시 보색단계 회귀 → 운영 프로세스로 정착, 지속적 성능 거버넌스 |
