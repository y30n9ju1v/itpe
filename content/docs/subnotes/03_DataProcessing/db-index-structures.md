# DB 인덱스: 클러스터드 vs 논클러스터드 서브노트

> **두음 머리에 박기 🧠**
> - **선·복·과·커** (인덱스 설계 4대 고려사항: **선**택도, **복**합 인덱스 컬럼 순서, **과**다 생성 시 DML 저하, **커**버링 인덱스)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **데이터베이스 인덱스: 클러스터드(Clustered) vs 논클러스터드(Non-clustered) 인덱스** |
| **정의** | 컬럼값-레코드위치 매핑 → 검색속도 향상 자료구조. 클러스터드=키순 물리적 정렬·저장, 논클러스터드=별도구조+데이터포인터(RID) 저장 |
| **키워드** | B+Tree, 물리적 정렬, RID, 선택도(Selectivity), 최좌측 접두사, 커버링 인덱스, Full Table Scan |
| **개념도** | `[쿼리 실행]` ➔ `{인덱스 없음: Full Table Scan O(n)} / {인덱스 있음: B+Tree 탐색 O(log n)}`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`│`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`리프 노드: [클러스터드=실제 데이터 페이지] / [논클러스터드=데이터 포인터(RID)]` |
| **구성요소** | 1. **B+Tree 구조**: 대부분 DBMS의 기본 인덱스 자료구조, 리프 노드에 실제 데이터 또는 포인터 저장<br>2. **클러스터드 인덱스**: 테이블당 1개, PK·범위 쿼리 컬럼에 주로 사용<br>3. **논클러스터드 인덱스**: 테이블당 여러 개 생성 가능, 자주 조회되는 비PK 컬럼<br>4. **커버링 인덱스**: 인덱스만으로 쿼리 결과 반환, 테이블 접근 불필요<br>5. **선택도(Selectivity)**: 고유 값이 많을수록 인덱스 효율 상승 |
| **비교** | **클러스터드 인덱스**<br>- 데이터 페이지가 인덱스 키 순 물리적 정렬<br>- 리프=실제 데이터, 범위 검색 빠름<br>- INSERT 시 물리적 재정렬로 느릴 수 있음<br><br>**논클러스터드 인덱스**<br>- 별도 인덱스 구조, 데이터 순서와 무관<br>- 리프=데이터 페이지 포인터(RID), 별도 저장 공간 필요<br>- INSERT가 클러스터드보다 빠름 |
| **차별화** | **인덱스 설계 최적화 전략**<br>1. **컬럼특성 기반 배치**: 주문일자 등 범위조회 빈번 컬럼 → 클러스터드(물리적 연속성), 고객ID·상품코드 등 점조회 → 논클러스터드로 보완<br>2. **복합인덱스 컬럼순서**: 최좌측 접두사(Leftmost Prefix) 규칙 → WHERE 사용빈도·선택도 높은 컬럼을 앞배치<br>3. **인덱스 과다생성 방지**: 인덱스↑ → DML 시 갱신비용 누적 → 실행계획 분석 기반 실사용 인덱스만 유지 |
