# TEXT2SQL: 자연어의 SQL 변환 서브노트

> **두음 머리에 박기 🧠**
> - **스·의·생·검** (TEXT2SQL 4대 구성요소: **스**키마 인식, **의**도 파악, **생**성, **검**증·실행)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **TEXT2SQL (자연어의 SQL 자동 변환)** |
| **정의** | 자연어 질의를 SQL 쿼리로 자동 변환하는 기술로, LLM 기반 스키마 이해와 의도 파악을 통해 비전문가도 데이터베이스를 직접 조회할 수 있게 하는 데이터 민주화(Data Democratization) 핵심 기술 |
| **키워드** | LLM, 스키마 인식, 의도 파악, BI 민주화, 데이터 거버넌스·감사, 방언(Dialect), SQL Injection |
| **개념도** | `[자연어 질의] "2024년 1분기 서울 매출 상위 10개 제품은?"` ➔ `[LLM/NLP: 스키마 이해+SQL 생성]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[SQL 쿼리 생성]` ➔ `[DB 실행]` ➔ `[결과 반환]` |
| **구성요소** | 1. **스키마 인식**: DB 테이블·컬럼 구조 이해<br>2. **의도 파악**: 자연어의 의미·조건 추출<br>3. **SQL 생성**: 문법적으로 올바른 SQL 생성<br>4. **실행 및 검증**: 생성된 SQL 실행 후 결과 검증 |
| **비교** | **활용 사례 ① BI 민주화**<br>- 데이터 분석가 없이 현업이 직접 데이터 조회<br>- 도구: Tableau AI, PowerBI Copilot, ThoughtSpot<br><br>**활용 사례 ② 데이터 거버넌스·감사**<br>- 자연어로 접근 이력·이상 패턴 조회<br>- 감사 담당자의 SQL 의존성 해소 |
| **차별화** | **TEXT2SQL 실무 도입 시 리스크 관리 전략**<br>1. **복잡 쿼리 한계 대응**: 다중 JOIN·서브쿼리·윈도우 함수에서 오류율이 높으므로, 생성된 SQL을 실행 전 검증 단계(Dry-run, EXPLAIN)로 재확인.<br>2. **스키마 변경 대응 체계**: DB 구조 변경 시 스키마 재주입 또는 RAG 기반 벡터DB 스키마 검색을 병행하여 최신성을 유지.<br>3. **보안 통제**: 생성 SQL의 인젝션·과도한 데이터 접근을 막기 위해 바인딩 변수 강제, 권한 기반 행/열 접근 제어(RLS)를 함께 적용. |
