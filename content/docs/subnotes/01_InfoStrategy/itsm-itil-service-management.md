# ITSM/ISO20000과 ITIL 서비스관리, 인시던트·문제·포트폴리오 관리 서브노트

> **두음 머리에 박기 🧠**
> - **전·설·전·운·개** (ITIL V3 서비스 수명주기 5단계: **전**략 ➔ **설**계 ➔ **전**환 ➔ **운**영 ➔ 지속적 **개**선)
> - **P·I·E·D·O·D** (ITIL V4 서비스가치사슬 6대 활동: **P**lan·**I**mprove·**E**ngage·**D**esign&Transition·**O**btain/Build·**D**eliver&Support)
> - **파·카·포** (서비스 3단계: **파**이프라인(미래) → **카**탈로그(현재) → **포**트폴리오(전체 집합))

| **토픽명** | **IT서비스관리(ITSM), ISO/IEC 20000, ITIL(V3/V4), 인시던트·문제 관리, 서비스 포트폴리오** |
| **정의** | ITSM: IT자원·서비스 비즈니스목표 부합 계획·구축·운영·개선하는 서비스중심 관리패러다임 → 대표 프레임워크 ISO/IEC 20000(인증표준)·ITIL(Best Practice) / 운영단계 핵심프로세스: 인시던트·문제관리 / 투자우선순위 관리저장소: 서비스포트폴리오(파이프라인·카탈로그 포함) |
| **키워드** | ITIL V3(수명주기) vs V4(SVS), ISO/IEC 20000 SMS, 인시던트 vs 문제 관리, 서비스 포트폴리오/카탈로그/파이프라인, SoW 유형 |
| **개념도** | `[ ITSM 모델 비교: ITIL / ISO20000 / CMMI-SVC / COBIT / MOF ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ ITIL V3: 전략-설계-전환-운영-개선(전·설·전·운·개) ]` ➔ V4 개정 ➔ `[ ITIL V4: 서비스가치시스템(SVS) + 6대 활동 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`│(운영단계)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 인시던트 관리(신속 복구) ] ──반복 시 승격──➔ [ 문제 관리(근본원인 제거) ]`<br>`[ 서비스 파이프라인(개발중) ] ➔ [ 서비스 카탈로그(운영중) ] ➔ [ 폐기 서비스 ] ⊂ 서비스 포트폴리오(전체)` |
| **구성요소** | 1. **ITSM 검토모델**: ITIL(AXELOS, 서비스수명주기 Best Practice), ISO/IEC 20000(PDCA기반 인증표준), CMMI-SVC(성숙도모델), COBIT(거버넌스·통제), MOF(MS플랫폼 특화)<br>2. **ITSM 성공요건**: 경영진지원, 프로세스표준화, 조직/역할정의(Service Desk·CAB), 도구지원, SLA/OLA체계, 변화관리, CSI(지속적개선)<br>3. **ISO/IEC 20000 설계·전환**: 요구사항정의→서비스설계(SLA안)→예산/일정→위험평가 / 전환: 롤백시나리오→테스트→지식이전→Go-Live(CAB승인)→안정화(ELS)<br>4. **ITIL V4 구성요소**: 서비스가치사슬(SVC: Plan-Improve-Engage-Design&Transition-Obtain/Build-Deliver&Support), 4대차원(조직/인력·정보/기술·파트너/공급자·가치흐름), 7대 가이딩원칙, 34개 Practice, CI(지속적개선)<br>5. **ITIL V3 수명주기(전·설·전·운·개)**: 서비스전략(포트폴리오·수요·재무관리)-설계(SLA·가용성·용량관리)-전환(변경·형상·릴리즈관리)-운영(인시던트·문제·이벤트관리)-CSI(7단계)<br>6. **인시던트 vs 문제**: 인시던트(접수→분류→조사→해결→종료, MTTR지표), 문제(식별→RCA(5-Why/Fishbone)→KEDB등록→해결책→검토)<br>7. **서비스포트폴리오 3요소(파·카·포)**: 파이프라인(개발중·비노출), 카탈로그(운영중·고객노출·SLA기준), 폐기서비스(과거) → 포트폴리오는 전체 아우르는 투자우선순위 근거<br>8. **SoW 유형(PMBOK 6판)**: 성과기반(결과중심), 기능기반(기능중심), 상세(절차까지 명시) |
| **비교** | **ITIL V3**<br>- 구조: 서비스수명주기 5단계(선형)<br>- 접근방식: 순차적 프로세스중심, 26개 프로세스<br>- 문화: 전통적 폭포수식 IT운영<br><br>**ITIL V4**<br>- 구조: 서비스가치사슬(SVC) 6개활동 유연조합<br>- 접근방식: 애자일/데브옵스, 반복·비선형, 34개 실무<br>- 문화: 린·애자일·데브옵스 통합, 가치공동창출<br><br>**인시던트 관리**<br>- 목적: 서비스 신속복구(임시조치)<br>- 시간관점: 단기(Reactive)<br><br>**문제 관리**<br>- 목적: 근본원인 제거(영구조치)<br>- 시간관점: 중장기(Proactive) |
| **차별화** | **ITSM 표준 통합구축 및 도구자동화 전략**<br>1. **ISO20000 인증-ITIL 실무 역할분리**: ISO20000=대외인증·감사요구사항, ITIL=실제구현 프로세스가이드 → 이중관리 부담경감<br>2. **인시던트-문제 자동승격체계**: ITSM도구(ServiceNow 등)에서 동일인시던트 임계횟수 초과시 자동 문제티켓 생성 룰 설정 → 근본원인분석 누락방지<br>3. **서비스카탈로그 셀프서비스 포털화**: 단순목록문서 → 셀프서비스 포털 구축, 사용자 SLA조건확인·직접요청 → 서비스데스크 부하경감 |
