# ITSM/ISO20000과 ITIL 서비스관리, 인시던트·문제·포트폴리오 관리 서브노트

> **두음 머리에 박기 🧠**
> - **전·설·전·운·개** (ITIL V3 서비스 수명주기 5단계: **전**략 ➔ **설**계 ➔ **전**환 ➔ **운**영 ➔ 지속적 **개**선)
> - **P·I·E·D·O·D** (ITIL V4 서비스가치사슬 6대 활동: **P**lan·**I**mprove·**E**ngage·**D**esign&Transition·**O**btain/Build·**D**eliver&Support)
> - **파·카·포** (서비스 3단계: **파**이프라인(미래) → **카**탈로그(현재) → **포**트폴리오(전체 집합))

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **IT서비스관리(ITSM), ISO/IEC 20000, ITIL(V3/V4), 인시던트·문제 관리, 서비스 포트폴리오** |
| **정의** | ITSM은 IT 자원과 서비스를 비즈니스 목표에 부합하도록 계획·구축·운영·개선하는 서비스 중심 관리 패러다임으로, ISO/IEC 20000(국제 인증표준)과 ITIL(Best Practice 가이드)이 대표 프레임워크이며, 서비스 운영 단계의 핵심 프로세스가 인시던트·문제 관리, 투자 우선순위 결정을 위한 관리 저장소가 서비스 포트폴리오(파이프라인·카탈로그 포함)이다 |
| **키워드** | ITIL V3(수명주기) vs V4(SVS), ISO/IEC 20000 SMS, 인시던트 vs 문제 관리, 서비스 포트폴리오/카탈로그/파이프라인, SoW 유형 |
| **개념도** | `[ ITSM 모델 비교: ITIL / ISO20000 / CMMI-SVC / COBIT / MOF ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ ITIL V3: 전략-설계-전환-운영-개선(전·설·전·운·개) ]` ➔ V4 개정 ➔ `[ ITIL V4: 서비스가치시스템(SVS) + 6대 활동 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`│(운영단계)`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 인시던트 관리(신속 복구) ] ──반복 시 승격──➔ [ 문제 관리(근본원인 제거) ]`<br>`[ 서비스 파이프라인(개발중) ] ➔ [ 서비스 카탈로그(운영중) ] ➔ [ 폐기 서비스 ] ⊂ 서비스 포트폴리오(전체)` |
| **구성요소** | 1. **ITSM 검토 모델**: ITIL(AXELOS, 서비스수명주기 Best Practice), ISO/IEC 20000(ISO, PDCA 기반 인증표준), CMMI-SVC(성숙도모델), COBIT(거버넌스·통제), MOF(MS 플랫폼 특화)<br>2. **ITSM 성공 구축 요건**: 경영진 지원, 프로세스 표준화, 조직/역할 정의(Service Desk·CAB), 도구 지원, SLA/OLA 체계, 변화관리, 지속적 개선(CSI)<br>3. **ISO/IEC 20000 서비스 설계·전환**: 요구사항정의→서비스설계(SLA안)→예산/일정→위험평가 / 전환단계는 롤백시나리오→테스트→지식이전→Go-Live(CAB승인)→안정화(ELS)<br>4. **ITIL V4 구성요소**: 서비스가치사슬(SVC, Plan-Improve-Engage-Design&Transition-Obtain/Build-Deliver&Support), 4대 차원(조직/인력, 정보/기술, 파트너/공급자, 가치흐름), 7대 가이딩원칙, 34개 실무(Practice), 지속적개선(CI)<br>5. **ITIL V3 서비스 수명주기(전·설·전·운·개)**: 서비스전략(포트폴리오·수요·재무관리)-서비스설계(SLA·가용성·용량관리)-서비스전환(변경·형상·릴리즈관리)-서비스운영(인시던트·문제·이벤트관리)-지속적서비스개선(CSI 7단계)<br>6. **인시던트 vs 문제 관리**: 인시던트관리(접수→분류→조사→해결→종료, MTTR 지표), 문제관리(식별→RCA(5-Why/Fishbone)→KEDB등록→해결책→검토)<br>7. **서비스 포트폴리오 3요소(파·카·포)**: 파이프라인(개발중, 비노출), 카탈로그(운영중, 고객 노출·SLA 기준), 폐기서비스(과거), 포트폴리오는 이 전체를 아우르는 투자 우선순위 결정 근거<br>8. **SoW 유형(PMBOK 6판)**: 성과기반(Performance-based, 결과 중심), 기능기반(Functional, 기능 중심), 상세(Design/Detailed, 절차까지 명시) |
| **비교** | **ITIL V3**<br>- 구조: 서비스 수명주기 5단계(선형)<br>- 접근방식: 순차적 프로세스 중심, 26개 프로세스<br>- 문화: 전통적 폭포수식 IT 운영<br><br>**ITIL V4**<br>- 구조: 서비스가치사슬(SVC) 6개 활동의 유연한 조합<br>- 접근방식: 애자일/데브옵스 반영, 반복·비선형적, 34개 실무<br>- 문화: 린·애자일·데브옵스 통합, 비즈니스 가치 공동창출<br><br>**인시던트 관리**<br>- 목적: 서비스 신속 복구(임시조치)<br>- 시간관점: 단기(Reactive)<br><br>**문제 관리**<br>- 목적: 근본원인 제거(영구조치)<br>- 시간관점: 중장기(Proactive) |
| **차별화** | **ITSM 표준 통합 구축 및 도구 자동화 전략**<br>1. **ISO 20000 인증과 ITIL 실무 가이드의 역할 분리**: ISO 20000은 대외 인증·감사 대상 요구사항으로, ITIL은 그 요구사항을 실제로 구현하는 프로세스 실무 가이드로 역할을 분리해 이중 관리 부담을 줄임.<br>2. **인시던트-문제 관리의 자동 승격 체계 구축**: ITSM 도구(ServiceNow 등)에서 동일 인시던트가 임계 횟수 이상 반복될 경우 자동으로 문제 티켓을 생성하도록 룰을 설정해, 근본원인 분석이 누락되지 않도록 통제.<br>3. **서비스 카탈로그의 셀프서비스 포털화**: 서비스 카탈로그를 단순 목록 문서가 아닌 셀프서비스 포털로 구축하여, 사용자가 SLA 조건을 확인하고 직접 서비스를 요청하도록 하여 서비스데스크 부하를 경감. |
