# Lean UX의 개념과 원칙, 적용 프로세스 서브노트

> **두음 머리에 박기 🧠**
> - **디·애·린** (Lean UX 3대 원칙: **디**자인 씽킹, **애**자일 결합, **린** 스타트업 사고)
> - **가·비·측·학** (적용 프로세스 4단계: **가**설 ➔ **비**Build ➔ **측**Measure ➔ **학**Learn)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **Lean UX (린 UX)** |
| **정의** | 산출물(Deliverable)이 아닌 결과(Outcome) 집중 → MVP 수준 프로토타입 빠르게 제작, 실사용자 피드백으로 가설 검증·개선하는 협업적 UX 방법론 (Lean Startup Build-Measure-Learn + 애자일 반복개발을 UX에 접목) |
| **키워드** | MVP, Build-Measure-Learn, 가설 기반 사고, Just Enough Documentation, 디자인 씽킹 |
| **개념도** | `[ 가설 선언(우리는 ~라고 믿는다) ] ➔ [ Build: Wireframe/Prototype ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ Learn: 검증/기각 판단 ] ◀── [ Measure: A/B Test·실험 데이터 ]` |
| **구성요소** | **개념·특징**: 가설기반("우리는 ~라고 믿는다"), 협업중심(화이트보드 상시협업), 결과지향(전환율 등 비즈니스결과), 빠른반복(Build-Measure-Learn 순환), 최소문서화(Just Enough Documentation)<br>**3대 원칙(디·애·린)**: ①디자인씽킹 - 사용자공감 기반 문제재정의(Empathize→정의→아이데이션→프로토타입→테스트) ②애자일 결합 - 짧은 스프린트 단위 반복개발+UX설계 병행 ③린스타트업 사고 - 가설-실험-학습 과학적 접근 → 낭비제거(MVP 최소투자, 빠른실패, 빠른학습)<br>**적용 프로세스(가·비·측·학)**: 가설(가설선언문·Persona, Lean Canvas)→Build(Wireframe/Prototype, Figma)→Measure(실험결과 데이터, GA/A·B Test)→Learn(검증/기각 판단, Retrospective) |
| **비교** | **전통적 UX 설계**<br>- 산출물중심: 완성된 문서·화면설계서<br>- 피드백주기: 느림(단계별 완료후 검토)<br><br>**Lean UX**<br>- 결과중심: 비즈니스 성과(전환율 등)<br>- 피드백주기: 빠름(짧은 스프린트마다 실사용자 검증) |
| **차별화** | **커머스·핀테크 등 결과지향 산업의 Lean UX 정착전략**<br>1. **가설 품질관리 체계화**: 가설선언 시 측정가능 성공기준(전환율 X% 등) 명시 표준템플릿 강제 → 검증불가 막연가설 남발 방지<br>2. **애자일 스프린트-UX검증 주기 동기화**: 스프린트 종료시점 맞춰 A/B Test 통계적유의성 확보기간 사전설계 → 미검증 UX변경 배포 방지<br>3. **최소문서화 원칙 조직적 합의**: "문서화 생략" 오인방지 → 핵심 의사결정근거(가설·실험결과)만 필수기록하는 최소문서 기준 표준화 |
