# 프로젝트 위험관리 (PMBOK 위험관리 프로세스) 서브노트

> **두음 머리에 박기 🧠**
> - **계·식·정정·대·감** (PMBOK 위험관리 6단계: 위험관리 **계**획, 위험 **식**별, **정**성적 위험분석, **정**량적 위험분석, 위험 **대**응계획, 위험 감시·통제)
> - **회·전·완·수** (위협(Threat) 대응 4대 전략: **회**피 Avoid, **전**가 Transfer, **완**화 Mitigate, **수**용 Accept)
> - **활·공·강·수** (기회(Opportunity) 대응 4대 전략: **활**용 Exploit, **공**유 Share, **강**화 Enhance, **수**용 Accept)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **프로젝트 위험관리 (Project Risk Management, PMBOK)** |
| **정의** | 프로젝트 목표 달성에 영향을 미칠 수 있는 불확실한 사건이나 조건을 체계적으로 식별·분석·대응하는 프로세스로, PMI PMBOK 기준 **6개 프로세스(계·식·정정·대·감)**로 구성되며 위협(Threat)과 기회(Opportunity)를 구분하여 각기 다른 대응 전략을 적용한다 |
| **키워드** | 위험관리 6단계, 정성적/정량적 위험분석, 위협 대응(회·전·완·수), 기회 대응(활·공·강·수), 위험 등록부(Risk Register) |
| **개념도** | `[ 1.위험관리계획 ] ➔ [ 2.위험식별 ] ➔ [ 3.정성적분석(P×I 매트릭스) ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`▼`<br>`[ 6.위험 감시·통제 ] ◀── [ 5.위험 대응계획(회·전·완·수 / 활·공·강·수) ] ◀── [ 4.정량적분석(몬테카를로) ]` |
| **구성요소** | 1. **위험관리 계획**: 위험 관리 접근법·활동 정의, 위험 등록부 양식 수립<br>2. **위험 식별**: 브레인스토밍, 체크리스트, SWOT 분석으로 위험 도출<br>3. **정성적 위험 분석**: 확률·영향 개별평가, 확률-영향 매트릭스(고/중/저 등급), 위험데이터 품질평가, RBS 기반 카테고리 분석 등으로 신속히 우선순위화<br>4. **정량적 위험 분석**: EMV 분석(의사결정나무), 민감도 분석(토네이도 다이어그램), 몬테카를로 시뮬레이션(완료일·비용 확률분포 S-Curve), PERT 3점 추정(기대공수=(O+4M+P)/6) 등으로 정성분석에서 선별된 고위험군을 정밀 계량화<br>5. **위험 대응 계획**: 회피·전가·완화·수용(위협) / 활용·공유·강화·수용(기회) 전략 수립<br>6. **위험 감시 및 통제**: 잔존 위험 모니터링, 새로운 위험 식별<br>7. **위험 등록부(Risk Register)**: 위험 ID, 발생확률, 영향도, 위험점수(P×I), 대응전략, 담당자(Risk Owner), 잔존위험을 기록하는 핵심 산출물<br>8. **Boehm의 10대 위험 목록(1991)**: ①인력부족 ②비현실적 일정·예산 ③잘못된 기능 개발 ④잘못된 UI 개발 ⑤도금(Gold Plating) ⑥요구사항 지속변경 ⑦외부 공급 컴포넌트 결함 ⑧외부 수행작업 결함 ⑨실시간 성능문제 ⑩컴퓨터과학 한계 도전<br>9. **위험(Risk) vs 이슈(Issue) 구분**: 위험은 발생 여부가 불확실한 미래 사건(사전/Proactive, 확률×영향 정량평가, Risk Register), 이슈는 이미 발생이 확정된 현재 문제(사후/Reactive, 즉시조치·담당자 배정, Issue Log). 위험의 조기경보지표가 임계치를 넘으면 이슈로 자동 승격(Escalation) |
| **비교** | **위협(Threat) 대응 전략**<br>- 회피(Avoid): 위험 원인 제거 (일정 변경, 범위 축소)<br>- 전가(Transfer): 보험·계약으로 제3자 이전<br>- 완화(Mitigate): 발생 확률·영향도 감소 (프로토타입, 추가 테스트)<br>- 수용(Accept): 능동적(예비비) 또는 수동적(발생 시 대응)<br><br>**기회(Opportunity) 대응 전략**<br>- 활용(Exploit): 기회 실현을 확실히 함 (우수 인력 배치)<br>- 공유(Share): 파트너와 기회 공동 추구 (조인트벤처)<br>- 강화(Enhance): 기회 발생 확률·영향도 증가<br>- 수용(Accept): 별도 조치 없이 기회 발생 시 혜택 수용 |
| **차별화** | **위험 대응 실행력 확보를 위한 실무 전략**<br>1. **위험 소유자(Risk Owner) 명시적 지정**: 위험 등록부의 각 위험 항목에 담당자를 지정하지 않으면 대응 전략이 문서로만 남고 실행되지 않으므로, 식별 즉시 담당자와 대응 시한을 함께 확정.<br>2. **정성적→정량적 분석의 단계적 적용**: 모든 위험에 몬테카를로 시뮬레이션 같은 정량적 분석을 적용하면 비용이 과다하므로, 정성적 분석(P×I 매트릭스)으로 상위 위험만 선별한 뒤 그 위험에 한해 정량적 분석을 수행하는 2단계 필터링 전략.<br>3. **잔존 위험·2차 위험 추적 체계화**: 대응 전략 실행 후에도 남는 잔존 위험(Residual Risk)과 대응 자체가 유발하는 2차 위험(Secondary Risk)을 위험 등록부에 별도 컬럼으로 관리하여 감시·통제 단계에서 누락을 방지. |
