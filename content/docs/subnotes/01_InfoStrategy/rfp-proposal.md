# 제안요청서(RFP)의 목차 구성과 필수 요구사항 서브노트

> **두음 머리에 박기 🧠**
> - **개·추·제·관·작·평·계** (RFP 7대 목차: **개**요 ➔ **추**진계획 ➔ **제**안요청내용 ➔ 사업**관**리요구사항 ➔ 제안서**작**성지침 ➔ **평**가기준 ➔ **계**약조건)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **제안요청서(RFP, Request For Proposal)** |
| **정의** | RFP는 발주기관이 사업목적·범위·요구사항·평가기준을 명시하여 제안서 작성을 요청하는 공식 문서로, 소프트웨어산업진흥법에 따라 공공정보화사업은 요구사항을 명확하고 상세하게 RFP에 담도록 의무화되어 있으며, 이는 발주 이후의 과업변경(Scope Creep) 분쟁을 예방하는 핵심 장치이다 |
| **키워드** | SIRS(요구사항 명세), 소프트웨어산업진흥법, 기술평가/가격평가, PMO 사업 RFP |
| **개념도** | `[ I.사업개요 ] ➔ [ II.추진계획 ] ➔ [ III.제안요청내용(SIRS) ] ➔ [ IV.사업관리요구사항 ] ➔ [ V.제안서작성지침 ] ➔ [ VI.평가기준 ] ➔ [ VII.계약조건 ]` |
| **구성요소** | **RFP 7대 목차(개·추·제·관·작·평·계)**: Ⅰ.사업개요(사업명·목적·배경·기간·예산), Ⅱ.추진계획(사업범위·추진체계·일정 WBS), Ⅲ.제안요청내용(기능/성능/시스템/데이터/보안 요구사항, SIRS 기준 고유번호 부여), Ⅳ.사업관리요구사항(프로젝트관리·품질보증·형상관리, PMO/감리 연계), Ⅴ.제안서작성지침(목차·분량·제출방법, 공정경쟁 보장), Ⅵ.평가기준(기술/가격평가 배점표), Ⅶ.계약조건(대가지급·하자보수·지식재산권)<br>**PMO 사업 RFP 필수 요구사항**: 관리요구사항(SMR) 중심(일반 SI는 기능요구사항 SFR 중심), 산출물이 점검보고서·개선권고서·이슈로그 중심(일반 SI는 소스코드·시스템), 평가 포인트가 PM경력·방법론이해도·독립성(일반 SI는 기술아키텍처 역량) |
| **비교** | **일반 SI 개발 RFP**<br>- 중심 요구사항: 기능 요구사항(SFR) 최다<br>- 산출물: 소스코드, 시스템<br>- 평가 포인트: 기술 아키텍처 역량<br><br>**PMO 사업 RFP**<br>- 중심 요구사항: 관리 요구사항(SMR) 최다<br>- 산출물: 점검보고서, 개선권고서, 이슈로그<br>- 평가 포인트: PM 경력, 방법론 이해도, 독립성 |
| **차별화** | **모호한 요구사항으로 인한 분쟁 예방 실무 전략**<br>1. **SIRS 고유번호 부여를 통한 추적성 확보**: 제안요청내용의 각 요구사항에 고유번호를 부여해 개발 단계의 요구사항추적표(RTM)와 연계, 향후 과업변경 시 계약범위 내외 판단의 객관적 근거로 활용.<br>2. **평가기준 배점의 사전 공개로 공정성 확보**: 기술평가·가격평가 배점표를 RFP 단계부터 명확히 공개하여, 사업자 선정 이후 발생할 수 있는 이의제기·소송 리스크를 사전에 차단.<br>3. **PMO/감리 연계 요구사항의 명시적 반영**: 사업관리요구사항 목차에 PMO 및 감리 수행 시점·범위를 사전에 명시하여, 착수 이후 PMO·감리와 수행사 간 R&R 혼선을 예방. |
