# 서브네팅 및 VLSM/CIDR 서브노트

> **두음 머리에 박기 🧠**
> - **넷·호** (IP 주소의 구조적 분할: **넷**워크 ID 영역 + **호**스트 ID 영역)
> - **2^H - 2** (서브넷당 할당 가능한 실제 유효 호스트 수: 호스트 비트 수가 $H$일 때, 네트워크 주소(모두 0)와 브로드캐스트 주소(모두 1)를 차감한 수식)
> - **앤드(AND) 연산** (서브넷 네트워크 주소 추출 방식: IP 주소와 서브넷 마스크 비트를 비트별 **AND** 연산 처리)

---

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **IP 서브네팅 (Subnetting), 가변 길이 서브넷 마스크 (VLSM) 및 CIDR** |
| **정의** | 고정된 IP 클래스 주소 낭비를 막기 위해 호스트 비트를 차용하여 여러 서브넷으로 쪼개는 **서브네팅**과, 가변 크기 마스크를 적용하는 **VLSM**, 비트 단위로 네트워크를 통합/분할하는 **CIDR 기술** |
| **키워드** | Classless, VLSM, CIDR Prefix (접두사), 수식 ($2^H - 2$), 라우팅 요약 (Route Summarization), FLSM |
| **개념도** | **[ 192.168.1.0/24 대역의 VLSM 서브네팅 예시 ]**<br>전체 대역: `192.168.1.0/24` (총 256개 IP)<br>&nbsp;&nbsp;&nbsp;&nbsp;`├── 서브넷 A (100대 필요) ➔ 192.168.1.0/25` (IP 범위: .0 ~ .127, 서브넷 마스크: 255.255.255.128)<br>&nbsp;&nbsp;&nbsp;&nbsp;`├── 서브넷 B (50대 필요)  ➔ 192.168.1.128/26` (IP 범위: .128 ~ .191, 서브넷 마스크: 255.255.255.192)<br>&nbsp;&nbsp;&nbsp;&nbsp;`└── 서브넷 C (25대 필요)  ➔ 192.168.1.192/27` (IP 범위: .192 ~ .223, 서브넷 마스크: 255.255.255.224)<br>&nbsp;&nbsp;&nbsp;&nbsp;`[ 가변 길이 마스크(VLSM)를 적용하여 남은 IP(.224 ~ .255)는 타 용도로 세이브 ]` |
| **구성요소** | 1. **서브넷 마스크 (Subnet Mask)**: IP 주소에서 네트워크 ID(1로 표시)와 호스트 ID(0으로 표시)를 구별하는 32비트 마커<br>2. **FLSM (Fixed Length Subnet Mask)**: 단일 네트워크 내 모든 서브넷을 동일한 고정 크기 마스크로 일률 분할 기법<br>3. **VLSM (Variable Length)**: 각 서브넷에 연결될 단말(호스트) 수 요구량에 맞춰 가변적 마스크 크기를 매핑하는 기법<br>4. **CIDR (Classless Inter-Domain Routing)**: 클래스리스 기반. 접두사 표기법(예: `/22`)으로 여러 C클래스 네트워크 통합 |
| **비교** | **FLSM (고정 길이 서브넷 마스크)**<br>- **서브넷 마스크**: 모두 동일 (예: 전부 `/26` 고정)<br>- **IP 효율성**: 매우 낮음 (호스트 수가 적은 지사에도 큰 대역 할당으로 낭비 유발)<br><br>**VLSM (가변 길이 서브넷 마스크)**<br>- **서브넷 마스크**: 필요한 크기에 따라 개별 다름 (예: `/25`, `/26`, `/30` 혼재)<br>- **IP 효율성**: 최상 (요청된 크기에 딱 맞춘 분할로 잔여 IP 절약) |
| **차별화** | **인터넷 백본망 라우팅 테이블 축소를 위한 CIDR 기반 라우팅 요약(Route Summarization) 전략**<br>1. **라우팅 요약(Supernetting)을 통한 메모리 아웃오브메모리(OOM) 방지**: 코어 라우터가 보관해야 하는 라우팅 경로 수가 기하급수적으로 늘어나는 테이블 오버헤드를 제어하기 위해, 하위 4개의 연속된 네트워크 대역(`10.1.0.0/24`, `10.1.1.0/24`, `10.1.2.0/24`, `10.1.3.0/24`)을 하나의 묶음 대역인 `10.1.0.0/22`로 요약하여 상위 라우터에 전파.<br>2. **서브네팅 시의 네트워크 주소 및 브로드캐스트 주소 유실 관리**: 각 서브넷 분할 시마다 첫 주소(네트워크 주소)와 마지막 주(브로드캐스트 주소) 2개는 호스트 IP로 할당 불가능하므로, 서브넷을 지나치게 작게 여러 개 쪼갤수록 소모되는 낭비 주소 비중($2 \times 서브넷 개수$)이 비대해짐에 유의하여 설계.<br>3. **사설 IP 대역(RFC 1918)과의 매핑**: 내부망 기획 시 공인 IP 부족을 피하기 위해 A클래스(`10.0.0.0/8`), B클래스(`172.16.0.0/12`), C클래스(`192.168.0.0/16`) 사설 대역을 설정하고, 내부 서브네팅 및 외부망 경계에서의 NAT 연동 구조 설계. |
