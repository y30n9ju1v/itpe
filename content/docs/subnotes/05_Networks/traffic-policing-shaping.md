# 트래픽 폴리싱과 트래픽 쉐이핑 서브노트

> **두음 머리에 박기 🧠**
> - **시·피·씨·티** (트래픽 제어 4대 파라미터: 보장전송률 **C**IR, 최대전송률 **P**IR, 버스트크기 **C**BS, 측정구간 **T**C)
> - **그·옐·레** (Two-Rate Three-Color Marker 3색 마킹: CIR이하 **그**린, CIR~PIR **옐**로우, PIR초과 **레**드)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **트래픽 폴리싱(Traffic Policing) 및 트래픽 쉐이핑(Traffic Shaping)** |
| **정의** | QoS 구현을 위한 네트워크 트래픽 제어 기법으로, 폴리싱은 허용 대역폭 초과 트래픽을 즉시 드롭·마킹하고 쉐이핑은 버퍼에 지연 저장해 전송 속도를 평탄화(Smoothing)하는 방식 |
| **키워드** | CIR/PIR/CBS/TC, 토큰 버킷, 리키 버킷, Two-Rate Three-Color Marker, VoIP/HTTP 적용 사례 |
| **개념도** | **[ 토큰 버킷 vs 리키 버킷 ]**<br>`토큰 버킷(Token Bucket)`<br>`[ 버킷에 CIR 속도로 토큰 생성 ] → 패킷 전송 시 토큰 소모`<br>`토큰 없음 → 폴리싱: Drop / 쉐이핑: 대기(버퍼)`<br>&nbsp;&nbsp;&nbsp;&nbsp;`↓`<br>`리키 버킷(Leaky Bucket)`<br>`[ 입력 패킷 → 버퍼 저장 ] → 일정 속도(CIR)로만 출력`<br>`버킷 가득 참 → Drop (완벽한 평탄화)` |
| **구성요소** | 1. **CIR(Committed Information Rate)**: 보장된 기본 전송률<br>2. **PIR(Peak Information Rate)**: 허용 최대 전송률<br>3. **CBS(Committed Burst Size)**: 허용 순간 버스트 크기<br>4. **토큰 버킷 알고리즘**: CIR 속도로 토큰 생성, 패킷 전송 시 토큰 소모, 버스트 허용(CBS 범위)<br>5. **리키 버킷 알고리즘**: 입력을 버퍼에 저장 후 CIR 속도로만 출력해 완전한 평탄화 수행<br>6. **듀얼 토큰 버킷(Two-Rate Three-Color Marker)**: CIR·PIR 버킷을 동시 운영해 Green/Yellow/Red로 3색 마킹 |
| **비교** | **트래픽 폴리싱 (Policing)**<br>- 초과 처리: 드롭(Drop) 또는 마킹(Re-marking), 즉시 처리<br>- 지연: 없음 / 패킷 손실: 있음<br>- 적용 위치: 인그레스·이그레스(ISP 경계, SLA 적용)<br>- 적합 트래픽: 실시간(VoIP) 경계 제어<br><br>**트래픽 쉐이핑 (Shaping)**<br>- 초과 처리: 버퍼에 저장 후 지연 전송<br>- 지연: 있음(버퍼링) / 패킷 손실: 적음<br>- 적용 위치: 이그레스(WAN 엣지, 다운스트림 제어)<br>- 적합 트래픽: 탄력적 데이터(HTTP) |
| **차별화** | **QoS 정책 설계 시 트래픽 유형별 제어 기법 선정 전략**<br>1. **실시간 트래픽은 폴리싱 우선**: VoIP·화상회의 등 지연에 민감한 트래픽은 버퍼링으로 인한 지터 발생을 피하기 위해 경계에서 즉시 드롭/마킹하는 폴리싱을 적용.<br>2. **탄력적 트래픽은 쉐이핑 우선**: 파일 전송·웹 트래픽처럼 지연에 덜 민감한 트래픽은 버퍼링으로 순간 버스트를 흡수하는 쉐이핑을 적용해 패킷 손실을 최소화.<br>3. **3색 마킹 기반 차등 서비스 연계**: Two-Rate Three-Color Marker로 Green/Yellow/Red를 구분한 뒤, DiffServ의 우선순위 큐잉과 연계하여 혼잡 시 Red 트래픽부터 선택적으로 폐기하는 계층적 QoS 구조를 구성. |
