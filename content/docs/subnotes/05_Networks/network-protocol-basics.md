# 네트워크 프로토콜 기본 개념 서브노트

> **두음 머리에 박기 🧠**
> - **신·시·타** (프로토콜 3요소: 형식·구조 **신**택스 Syntax, 의미 **시**맨틱스 Semantics, 순서·속도 **타**이밍 Timing)
> - **캡·단·오·흐·혼·주·다·동** (프로토콜 8대 기능: **캡**슐화, **단**편화·재조립, **오**류제어, **흐**름제어, **혼**잡제어, **주**소지정, **다**중화, **동**기화)

| 분류 | 기술 기술사 서브노트 작성 예시 (1교시형 포맷) |
| :--- | :--- |
| **토픽명** | **네트워크 프로토콜 (Network Protocol) 개념·3요소·기능** |
| **정의** | 통신 개체들이 데이터를 주고받기 위해 합의한 규칙과 절차의 집합으로, 이기종 시스템 간 표준화된 통신을 가능하게 하며 신택스·시맨틱스·타이밍의 3요소로 구성됨 |
| **키워드** | Syntax/Semantics/Timing, 캡슐화, 흐름제어, 혼잡제어, 표준화기관(ISO/IETF/IEEE/ITU-T) |
| **개념도** | **[ 프로토콜 3요소 및 계층 간 캡슐화 ]**<br>`[ Syntax : 헤더 필드 배치·인코딩 ]`<br>`[ Semantics : ACK=수신확인, SYN=연결요청 등 필드 의미 ]`<br>`[ Timing : 전송속도·순서·RTO 재전송 타임아웃 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`↓ 상위 계층 데이터`<br>`[ 헤더(주소·제어정보) + Payload ] → 캡슐화(Encapsulation) → 하위 계층 전달` |
| **구성요소** | 1. **Syntax(구문)**: 데이터의 형식·구조·부호화 방식(헤더 필드 배치, 비트 순서, 인코딩)<br>2. **Semantics(의미)**: 각 비트·필드의 의미와 오류·흐름 제어 방법(ACK=수신확인, SYN=연결요청)<br>3. **Timing(타이밍)**: 데이터 전송 속도·순서·동기화(흐름 제어, 재전송 타임아웃 RTO)<br>4. **표준화 기관**: ISO(OSI 모델), IETF(TCP/IP), IEEE(유무선 LAN), ITU-T(통신)<br>5. **8대 기능**: 캡슐화, 단편화·재조립, 오류 제어(CRC/ARQ), 흐름 제어(슬라이딩 윈도우), 혼잡 제어, 주소 지정(MAC/IP/포트), 다중화·역다중화, 동기화 |
| **비교** | **연결지향 프로토콜 (예: TCP)**<br>- 특징: 3-way handshake로 세션 수립 후 전송, 순서·신뢰성 보장<br>- 활용: 파일 전송, 신뢰성이 중요한 응용<br><br>**비연결지향 프로토콜 (예: UDP)**<br>- 특징: 세션 수립 없이 즉시 전송, 순서·신뢰성 미보장<br>- 활용: 실시간 스트리밍, DNS 질의 등 저지연 응용 |
| **차별화** | **프로토콜 3요소·기능을 실제 네트워크 설계에 적용하는 관점**<br>1. **표준화 기관별 역할 분담**: ISO(OSI 참조모델)-IETF(TCP/IP 실질 표준)-IEEE(물리/데이터링크 유무선 LAN)-ITU-T(통신망 전반)가 계층별로 표준을 분담해 이기종 시스템 간 상호운용성을 보장.<br>2. **오류·흐름·혼잡 제어의 계층적 배치**: 오류 제어는 데이터링크(HDLC의 CRC/ARQ)와 전송 계층(TCP 재전송) 모두에서, 흐름 제어(슬라이딩 윈도우)와 혼잡 제어(TCP 혼잡 윈도우)는 주로 전송 계층에서 수행되어 종단간 신뢰성을 이중으로 확보.<br>3. **캡슐화 기반 계층 독립성**: 각 계층이 상위 데이터에 자신의 헤더만 추가(캡슐화)함으로써 계층 간 결합도를 낮추고, 프로토콜 변경 시 다른 계층에 미치는 영향을 최소화. |
