# 네트워크 프로토콜 기본 개념 서브노트

> **두음 머리에 박기 🧠**
> - **신·시·타** (프로토콜 3요소: 형식·구조 **신**택스 Syntax, 의미 **시**맨틱스 Semantics, 순서·속도 **타**이밍 Timing)
> - **캡·단·오·흐·혼·주·다·동** (프로토콜 8대 기능: **캡**슐화, **단**편화·재조립, **오**류제어, **흐**름제어, **혼**잡제어, **주**소지정, **다**중화, **동**기화)

---

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **네트워크 프로토콜 (Network Protocol) 개념·3요소·기능** |
| **정의** | 통신개체 간 데이터 송수신 합의 규칙·절차 집합 → 이기종시스템 표준통신, 신택스·시맨틱스·타이밍 3요소 구성 |
| **키워드** | Syntax/Semantics/Timing, 캡슐화, 흐름제어, 혼잡제어, 표준화기관(ISO/IETF/IEEE/ITU-T) |
| **개념도** | **[ 프로토콜 3요소 및 계층 간 캡슐화 ]**<br>`[ Syntax : 헤더 필드 배치·인코딩 ]`<br>`[ Semantics : ACK=수신확인, SYN=연결요청 등 필드 의미 ]`<br>`[ Timing : 전송속도·순서·RTO 재전송 타임아웃 ]`<br>&nbsp;&nbsp;&nbsp;&nbsp;`↓ 상위 계층 데이터`<br>`[ 헤더(주소·제어정보) + Payload ] → 캡슐화(Encapsulation) → 하위 계층 전달` |
| **구성요소** | 1. **Syntax(구문)**: 데이터 형식·구조·부호화 (헤더필드 배치, 비트순서, 인코딩)<br>2. **Semantics(의미)**: 비트·필드 의미, 오류·흐름제어 방법 (ACK=수신확인, SYN=연결요청)<br>3. **Timing(타이밍)**: 전송속도·순서·동기화 (흐름제어, 재전송타임아웃 RTO)<br>4. **표준화기관**: ISO(OSI모델), IETF(TCP/IP), IEEE(유무선LAN), ITU-T(통신)<br>5. **8대 기능**: 캡슐화, 단편화·재조립, 오류제어(CRC/ARQ), 흐름제어(슬라이딩윈도우), 혼잡제어, 주소지정(MAC/IP/포트), 다중화·역다중화, 동기화 |
| **비교** | **연결지향 프로토콜 (예: TCP)**<br>- 특징: 3-way handshake → 세션수립 후 전송, 순서·신뢰성 보장<br>- 활용: 파일전송 등 신뢰성 중요 응용<br><br>**비연결지향 프로토콜 (예: UDP)**<br>- 특징: 세션수립 없이 즉시전송, 순서·신뢰성 미보장<br>- 활용: 실시간 스트리밍, DNS질의 등 저지연 응용 |
| **차별화** | **프로토콜 3요소·기능의 네트워크 설계 적용 관점**<br>1. **표준화기관별 역할분담**: ISO(OSI 참조모델)-IETF(TCP/IP 실질표준)-IEEE(물리/DL 유무선LAN)-ITU-T(통신망 전반) → 계층별 표준분담 → 이기종 상호운용성 보장<br>2. **오류·흐름·혼잡제어 계층적 배치**: 오류제어(DL: HDLC CRC/ARQ + 전송계층: TCP 재전송) 이중화, 흐름제어(슬라이딩윈도우)·혼잡제어(TCP 혼잡윈도우)는 전송계층 → 종단간 신뢰성 확보<br>3. **캡슐화 기반 계층 독립성**: 계층별 자기 헤더만 추가 → 계층간 결합도↓, 프로토콜 변경영향 최소화 |
