# 소프트웨어 신뢰성 및 가동율 평가 서브노트

> **두음 머리에 박기 🧠**
> - **엠·엠·엠** (가용성 평가 3대 실측 지표: 평균고장간격 **MTBF**, 평균고장시간 **MTTF**, 평균수리시간 **MTTR**)
> - **엠·엠·플러스·엠** (시스템 가동율 가용도 공식: $A = \frac{MTBF}{MTBF + MTTR}$ 또는 $\frac{MTTF}{MTTF + MTTR}$)
> - **파이브 나인스 (99.999%)** (미션 크리티컬 가용성 극대 지표: 연간 고장 허용 한계 시간이 단 **5.26분** 이내인 등급)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **시스템 신뢰성 (Reliability) 및 고가용성 (HA, High Availability) 가동율 평가** |
| **정의** | 시스템이 오작동 없이 연속 동작하는 신뢰도와 장애에 대비해 즉시 복구되는 가용성을 **MTBF/MTTR 지표를 기반으로 정량 평가하고 직/병렬 수학적 가동율로 산출하는 기술** |
| **키워드** | MTBF, MTTF, MTTR, 가용율 공식 (A), 직렬 vs 병렬 신뢰성, SRE (사이트 신뢰성 공학), 에러 버짓 (Error Budget) |
| **개념도** | **[ 시스템 고장 및 복구 생명주기 타임라인과 가용성 수식 구조 ]**<br>`├─────── 가동 동작 (UP) ───────┤ (고장 발생) ├── 수리 (DOWN) ──┤ (복구 완료) ├────── 가동 동작 (UP) ──────┤`<br>`│◀──────────  MTTF  ──────────▶│◀─────  MTTR  ─────▶│◀──────────  MTTF  ──────────▶│`<br>`│◀───────────────────────────────────────  MTBF  ──────────────────────────────────────▶│`<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;**[ 가중 신뢰성 계산 구조 ]**<br>&nbsp;&nbsp;&nbsp;&nbsp;`[ 직렬 구조 : A ➔ B ] ➔ 가동율 = A * B` &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;`[ 병렬 이중화 구조 (Parallel) ] ➔ 가동율 = 1 - (1 - A)(1 - B)` |
| **구성요소** | 1. **MTTF (Mean Time To Failure)**: 평균 고장 시간. 수리 불가 장비의 수명 혹은 최초 고장 발생까지의 평균 동작 시간<br>2. **MTTR (Mean Time To Repair)**: 평균 수리 시간. 고장 시점부터 장애를 탐지하고 복구 조치 완료까지 소요된 시간의 평균<br>3. **MTBF (Mean Time Between Failures)**: 평균 고장 간격. $MTBF = MTTF + MTTR$로 정의하며, 고장에서 다음 고장 사이의 시간<br>4. **고가용성 (HA)**: Active-Active 클러스터링, 무중단 백업 장치 등을 배치하여 시스템 다운타임을 수 분 이내로 제어하는 기법 |
| **비교** | **직렬 시스템 신뢰성 (Serial)**<br>- **연결 특징**: 하드웨어가 꼬리에 꼬리를 무는 단일 경로 구성<br>- **가동율 연산**: $A_1 \times A_2 \times A_3$ (각 단위 가동율 곱)<br>- **최종 가용성**: 개별 장비 가동율보다 전체 가동율이 반드시 감쇄됨<br><br>**병렬 시스템 신뢰성 (Parallel)**<br>- **연결 특징**: 컴포넌트가 이중화/삼중화되어 우회 경로 존재<br>- **가동율 연산**: $1 - (1-A_1)(1-A_2)$ (전체 동시 고장 확률 차감)<br>- **최종 가용성**: 개별 장비 가동율보다 전체 가동율이 비약적 상향 |
| **차별화** | **SRE (Site Reliability Engineering) 관점의 에러 버짓 (Error Budget) 도입 및 시스템 모니터링 전략**<br>1. **에러 버짓 (Error Budget) 거버넌스 도입**: 완벽한 $100\%$ 가용성 달성은 기하급수적 비용 낭비와 릴리즈 속도 저해를 낳으므로, 합의된 서비스 수준 목표(SLO - 예: $99.9\%$)를 뺀 나머지 불가동 허용 범위(에러 버짓 - $0.1\%$, 연간 8.76시간)를 정립. 에러 버짓 소진 시 신규 기능 배포를 전면 중단하고 장애 안정화에 올인.<br>2. **가용성 극대화를 위한 Active-Active 멀티 리전(Region) 설계**: 전력 마비나 지진 등 대형 물리 장애에 대응해 클라우드 이종 리전에 분산 Active-Active 배포를 하고 글로벌 DNS(GSLB)의 헬스체크 연동을 통해 무정지 장애 극복(Failover) 구현.<br>3. **SLA(서비스 수준 약정) 컴플라이언스 관리**: 다운타임 발생 시 고객 배상 및 패널티 부과 기준이 되는 SLA 지표를 실시간 가동율 모니터링 툴(Datadog, Prometheus)과 연동하여 위험 임계치 사전 푸시 시스템 가동. |
