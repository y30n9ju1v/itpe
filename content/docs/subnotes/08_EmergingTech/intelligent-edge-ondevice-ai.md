# 지능형 엣지 컴퓨팅 및 클라우드 AI vs 온디바이스 AI 서브노트

> **두음 머리에 박기 🧠**
> - **디·엣·M·클** (지능형 엣지 컴퓨팅 4계층 구조: **디**바이스(센서/경량추론) → **엣**지서버/게이트웨이 → **M**EC(기지국 근처) → **클**라우드(학습/집계))
> - **저·대·프·오·연** (지능형 엣지 5대 핵심 특성: **저**지연 실시간, **대**역폭 절감, **프**라이버시 보호, **오**프라인 동작, **연**합학습)
> - **양·프·증** (온디바이스 AI 3대 경량화 기법: **양**자화, **프**루닝, 지식 **증**류) |

| :--- | :--- |
| **토픽명** | **지능형 엣지 컴퓨팅 (Intelligent Edge) 및 클라우드 AI vs 온디바이스 AI** |
| **정의** | 엣지 노드에서 직접 AI 추론·의사결정을 수행하는 **지능형 엣지 컴퓨팅**과, 원격 데이터센터에서 실행되는 **클라우드 AI** 대비 단말 내 NPU에서 직접 추론하는 **온디바이스 AI**의 구조적 비교 |
| **키워드** | MEC(Mobile Edge Computing), 연합학습(Federated Learning), NPU/AP, TinyML/ONNX Runtime, 하이브리드 AI |
| **개념도** | **[ 엣지 컴퓨팅 진화 및 계층 구조 ]**<br>`클라우드 중심(중앙처리) → 엣지 컴퓨팅(근거리처리) → 지능형 엣지 컴퓨팅(근거리 AI추론)`<br>`[엣지 디바이스: 센서/경량추론] → [엣지서버/게이트웨이: MEC서버] → [클라우드: 학습/글로벌집계]`<br><br>**[ 하이브리드 AI 분산 처리 ]**<br>`[단말: 온디바이스 NPU - 단순 추론(음성인식/번역)] ⇄ [클라우드: 복잡 추론(대규모 연산)] — 지능형 엣지가 중간 계층 중계` |
| **구성요소** | 1. **엣지 디바이스**: 스마트카메라·IoT센서, 센서 데이터 수집 및 경량 추론<br>2. **MEC(Mobile Edge Computing)**: 5G 기지국 근처 배치된 클라우드, 저지연 처리<br>3. **연합학습(Federated Learning)**: 엣지 단말에서 개인 데이터 유출 없이 모델 파라미터만 중앙 집계<br>4. **온디바이스 경량화 기법**: 양자화(FP32→INT8), 프루닝, 지식증류로 NPU 탑재 가능한 크기로 축소<br>5. **전용 하드웨어**: Apple Neural Engine, Qualcomm Hexagon NPU, NVIDIA Jetson |
| **비교** | **클라우드 AI**<br>- 실행위치: 원격 데이터센터, 지연: 100ms 이상<br>- 모델크기: GPT-4급 수백B 파라미터 가능, 네트워크 필수<br><br>**온디바이스 AI**<br>- 실행위치: 단말 내 NPU/AP, 지연: 수ms<br>- 모델크기: 1~7B 경량화 모델(sLLM), 오프라인 가능·프라이버시 우수 |
| **차별화** | **지연·프라이버시·비용을 고려한 하이브리드 엣지-클라우드 배치 전략**<br>1. **작업 특성별 실행 위치 분리**: 실시간성이 중요한 단순 추론(음성인식, 이상감지)은 온디바이스/엣지에 배치하고, 대규모 연산이 필요한 복잡 추론은 클라우드로 위임하는 하이브리드 AI 아키텍처 설계.<br>2. **연합학습을 통한 프라이버시-성능 균형**: 각 엣지 단말에서 로컬 학습한 모델 파라미터만 중앙 서버로 전송해 원본 개인 데이터 유출 없이 전역 모델을 지속 개선.<br>3. **MEC-5G 연계 저지연 서비스**: 자율주행·스마트팩토리 등 ms 단위 응답이 필요한 서비스는 5G MEC 서버에 AI 추론 애플리케이션을 배치해 백홀 왕복 지연을 제거. |
