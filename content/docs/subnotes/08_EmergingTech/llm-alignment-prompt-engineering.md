# LLM 정렬 학습(RLHF·RAFT) 및 프롬프트 엔지니어링 서브노트

> **두음 머리에 박기 🧠**
> - **S·R·P** (RLHF 3단계 파이프라인: **S**FT 지도 학습 초기 파인튜닝 ➔ **R**M 보상 모델 학습 ➔ **P**PO 강화학습 정책 최적화)
> - **제·명·역·예·반** (프롬프트 설계 5대 원칙: 출력형식/길이 **제**약조건, **명**확성, **역**할부여 Persona, **예**시제공 Few-shot, **반**복개선 Iteration)
> - **제·프·씨·티·롤·랙·구** (프롬프트 기법 총정리: **제**로샷, **프**롬프트(few-shot), **씨**오티 CoT, **티**오티 ToT, **롤**플레잉(Role), **랙**(RAG) 연계, **구**조화 출력)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **LLM 정렬 학습 파이프라인 (RLHF/RAFT) 및 프롬프트 엔지니어링 (Prompt Engineering)** |
| **정의** | 인간 선호도/도메인 지식 맞춰 LLM 가중치 재조정 **정렬(Alignment) 학습(RLHF/RAFT)** + 재학습 없이 입력설계만으로 출력유도 **프롬프트 엔지니어링** |
| **키워드** | S·R·P(RLHF), RAFT(2가지 정의), CoT/ToT, Few-shot, RAG 연계, KL 발산 페널티 |
| **개념도** | **[ RLHF 파이프라인 ]**<br>`SFT(인간 시범 데이터 지도학습) → 인간 피드백 수집(선호쌍) → RM(보상모델) 학습 → PPO 강화학습(KL 페널티로 기존모델 이탈 방지)`<br><br>**[ RAFT 정의 A: Retrieval-Augmented Fine-Tuning ]**<br>`문서 코퍼스 → RAG Q&A 생성 → Oracle/Distractor 혼합 데이터셋 → SFT 학습`<br><br>**[ RAFT 정의 B: Reward rAnked Fine-Tuning ]**<br>`샘플 생성 → 보상모델 평가·랭킹 → 최상위(Top-K) 필터링 → SFT 반복 학습` |
| **구성요소** | 1. **SFT (지도 학습 미세조정)**: 고품질 인간 작성 QA 데이터로 초기 파인튜닝<br>2. **RM (보상 모델)**: 인간 선호도 쌍(preferred/rejected)으로 보상 함수 학습<br>3. **RAFT 정의 A**: Oracle(정답 근거)·Distractor(노이즈) 문서를 섞어 SFT, RAG 인용 정확도 내재화<br>4. **RAFT 정의 B**: PPO 없이 보상 필터링된 Top-K 샘플만으로 반복 SFT하는 안정적 대안<br>5. **CoT (Chain-of-Thought)**: "단계별로 생각하라" 지시로 추론·수학 문제 정확도 향상 |
| **비교** | **RLHF (PPO 기반)**<br>- 학습 방식: 보상 모델 기반 강화학습(PPO) 정책 최적화<br>- 비용/안정성: 매우 높은 자원 소모, 극심한 학습 불안정성<br><br>**RAFT 정의 B (Reward rAnked Fine-Tuning)**<br>- 학습 방식: 보상 필터링된 최상위 샘플로 반복 SFT (RL 미사용)<br>- 비용/안정성: 중간 비용, RL 대비 극도로 안정적 |
| **차별화** | **정렬 기법 선택 및 프롬프트 품질 관리 실무 전략**<br>1. **목적별 정렬 기법 선택**: 안전성·무해성 선호정렬 핵심 → RLHF / RAG 인용정확도 핵심 → RAFT(A) / PPO 인프라無 안정정렬 → RAFT(B)<br>2. **CoT+RAG 결합 설계**: 공공 민원 FAQ 등 환각저감 → 검색문서 프롬프트 주입(RAG) + CoT 단계적 근거추론 이중 안전장치<br>3. **Iteration 자동화**: 출력결과 자동평가지표 채점 → 프롬프트 자동재작성 최적화 파이프라인(APE 등) → 수작업 튜닝비용 절감 |
