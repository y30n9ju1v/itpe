# 클라우드 서비스 유형(IaaS/PaaS/SaaS/FaaS) 및 멀티클라우드 전략 서브노트

> **두음 머리에 박기 🧠**
> - **I·P·S·F** (클라우드 서비스 4대 유형, 추상화 증가 순: **I**aaS(인프라) → **P**aaS(플랫폼) → **S**aaS(소프트웨어) → **F**aaS(함수/서버리스))
> - **벤·서·가·규·비** (멀티클라우드 도입 5대 필요성: **벤**더Lock-in 방지, **서**비스 최적화(CSP별 강점 활용), **가**용성/DR 향상, **규**제 준수(데이터주권), **비**용 최적화)
> - **통·네·아·데·보·모** (멀티클라우드 6대 시스템 요구사항: **통**합관리플레인, **네**트워크 연결성, **아**이디IAM/SSO, **데**이터 이동성, **보**안정책 일관성, **모**니터링 통합)

| **토픽명** | **클라우드 컴퓨팅 서비스 유형 (IaaS·PaaS·SaaS·FaaS) 및 멀티클라우드 (Multicloud) 전략** |
| **정의** | 추상화수준별 IaaS/PaaS/SaaS/FaaS 분류 **클라우드 서비스 유형** + 벤더종속 방지·최적서비스 활용 위한 복수 퍼블릭클라우드 조합 **멀티클라우드 전략** |
| **키워드** | 공유 책임 모델, IaaS~FaaS 추상화 스펙트럼, Vendor Lock-in, Egress Cost, Kubernetes/Terraform, 하이브리드 클라우드 |
| **개념도** | **[ 클라우드 서비스 유형별 책임 범위 (사용자 관리 ↓, 클라우드 관리 ↑) ]**<br>`On-Premise: HW+OS+미들웨어+앱 전부(사용자)`<br>`IaaS: OS+미들웨어+앱(사용자) / HW+가상화(클라우드)`<br>`PaaS: 앱+데이터(사용자) / OS+미들웨어+HW(클라우드)`<br>`SaaS: 데이터·설정만(사용자) / 나머지 전부(클라우드)`<br>`FaaS: 함수 코드만(사용자) / 런타임+인프라 전부(클라우드)`<br><br>**[ 멀티클라우드 워크로드 분산 전략 ]**<br>`[핵심 원장(온프레미스/AWS)] + [AI·빅데이터(GCP)] + [협업·SaaS(Azure)] → 통합 관리 플레인(CMP)으로 단일 콘솔 관리` |
| **구성요소** | 1. **IaaS**: 가상서버·스토리지·네트워크 제공 → 사용자 OS 직접관리(AWS EC2)<br>2. **PaaS**: 개발·배포 플랫폼 제공 → 앱코드만 작성(Google App Engine)<br>3. **SaaS**: 완성앱 제공 → 사용자 데이터·설정만 관리(Salesforce)<br>4. **FaaS**: 이벤트트리거 함수실행 → 실행시간·횟수 과금(AWS Lambda)<br>5. **멀티클라우드 핵심도구**: Kubernetes(오케스트레이션), Terraform(IaC), Istio(서비스메시), CASB(보안) |
| **비교** | **멀티클라우드 (Multicloud)**<br>- 정의: 복수 퍼블릭클라우드 조합, 목적: 벤더다양화·최적서비스·비용최적화<br>- 데이터위치: 복수 퍼블릭클라우드 간 분산<br><br>**하이브리드 클라우드 (Hybrid Cloud)**<br>- 정의: 온프레미스+퍼블릭클라우드 연계, 목적: 레거시연동·규정준수·기밀데이터 자체보관<br>- 데이터위치: 사내서버+퍼블릭클라우드 혼재 |
| **차별화** | **멀티클라우드 관리 복잡성 해소 실무 아키텍처**<br>1. **클라우드 중립 배포계층**: K8s 멀티클러스터+Terraform IaC → CSP 비종속 배포파이프라인 → 벤더전환 유연성 확보<br>2. **Egress Cost·레이턴시 최적화**: 이동잦은 워크로드는 동일CSP 배치, CSP간 통신 시만 전용망(Direct Connect) → 비용·지연 최소화<br>3. **통합 IAM/보안정책 표준화**: CASB+통합SSO로 CSP별 IAM 단일정책 통제, 통합모니터링(Datadog)으로 비용·가용성·보안 단일뷰 |
