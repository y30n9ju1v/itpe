# 클라우드 서비스 유형(IaaS/PaaS/SaaS/FaaS) 및 멀티클라우드 전략 서브노트

> **두음 머리에 박기 🧠**
> - **I·P·S·F** (클라우드 서비스 4대 유형, 추상화 증가 순: **I**aaS(인프라) → **P**aaS(플랫폼) → **S**aaS(소프트웨어) → **F**aaS(함수/서버리스))
> - **벤·서·가·규·비** (멀티클라우드 도입 5대 필요성: **벤**더Lock-in 방지, **서**비스 최적화(CSP별 강점 활용), **가**용성/DR 향상, **규**제 준수(데이터주권), **비**용 최적화)
> - **통·네·아·데·보·모** (멀티클라우드 6대 시스템 요구사항: **통**합관리플레인, **네**트워크 연결성, **아**이디IAM/SSO, **데**이터 이동성, **보**안정책 일관성, **모**니터링 통합)

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **클라우드 컴퓨팅 서비스 유형 (IaaS·PaaS·SaaS·FaaS) 및 멀티클라우드 (Multicloud) 전략** |
| **정의** | 추상화 수준에 따라 IaaS/PaaS/SaaS/FaaS로 분류되는 **클라우드 서비스 유형**과, 벤더 종속 방지와 최적 서비스 활용을 위해 복수 퍼블릭 클라우드를 조합하는 **멀티클라우드 전략** |
| **키워드** | 공유 책임 모델, IaaS~FaaS 추상화 스펙트럼, Vendor Lock-in, Egress Cost, Kubernetes/Terraform, 하이브리드 클라우드 |
| **개념도** | **[ 클라우드 서비스 유형별 책임 범위 (사용자 관리 ↓, 클라우드 관리 ↑) ]**<br>`On-Premise: HW+OS+미들웨어+앱 전부(사용자)`<br>`IaaS: OS+미들웨어+앱(사용자) / HW+가상화(클라우드)`<br>`PaaS: 앱+데이터(사용자) / OS+미들웨어+HW(클라우드)`<br>`SaaS: 데이터·설정만(사용자) / 나머지 전부(클라우드)`<br>`FaaS: 함수 코드만(사용자) / 런타임+인프라 전부(클라우드)`<br><br>**[ 멀티클라우드 워크로드 분산 전략 ]**<br>`[핵심 원장(온프레미스/AWS)] + [AI·빅데이터(GCP)] + [협업·SaaS(Azure)] → 통합 관리 플레인(CMP)으로 단일 콘솔 관리` |
| **구성요소** | 1. **IaaS**: 가상 서버·스토리지·네트워크 제공, 사용자가 OS 직접 관리(AWS EC2)<br>2. **PaaS**: 개발·배포 플랫폼 제공, 앱 코드만 작성(Google App Engine)<br>3. **SaaS**: 완성된 앱을 제공, 사용자는 데이터·설정만 관리(Salesforce)<br>4. **FaaS**: 이벤트 트리거 함수 실행, 실행 시간·횟수 기준 과금(AWS Lambda)<br>5. **멀티클라우드 핵심 도구**: Kubernetes(컨테이너 오케스트레이션), Terraform(IaC), Istio(서비스 메시), CASB(보안) |
| **비교** | **멀티클라우드 (Multicloud)**<br>- 정의: 복수의 퍼블릭 클라우드 조합, 목적: 벤더 다양화·최적서비스·비용최적화<br>- 데이터 위치: 복수 퍼블릭 클라우드 간 분산<br><br>**하이브리드 클라우드 (Hybrid Cloud)**<br>- 정의: 온프레미스(프라이빗)+퍼블릭 클라우드 연계, 목적: 레거시 연동·규정준수·기밀데이터 자체보관<br>- 데이터 위치: 사내 서버+퍼블릭 클라우드 혼재 |
| **차별화** | **멀티클라우드 관리 복잡성 해소를 위한 실무 아키텍처**<br>1. **클라우드 중립적 배포 계층 구축**: Kubernetes 멀티클러스터와 Terraform IaC로 CSP에 종속되지 않는 배포 파이프라인을 구성해 벤더 전환 유연성 확보.<br>2. **Egress Cost 및 레이턴시 최적화**: 데이터 이동이 잦은 워크로드는 동일 CSP 내에 배치하고, CSP 간 통신이 필요한 경우에만 전용 네트워크(Direct Connect 등)를 사용해 비용·지연을 최소화.<br>3. **통합 IAM/보안 정책 표준화**: CASB와 통합 SSO로 CSP별 상이한 IAM 권한 체계를 단일 정책으로 통제하고, 통합 모니터링(Datadog 등)으로 전체 비용·가용성·보안 상태를 단일 뷰로 가시화. |
