# 에이전틱 AI, MCP 및 다중 에이전트 시스템(MAS) 서브노트

> **두음 머리에 박기 🧠**
> - **자·도·장·계·적** (에이전틱 AI 5대 핵심 특성: **자**율성, **도**구사용, **장**기기억, **계**획수립(ReAct/CoT), **적**응성)
> - **T·R·P** (MCP 3대 기본 요소: **T**ools(실행함수), **R**esources(데이터), **P**rompts(재사용 템플릿))
> - **오·전·검·실** (MAS 4대 에이전트 역할: **오**케스트레이터(태스크 분해·할당), **전**문 에이전트, **검**증 에이전트(Critic), **실**행 에이전트)
> - **입·권·체·유·붕** (에이전틱 AI 5대 보안위협: **입**력조작(프롬프트인젝션·환각), **권**한남용(과도한 권한위임), **체**인공격(툴 체이닝 익스플로잇), **유**출(메모리/맥락 유출), **붕**괴(다중에이전트 오염·신뢰경계 붕괴))

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **에이전틱 AI (Agentic AI), MCP (Model Context Protocol) 및 다중 에이전트 시스템 (MAS)** |
| **정의** | 스스로 계획을 세우고 도구를 사용해 자율적으로 목표를 달성하는 **에이전틱 AI**, 이를 위한 AI-도구 연동 표준 **MCP**, 그리고 복수 에이전트가 협업하는 **MAS** |
| **키워드** | 자·도·장·계·적, ReAct/CoT, JSON-RPC 2.0, M×N 문제, T·R·P, 프롬프트 인젝션, PoLP/RBAC, Human-in-the-loop |
| **개념도** | **[ 에이전틱 AI 아키텍처 루프 ]**<br>`[사용자 목표] → [계획 모듈: CoT/ReAct 하위작업 분해] → [실행 모듈: 도구 호출(API/Code/Browser)] → [메모리 모듈: 단기+장기(VectorDB)] → [반성/검증: 결과 평가·재계획]`<br><br>**[ MCP M×N → M+N 구조 전환 ]**<br>`(기존) M개 AI × N개 서비스 = M×N개 커스텀 통합`<br>`(MCP) [MCP Client(Claude 등)] ←JSON-RPC→ [MCP Server(파일시스템/DB/GitHub 등)] = M+N개 표준 연동`<br><br>**[ MAS 협업 구조 ]**<br>`[오케스트레이터] → 하위 태스크 할당 → [전문 에이전트1][전문 에이전트2] → [검증 에이전트(Critic)] → [실행 에이전트(도구 호출)]` |
| **구성요소** | 1. **에이전틱 AI 5대 특성**: 자율성·도구사용·장기기억·계획수립·적응성으로 단순 챗봇과 구별<br>2. **MCP 3대 요소**: Tools(함수 실행), Resources(데이터 접근), Prompts(재사용 템플릿), JSON-RPC 2.0 기반<br>3. **MAS 4대 역할**: 오케스트레이터(분해·통합), 전문 에이전트(특화 수행), 검증 에이전트(품질 평가), 실행 에이전트(도구 직접 호출)<br>4. **MAS 필요성**: 단일 LLM 컨텍스트/전문성 한계 극복, 병렬 처리로 효율화, 역할 분리로 오류 감소<br>5. **에이전틱 AI 5대 보안위협**: 프롬프트 인젝션(악성지시 은닉)·환각 기반 오작동, 과도한 권한위임(파일삭제·결제 등 오남용), 툴 체이닝 익스플로잇(도구 연쇄 우회공격), 메모리/맥락 유출(장기메모리 민감정보 노출), 다중에이전트 오염(오염 에이전트의 협업체계 전파)<br>6. **관리적·기술적 보안대책 2×2**: [권한통제] PoLP 정책+RBAC 스코프 제어, [입력검증] 가이드라인+프롬프트인젝션 탐지, [모니터링] 감사체계+행동로깅·이상탐지, [승인절차] Human-in-the-loop+민감작업 승인게이트, [격리] 업무별 에이전트 분리+샌드박스·네트워크 세그멘테이션, [데이터보호] 보존기간·파기정책+메모리암호화·PII마스킹 |
| **비교** | **단일 에이전트**<br>- 구조: 하나의 LLM+도구, 처리방식: 순차적<br>- 오류 검증: 자기 검증 어려움, 구현 복잡도 낮음<br><br>**다중 에이전트 시스템(MAS)**<br>- 구조: 복수 LLM/에이전트 협력, 처리방식: 병렬·분산<br>- 오류 검증: 에이전트 간 상호 검증 가능, 구현 복잡도 높음(조율 오버헤드) |
| **차별화** | **에이전틱 AI 확산에 따른 보안·거버넌스 리스크 관리 전략**<br>1. **과도한 권한(Excessive Agency) 통제**: MCP 서버·도구 호출에 대해 최소 권한 원칙(PoLP)을 적용하고, 되돌릴 수 없는 작업(파일 삭제, 결제 등)은 반드시 인간 승인 단계(Human-in-the-loop)를 거치도록 설계.<br>2. **MCP 공급망 신뢰성 검증**: 외부 MCP 서버의 코드/권한 범위를 사전 검증하고 에이전트 행동 감사 로그를 필수화하여 프롬프트 인젝션 확산 위험 차단.<br>3. **MAS 책임 소재 추적 체계**: 오케스트레이터가 각 서브 에이전트의 작업 이력을 트레이싱하도록 하여, 오류 발생 시 책임 에이전트를 즉시 식별하고 비용(다중 LLM 호출) 대비 효과를 모니터링.<br>4. **자율성 등급별 단계적 확대**: 업무 위험도에 따라 완전자동/반자동(승인)/수동 3단계로 자율성 등급을 구분하는 거버넌스와 MCP 서버·플러그인 화이트리스트·서명 검증 등 공급망 관리를 병행하고, 공공부문은 저위험 업무부터 시범 적용 후 고위험 업무로 확대하는 관리적·기술적 심층방어(Defense in Depth)를 적용. |
