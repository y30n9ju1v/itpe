# 공공 마이데이터 활용 방안 서브노트

> **두음 머리에 박기 🧠**
> - **금·복·의·교·부** (공공 마이데이터 5대 활용분야: **금**융(대출자동화), **복**지(자격자동확인), **의**료(중복검사방지), **교**육(취업연계), **부**동산)
> - **표·지·동·이** (공공 마이데이터 4대 구현 기술체계: **표**준API(OAuth2.0), 마이데이터 **지**갑, **동**의·철회관리, **이**력관리(유통로그))
> - **표·고·재·동** (공공 마이데이터 4대 추진과제/한계: **표**준화 부족, **고**령층 접근성, **재**식별 위험, **동**의피로(Consent Fatigue))

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **공공 마이데이터 (Public MyData) 활용 방안 — 데이터 이동권 기반** |
| **정의** | 행정·공공기관이 보유한 개인정보를 정보주체(개인)의 요구에 따라 본인 또는 제3자에게 전송하는 **공공 마이데이터** 제도로, 개인정보보호법·전자정부법 개정으로 명시된 **데이터 이동권**에 근거 |
| **키워드** | 데이터 이동권, 정부24 마이데이터, OAuth 2.0 표준API, 마이데이터 지갑, 동의 피로 |
| **개념도** | **[ 공공 마이데이터 데이터 흐름 ]**<br>`[정보주체(개인) 전송요구] → [공공기관 보유 데이터(소득/복지/의료/교육 등)] → OAuth 2.0 표준API 인증 → [마이데이터 지갑(정부24/민간앱)] → [제3자 서비스(대출심사/취업플랫폼 등)]`<br>`         ↓ 전 과정 유통이력(로그) 보관, 항목별 동의·철회 관리` |
| **구성요소** | 1. **마이데이터 개념**: 정보주체가 자신의 데이터 열람·전송·활용을 직접 통제하는 권리<br>2. **5대 활용분야**: 금융(소득·납세 자동전송), 복지(생애주기 자격 자동확인), 의료(예방접종·처방 이력 공유), 교육(성적·자격증 전송), 부동산<br>3. **구현 기술체계**: 표준API(OAuth 2.0), 마이데이터 지갑(정부24/네이버/카카오), 세분화된 동의·철회 관리, 데이터 유통 이력 로그<br>4. **추진 한계**: 기관 간 데이터 표준화 부족, 고령층 접근성, 결합 시 재식별 위험, 동의 피로(Consent Fatigue) |
| **비교** | **금융 마이데이터 (선행 제도)**<br>- 적용분야: 은행·카드·보험 등 금융권 데이터<br>- 성숙도: 신용정보법 기반 상용화 완료<br><br>**공공 마이데이터 (확장 제도)**<br>- 적용분야: 행정·공공기관 보유 개인정보(복지/의료/교육 등)<br>- 성숙도: 개인정보보호법·전자정부법 개정 기반 확산 중 |
| **차별화** | **공공 마이데이터 신뢰성 및 접근성 제고 전략**<br>1. **PET(프라이버시 강화기술) 결합**: 데이터 결합 시 발생하는 재식별 위험을 방지하기 위해 가명처리·차분프라이버시 등 PET를 마이데이터 전송 파이프라인에 적용.<br>2. **동의 피로 완화를 위한 UX 표준화**: 세분화된 항목별 동의 절차를 정부24 등 단일 플랫폼에서 원클릭 일괄동의·주기적 재동의 알림 방식으로 단순화해 이용자 이탈 방지.<br>3. **디지털 취약계층 접근성 보장**: 고령층 등 디지털 취약계층을 위한 대면·전화 기반 마이데이터 대리 신청 채널을 병행 운영하고, 기관 간 데이터 표준화(공통 API 스키마)를 우선 추진해 활용 분야를 단계적으로 확대. |
