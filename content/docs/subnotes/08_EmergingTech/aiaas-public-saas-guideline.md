# AIaaS 및 공공부문 SaaS 이용 가이드라인 서브노트

> **두음 머리에 박기 🧠**
> - **API·ML·에** (AIaaS 3대 계층: AI **API** 호출, **ML**aaS(학습·배포 플랫폼), **에**이전트 서비스 호스팅)
> - **책·위·지·투** (공공 SaaS 위험관리 4대 원칙: **책**임공유모델, **위**험기반접근, **지**속적모니터링, **투**명성)
> - **기·민·공** (공공데이터 3등급별 SaaS 허용기준: **기**밀(민간전용 클라우드 권장), **민**감(CSAP인증 SaaS만), **공**개(일반 퍼블릭 SaaS 허용))

| 항목 | 내용 |
| :--- | :--- |
| **토픽명** | **AIaaS (AI as a Service) 및 공공부문 SaaS 이용 가이드라인 (CSAP·SLA)** |
| **정의** | AI 인프라·모델을 클라우드 서비스 형태로 제공하는 **AIaaS**와, 공공기관이 SaaS를 안전하게 도입하도록 위험관리·SLA 기준을 규정한 **공공부문 SaaS 이용 가이드라인** |
| **키워드** | API·ML·에(AIaaS 3계층), MLaaS, Foundation Model API, CSAP, 책임공유모델, RTO/RPO |
| **개념도** | **[ AIaaS 계층 구조 ]**<br>`[AI API 호출: GPT API/Vision AI] → [MLaaS: SageMaker/Vertex AI(학습·배포·모니터링)] → [AI 에이전트 서비스: Bedrock Agents(자율 호스팅)]`<br><br>**[ 공공 SaaS 데이터 등급별 허용 절차 ]**<br>`정보자산 분류·민감도 평가 → 등급 판정(기밀/민감/공개) → CSAP 인증 확인 → 책임공유모델 기반 통제 도출 → SLA·계약서 반영` |
| **구성요소** | 1. **AIaaS 3계층**: AI API(단순호출) → MLaaS(모델 학습·배포·모니터링) → AI 에이전트 서비스(자율 호스팅)<br>2. **AIaaS 6대 도입 고려사항**: 데이터주권, 벤더종속, SLA/가용성, 모델버전관리, 비용예측, 규제준수<br>3. **공공 SaaS 데이터 3등급**: 기밀(제한적 허용)/민감(CSAP 인증 SaaS만)/공개(일반 허용)<br>4. **SLA 핵심 지표**: 가용성 99.9%(월 43.8분 미만 장애), 보안사고 통보 1시간 이내, 중요시스템 RTO 4시간/RPO 1시간<br>5. **Lock-in 방지**: 데이터 포맷 표준화(CSV/JSON), 서비스 종료 시 90일 이내 데이터 반환 의무화 |
| **비교** | **AI API (단순 호출형 AIaaS)**<br>- 특징: 특정 AI 기능만 호출(OpenAI GPT API), No-Code 활용 가능<br>- 적합: 빠른 프로토타이핑, 전문인력 불필요<br><br>**MLaaS (플랫폼형 AIaaS)**<br>- 특징: 모델 학습·배포·모니터링 전 과정 관리형 제공(SageMaker)<br>- 적합: 도메인 특화 모델 자체 구축·운영이 필요한 조직 |
| **차별화** | **공공기관 AI·SaaS 도입의 데이터 주권 및 Lock-in 리스크 관리 전략**<br>1. **데이터 등급별 차등 도입 전략**: 기밀 데이터는 민간전용 클라우드 또는 온프레미스 AI로 한정하고, 민감 데이터는 CSAP 인증 AIaaS/SaaS로 제한하며, 공개 데이터만 일반 퍼블릭 서비스 활용을 허용하는 3단계 정책 수립.<br>2. **SLA 기반 서비스 연속성 확보**: RTO/RPO 목표를 계약에 명시하고, 침해사고 1시간 이내 통보 조항을 반영해 AI API 장애·모델 버전 변경으로 인한 서비스 중단 리스크를 계약적으로 방어.<br>3. **Lock-in 방지 및 이식성 확보**: 개방형 데이터 포맷과 표준 API 사용을 계약 조건화하고, 멀티클라우드 전환 가능성을 사전 검토해 특정 AIaaS/SaaS 공급자 종속을 최소화. |
